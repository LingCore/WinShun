# 压缩包搜索 · Archive search

插件库里的 C++ 常驻插件（设置 → 插件 → 插件库 里安装）。装上并打开后，压缩包里的文件也能按名字搜到：记得有份“报价单”，却忘了它打包在哪个 zip 里，直接搜就行。

- **怎么搜**：和平时一样在搜索框里输入文件名（“全部”或“内容”里），压缩包里叫这个名字的文件会跟在普通结果后面；输入 `zip` 加空格（或 `压缩包`），只看压缩包里的。几个词用空格隔开，要都出现在文件的路径里；其中的词也可以是压缩包自己的名字，比如 `备份 报价` 能找到 `2025备份.zip` 里的 `报价单.xlsx`。
- **每一行是什么**：标题是压缩包里的文件名，下面一行是压缩包的完整路径和文件在包里的文件夹。`Enter` 打开压缩包；`Ctrl+Enter` 把这一个文件解压出来并打开（解到插件自己的数据文件夹里，是一份副本，改了不会写回压缩包）；`Shift+Enter` 打开压缩包所在的文件夹。在“内容”里选中一行，右边的内容详情和预览直接显示这个文件（32 MB 以内）。
- **支持的格式**：zip、7z、rar（含 RAR5）、tar、tar.gz / tgz、tar.xz / txz、cab、iso。按文件内容认格式，不看扩展名；jar、apk、epub 这类其实也是压缩包的，在插件卡片的“还要收录的类型”里加上就行。
- **只读文件列表，不解压**：后台用最低的磁盘优先级，把每个压缩包打开一次、读出里面的文件名，之后只在压缩包变了时重读。有哪些压缩包是从 Win顺 自己的索引里拿的，不会再扫一遍硬盘。同一个压缩包放了好几份（交付包、备份的备份）时，文件名、大小、时间都一样的只读第一份，里面的清单在内存和硬盘上也只存一份；搜索结果里先各列一份，其余的拷贝排在后面。进度显示在插件卡片上，可以暂停。
- **做不到的会写明**：文件名也加了密码的压缩包（7z 的“加密文件名”、rar 的 `-hp`）看不到里面有什么；只给内容加密码的照常能搜到名字，但预览和解压要密码，请打开压缩包。网盘上没下载到本机的压缩包不会为了这个去下载。损坏的、只读到一部分的，卡片上都有数。tar.bz2、tar.zst 暂不支持；网络共享上的压缩包不读。
- **中文文件名**：老的 zip 不标明文件名的编码，按系统的编码（中文 Windows 是 GBK）来读，一般不会乱码。
- **权限**：`winshun:search` 用来向 Win顺 要压缩包的清单；`files:read` 说明它会读这些压缩包。不联网，不改任何文件；在严格沙箱（低完整性）里运行，只能写自己的数据文件夹。读压缩包用的是 libarchive（许可证在 `licenses` 文件夹里）。

A resident C++ plugin from the plugin library (Settings → Plugins → Plugin library). Once on, files inside archives are found by name: you remember an invoice but not which zip it went into, so you just search. Type the name in the search box as usual (in All or Content) and members of archives with that name follow the ordinary results; `zip` and a space lists those alone. Several words must all be in the member's path; a word may also be in the archive's own name (`backup invoice` finds `invoice.xlsx` in `2025-backup.zip`). A row's title is the member's name, its second line the archive's full path and the folder inside it. `Enter` opens the archive, `Ctrl+Enter` unpacks that one file and opens it (a copy in the plugin's data folder: changes are not written back), `Shift+Enter` shows the archive in its folder; in Content, the details pane and the preview show the member itself (up to 32 MB). It reads zip, 7z, rar (RAR5 too), tar, tar.gz / tgz, tar.xz / txz, cab and iso, told by their bytes, not their names; add jar, apk, epub and the like under “More types” on the plugin's card. Only the lists of files are read, in the background at the lowest I/O priority, once per archive and again when it changed; which archives there are comes from WinShun's own index, so no disk is walked again. Of several copies of one archive (the same name, size and time) only the first is read, their list is kept once in memory and on disk, and a search lists each member once before its copies. Progress is on the plugin's card and can be paused. What it cannot do is said there: archives whose names are behind a password (7z “encrypt file names”, rar `-hp`) cannot be looked into; with only the content encrypted the names are found, but preview and unpacking need the password, so open the archive. Cloud files that are online only are not downloaded for this. tar.bz2 and tar.zst are not read yet, nor archives on network shares. Names in old zip files that do not say their encoding are read in the system's (GBK on a Chinese Windows). It needs `winshun:search` for the list of archives and declares `files:read` for reading them; no network, nothing is changed, and it runs in the strict sandbox (low integrity), able to write only its own data folder. Archives are read with libarchive (its license is in `licenses`).
