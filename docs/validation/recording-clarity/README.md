# 录屏：更清晰的画质，30 / 60 帧，占用与老系统

日期：2026-11-24　主机：Windows 11 26200，RTX 4060 Laptop（NVIDIA H.264 Encoder MFT），i9-14900HX，240 Hz 屏，本地构建 `build/recording-clarity`。虚拟机：Windows 10 LTSC 2019（17763）和 Windows 10 22H2（19045），都没有显卡。

## 先量出来的事实

用 `recording-probe sample` 录生成画面（深色、彩色、深底浅色小字），ffmpeg 的 `psnr` 对比原图，1280 × 720、30 帧：

| 编码质量 | 亮度还原度 | 含颜色的还原度 | 码率 |
|---|---|---|---|
| 70（原“小体积”） | 46 dB | 30.2 dB | 355 kbps |
| 80 | 49 dB | 30.5 dB | 414 kbps |
| 90 | 52 dB | 30.6 dB | 480 kbps |
| 100 | 54 dB | 30.7 dB | 570 kbps |

亮度每档都在变好，但含颜色的还原度一直停在 30 dB 上下：H.264（4:2:0）每 2 × 2 个像素只存一种颜色，彩色小字和 ClearType 字边的颜色被抹掉。原来的三档（70 / 75 / 88）肉眼几乎分不出来，原因在这里，不在码率。

## 改法

- 画质四档：小体积、标准、高清、超清，编码质量 70 / 80 / 90 / 100。
- “超清”在选区不超过 H.264 Level 5.2 能装下的大小时（30 帧时 2048 × 1152，60 帧时约 1920 × 1080），把每个像素放大成 2 × 2 块再编码，每个像素留住自己的颜色。选区更大时按原尺寸、质量 100。
- 帧率单独选：15 / 30 / 60。帧时间按帧序号算，等待改用高精度定时器。
- Windows 11 24H2 起让系统按录制帧率送帧（`MinUpdateInterval`）。
- 编码逐级回退：显卡 2 倍 → 显卡原尺寸 → 软件 2 倍 → 软件原尺寸；被拒的每一步写进日志；没按 2 倍保存、没跟上帧率时，保存后的面板说明。
- 编码器不接受质量模式时，码率按档位翻倍（原来各档同一个码率）。
- GIF 不缩小时，中间视频也按 2 倍录，导出时缩回原尺寸；新增“超清”档保持原尺寸。
- 选项面板改成两栏，占满面板宽度（`panel-options.png`）。

## 清晰度

同一画面，1280 × 720、30 帧、质量 100：

| | 含颜色的还原度 | 码率 |
|---|---|---|
| 原尺寸，显卡编码 | 30.7 dB | 570 kbps |
| 2 倍，显卡编码 | 47.1 dB | 1,048 kbps |
| 原尺寸，软件编码 | 30.7 dB | 693 kbps |
| 2 倍，软件编码 | 47.1 dB | 1,382 kbps |

`compare-light.png`、`compare-dark.png`：从上到下依次是原图、原尺寸质量 80、原尺寸质量 100、2 倍质量 100（放大 4 倍看）。前三行里红字发暗发灰，第四行和原图一样。

GIF（641 × 361，不缩小）：彩色小字还原度从 26.7 dB 到 39.2 dB，尺寸不变。

## 帧率

1920 × 1080 选区按 2 倍录成 3840 × 2160、60 帧，显卡和软件编码 3 秒都是 180 帧。定时方式对比（1280 × 720、60 帧、3 秒，各跑 4 次）：高精度定时器 4 次都是 180 帧、帧间隔都是 16.7 ms；`Sleep` 有一次只有 133 帧，最长空档 83 ms。32 个逻辑核全部占满时录 60 帧 6 秒：360 / 360 帧，没有空档。

## 占用

录屏幕上一个每帧都在变的 1280 × 720 窗口（240 Hz 屏），录制进程的占用：

| | CPU（单核的百分比） | GPU |
|---|---|---|
| 30 帧，原尺寸，显卡编码 | 3.4% | 5.4% |
| 60 帧，原尺寸，显卡编码 | 5.0% | 10.1% |
| 60 帧，2 倍，显卡编码 | 5.5% | 21.9% |
| 60 帧，2 倍，显卡编码，系统不按帧率送帧 | 10.9% | 27.1% |
| 30 帧，原尺寸，软件编码 | 33.6% | 1.7% |
| 60 帧，原尺寸，软件编码 | 63.7% | 1.2% |
| 60 帧，2 倍，软件编码 | 187.6% | 9.8% |

系统合成器（`dwm.exe`）在各种情况下都是 3%–5% GPU，和不录时差不多。

## 老系统

`WinShunCapture.exe --preview-recording … --auto`（经面板、选区、采集、工作进程），虚拟机里跑：

| 系统 | 情况 | 结果 |
|---|---|---|
| Windows 10 LTSC 2019（17763） | 标准，30 帧 | 95 帧 / 3.17 秒，正常 |
| | 超清，60 帧 | 录成了，原尺寸，约 31 帧/秒；面板两行提示（`panel-advice-1809.png`）。日志：`read 31.5 ms, encode 0.7 ms a frame, waits by timer`，慢在传统方式读屏幕，不在编码和定时 |
| | GIF，超清 | 正常，800 × 460、20 帧 |
| Windows 10 22H2（19045） | 标准，30 帧 | 94 帧 / 3.12 秒，正常 |
| | 超清，60 帧 | 186 帧 / 3.10 秒，原尺寸（没有显卡，放不了 2 倍，面板有提示）；`read 0.1 ms, encode 1.3 ms a frame` |

主机上同样的流程：`--ultra-quality --fps 60` 把 800 × 460 选区存成 1600 × 920、60 帧，3.117 秒 187 帧，显卡编码；`--gif --ultra-quality`、默认档、`--ui-only`（100% 和 150%，中文和英文，GIF，窄面板退回一栏）都通过。

## 别的编码

同一段滚动文字（2 倍尺寸、30 帧），本机 NVENC 经 Media Foundation（ffmpeg 的 `h264_mf` / `hevc_mf` / `av1_mf`）：

| | 质量 70 | 质量 90 |
|---|---|---|
| H.264 | 1,549 kbps，41.7 dB | 1,909 kbps，45.7 dB |
| HEVC | 1,348 kbps，42.5 dB | 1,809 kbps，46.1 dB |
| AV1 | 1,034 kbps，40.4 dB | 1,196 kbps，42.5 dB |

HEVC 只小 5%–13%，Windows 自带播放器放它还要另装扩展；AV1 在相近还原度下小约四分之一，但只有较新的显卡能编，系统没有软件编码器。所以仍用 H.264。

## 自动测试

`ctest -R "^(tst_recording|tst_capturesettings|tst_keycaps)$"` 通过。`clarityByQuality` 检查亮度还原度逐档提高、2 倍比原尺寸在颜色上至少高 8 dB；`doubledWhereItCan` 检查 2 倍做不了时退回原尺寸而不是失败；`gifFromDoubledVideo`、`sharpScaleLimits`、`bitrateByQuality`、`fallenShort` 和 `encodedVideo` 的 15 / 60 帧各行覆盖其余部分。

## 没有验证的

- AMD、Intel 显卡的编码器：主机只有 NVIDIA，虚拟机没有显卡。它们不接受 2 倍尺寸或质量模式时走的回退路径和上面测过的相同，但没有在这两种显卡上实机跑过。
- HDR 屏幕上的 60 帧：HDR 每帧要在 CPU 上转换，可能跟不上，此时面板会提示。
- 真机上的 Windows 10 1809：虚拟机里读屏幕每帧 31.5 ms，真机可能快一些，没有量过。
- 运动剧烈的画面（游戏、视频）下各档的体积差别。
