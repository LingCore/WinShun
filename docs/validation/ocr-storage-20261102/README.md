# OCR 索引存储优化验证 · 2026-11-02

本次仅优化 `winshun.ocr-search` 的索引存储；主程序的文件名索引与原生内容索引没有改格式。没有安装／启用用户配置中的 OCR 搜索插件，没有修改用户索引或停止正在运行的 Win顺，也没有提交、推送或发布版本。

## 研究与取舍

- [SQLite FTS5 数据结构](https://sqlite.org/fts5.html#fts5_data_structures)：倒排文档列表使用变长整数与文档 ID 差分，词典在页内压缩前缀，避免关系逐行存储的开销。`content=''` 避免重复正文，`detail=none` 不存词偏移，`columnsize=0` 不存词数表。查询完成后仍以已有压缩文字核验，识别框继续独立保存，所以没有取消短语核验或高亮能力。
- [Lucene 10.3 倒排格式](https://lucene.apache.org/core/10_3_1/core/org/apache/lucene/codecs/lucene103/Lucene103PostingsFormat.html)：按整数块及变长整数存文档关系，并把位置／载荷分离。这支持本次“压缩候选索引、按需读取高亮”的方向；没有引入 Lucene 的运行时或复制其具体块编码。
- [SQLite WITHOUT ROWID](https://sqlite.org/withoutrowid.html)：旧 `grams` 表本来已经是复合主键、`WITHOUT ROWID`；继续调整同类普通表无法消除每条关系的记录开销。选择共享 Qt 已有的 FTS5，保留 SQLite 事务与已有文件／页／资产结构，避免另写增量索引引擎。

## 改动

1. `asset_terms` 为 contentless FTS5，仅存十六进制片段词元的压缩倒排表。中文单字／双字、ASCII 三字符片段规则不变。候选图片按每个查询词筛选，再在文件层取交集；跨页 AND、短语及精确文字核验保持有效。
2. 数据库版本从 1 升为 2。单事务从已有压缩识别文字重建候选表，再删除旧关系表。源文件离线也能迁移；已有资产 ID、原文与识别坐标保留。容量不足会回滚，更高版本拒绝打开。OCR 语义未改，不需要重新识别。
3. 清理时在同一事务删除倒排项与无引用资产，再合并倒排段、回收空闲页、截断 WAL。定位到 QSQLITE 的零列 PRAGMA 行为：`incremental_vacuum` 单次执行只释放一页，`next()` 无法继续，现循环检查 freelist 的实际进展。避免用完整 VACUUM 重写整个索引。
4. 容量按实际 `page_size` 换算，修正以 4096 字节写死换算时，8192 字节页数据库会获得双倍预算的问题。使用实际 8192 字节页数据库验证 16 MiB 预算及超限写入拒绝。
5. 界面占用统计计入数据库、WAL、SHM。默认 512 MB 是数据库上限，并非预分配；模型、原文件、WAL／SHM 不属于页数限额，活跃读事务可能暂缓日志截断。
6. 集成测试发现共享 `WindowEdge.qml` 已依赖 `WindowMask`，而 OCR 插件缺少类型和着色器资源。补齐该插件的 CMake 接入，真实宿主安装、索引、搜索和打开管理窗口现均通过；没有改动界面设计。

## 体积与速度

Windows 11、Qt 6.12.0、MSVC 2022 x64 Release，同机、同数据生成规则，临时目录隔离测试。两组都是**合成文字索引**，不能视为数万份真实文档的 OCR 耗时或体积承诺。真实 OCR 另有完整回归。

| 数据与指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 10,000 条短文本，数据库与日志 | 13,828,096 B | 10,272,768 B | 约减少 26% |
| 上述样本，20 次暖查询 P95 | 40 ms | 15 ms | 更快 |
| 500 页，每页 40 行中英文／数字／随机汉字，整理后占用 | 10,465,280 B | 3,657,728 B | 约减少 65% |
| 上述密集样本，选择性查询 | 2 ms | 2 ms | 未见退化 |
| 清空密集样本后占用 | 10,473,552 B | 81,920 B | 回收至 80 KiB |

口径说明：旧统计为数据库 + WAL，新统计还包括固定 32 KiB SHM。表中保留两版原始输出，给旧版也加上 SHM 后，缩小比例仍分别约 26%／65%。10,000 条样本按原回归流程直接测量，密集样本按实际后台更新收尾调用 `compact()` 后测量。没有把整理前后的不同时点混为同一指标。

## 验证

`tst_ocrsearch`：20 通过、0 失败、0 跳过（含初始化／清理），约 17 秒。覆盖：

- 中英文、中文单字／双字、短语、误命中核验、跨页 AND、范围与取消。
- 图片／Office／PDF 提取、实际 OCR 增量更新、重命名复用、工作进程超时与恢复。
- 版本 1 离线迁移、再次打开、删除后资产 ID 复用、容量不足迁移回滚、拒绝未来数据库版本。
- 8192 字节页的容量约束、实际超限写入失败且无残留资产。
- 密集索引删除一半后缩小且搜索正确、清空后小于 256 KiB；10,000 条短文本小于 11 MiB、500 页密集样本小于 8 MiB 的体积回归预算。
- 生成插件包，经生产安装器、Host、runner 安装启动，实际索引与关键词／内容搜索，再打开真实管理窗口。

真实 OCR 样本本轮新识别 3 张图片，约 1,867 ms；测试同时覆盖嵌入这些图的 DOCX／PPTX／XLSX、混排 PDF。该数字仅代表这些本机小样本。

构建及测试证据：[最终构建](build.txt)、[完整回归](tests.txt)、[旧版短文本基线](before-10000.txt)、[旧版密集页基线](before-dense.txt)。中间发现的空间回收失败和缺少窗口类型问题均已修复后重新完整验证；最终日志未将失败项算作通过。
