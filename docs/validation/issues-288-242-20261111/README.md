# #242（输入插件关键字后别的结果不见了）和 #288（以管理员身份运行 Win顺 的入口）

2026-11-11。Windows 11，3840 宽、200% 缩放。程序是这次改动的构建（`dist\i288\WinShun`），用单独的配置启动（`--profile build\i288\live\profile`），普通权限；测试前没有 Win顺 在运行。脚本在 `scripts/`，原始输出在 `logs/`。截图没有入库（里面有本机的文件名和路径）。

## #242：打出 `pl`、`ocr`，列表里只剩插件那一行

对方用的是 OCR Studio、批量重命名 1.1.2（命令是 `instant`：关键字后面不用加空格）。原来的规则是：`instant` 命令的关键字一打全，整个列表就归这个命令，按这个词找到的文件、程序都不显示；再多打一个字母它们才回来。

改法（主程序）：`instant` 命令的关键字单独打出来时，列表还是搜索的，这个命令的结果排在最前面（全部、按插件给的顺序），后面照常是按这个词找到的东西。关键字后面加了空格才进入这个命令自己的列表（和 `list` 命令一样）。插件还没答复（进程刚起）时，先放一行“关键字 — 命令名”占住第一行，回车进入它的列表，免得回车打开了排在第一的文件。插件不用改。

真实程序里（`scripts/live.ps1`，测试插件 `test.instant`：零代码、`instant`、关键字 `notepad`、两行结果）：

| 输入 | 结果 |
|---|---|
| `notepad` | 第 1、2 行是插件的两行，第 3 行起是记事本、Notepad++、几个 notepad.exe；按两次 ↓ 落在第 3 行（记事本），底栏是它的“打开／打开安装文件夹” |
| `notepad `（带空格） | 只有插件的两行，“全部 ›”后面有命令的标签，和原来一样 |
| `notepa` | 照常的搜索结果，插件的关键字作为一行提示排在程序后面，和原来一样 |

`tst_plugin`（`logs/tst_plugin.txt`）通过，新加 `instantKeywordAlone`：占位行、答复后全部在最前且不受 3 行限额、再次答复就地更新、先答复后出名字时没有占位行、键盘已经下移时排在那一行下面、空答复、“文件”范围不变、带空格仍是命令自己的列表。

没测的：真实的 OCR Studio／批量重命名（走的是同一条路，上面用零代码插件代替）；面板模式。

## #288：想让要管理员权限的插件一直能用

对方的情况：带 `elevated` 的插件只在 Win顺 以管理员身份运行时才以管理员身份运行；Win顺 更新后或者下次普通启动，插件就回到普通权限。“每次都以管理员身份启动”其实已经有了（索引方式选“管理员直读”，开机自启和更新后都会以管理员身份启动），只是从名字上想不到，也没有随手提权一次的入口。

改法：

- 搜索框：搜“管理员”“提权”“admin”有一行“以管理员身份重新启动 Win顺”。只在管理员账户、Win顺 是普通权限时出现。
- 设置 › 插件：带 `elevated` 的插件，在 Win顺 是普通权限时卡片上多一行说明和“以管理员身份重新启动”按钮，并说明想每次都这样去选“管理员直读”。重启后设置窗口回到原来的页面。

真实程序里（同一个脚本）：

| 步骤 | 结果 |
|---|---|
| 普通权限，搜“管理员” | 第 1 行“以管理员身份重新启动 Win顺”，副标题“Windows 会请你确认一次” |
| 搜全名后回车 | 原进程退出，新进程起来，令牌是管理员（`rights: elevated`）；这台电脑的 UAC 设成了不提示，所以没有弹确认 |
| 管理员权限下再搜“管理员” | 没有这一行 |
| 收尾 | 测试副本已退出；开机自启任务、右键“在此搜索”的注册表项没变 |

卡片用离屏预览看的（`WinShun.exe --preview-plugins out.png --host-normal [--dark]`，新加的示例）：说明两行、按钮靠右，浅色深色都正常，0 个 QML 警告。

没测的：卡片上的按钮在真实设置窗口里点（它和“索引方式”那一行已有的按钮走同一个 `App::restart`）；UAC 弹确认后点“否”（已有逻辑：以普通权限回来）；不是管理员的账户（代码里不显示这一行和卡片上的说明）；英文界面。
