# 菜单、截图插件与主题抓手跟进验证

日期：2026-11-07。本轮为本地修复及验证，尚未提交或发布。

## 问题与处理

### 菜单高亮落后于鼠标

在实际设置窗口中复现：指针已移到“说明”，高亮仍停在“打开文件夹”；点击动作与视觉反馈不一致。

`DropMenu.qml` 的目标位置改变后立即重启动画，但动画 `to` 的绑定尚可能保留上一个目标。改为在重启前明确赋值 `slide.to = wantedY`，让本次动画使用当前目标；具有相同实现的 `ContextMenu.qml` 同步修复。保留原有动画与菜单操作方式。

回归向生产 QML 菜单发送 Qt 鼠标移动事件，依次经过末项、首项、第二项、末项、首项，同时检查命中项与绘制高亮的位置。修复前第一次移动通过，之后四次出现 `hit=1 painted=0`，见 [修复前记录](menu-before.txt)；修复后四个主题全部为 `hit=1 painted=1`。

最终又在真实设置窗口中用鼠标从“打开文件夹”移回“说明”，观察到高亮正确跟随，验证后关闭菜单。

### 截图插件退出码 3

本次用户日志明确报错：

```text
WinShunCapture: no Qt6Core.dll in WS_APP_DIR: this Win顺 cannot run the plugin
```

原因是此前启动了未完整部署 Qt 运行库的本地构建目录。主程序可以从 PATH 加载 Qt，而截图插件的启动器按现有安全规则只从主程序目录加载共享运行库，因此退出并触发连续崩溃停用。这次启动方式是本轮前一次操作的疏漏，不是已确认的截图业务代码故障。

补齐运行库后恢复插件，实际设置页显示“运行中”，并成功打开“截图设置”窗口；关闭设置窗口时没有修改截图配置。随后将修正版完整部署到 `dist/menu-capture-followup/WinShun/`，核对 Qt、QML、平台插件及辅助程序，正常退出旧预览并启动修正版。最终再次确认截图插件运行中。安装的截图插件为 1.1.3，本次未修改插件源码或版本。

部署没有复制或覆盖便携版 `data`，继续使用既有用户配置。后续本地运行需要使用完整部署目录，不能只依赖 PATH 中的 Qt 库判断插件运行条件。

### 品牌色彩与轻拟物质感的拖动入口

原有两个主题隐藏了顶部横条，仅剩 Logo 可拖，入口不够明显。现在所有主题的独立搜索框和搜索面板都显示小横条；品牌与触感主题将其放在输入框上方留白中，避免压住输入框边缘。输入区仍用于选中文字，“全部／文件／内容”继续并排、单击切换。

可拖动顶部横条或左侧 Logo；双击横条请求展开／收回搜索面板。嵌入文件对话框的搜索栏继续遵循原有布局，不额外显示横条。
