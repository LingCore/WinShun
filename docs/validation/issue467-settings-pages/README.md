# #467 设置窗口开着时，看过的页面一直占着内存

2026-11-26，Hyper-V 虚拟机 Windows 10 22H2（19045.6456，1920×1080，100% 缩放，`Renderer=d3d11`，无显卡走 WARP），安装版 0.48.0 + 截图插件 1.1.38；改后只替换 `WinShun.exe`（`build\issue467`）。

## 现象与原因

反馈的四张截图都是开着设置窗口（运行状况页）截的：主程序 365–549 MB，其中“窗口和数据” 254–429 MB。

- 设置的页面去到哪页才建哪页，每页约 20–40 MB；#459 只在窗口关闭 30 秒后释放。窗口一直开着（比如开着看运行状况）时，逛过的页面全都留着。
- 窗口在前台时空闲归还不触发，所以这部分一直算在“内存”里。

## 改动

- 设置窗口开着、停在一页满 30 秒：当前页以外的页面释放（`SettingsWindow.putPagesAway`），回到某页时重建并恢复滚动位置；设置内搜索进行中、对话框打开、录制快捷键时不动。
- 释放后主动归还一次（`IdleTrim::freed`）：腾出的堆页不再留在工作集里。

## 实测

虚拟机里用真实鼠标点击依次点开 11 个分类，停在运行状况页，每 0.4 秒记录一次主程序（`Win32_PerfRawData_PerfProc_Process`）。

| 时刻 | 0.48.0 私有工作集 / 私有提交 | 改后 私有工作集 / 私有提交 |
|---|---|---|
| 后台启动后空闲 | 7.9 MB / 107 MB | 7.9 MB / 104 MB |
| 打开设置（首页） | 79 MB / 155 MB | 80 MB / 153 MB |
| 11 个分类都点过 | 319 MB / 397 MB | 323 MB / 398 MB |
| 停在运行状况页 45 秒 | 304 MB / 399 MB | 37 MB / 335 MB |
| 再点一下窗口，15 秒后 | 293 MB / 400 MB | 42 MB / 333 MB |

运行状况页自己的读数：改前 309 MB（窗口和数据 300 MB，[before-0.48.0.jpg](before-0.48.0.jpg)），改后 43 MB（窗口和数据 36 MB，[after.jpg](after.jpg)）。

释放之后再点“结果列表”、标题栏的返回、“快捷键”，页面照常显示，返回回到运行状况页。

## 测试

- `ctest -R "^tst_idletrim$"` 通过（新增 `freedGivesBackWhileInUse`）。
- `WinShun.exe --probe-runtime <dir> --settings-reopen-check --renderer d3d11` 全部通过（新增 6 项 `left_page*`）：窗口开着释放后工作集 423 MB → 9 MB。机器负载高时该探针原有的 `pages_made_after_first_frame`（6 秒内建完各页）会超时，与本改动无关，空闲时重跑通过。
- 未测：150% 以上缩放与多显示器下的实际数值（探针在本机 150% 下通过）。
