# 系统搜索上重新打开剪贴板的预览状态

2026-11-02。原生系统搜索上使用独立 UIAccess 显示进程时，预览重新打开会先展开再折叠。

原因有两处：显示进程在原窗口完成 `placed` 后才激活同步，错过预览恢复信号；实际显示窗口又先显示、再收到清空本地预览的 `shown`。此外，每次状态同步都把隐藏原窗口的旧宽度应用到显示窗口，干扰显示端的预览开关。

修正为在显示前依次完成 `shown`、`placed`，并让显示端 QML 管理宽高，主进程只同步位置和可用空间。没有改变保存的预览偏好。

回归从真实 WM_HOTKEY 入口打开、展开预览、关闭后重新打开，检查预览恢复；再折叠并等待状态同步，检查尺寸保持折叠。两种快捷键入口在修正前均失败，修正后独立普通令牌显示进程和真实系统 Start/Search 上的 UIAccess 显示均通过。证据为 `preview-before.json`、`preview-transport.json`、`preview-native.json`。修复后的主程序已更新至安装目录并启动，配置和历史数据未覆盖。
