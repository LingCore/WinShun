# #82（Opus 的“此电脑”里打字）和 #242（OCR Studio／批量重命名第一次启动没窗口）

2026-11-11。Windows 11，3840 宽、200% 缩放。Directory Opus 13.25（用户自己开着的那个文件窗口：左右两个文件列表加文件夹树，测试前是最小化的，测完改回原来的文件夹并重新最小化）。

程序是 `dist\issues-242-82\WinShun`（0.24.0 正式包的副本），用单独的配置启动（`--profile build\issues-242-82\profile`，只开了 `OpusTyping`、装了两个插件），普通权限。脚本在 `scripts/`，原始输出在 `logs/`。截图没有入库（里面有本机的盘符和容量）。

## #82：左栏打字进了 Opus 自己的查找栏

对方截图里左栏开的是“此电脑”，右栏是普通文件夹：和左右无关，是“此电脑”没有磁盘路径。

原因：`dopusrt /info …,paths` 的应答里**不列**“此电脑”那个标签（左栏此电脑、右栏文件夹时只有右栏一条 `<path>`）。原来找不到标签就当成没拿到文件夹，把按键还给 Opus。

改法：这种标签算“已知、没有文件夹”，搜索框照常弹出，不带文件夹前缀，搜整机。Opus 没应答时才把按键还回去。资源管理器不变。

| 程序 | 左栏（此电脑）按 Q | 右栏（测试文件夹）按 Q |
|---|---|---|
| 0.24.0 正式版 | 不出搜索框，前台仍是 Opus（`logs/opus-0.24.0.txt`） | 出，在右栏里面 |
| 改后 | 出，在左栏里面、靠下，没有文件夹前缀 | 出，在右栏里面，和原来一样 |

- 每次点击前检查指针下是 Opus 窗口，点完检查焦点在那个文件列表上；按 Esc 前检查前台是 Win顺。
- `tst_shelllaunch opusTypingNavigation`（真 Opus，右栏有焦点）通过：进子文件夹、定位文件、去“此电脑”（`opusPlace` 给出“已知、空”）、回原处。
- `tst_core fileManagerText` 通过：`opusAnswered` 认 `<results … result="1">`，空应答也算应答；`result="0"`、不是 XML、空串不算。
- 没测的：库（`lib://`）、FTP、压缩包里的标签（代码走同一条路：应答里有、但不是磁盘文件夹）；单栏窗口；选中结果后在“此电脑”那一栏里打开（这段代码没改，范围设成“整机”时本来就走它）。

## #242：重启 Win顺 后第一次启动插件，搜索框消失、没有窗口

对方在 0.23 便携版上用 1.1.0 报的三个现象，其中“没按回车就启动”“第二次搜索框不消失”是 1.1.0 在打字时就开窗口造成的，1.1.1 已改成按回车才开。剩下“第一次没窗口”在 1.1.1 上还在，只是变成了：第一次打出 `pl`，搜索框自己收起。

原因：插件进程是第一次打出关键字时才起的，那时搜索框在前台。Tk 会激活它建的第一个窗口，隐藏的也激活，于是一个看不见的窗口成了前台窗口，搜索框失去焦点就收起（`logs/plugin-1.1.1-foreground-probe.txt`：每 30 ms 记一次前台窗口，第 1 轮约 0.5 s 时前台变成 `BatchRename/TkTopLevel`、可见的插件窗口为 0，随后搜索框收起；第 2 轮进程已在，搜索框留着）。

改法（插件 1.1.2，两个都改）：建窗口那一段不让前台变动（`LockSetForegroundWindow`），建完立刻放开；按回车后照常显示并到前台。批量重命名显示时也短暂置顶，和 OCR Studio 一样。

源码对照（`scripts/parent.py` 扮演搜索框：自己到前台，带管道起子进程，看 4 秒内前台有没有被拿走；`--action --grant` 再发一次 `action`，像 Win顺 那样先允许它到前台）：

| 子进程 | 结果 |
|---|---|
| `tk.Tk(); withdraw(); mainloop()`（最小复现） | 92 ms 后前台丢给不可见的 TkTopLevel |
| 两个插件改前的 `main.py` | 约 180 ms 后丢 |
| 两个插件改后的 `main.py` | 保住；`action` 后插件窗口显示并在前台 |

真实 Win顺 里装插件库的正式包（`logs/fixed-build-and-plugins-1.1.2.txt`；包的 SHA-256 和线上 index 一致）：

| 插件 1.1.2 | 第几次 | 打出关键字 3 秒不按回车 | 按回车后 |
|---|---|---|---|
| 批量重命名 | 1（进程冷启动） | 没有插件窗口，搜索框还在 | 347 ms 出窗口，在前台，搜索框收起 |
| 批量重命名 | 2、3 | 同上 | 124 ms、489 ms，同上 |
| OCR Studio | 1（进程冷启动） | 没有插件窗口，搜索框还在 | 123 ms 出窗口，在前台，搜索框收起 |
| OCR Studio | 2、3 | 同上 | 108 ms、106 ms，同上 |

插件自己的测试（Python 3.10 的临时环境）：OCR Studio 27 个全过；批量重命名新加的 3 个过，另有 23 个在 3.10 上本来就跑不了（用了 3.12 的 `Path.is_junction`，改动前后一样）。插件仓库的 `tools/check.py` 0 处错误。

主程序没有改（原因和以后的候选做法见 `docs/pitfalls.md` 开头那一条）。
