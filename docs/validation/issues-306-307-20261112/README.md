## #307：Markdown 预览一直“正在读取…”

报告：0.25.0，Windows 10 22H2，搜 `*.md`，选一个 .md 按 Alt+P，预览窗口一直显示“正在读取…”，重启后一样。

**没有复现。** `--preview-results <目录> --file-metadata --file-gallery --scale 1.5 --preview-file docs\pitfalls.md`（963 kB，5499 行）显示为文本（`kind 2`，UTF-8）。逐段读了读文件线程上的代码（属性、类型名、读开头 1 MB、判断编码、分行、Markdown 着色、标记搜索词），没有找到不结束的循环；带通配符的搜索（`*.md`）不产生要标记的词。

截图里的预览窗口是“读取中”的大小（560×460，按 125% 缩放量），不是文本的大小，说明结果一直没从读文件的线程回来，而不是界面画不出来。卡在哪一步不知道，已请报告者提供卡住时的转储文件和诊断包。

**改了的**（不依赖原因）：见 `docs/pitfalls.md`“一个文件读不出来，后面所有文件的预览都停在‘正在读取…’”。

| 检查（`stuck.md` 的读取被 `FilePreview::setReadProbe` 拦住不返回） | 结果 |
|---|---|
| `stuck.md` 2.3 秒内一直是读取中，没有过早说“没有响应” | 通过 |

同一次运行里原有的预览检查（图片、.psd、.ai、代码 / Markdown / JSON 着色、选字复制）都通过。这次运行另有 3 条“clipboard sizing”警告（真实鼠标拖窗口角的检查，本机一直如此，和这次改动无关）。

## #306：设置 › 插件页的小点

报告：0.25.0，Windows 11，设置窗口 920×720（100% 缩放），插件卡片开关左边有灰色小点，打开插件后变多。

**没有复现。** `--preview-settings <目录> --scale 1` 渲染全部 29 张设置页，逐张找“2×2 像素、四周是底色”的灰点：0 个。离屏渲染用的是 6 个示例插件；报告者装了 28 个，头几张是他自己开发中的插件（tio 串口终端、磁盘透视，不在插件库里）。

量截图得到的：每个点正好 2×2 像素，颜色 (179,179,179)，不随底色变；横向间隔约 9.25 像素、纵向 9 像素，位置不跟着卡片走（有的落在两张卡片之间）。源码里没有这个颜色的部件。是哪个部件画的没有查明，已请报告者一次补齐信息（点是否跟着列表滚动、显卡和驱动、界面风格、头一张卡片的 `plugin.json`、诊断包）。
