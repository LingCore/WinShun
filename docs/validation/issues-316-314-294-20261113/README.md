# 第二轮：#234 文件夹里打字的搜索框、#185 / #244 纯净模式的按钮、#267 选中行（同日）

## 改了什么

| Issue | 现象 | 改动 |
|---|---|---|
| #234 | 搜索框弹出后先列出当前文件夹里的东西（和输入的字无关），结果到了再变高 | 由打字弹出时，字还在路上，先不列任何行（`Launcher::awaitTyping`）；输入框内容变了或窗口隐藏后恢复原样 |
| #234 | 变高的那一帧露出黑块 | 原来是“先变高、再上移”两步，中间一帧窗口挂在列表下方、新增部分还没画。现在在文件列表角落里时由 `Placement::fitHeight` 一次 `SetWindowPos` 同时改位置和高度 |
| #234 | 没有贴紧文件列表右下角，离边和滚动条各 12 像素 | 资源管理器的列表（本来就不含滚动条）改为贴角（`kExplorerListGap = 0`）；物理像素换算成逻辑像素时向内取整，150% 下不会压到滚动条。Directory Opus 的列表窗口自带滚动条，仍留 12 像素 |
| #185 / #244 | 纯净搜索模式下，右上角“搜索历史”“展开面板”两个按钮藏不掉 | 纯净模式下这两个按钮一直隐藏，范围标签顶到搜索框右边；`Ctrl+↑/↓`、`Ctrl+E` 照常。面板自己的搜索栏、文件夹内搜索、任务栏搜索不变 |
| #267 | “品牌色彩”风格浅色下，选中行（白底）比鼠标悬停行（灰底）还不显眼 | 选中行的描边 8% → 16%，阴影 4% → 10%（只改浅色） |

# 第四轮：#319 命令关键词后面的字用来搜索文件（同日）

Issue 提了三件事；只做第三件。合并“快捷跳转”插件与收藏命令、新建一级菜单“快捷命令”不做（维护者同意）。

**改动**：收藏夹里的命令新增勾选项“关键词后面的字用来搜索文件”（`Favorite::searchFiles`，默认关，命令里要有 `{query}`）。勾上后输入 `关键词 名字`：
- 列出“名字”搜到的文件和文件夹（排序、高亮和平时一样），应用、设置、网站不列；
- 在其中一行按 Enter，把该行完整路径作为 `{query}` 交给命令，底栏提示“用“命令名”打开”；
- 命令自己那一行排在最后，Enter 仍把输入的字原样传入；输入的字是一个存在的本地路径时它排第一，和以前一样。

没勾的命令行为不变。`favorites.json` 多一个可选字段 `searchFiles`，文件版本号不变；旧版本读得了，保存时会丢掉这个字段。

**验证**
- `tst_commandlaunch` 31 通过（新增：字段的读写、不是 `true` 时算没勾、关键词和后面的字的拆分）。
- `--preview-results <目录> --search-experience`：新增 7 项检查全部通过（`ed report` 列出 3 个文件/文件夹加命令行共 4 行，命令行在最后；没有应用；文件行的 Enter 提示是“用“编辑器”打开”；命令行的提示是“原样传入“report””；只输关键词时仍是命令本身；没勾的命令照旧）。见 `command-files.png`。
- `--preview-settings <目录> --command-form`：0 警告，新勾选项显示在“工作文件夹”下面（`command-form.png`）。

**没有实测的**
- 没有真的按 Enter 启动一次程序：探针核对了提示文字和行的内容，实际交给命令的路径由同一个函数（`shell::runCustom`）处理，和原来传文字走同一条路。
- “输入的是已存在路径时命令行排第一”没有单独的检查。
- 多选几行一起回车、文件夹菜单里的命令，不受这个选项影响，也没有测。
