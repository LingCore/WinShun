# #273 资源管理器标签页保存与恢复、#272 程序自己的选文件窗口（2026-11-12）

构建：`build\issues-273-272`（Release，Qt 6.12.0，MSVC 14.44），Windows 11 build 26200，缩放 150%。

## #273 打开上次的标签页（winshun.explorer-tabs 1.1.0）

做法：插件多一个线程（`Keeper`），每 3 秒不调用资源管理器地比较一次窗口的样子（句柄、标题、位置），变了并稳定两次后才问资源管理器各标签页在哪、标签栏顺序如何，写进数据目录的 `session.txt`；每次登录后第一次启动时把上次留下的另存为 `previous`。设置“开机后打开上次的标签页”（默认关）打开时自动恢复，输入 `标签页` 的第二行可随时手动恢复。恢复期间合并引擎暂停，恢复出来的窗口不会被并到一起。

自动测试：`ctest -R tst_explorertabs` 通过。新增 5 个用例：文件写出再读回一致；读不懂的行、截断的文件被略过；最后一个窗口关掉后保留窗口列表；恢复计划（都没开、都开着、Windows 自己还原了一个标签页时并进那个窗口）；控制面板不恢复。

实机：`tools\verify-explorer-tabs-session.ps1 -Plugin build\issues-273-272\WinShunExplorerTabs.exe -WorkDir build\issues-273-272\tabs-live`，19 项全部通过（最后一轮构建后重跑）。脚本单独启动插件程序，用 `WINSHUN_TABS_TEST_ROOT` 限定只看它自己建的测试文件夹；桌面上原有的 5 个资源管理器窗口前后句柄和位置一致，没有被记进文件。不按键、不移动鼠标。

| 步骤 | 结果 |
| --- | --- |
| 手写上次登录留下的两个窗口（3 个标签页 + 1 个），按登录后启动 | 两个窗口回来，标签页齐全、顺序对；第二个标签页在前面；窗口位置 `150,120,1250,820`、`420,260,1420,900` 与记录一致；恢复期间和之后都没有被合并成一个窗口 |
| 等插件记录 | `session.txt` 里两个窗口、标签页顺序、前台标签都与当前一致 |
| 像关机那样结束插件（窗口还开着）、关窗口、再按登录后启动 | 文件仍是 `open 1`；窗口和标签页照原样回来 |
| 手动关掉所有窗口，输入关键词 | 文件变成 `open 0`；出现“打开上次的标签页 / 上次登录留下 2 个窗口、4 个标签页 · 已经开着的不重复打开”；回车后都回来 |
| 全开着时再要一次 | 没有多开 |
| 只开着第二个文件夹时再要 | 另外两个标签页加进它所在的窗口，另一个窗口单独回来；记下的顺序与标签栏一致（乙、甲、丙） |
| 设置关着，按登录后启动 | 没有窗口打开 |
| 回归：开一个窗口，桌面在前台时再打开第二个文件夹 | 第二个并成第一个窗口的标签页（插件日志 `merged`）：把读取窗口的函数搬到共享头文件后，原有的合并没有变 |

实机中发现并改掉的问题：`IShellWindows` 给的顺序不是标签栏的顺序，改为用 UI Automation 读标签栏（见 `docs/pitfalls.md`）。

没有覆盖：

- **真实的注销、关机、重启**：会结束当前会话，没有在本机做。关机时不改写文件靠 `SM_SHUTTINGDOWN` 和外壳窗口是否还在来判断，“本次登录第一次启动”靠全局原子判断，这两处只按文档行为实现，登录后启动用 `WINSHUN_TABS_LOGON=1` 模拟。
- Windows 自己的“登录时还原上一个文件夹窗口”同时开着的情形：只有恢复计划的单元测试和实机第 6 步（已有标签页时并进去）间接覆盖。
- 最大化的窗口、多显示器、网络位置和已拔掉的盘：位置用 `SetWindowPlacement` 还原，解析不了的路径跳过，未单独实测。
- 经由 Win顺 插件运行器启动的整条链路（本机正在运行的是别的会话留下的测试版，没有替换它）。

## #272 程序自己的选文件窗口

见 [docs/dialog-compatibility.md](../dialog-compatibility.md) 的“程序自己画的选文件窗口”一节。`ctest -R "tst_dialogrules|tst_filedialog|tst_dialognav"` 通过（5 项），真实主程序的离屏检查中、英文各 20 项通过。**本机没有 ArcGIS，ArcMap／ArcGIS Pro 均未实测。**

离屏检查中文跑了两遍都通过。英文头两遍失败，原因是倒数期间前台被桌面上另一个测试中的 Win顺 进程（`build\issue280\WinShun-baseline.exe`，别的会话的）抢走：一遍把那个进程的窗口识别了进去，一遍回车没能发出；随后连跑两遍均通过。这也说明“识别窗口”认的就是倒数结束时在前台的窗口，认错了再点一次即可（同一个窗口的规则会被替换，不会重复）。
