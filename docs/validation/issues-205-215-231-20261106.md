# #205、#215、#231：实现与验证

2026-11-06，Windows 11 x64、Qt 6.12.0、MSVC 2022 Release。

本轮选择三项高频交互改进。避开用户明确指定的 #204、#217、#119、#174、#186、#176，也避开工作区已有实现和正在等待报告者反馈的问题。共享工作区中其他任务的改动均保留。实现和验证完成后，用户另行要求提交修改并回复对应 issue；本记录不表示已推送、发布或关闭 issue。

## #205：紧凑菜单

确认的问题是：原先文件夹菜单和结果右键菜单使用固定字号、固定行高，外观中的“紧凑”设置没有作用于它们。

- 菜单字号和说明字号现在读取现有 `UiScale`；紧凑时为 14/12 逻辑像素。
- 三种主题共用密度调整：紧凑行高在主题基准上减少 6，宽松增加 4；标准尺寸保留。主题负责颜色和外观，宿主负责交互尺寸。
- 文件夹菜单紧凑宽度由 360 降至 300 逻辑像素，仍受工作区限制；长列表滚动、键盘导航和长路径提示保留。
- 结果右键菜单、下拉菜单、字体选项同步使用相应菜单字号，避免同一种设置只改变部分控件。
- 文件夹打字搜索已有其他任务实现的紧凑布局，本轮没有重写该路径；本轮新增验证针对菜单，不将既有文件夹搜索测试当作本轮端到端证据。

## #215：双击动作

入口：设置 → 打开 Win顺 → 快捷键 → 双击修饰键呼出 → 双击后做什么。

- 继续使用已有 Ctrl / Alt / Shift 双击检测、左右键选择、游戏和全屏避让。每个配置的双击手势只对应一个动作。
- 可选择搜索框、剪贴板，或支持宿主快捷键通知的已启用插件动作；原有组合键保留。
- 插件列表来自实际 `register_hotkeys` 请求。旧插件仅报告 `winshun/hotkeys` 并不足以证明它理解宿主通知，因此不将这种插件列为可执行目标。
- 直接通知对应插件，不模拟全局组合键；注册冲突不会把双击动作发送给占用该组合键的其他应用。
- 插件退出后移除可用动作，已保存的选择以“暂不可用”保留。触发不可用动作时提示重新启用或选择，不退回搜索框。
- 配置持久化采用可校验的动作标识；旧配置默认继续呼出搜索框。设置、按键一览、托盘和管理员窗口提示避免错误宣称该手势仍呼出搜索框。
- 使用标准 Qt ComboBox 的键盘行为，外观、菜单字号、颜色和箭头沿用现有主题。

## #231：已有窗口优先

- “全部”范围按匹配程度搜索时，在后台搜索线程枚举当前桌面有标题的可见任务窗口；最小化窗口仍可搜索。
- 复用现有查询匹配器，支持中文、拼音、大小写不敏感及多词匹配；按窗口标题和程序名查找。
- 最多枚举 256 个符合条件的窗口，每次展示最相关的 8 个。同等匹配维持窗口前后顺序，同一程序的不同窗口分别保留。
- 匹配窗口置于通常搜索结果之前，标记“已打开”，Enter 明确显示“切换到窗口”。原应用、文件结果保留，用户仍可选择打开它们。
- 文件、内容范围、扩展名等文件筛选、指定目录、按时间或列排序、网页关键词和文件夹打字搜索不混入这些窗口结果。
- 原生窗口句柄、进程和线程身份以及标题在执行前重新检查；失效或系统拒绝切换时显示说明，不启动一个新副本。
- 窗口是独立结果类型，不写入最近打开记录、收藏夹或文件索引，不提供删除、管理员运行或文件定位操作。
- 此次范围是 Windows 顶层窗口及其当前显示的标题，不读取 Chrome 等浏览器后台标签页，也不枚举文件管理器隐藏标签。浏览器、文档和文件夹的当前窗口标题可以匹配；没有声称完整解决所有应用内部标签的跳转。

原生标题读取和异步恢复依据 [GetWindowTextW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw) 与 [ShowWindowAsync](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindowasync) 的契约；先排除宿主自身窗口，避免跨线程调用自身窗口标题处理器。

## 验证边界

- 界面检查使用临时配置、数据库和不激活的屏幕外窗口。原生成功切换测试另外短暂在两个自建窗口间切换，随后断言原前台已恢复；没有输入按键、停止用户程序、修改用户历史或写入系统剪贴板。
- 设置测试使用合成的插件动作列表，验证真实 QML → SettingsEditor → 配置保存链路；双击检测由既有检测器回归覆盖，真实插件进程另行补测。没有在共享桌面注入实际双击修饰键，也没有将测试插件视为所有第三方插件的兼容性证明。
- 私有桌面原生测试验证枚举、最小化保留、异步恢复、身份失效和前台请求被系统拒绝的返回值。私有桌面不能成为当前输入桌面的前台，拒绝没有被当作成功切换的证据。另一个测试在当前桌面的两个自建原生窗口间确认成功切换和最小化恢复；没有打开、关闭或编辑用户的应用内容，没有实测每个第三方应用的窗口策略。
- 窗口结果的 UI 截图是合成文档标题。原生枚举、查询引擎和失效检查另有测试，截图本身不能证明真实 Office/Chrome 内部标签行为。
- 首轮测试发现 `hasFilters()` 不包含扩展名约束，已显式排除扩展名查询并复测。原生测试补上消息泵等待 `ShowWindowAsync`；150% 屏幕外窗口偏移换算成逻辑坐标，消除超过 Win32 坐标范围的测试警告。
- 插件补测首先确认了通知送达，但初版测试错误地假定 runtime 启动探针的窗口已隐藏。随后在触发前明确建立并断言隐藏状态，复测确认插件动作不会额外打开搜索或剪贴板。
- 构建期间另一个任务更新了共享的 Preview/NavigationProbe 文件，一次链接失败来自新旧探针对象不一致。确认函数存在后增量重编成功，没有删除或替换其他任务的代码。

本轮没有发布版本，也没有将这份本地验证等同于 issue 已在用户原环境完全解决。
