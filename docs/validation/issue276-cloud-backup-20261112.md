# 云备份插件（GitHub #276）验证记录

日期：2026-11-12。构建：`build/cloud-backup`（Release，MSVC，Qt 6.12.0），源码在工作树 `.worktrees/cloud-backup`。

## 做了什么

- 插件库新插件 `winshun.cloudbackup` 1.0.0（`src/cloudbackup-plugin`）：把设置备份传到 WebDAV 文件夹或 GitHub 私有仓库，两处可同时用；`cloud` 立即备份、列出云端备份、恢复。
- 主程序：新权限 `winshun:backup`，工具 `backup_export`、`backup_restore`（`Backup::exportTool` / `restoreTool`）。
- C++ SDK：`tool()` 可以从 `serve()` 以外的线程调用。

## 实际运行

- **真实 WebDAV 服务器**（wsgidav 4.4.0，本机，Basic 认证）：地址含中文和空格的文件夹、密码含空格和中文；末级文件夹自动建出；连传三份后服务器上剩两份（保留数设为 2）；列表行带时间、电脑名和大小；下载回来的文件与上传的逐字节相同；密码填错时状态行写“WebDAV 的用户名或密码不对”。全部通过。
- **真实 GitHub 接口**（只读）：公开仓库 `LingCore/WinShun` 被拒绝并说明原因；不存在的仓库、错误的令牌各自报对了原因。
- **真实 GitHub 私有仓库**（临时建的测试仓库，贴的是仓库网址）：空仓库里第一次上传成功；连传三份后仓库里剩两份（保留数设为 2，最旧的一份被删掉）；仓库里最新的文件与上传的逐字节相同；设置没变时不再上传；列表两行带时间（同一分钟的显示到秒）、电脑名和大小；下载回来交给恢复的文件与最新备份逐字节相同。全部通过。
- **经真实运行器启动**（`wsbench --plugin`）：清单校验通过，进程在作业里以普通权限运行，冷启动约 1 秒，之后每次查询约 0.2 毫秒。

## 在真实的 Win顺 里走一遍

部署了一份新版（`dist/cloud-live/WinShun`，临时配置 `--profile`，原来的 Win顺 已退出，测完重新启动），云端是本机的 wsgidav（带密码，密码放在 Windows 凭据管理器里），按键由脚本发送，每次发送前检查前台窗口是这份新版。截图在 `issue276-cloud-backup-20261112/`。

- **自动备份**：启动整两分钟后，服务器上出现第一份备份，是 Win顺 自己做的 ZIP（含 `backup.json`、`WinShun.ini`），里面没有密码。
- **搜索框**：`cloud ` 列出状态行和备份行，图标、时间、电脑名、大小都对，底栏写着这一行按 Enter 做什么（`s2-list.png`）。
- **手动备份**：改了一项设置（结果排序）后重启，状态行仍写着上次备份的时间；按 Enter，几秒后服务器上有第二份，列表自己刷新成两份（`s4-two.png`）。
- **恢复**：选中较旧的一份按 Enter，出现“恢复…的备份？/不恢复”，键盘停在“不恢复”上；等过一次定时刷新（36 秒）两行还在；“不恢复”回到列表。再选一次，上移到“恢复…？”按 Enter（`s10-confirm-selected.png`）：Win顺 重启并打开设置窗口，结果排序回到备份时的值，配置文件夹的 `backups` 里多了一份恢复前的备份，没有留下临时文件。
- **设置页**：插件卡片显示“运行中”，权限里有“取得 Win顺 的设置备份，并用备份恢复设置”一行并打勾（`s13-card.png`）。

这一遍查出并改掉的三处：

1. 主程序：插件结果行的 `ph:` 图标一直没画出来（图标请求分发时漏了 `ph/`，显示成空白文件图标）。
2. 插件：底栏原来写“Enter 复制”，现在每行有自己的动作名（立即备份、恢复、确认恢复、返回）。
3. 插件：确认界面停着时，列表的定时刷新会把两行换回普通列表，再按 Enter 就落到别的行上。现在确认状态保持 45 秒，或到输入框里的字变了为止。
