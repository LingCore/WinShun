**状态：没有在真的 Directory Opus 里测成。** 本机装的 Opus 13.25 从没注册过，启动后只出“授权管理”窗口（“Directory Opus 未注册……申请免费试用以获得 60 天的试用”），不开文件窗口。申请试用要向 GPSoftware 提交邮箱，这一步要用户自己决定，没有做。授权窗口已关掉，Opus 进程已退出。

## 对方 0.21.0 的截图说明了什么

对方最后一条反馈（2026-11-06 16:29 UTC）用的是 0.21.0。两张截图都是 2560×1600、150% 缩放（0.20.0 那张里默认宽度 760 的框约 1130 物理像素，1130 ÷ 760 ≈ 1.49），和本机一样。

0.21.0 那张：

- Opus 自己的搜索栏写着“在 Keyboard_firmware 中……”，所以是在右边的文件列表里打的字。
- 搜索框的右边缘紧贴右边列表的右边缘，位置是对的；左边缘伸进了左边列表大约 170 物理像素。
- 搜索框约 955 物理像素宽，合 637 逻辑像素，就是 0.21.0 里搜索框的最小宽度 640。右边列表约 805 物理像素，合 537 逻辑像素，放不下。

也就是说 0.21.0 往列表里放了，但最窄只能到 640，比对方的列表宽。

## 0.22.0 已经改了

`965d315`（在 0.22.0 里，2026-11-07 发布，对方还没反馈过）把在文件列表里打字时的搜索框改成最宽 460、最窄 320 逻辑像素（`Placement::settleAvoiding`）。对方的列表是 537，减去两边各 12 的边距是 513，所以会是 460 宽、放在右边列表里面，离右边和下边各 12。

仓库里 `--probe-runtime ... --folder-typing` 用一个类名相同的替身窗口量过一个 540 逻辑像素宽的列表：框 460 宽、在列表里面（0.22.0 的验证记录 `docs/validation/issues-227-233-234-20261106.md`，41/41）。替身不是真的 Opus：真 Opus 里哪个窗口有焦点、文件列表窗口的大小是不是和看到的一致，替身证明不了。
