# #459 空闲归还后内存仍高：热页保留设上限

2026-11-25，本机（Windows 11 26200，RTX 4060 Laptop，150% 缩放），`build\release`。

## 现象与原因

反馈截图：主进程 642 MB，其中“窗口和数据” 587 MB，上次归还只还了 42 MB。

本机已安装的 0.45.0 诊断日志（`events.jsonl` 的 `idle-trim` / `trigger`）给出同一类现象的实证：

| 时间（UTC） | 归还前 `private_mb` | 保留 `keep_mb` |
|---|---|---|
| 00:24 | 222 | 130 |
| 01:20 | 128 | 144 |
| 01:54 | 310 | 156 |
| 02:19 | 231 | 171 |
| 04:24 | 254 | 174 |

- 搜索框与剪贴板的热页各自学习、各自封顶（首次 ≤ 96 MB，可涨到 2 倍），合计上限 384 MB；本机一上午从 130 MB 涨到 174 MB（剪贴板 79→107 MB，搜索框 37→63 MB）。
- 这部分归还时特意不还，于是空闲内存 = 保留量 + 零头；运行状况页又把它并在“窗口和数据”里，看不出来。
- 归还记录只写归还前的量，不写归还后还剩多少。

## 改动

- 归还时真正留下的热页合计不超过 64 MB（`HotPages::kKeptBytes`，`HotPages::kept`）：并集里留零散页，放走长连续段；各窗口学到的全集不变，仍在按下快捷键时批量预读。
- 运行状况页与诊断包 `memory.parts_mb` 单列“快速打开预留”（`kept`）。
- `idle-trim` 记录改为归还结束后写一条，带 `stayed_mb`；剩余远超保留量时不受每十分钟一条的限制。

## 呼出耗时对比

```powershell
build\release\WinShun.exe --probe-runtime build\issue459\<run> --idle-open-check --with-clipboard --renderer d3d11 `
    --idle-open-cycles 5 --idle-open-index "C:\Windows;C:\Program Files" [--idle-open-kept 16]
```

每轮搜索框、剪贴板各 5 次“闲置后”与 5 次“紧接着再开”，取按下到窗口可见的中位数（ms）。改前跑了三遍作噪声参照。

| 运行 | 归还时保留 | 归还后私有工作集 | 搜索框 闲置后 / 紧接 | 剪贴板 闲置后 / 紧接 | 归还后首次呼出 |
|---|---|---|---|---|---|
| 改前 ×3 | 71–73 MB | 39.2–40.2 MB | 23.4–23.8 / 21.2–22.0 | 9.6–10.8 / 8.2–8.5 | 20–24 ms，187–214 次缺页 |
| 改后（64 MB） | 63 MB | 33.3 MB | 23.3 / 22.0 | 9.7 / 8.2 | 24 ms，941 次缺页 |
| 探针压到 16 MB | 15 MB | 10.9 MB | 23.9 / 22.3 | 9.6 / 8.1 | 27 ms，6407 次缺页 |

- 64 MB 上限：呼出耗时与改前在噪声内一致。
- 作为最坏情况参照，压到 16 MB 也只是归还后的第一次呼出多约 5 ms（27 ms，多 6,000 次软缺页）；整个工作集被清空（探针 `windows` 行，约 8,500 次缺页）时搜索框 29–30 ms。
- 探针的全新配置里两窗热页合计只有约 71 MB，上限只裁掉约 8 MB；长期使用后的 174 MB 场景靠上表 16 MB 一行给出上界。未在内存紧张（`--idle-open-pressure`）下复测。

## 设置窗口：看过的页面关闭后释放

反馈截图是开着设置窗口截的。在隔离的探针实例里复现（`--probe-runtime <dir> --live`，全新配置，150%）：

| 步骤 | 主进程私有工作集 | 私有提交 |
|---|---|---|
| 启动后空闲 | 3 MB | 204 MB |
| 设置各页都看一遍 | 273–346 MB | 491–567 MB |
| 关闭设置 26 秒（已归还，页面还在） | 4 MB | 491 MB |
| 重开到运行状况页（页面还在） | 112 MB | 492 MB |
| 关闭设置 60 秒（页面已释放） | 7 MB | 453 MB |
| 重开到运行状况页（页面已释放） | 68 MB | 457 MB |

诊断包 `memory.parts_mb` 此时为 `windows` 334.8 MB、`program` 5.3 MB，与反馈截图（587 MB / 6.2 MB）同一形状。

- 改动：设置窗口关闭 30 秒后释放首页以外的页面（`SettingsWindow.unloadPages`），30 秒内重开保持原样。
- 逐堆统计（临时代码，未入库）：全部页面在时堆内占用 230 MB / 108 万块、窗口下 20,230 个对象；释放后 132 MB / 43 万块、4,077 个对象。释放出的约 100 MB 多半留在堆内待复用，私有提交当场只降 38–39 MB。
- `--probe-runtime <dir> --settings-reopen-check --renderer d3d11` 全部通过（新增 8 项 `unload_*`），释放后重开首帧 9–13 ms。
