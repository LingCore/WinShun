# 前台内存：搜索框打开、输入时占的内存

2026-11-15，Windows 11 x64、Qt 6.12.0、MSVC Release、D3D11、150% 缩放、32 个逻辑处理器。索引 C:、F: 两个盘，约 224.6 万条。

## 结论

| 阶段（任务管理器的“内存”，MB） | 改动前 | 前三处之后 | 再加索引拆分 | 一共少了 |
| --- | ---: | ---: | ---: | ---: |
| 闲置（已交还内存） | 3.2 | 3.9 | 3.8 | — |
| 呼出搜索框，还没输入 | 80.9 | 81.4 | 64.1 | 16.8 |
| 输入第一个词之后 | 151.6 | 129.0 | 113.0 | 38.6 |
| 连续搜 8 个词之后 | 171.5 | 148.7 | 135.3 | 36.2 |
| 同样 8 个词再搜两遍 | 175.0 | 154.8 | 142.3 | 32.7 |

- 私有提交（闲置也算在内的那个数）：314.5 → 268.3 MB，少 46 MB（索引拆分不改变它）。
- 速度没有变慢：按下一个键到列表出结果，其余按键中位数 9.9 → 9.8 → 9.4 ms，第一个键 18.6 → 18.1 → 18.0 ms；文件名搜索本身 6.12 → 6.11 → 5.57 ms（拆分后每条要过的字节从 17 降到 9）。
- 每一步都是新旧程序交替各跑 3 次，取中位数。“前三处”和“索引拆分”是两次对照：第二次的旧程序就是第一次的新程序，重测得 129.2、149.4、156.1，和第一次的 129.0、148.7、154.8 相差不到 1.5 MB，表里用的是各自那次的读数。原始读数在 [summary.json](summary.json)、[summary-index-split.json](summary-index-split.json)。

## 改了四处

1. **图标的字体不再和别的字体合并**（`Glyph.qml`、`SystemTheme.glyphFont`、各风格的 `Look.glyphFont`）。结果行的按钮是几行共用的，借给下一行时换图标；换的一瞬间，图标那个 `Text` 手里是“新图标的码 + 上一个图标的字体”，或者把 `copyPath` 这个名字当成了文字。字体里没有这个字形，Qt 默认会到别的字体里找，于是把系统装的字体挨个加载一遍：本机 69 个，约 17 MB，从第一次搜索起一直留着。现在图标用的字体带 `NoFontMerging`，字体里没有就不画（图标字体本来就该这样：私用区的码在每个字体里都是另一个图）。
2. **线程自己的存储里不放缓冲区**（`platform/ProcessUsage.cpp`）。“运行状况”页统计内存用的一个 64 KB 缓冲写成了 `thread_local` 数组；程序的线程局部存储会给**每个线程**复制一份，不管它用不用。本机 Win顺 有 169 个线程，共 10.7 MB。改成调用时从堆上取。程序的线程局部存储从 66,289 字节降到 737 字节。
3. **按数据加载的字体改为映射文件**（`FontFile.h`）。程序装在带中文的路径里时（便携版常见），FreeType 打不开路径，界面字体是整个读进内存再交给它的：8.5 MB 的文件占了一块 16 MB 的堆，另有两个图标字体 1 MB。现在映射文件，用到哪页取哪页，这些页属于文件、不算进任务管理器的“内存”。主程序、截图录屏、图片文字搜索三处都走同一个函数。这一条主要省私有提交（约 21 MB）；闲置交还过内存之后，前台的数字和第 2 条之后基本一样。

4. **文件索引的每一条分成两部分存**（`core/FileIndex`，`EntryScan` + `EntryLinks`）。原来每条 17 字节放在一起：名字位置、所在文件夹、标志，以及“第一个子项或文件大小、下一个兄弟”。搜索要把每一条都过一遍，但只读前三样；后两样只有列出文件夹内容、算文件夹大小、增删文件时才读。放在一起，搜索就把整块都带进了内存。现在前三样（9 字节）单独成块，后两样（8 字节）另成一块；搜索、内容搜索找候选文件、内容索引的定时巡检、AI 助手的搜索都只过前一块。两块加起来还是 17 字节，索引的总大小、索引文件的格式都没变。本机 224.6 万条：索引常驻从 70.9 MB 降到 56.8 MB，呼出搜索框时预读的从 58.5 MB 降到 41.2 MB。

## 怎么找到的

- **探针** `--foreground-use-check`（`ForegroundUseProbe`）：用正式的 App，按热键的路径呼出搜索框，逐个字符输入 8 个词（report、wx、项目、.pdf、a、setup exe、zhaopian、2026 notes），每个词之后记私有工作集、各部分（文件索引、堆、程序文件）和每个键到出结果的时间。开始前先等一次闲置交还，所以量到的都是为搜索框调入的。
- **谁占着堆** `--foreground-use-trace <起>[:<止>]`（`platform/AllocationTrace`）：把各模块导入的堆函数换成带记录的，按调用栈汇总还没释放的块。Windows 自带的 umdh 看不到 Windows 11 给进程的堆。
- **堆里是什么** `--foreground-use-walk`：按大小数堆块，并看每种大块开头的内容。16 MB 那块开头是字体文件头；10.7 MB 是 169 块 66,305 字节，正好是线程数乘以程序的线程局部存储。
- **Qt 的字体日志**（`QT_LOGGING_RULES=qt.text.font.*=true`）：改动前有 2 次“整条后备字体链”、每次 69 个字体；改动后 0 次。

## 验证

- **内存和速度**：上表；新旧交替各 3 次。
- **图标逐像素**：新旧程序各跑 13 组界面探针（搜索框、快捷键面板、导航、剪贴板、三种风格、深色、100% 和 150%、设置各页、插件卡片菜单），261 张图里 260 张逐像素相同。不同的一张是快捷键面板里的搜索框：旧程序截到“正在搜索文件内容…”，新程序截到搜完之后，和图标无关（11-07 那轮也遇到过）。
- **回归检查**（加在 `--foreground-memory` 里，`tst_foregroundmemory`、`tst_foregroundpreload`）：
  - 窗口里所有图标文字的字体都带 `NoFontMerging`（71 个里 0 个没带）；
  - 程序的线程局部存储小于 4 KB（737 字节）。
- **索引拆分**：`tst_core`（含新增的 `indexKeepsWhatASearchReadsApart`：经过增、删、移动和压缩，两种读法对每一条说的都一样，两部分各有自己的块）、`tst_mcp`、`tst_cli`、`tst_everything`、`tst_remotecontent`、`tst_contentdetails`、`tst_contentpane`、`tst_querysyntax`、`tst_queryhistory`、`tst_searchworkload`、`tst_recentfolders`、`tst_foldermenu`、`tst_windowsearch`、`tst_scoperestore_content` 通过。8 个查询的结果条数和拆分前相同。`tst_puresearch` 没过，拆分前的程序同样不过（同一类“列表等结果超过 1 秒”的警告）。
- **闲置后再呼出没有变慢**（`--idle-open-check`，改动前的程序和最终程序交替各 2 轮，每轮 4 个来回）：闲置交还内存后呼出到显示 21.9 → 23.0 ms，刚用过再呼出 22.4 → 20.4 ms，系统清空工作集后 26.3 → 26.4 ms，都在一两毫秒的波动之内；呼出后（不输入）占 83.0 → 64.7 MB，闲置 20.0 → 19.8 MB。
- **定向测试**：`tst_foregroundmemory`、`tst_foregroundpreload`、`tst_uifont_freetype`、`tst_uifont_gdi`、`tst_commandicons`、`tst_settingsscreen`、`tst_settingslazy`、`tst_clipboardsizing` 通过。`tst_searchlogo`、`tst_searchnavigation` 没过：旧程序在本机同样不过，警告内容一样（列表等结果超过 1 秒、预览读取线程等时序类），不是这次改的。
- **记录器自检**：8 个线程各分配、释放两万块各种大小的内存，记录器报的在用量 983.9 MB，实际 982.9 MB，全部释放后为 0。
- 截图录屏、图片文字搜索两个插件能编译（它们也编译 `SystemTheme.cpp`、`Phosphor.cpp`、`Glyph.qml`）；下次发布时这两个插件要升版本。
- 没有在安装版上实测；用户正在用的 Win顺 没有动。

## 复测

```powershell
# 需要 Qt 的 bin 在 PATH 里；和正在运行的 Win顺 并存
WinShun.exe --probe-runtime <新目录> --foreground-use-check --renderer d3d11 --idle-open-index "C:/;F:/" --foreground-use-rounds 3
# 谁占着堆（带 /DEBUG 重新链接一份，栈里才有函数名）
WinShun.exe --probe-runtime <新目录> --foreground-use-check --renderer d3d11 --idle-open-index "C:/;F:/" --foreground-use-rounds 1 --foreground-use-trace start:round1
```

## 剩下的是什么

三轮之后的 142 MB 里：

- 文件索引 57 MB：名字 22、每条 9 字节的那一块 20、修改时间 9，其余是用到的创建时间和文件夹链。名字和那 9 字节是每次搜索都要过的。
- 堆约 62 MB：界面对象、场景图、字形缓存、图标，分散在几千处，没有单独的大块；其中约 16 MB 是已释放、堆还没还给系统的。
- 其余约 20 MB：显卡驱动的上传缓冲、线程栈、脚本引擎。
