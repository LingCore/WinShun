# #287 管理员程序在前时，按住连按快捷键、松开粘贴（2026-11-11）

GitHub #287：开着“粘贴到以管理员身份运行的程序”和“按住连按快捷键，松开粘贴”，在管理员程序上能往下选，松开却不粘贴，要再按回车。

原因：管理员窗口在前时普通权限的钩子听不到按键，剪贴板面板自己拿焦点；这种情况原来只做了“再按往下选”，没有“松开粘贴”（那时也粘贴不进管理员程序，0.24.0 的 #277 才能）。

改法：面板自己有键盘时，用它自己看到的按键驱动同一套判断（`core/HotkeySteps.h` 新增 `OwnWatch`，给 `Hold` 的说明和钩子给的一样）：快捷键再来一次 `WM_HOTKEY` 是一步；面板到前台后读 `GetAsyncKeyState`（每 50 ms 一次，窗口收到按键抬起时立刻再读一次），修饰键和那个键全松开就粘贴；按了别的键就不再粘贴。面板到前台之前就松开的，按了多久说不准，只认已经走过的步数，不认“按满一秒”（弹出慢的机器上快按一下不会误粘贴）。只在“粘贴到以管理员身份运行的程序”开着时这样做，关着时和原来一样只往下选。

这里只有文字日志。Qt 6.12.0 / MSVC Release，构建目录 `build/i287`（工作树路径带中文，经目录链接 `F:\wswt\i287` 编译）。只跑了这次改动涉及的测试。

## 单元测试

`tst_core hotkeySteps hotkeyStepsOwnWindow`：2 项通过。新的一项 10 种情况：连按两下再松、两个修饰键同时松、修饰键先松键后松、快按快放、按满一秒、面板到前台前就松开（过了 1.5 秒也不粘贴）、同样情况但已走一步（粘贴）、松了一个修饰键再整个按一次（照常关闭）、按了别的键、多按了别的修饰键。

## 现场 `e2e/`

`harness/run-e2e.ps1`（普通权限）沿用 #277 的做法：暂存一份 0.24.0，换上这次构建的程序，独立配置（快捷键 Ctrl+Alt+F11，两项设置都开），隔离的 SYSTEM 测试服务；复制三行测试文字。`harness/e2e-hold.ps1`（提权）开一个带文本框的管理员窗口，在它前面按 8 种按法，每种之后记下文本框里的字。

- `run.log`：8 种全对。按一下就松：不粘贴；按住再按一下、松开：第 2 条；再按两下：第 3 条；按住 1.5 秒松开：第 1 条；15 ms 内连按两下马上松（面板还没出来）：第 2 条；按住时按了 ↓：不粘贴；松开 Alt 再整个按一次：面板关掉，不粘贴；按一下打开再回车：第 1 条（#277 原来的路）。测完剪贴板文字放回，资源管理器右键项没变，Windows 自己的剪贴板历史条数前后都是 1。当时用户的 Win顺 没有运行。
- `harness.log`：每种按法后的前台窗口和文本框内容。
- `journal.txt`：暂存版的 `clipboard-hold-end`（原因、步数、按了多久）和 `clipboard-paste`（`method: service`，`outcome: pasted`）。

实测里还找到一处：15 ms 内连按两下马上松开时，Windows 没让面板到前台（`front: refused`），粘贴成功了，面板却因为没有焦点可丢而留在屏幕上，下一次按快捷键只是把它关掉。现在这样粘贴后直接收起面板（`App::clipboardHoldNote`）；`journal.txt` 里之后那一轮“按了别的键”是从第一下算起的（1078 ms、1 步）。

第一次跑没通过，两处都在测试这一边：从目录链接启动暂存版，测试服务按真实路径认界面程序，没给粘贴能力（`not-offered`）；当时用户正在打字，字进了测试窗口。改成从真实路径跑、键盘鼠标空闲 45 秒后才开始。
