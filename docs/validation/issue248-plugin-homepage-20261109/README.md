# #248：插件库条目上的「主页」，以及主页只当网址打开

2026-11-09，Windows 11 25H2、Qt 6.12.0、MSVC 2022 x64 Release，构建目录 `build/issues-249-253-256-20261108`（沿用前几轮的目录）。

**状态：写好了，离屏渲染里看过、量过，自动测试通过。没有在真实窗口里用鼠标试过：提示气泡长什么样、键盘焦点下的样子、点下去打开浏览器，都没有实际看到。** 见“没有验证的”。

## 原来的情况

- 插件库（`index.json`）里每个插件本来就有 `homepage`，程序也读进来了，但插件库页面完全没用它：安装之前没有任何入口能去插件自己的页面。提出 #248 的人截的就是这一页。
- 已安装的卡片有「主页」，在“…”菜单里。

## 改成什么样

- 插件库条目的标题行，版本号后面多一个链接图标（和卡片菜单里「主页」同一个图标）。指上去提示“主页：`<域名>`”，点了在浏览器里打开。平时是 55% 的不透明度，指针或键盘焦点在它上面时才是全黑。
- 只有 `homepage` 是 `http://` 或 `https://` 的完整网址（有主机名、不带用户名密码）才显示这个图标；没写、或写的是别的东西，就没有图标，也不留空位。
- 已安装卡片的版面没有动。

图：`library-entries.png`（最终构建的离屏渲染，150%，浅色，前三个条目）；`title-line-full-ink-then-final-4x.png`（同一行标题放大 4 倍：上面是全黑的样子，下面是最终的样子）。

## 顺带修掉的一处（和安全有关）

已安装卡片“…”菜单里的「主页」，原来只判断不为空，就把 `plugin.json` 里 `homepage` 那个字符串原样交给系统去打开（`shell::openUrl` → `ShellExecute`），而清单解析只要求它是字符串。也就是说它如果写的是一个程序或脚本的路径、`file://` 地址或别的协议，点「主页」就会把它当程序或文件打开。插件自己的结果行在没有“启动程序”权限时只能打开 http/https/mailto（`plugin/OpenPolicy`），这一处绕过了那条限制，代价是用户点一下菜单。

现在两处都一样：只有 `readme::webLink` 认可的网址才显示「主页」，点的时候再判断一次。这是读代码发现的，没有做过利用尝试；需要“已安装该插件 + 用户点菜单”才会触发。同一个文件里另外两处打开链接的地方原来就有这个判断；程序里其余十几处 `shell::openUrl` 当天上午没有查，下午逐个查了，见下一节。

## 其余打开链接的地方（同一天下午逐个查了）

`shell::openUrl` 会把交给它的字符串原样交给系统打开，写的是程序就启动程序。程序里调用它的地方逐个看了一遍：

| 地方 | 打开的是什么 | 结论 |
|---|---|---|
| 识别文字后网页搜索、启动器里的网页搜索行（单选和多选）、设置里网页搜索的“打开主页” | 用户自己设置的网址，搜索词编码后放进去 | 用户自己的设置，不改 |
| AI 工具 `open_url` | AI 或插件给的地址 | 已限制为 http、https、mailto，且要有主机名 |
| 插件结果行、插件动作返回的“打开”、免代码插件声明的网址 | 插件给的地址 | 没有“启动程序”权限时只放行 http、https、mailto（`plugin/OpenPolicy`） |
| 插件设置：说明里的链接、安装来源、主页；插件库的主页 | 插件清单里的地址 | 都要求是网址（`readme::webLink`） |
| 剪贴板“在浏览器中打开” | 剪贴板里那条的文字 | 菜单只对“链接”类条目出现，打开时原来不再查。现在打开前再查一次。这一处不是能触发的漏洞，只是第二道检查 |
| 截图键、插件库的仓库地址、关于页的链接、任务栏设置页、更新的下载页 | 写死的地址；更新信息里给的页面只认 `https://lcstp.com/`，否则用写死的地址 | 没有问题 |

**留着没改的一处**：网页搜索的网址除了 `file:` 以外什么协议都收，从导入的网页搜索文件进来的也一样。这是有意的，为了支持应用自己的链接（比如某个软件的 `xxx://` 地址）；收紧就会让这类链接用不了。导入别人给的网页搜索文件时，要用户自己看一眼。

## 位置和样子是怎么定的（可以推翻）

- 先试过放在右边的操作区（状态文字左边）。渲染出来不行：有状态文字的行里，图标悬在中间，离按钮的远近随文字长短变，一列下来是散的。所以挪到标题行、紧跟版本号：右边的状态文字和按钮完全不动，按钮右边缘还是齐的。
- 挪过去以后全黑的图标和加粗的名字抢眼（见放大图上半），所以平时降到 55%。
- 没有把名字本身做成可点：不加链接样式看不出能点，加了又要改整列标题的样子。
- 没有给已安装卡片再加一个图标：它的“…”菜单里已经有「主页」。

## 测试

- `tst_pluginhomepage`（`--preview-plugins <png> --homepage-check --scale 1.5`）：在预览用的 9 个插件库条目上按对象名找到按钮，7 个有网址的显示，2 个不显示（一个没写主页，一个写的是 `file:///…`，后者和真实列表走同一个判断函数）；提示里的域名是 `github.com`；不透明度平时 0.55，指针移上去是 1。指针是用 Qt 事件移到离屏窗口上的，**不按下**（按下会打开浏览器）。结果见 `homepage-check.log`。
- `tst_pluginreadme` 新增 `homepageIsOnlyAnAddressOfTheWeb`：`calc.exe`、`C:/Windows/System32/calc.exe`、`//server/share/tool.exe`、`file:///…`、`ms-settings:`、`mailto:`、`search-ms:`、没有主机名的 `http:`、空串等都不算网址；`https://…` 和大写的 `HTTPS://…` 算。11 项通过。
- `ctest -R '^(tst_pluginhomepage|tst_pluginreadme)$'`：2 个都过（11:42），用的就是当前源码构建的程序（11:42:29）。两次运行前后都没有新的浏览器进程。

## 量到的几件事

- 图标实际画出来约 21×19 逻辑像素（按钮组件里写的是 `size: 14`，实际墨迹比这大），在 23.3 高的标题行里放得下；条目和标题行的高度和没有图标时一样（同一次渲染里，有图标和没图标的条目等高）。
- 指针在按钮上时，按钮自己的底板认为自己被悬停了（`hovered` 为真），但这个样式下没有画出可见的底色：按钮方块里除图标外的像素和旁边完全一样。所以悬停时看得见的反馈就是图标从灰变黑，加上提示。
- 指针进到一个分区里，整个分区的卡片区域会暗 10 级（251→241）。这是原有的行为，不是这次引入的：指针放到没被改动的“已安装”分区、或放到没有主页按钮的条目上，变化一样。它是怎么实现的没有查到。
- 最终构建和挪位置之后那次渲染相比，整页只有一小块不同：`file:///…` 那一行原来有图标、现在没有。

## 没有验证的

- **真实窗口里的样子和操作**：提示气泡（它是单独的窗口，离屏抓图抓不到）、键盘 Tab 到它上面的样子、真的点一下打开浏览器。
- **已安装卡片那一处判断没有自动测试**：卡片是从清单经插件宿主建出来的，预览数据不走那段代码；靠的是读代码，和它用的判断函数有单元测试。
- 只渲染了默认样式、150%、浅色和深色。其余三种界面样式、125% 和 175%、英文界面都没有渲染（32/24 这些尺寸在 125%、175% 下是整数个设备像素，这是算的，不是看的）。
- 离屏渲染用的是软件渲染，边缘和桌面上不完全一样（见 `docs/pitfalls.md`），不能用来数像素对齐；垂直位置是按整设备像素算的，没有在 D3D11 下比对。
- 两个新测试都是第一次跑就通过，没有看到过它们失败。

## 过程中出过的错（影响怎么读结果）

- 编辑工具会把源码里的 `\uE71B` 变成那个字符本身（看不见的私用区字符）。发现后按字节改回了转义写法，并核对新增的行里没有私用区字符。
- `--tree` 写出的控件树只到第 14 层，挪到标题行后的按钮在第 15 层，树里看不到；所以改用按对象名查找。
- 一开始把“整个分区变暗”说成是悬停的卡片自己的样子，又说成是两次渲染整体不同，都不对；后来做了对照（指针放在别处）才分清。
