# 本地模型验证

2026-11-25，Windows 11 Pro 26200，i9-14900HX + RTX 4060 Laptop（8 GB），`build/local-model`（Qt 6.12.0，llama.cpp b12359 Vulkan）。用户需求：支持本地模型，用户能导入自己的模型，用来翻译等。

做法：新库插件 `winshun.localmodel`（llama-server 跑在本机，前面一层中转只听 127.0.0.1:39281，不用时自动卸载）；翻译插件 2.3.0 新增服务“本地模型”，搜索框里边生成边显示。

| 验证 | 结果 |
|---|---|
| `tst_localmodel` | 21/21 通过。启动参数（`--fit`、`--cache-ram 0`、`--ctx-checkpoints 2`、`-lv 4`）、日志读出显卡和层数、下载续传与 SHA-256 不符、模型文件检查（嵌入模型、mmproj、LoRA 直接说明）、中转拒绝外来 Origin、并发过多、模型中途停了回 502 `stopped` |
| `tst_translate` | 45/45 通过。本地服务的请求与多行编号、SSE 流读取、加载慢时先回“翻译中…”再刷新出整句、没装/没运行时结果行回车打开“本地模型”卡片、端口没人听时说明原因 |
| `tst_plugin`（`fileExtensions`、`multilineText`） | 14/14 通过。`file` 设置的 `extensions` 只收扩展名，大小写与点号归一，用在文件夹和通配符上报错 |
| 真实插件进程实跑（隔离 profile，`--sandbox normal`，带作业内存限制） | GPU：首次连加载 2.3 s，之后每句 0.10–0.16 s，生成 57–125 tok/s；`wsbench` 翻译一句 377 ms；5 分钟不用自动卸载；没加载时 `/v1/models` 不触发加载 |
| 自己的模型文件（.gguf，只用 CPU） | 连加载 1.56 s，每句约 0.5 s，进程私有内存约 1.0 GB |
| 杀掉 llama-server | 卡片显示“模型意外停了（…），再用到时会重新加载”和“重试”，日志有一条 warn；下一次请求重新加载 |

实跑中发现并已修好：
- 显卡上的模型显存也计入作业的进程提交内存（1.2 GB 模型约 1.8 GB），原 2048 MB 上限会把 llama-server 杀掉。主程序 `memoryMB` 上限改为 16384，插件要求 Win顺 0.49.0。
- 显卡信息只在 `-lv 4` 时写日志，否则卡片误显示 CPU。`-lv 4` 不记录提示词，每次请求约 2.8 KB，每次启动重写日志。
- 模型加载成功后自己停了，卡片原先回到“就绪”什么也不说；现在显示原因，显存或内存不够时建议换小模型或只用 CPU。

## 按意思找用本地模型（2026-11-26）

“本地模型”再带一个嵌入模型（默认 Qwen3-Embedding 0.6B，610 MB，另起一个 llama-server，`/v1/embeddings` 归它）；“按意思找”1.1.0 新增服务“本地模型（离线）”。

| 验证 | 结果 |
|---|---|
| `tst_localmodel` | 21/21 通过。清单里对话模型和嵌入模型各自的选项与目录一致；嵌入模型的启动参数（`--embedding`，一段文字一个批次） |
| `tst_semantic`（新增 `localProvider`、`localModelIsAsked`） | 10/10 通过。向“本地模型”问到的是嵌入模型而不是对话模型；没有嵌入模型时把它自己说的原因交回；它没运行时说明去哪里打开 |
| `tst_translate` | 45/45 仍通过 |
| 真实插件进程实跑（“本地模型”带作业限制，“按意思找”在 strict 沙盒里连本机端口） | 嵌入模型没下载时请求回 503 并说明，卡片随后多出“下载嵌入模型”；下载 610 MB 用时 150 秒，校验通过；显卡上连加载 1.8 秒，之后一次请求 40 毫秒，占内存 1.4 GB；超出上下文的文字回 400，按意思找跳过该文件 |
| 用本仓库 `docs` 下 122 个文档（约 68 万字）建索引并查询 | 建索引 213 秒（人在用电脑，按设计只用三分之一时间）；“怎么发布新版本”→ `releasing.md`，“颜色和主题的规范”→ `colors.md`，“鼠标手势是怎么设计的”→ `design-gestures.md`，“how to write a plugin”→ `plugins.en.md`，“安装时文件被占用怎么办”→ 对应的验证记录，均排第一；每次查询约 0.3 秒 |
| 只用按意思找、没下对话模型 | 卡片不报警告（状态为正常），仍留着对话模型的“下载”按钮 |

没有验证的：自己的嵌入模型文件（如 bge-m3）只走了单元测试里的种类检查，没有实际加载；只用 CPU 时建索引的速度；对话模型和嵌入模型同时加载时的显存占用；换嵌入模型后重建索引只验证了签名会变。

没有验证的（翻译部分）：混元 HY-MT1.5 的实际下载与翻译（只验证了目录条目和校验流程）；AMD、Intel 显卡；显存不足时自动改用 CPU 只在单元测试里按日志模拟。
