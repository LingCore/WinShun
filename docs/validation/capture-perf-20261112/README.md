# 截图：按键到遮罩、指针（2026-11-12）

用户反馈：按快捷键偶尔黑屏卡一下；截图时指针有时不见。改动和原因见 [pitfalls.md](../../pitfalls.md) 的“遮罩出来后指针还是下面那个程序的”和“遮罩不走翻转呈现”两节。

## 环境和测法

- i9-14900HX，NVIDIA，单屏 2560×1600 @ 240 Hz，150%，SDR；Qt 6.12.0 Release。
- 单独启动的 `WinShunCapture.exe`（`WS_APP_DIR` 指向 0.25.0 的发布目录，独立数据目录，没有热键），[drive.py](drive.py) 按插件协议发 `action` 开始截图、再发一次取消。没有碰已安装的 Win顺。
- 黑帧：[blackprobe.cpp](blackprobe.cpp) 用桌面复制逐帧读屏，24×16 个采样点里纯黑的超过一半就报。
- 呈现方式：PresentMon 2.6.0（Intel 签名）按进程记录。
- 指针：`capture` 记录里的 `cursor_shown`（遮罩出来约 100 ms 后 `GetCursorInfo` 的指针大小和热点）。测试时鼠标不动。

## 结果

| 项目 | 改之前 | 改之后 |
| --- | --- | --- |
| 鼠标不动时遮罩上的指针 | 17 次里 16 次是下面程序的箭头 | 4 次全是截图的十字 |
| 遮罩的呈现方式 | `Composed: Flip` | `Composed: Copy with GPU GDI` |
| 黑帧（6 次 / 4 次截图，4000 多帧） | 0 | 0 |
| 启动后第一次截图，遮罩出现 | 96、94 ms | 81、87 ms |
| 之后的截图（各 10 次），中位 | 53 ms（49–60） | 46 ms（39–67） |
| 其中抓屏 | 31–39 ms | 21–37 ms |
| 空闲 50 秒（工作集清空后） | 67、96 ms | 74、62 ms |
| 遮罩不动时的帧数 | 出来后约 1 秒 40 帧，之后 0 | 一样 |

新旧两版在同一会话里交替各跑两轮（第一次和之后的数字）；更早单独跑的基线第一次是 150、210 ms。软件渲染也跑了两次截图，正常。

## 没有证实的

- 黑屏在本机没有复现。改成不走翻转呈现是按症状（黑一下、指针花掉）对应的常见成因做的防护，要报告者回测。
- 用户记录里 300–970 ms 的慢（启动后第一次、隔了几分钟以上）本机只复现到 150–210 ms。`HotPages` 预取、首帧前不读注册表和文件夹针对的是那种情形，没有实测到收益。
- 没有多显示器、HDR（走 WGC，这次没改）、核显的实测。
