# #191 截图翻译：译文显示在识别窗口里（2026-11-14）

分支 `features-1114`，构建目录 `build/features-1114`（Release，Qt 6.12.0）。上一版（同一天，`issues-171-191-20261114`）是把文字交给搜索框里的翻译插件，这一版改成译文直接显示在“识别文字”窗口里，并在截图工具条上加了“翻译”按钮。

## 自动测试

- `tst_capture ocrLinesBecomeParagraphs`：通过。英文折行接成一句、中文之间不加空格、连字符拆开的词接回、菜单短行不合并、句末标点和列表项处断开、空行和空白处理、3000 字上限。
- `tst_capture buttonsRunTheirActions`：9 项通过，含新的 `ocrtranslate`。
- `tst_ocr translationOfTheWords`：通过。请求带票号，旧票和换图后的回答丢弃；成功、失败、没设服务、没装插件四种结果；翻译状态变化不触发文字的 `changed`（不会盖掉用户改过的字）。
- `tst_ocr readThenTranslate`：通过。真实识别一张图后自动发起翻译；空白图不发起。
- `tst_capturesettings`：10 项通过（工具条按钮列表多了 `translate`）。

## 界面预览

`WinShunCapture.exe --preview-ocr <目录> --translation --scale 1.5`：翻译中、有译文、失败、没设服务、没装插件五种状态各出一张图，窗口高度 360 → 560，换文字后回到 360，“设置翻译服务…”按钮点得到。退出码是 1：有一条窗口重新创建句柄的警告，不带 `--translation` 的原有预览也是这样显示窗口的，不影响结果。

英文界面下发现底部一排按钮比窗口宽，最左边的按钮被挤出窗口（上一版加“翻译”按钮时带来的）。窗口宽度改成跟着按钮走：中文 460，英文 563（`preview-translated-150.png`、`preview-english-no-plugin-150.png`）。

## Win10 22H2 虚拟机，真实的 Win顺 和真实鼠标键盘

翻译服务用虚拟机里的假服务（`fake-tr.ps1`，监听本机 8765 端口，按 OpenAI 兼容接口回答，每段前面加“译文N：”），翻译插件的接口地址指向它。这样能看到真实链路上回来的结果，也能看出文字是怎么分段送出去的。

- 框选网页上的一段文字，工具条第二行有“翻译”按钮（`vm-toolbar-translate-button.png`）。
- 点它：窗口打开，上面是识别出的文字，下面先显示“正在翻译…”（`vm-translating.png`），随后是译文（`vm-translated.png`）。屏幕上折成三行的一句话作为一段送出去（译文 1），File / Edit / View 各是一段（译文 2–4）。
- 点译文右上角的复制按钮，剪贴板历史里第一条就是整段译文，189 字（`vm-translation-copied.png`）。
- 把翻译插件的服务改回“未设置”再试：窗口里写“还没有设置翻译服务，设置好后再点翻译”，下面有“设置翻译服务…”按钮（`vm-no-service.png`）。
- 点这个按钮：设置窗口打开在翻译插件那一栏，盖在识别窗口上面，下拉菜单打开时也不会被挡（`vm-settings-above.png`）；关掉设置后识别窗口自动回到最前，文字还在（`vm-back-from-settings.png`）。第一次试时设置窗口被识别窗口挡住，取消置顶后关掉设置又找不到识别窗口，改了两次才是现在这样。

## 没有覆盖

- 真实翻译服务（DeepL、微软、各家大模型）的结果和速度；保留换行的效果取决于服务本身。
- 没装翻译插件时的那一种提示（只在界面预览里看过，没在虚拟机里卸掉插件实测）。
- 旧版 Win顺（0.29.0 及以前）配新版截图插件时退回搜索框的路。
- 贴图和编辑窗口里的“识别文字”进来再点“翻译”（和截图走的是同一个窗口，没有单独测）。

## 第三步：译文盖在原图上（同一天）

工具条的“翻译”改成在原位贴一张译好的图；“识别文字”窗口里的“翻译”不变。

自动测试：

- `tst_capture ocrLinesBecomeBlocks`、`blockColorsFromThePicture`：通过。三行段落合成一块、标题和短标签各自一块、并排两栏不串、字号不同 / 离得远 / 缩进 / 句子结束 / 列表项 / 没到右边都不合并、中文不加空格、斜行单独标出；深色底浅色字的底色和字色取得准。
- `tst_pinwindow translationAndItsOtherSide`：通过。译文换上、`Tab` 翻面、位置不动；尺寸不对或图片已变时不换；翻转、旋转、编辑后只剩一面。
- `tst_ocr translatedInPlace`：通过。画一页（三行段落、一个标签、一块红色、一条深色栏上的浅色字）→ 真实识别 → 盖上中文 → 再识别一遍：中文都读得出，原来的英文读不到了，红色块逐像素不变；标签换成更长的英文时沿右边空白延伸，也读得出。
- `tst_translate`：35 项通过（提示词加了“一行对一行”）。

Win10 22H2 虚拟机，真实鼠标键盘，翻译服务仍是虚拟机里的假服务（这次按内容回中文）：

- 框选一页（粗体标题、三行段落、三个短标签、蓝底白字按钮、带边框按钮、深色栏）→ 点“翻译”（`vm-inplace-selected.png`）。
- 贴图立刻出现在原位，左上角“正在翻译…”（`vm-inplace-translating.png`）；约两秒后换成译文：段落从三行英文变成两行中文，按钮里的白字、深色栏里的浅色字颜色都对（`vm-inplace-translated.png`）。
- `Tab` 切回原文，再按切回译文；右键菜单里有“显示原文 Tab”和“复制译文”（`vm-inplace-menu.png`）。
- 没设翻译服务时：贴图关掉，改开识别窗口并说明（`vm-inplace-no-service.png`）。
- 第一次试时发现两处：深色栏上原字 g、y 的尾巴没盖住；“正在翻译…”没显示。都已修好并复测。

看得出的不足：

- 粗体标题译出来是常规粗细（没有判断原字的粗细）。
- 假服务有一行没给译文（它自己的对照表没匹配上），所以深色栏那一行显示的是原文加前缀，不是程序的问题。

没有覆盖：真实翻译服务（尤其大模型会不会把行数弄乱；弄乱时按设计退回识别窗口，这条路只在没设服务的情形下实测过）；中文译成英文变长的真实页面（只在自动测试里测了延伸）；照片、渐变底色上的效果；竖排文字；125% / 150% 缩放的真实屏幕（虚拟机是 100%）；多显示器。
