# 剪贴板历史：复制成文件的图片也能贴到屏幕、编辑

日期：2026-11-24　机器：本机 Windows 11（26200），2560×1600 150%，本地构建 `build/clip-pin-files`。

## 需求

用户私信：从微信、QQ 里复制图片，或在资源管理器里复制图片文件，剪贴板历史记成“文件”，右键菜单没有“贴到屏幕”。

## 原因

微信、QQ 复制图片时放到剪贴板上的是图片文件（`CF_HDROP`，指向它们的缓存文件），不是位图；Win顺 按“文件”记录。#369 起这类条目已经同时列在“图片”分类里，但菜单里的“贴到屏幕”“编辑”只给剪贴板历史自己存的图片。

## 改法

- 剪贴板历史：“文件”条目里的文件全是 Windows 能读的图片（和资源管理器右键“贴到屏幕”共用一份扩展名，`isPinnablePicture`：png、jpg、jpeg、jpe、jfif、bmp、dib、gif、webp、tif、tiff、ico，以及靠 Windows 扩展解码的 heic、heif、avif、jxr、wdp、hdp）时，菜单里有“贴到屏幕”（F3）和“编辑”（Ctrl+E，只有一张时）。一个条目里有几张、或多选几条图片时是“贴 N 张到屏幕”，一次最多 10 张（多了是“贴前 10 张到屏幕”）。文件已经被删（微信清了缓存）时提示“这些文件已经不存在了”，部分不在时贴其余的并说明几个不在。
- 启动器：图片文件那一行的“贴到屏幕”改用同一个判断，并加上“编辑”。
- 截图插件 1.1.33：一次贴几张时按 `slot` 依次错开 32 逻辑像素（往屏幕空的那边），并按请求的顺序叠放（后贴的在上面，即使前一张图大、解码慢）；`edit` 不带 `clipId` 时把图片文件当新图片打开（和长截图一样，Enter 复制成新的一条，原文件不动）。

## 验证

| 项目 | 结果 |
|---|---|
| `WinShun.exe --preview-results <目录> --clipboard-pin-files`（真实 QML 剪贴板页面、临时历史，不碰系统剪贴板） | 通过：单张图片文件有“贴到屏幕 F3”和“编辑 Ctrl+E”；两张是“贴 2 张到屏幕”；图片加文本文件、多选里有文字时都没有；12 张贴前 10 张、slot 0–9；文件已删时提示且不发请求；多选一张历史图片和一个图片文件一起贴；菜单关着时 F3、Ctrl+E 生效（Ctrl+E 先收起窗口）；插件关掉后两项消失。菜单截图：[menu.png](menu.png) |
| `WinShun.exe --preview-results <目录> --file-type-folder`（启动器） | 通过：图片文件行有“贴到屏幕”“编辑”（没有截图插件时都没有），“编辑”先收起启动器再交出文件；文本文件行没有 |
| `tst_pinclipboard`（新增 `cascade`，96/120/144/168 DPI） | 通过 |
| 直接按协议驱动构建出的截图插件（隔离的数据目录，`hostHotkeys`，不注册热键、不改 PrtScn）：同时贴 3 个图片文件（第一张 1400×900 噪点图，解码最慢） | 三张按顺序叠放、依次错开：[pins-cascade.jpg](pins-cascade.jpg)（噪点图在最下，绿 slot 1，蓝 slot 2 在最上；鼠标靠右下，所以往左上错开） |
| 同上，`edit` 只带图片文件 | 编辑窗口打开这张图，420×280、100%：[edit-file.jpg](edit-file.jpg) |

另见：插件开着贴图或编辑窗口时收到 `shutdown` 后进程不会自己退出，已发布的 1.1.32 也一样；Win顺 收到回答就结束进程（`Host::stopInstance`），用户无感，不属于这次改动。
