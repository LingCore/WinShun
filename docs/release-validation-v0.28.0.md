# Win顺 0.28.0 发布验证

2026-11-14，在 Windows 11 x64、Qt 6.12.0、MSVC 2022 Release 环境完成构建和相关验证。构建源码为 `8f31dd07`（版本号、发布说明与文档），构建目录 `build/release028`，交付文件在 `dist/release028`。此后的提交只更新海报、截图页和本记录。

本版来自分支 `issues-1113b`（基于 0.27.0 的 `522f264e`）：#322 #234 #321 #320 #305 #157 #124 #327 #324 #212 #260 #180，以及打包和安装程序的两处修复。发布时本机主工作目录里另有未提交的改动（字体选择、截图插件的若干文件），不属于本版，没有纳入。

## 构建与相关回归

- 全新配置，编译主程序及官方可选插件。标准、离线安装器及主程序版本资源均为 `0.28.0`。
- 版本号提升之前跑了 8 项相关 CTest，提升之后的发布构建跑 9 项（加 `tst_updater`、`tst_scoopinstall`），全部通过：`tst_settings`、`tst_capturesettings`、`tst_stage7`、`tst_core`、`tst_clipboard`、`tst_capturekeys`、`tst_printscreen`。[输出](validation/release028/ctest-related.txt)
- 打包脚本现在检查每个随包的程序和库依赖的运行库、Qt 库是否都在包里（`dumpbin /dependents`），缺了就不出包；本次通过，包里有 `msvcp140*.dll`、`vcruntime140*.dll` 共 8 个文件。

## 全新电脑上的首次安装

0.27.0 在没有装过 VC++ 运行库的电脑上打不开（缺 `MSVCP140_2.dll`，0xC0000135），这是本版最要紧的修复，所以单独验证：

- Hyper-V 虚拟机，Windows 10 企业版 22H2（19045），还原到刚装完系统的检查点：`System32` 里没有 `msvcp140.dll`、`msvcp140_2.dll`，没有装过 Win顺。
- 用本版的标准安装包（SHA256 与下文一致）静默安装，退出码 0，索引服务运行；在登录用户的桌面上启动 `WinShun.exe`，25 秒后进程仍在，显示首次引导窗口。[截图](validation/release028/clean-windows10-first-start.png)（右侧是 Windows 自己的网络提示）

## 安装和升级实测

- **占用文件的实测**（`tools/verify-installer.ps1`，`release.ps1` 打包前自动运行）：5 项全部通过。[报告](validation/release028/installer-test.json)
  - 如实记录：开发期间这一项在本机**没过**（“自己的程序还在运行”超时），用未改动的安装脚本对照也一样。原因是安装前“结束安装目录下还在运行的程序”这一步向 WMI 要了全部进程再逐个取，耗时随进程数平方增长，本机 547 个进程时 27 秒。改成只查询安装目录下的进程后，普通升级从 30 秒降到 3.9 秒。上一版记录里“文件被独占打开一项接近 30 秒时限”是同一个原因。
- **应用内更新整条链路**（`tools/verify-installed-upgrade.ps1 -Mode InApp`，经用户同意在开发机上做）：本机 Program Files 里装着的正式版 0.27.0（为所有用户安装，带索引服务）从本机的假更新服务检查到 0.28.0，下载、校验、运行安装程序，51.8 秒后新版本以普通权限启动；索引服务运行，设置、历史和索引文件不变，安装目录里没有留下 `.wsold`。更新后本机程序的 SHA256 与部署目录一致。[报告](validation/release028/upgrade-inapp.json)

## 各项改动的实测

在上面那台 Windows 10 虚拟机里用真实按键和鼠标（Hyper-V 的合成键盘、鼠标）做，逐帧录屏或截图核对；当时的截图没有留存，这里只记结论：

- #234：文件夹里打字的搜索框带着结果一次出现，变高变矮都没有黑块，位置贴窗口底边、让开滚动条（Direct3D 渲染；纯软件渲染下偶尔仍多一帧旧画面）。
- #157：微软拼音中文模式下在文件夹里打 `rep`，候选窗还开着时结果已经列出。
- #327：鼠标按着文件时按键没有反应，松开后按键照常弹出搜索框。
- #324：复制一个文本文件后，剪贴板预览栏显示文件内容。
- #260：“遮住内容”后列表和预览都只显示圆点。
- #180：右键 › 发送到 里有“局域网传输（Win顺）”，点了之后文件列在待发送里。
- #124、#212：贴图上按 `E` 进入编辑、`U` 收到顶边并展开、`O` 打开识别文字窗口。
- #259、#233、#307（没有复现）：截图复制后剪贴板里有图；双击和回车都能粘贴；预览正常。

## 没有覆盖的

- #322 用真实的 PrtScn 键验证（只有单元测试）。
- #180 多选文件、真正发到另一台设备。
- #324 的悬停预览小窗和加长后的悬停等待；#260 遮住的图片条目。
- 网页搜索插件卡片上的新开关和“置顶”按钮没有逐像素检查。
- 便携版自己更新、向导安装、“只为我安装”的升级：本版没有改这些路径，没有做。
- Windows 11 上没有重做上面各项的真实按键验证（开发机是 Windows 11，功能开发时用的是生产预览和探针）。

## 生产界面与海报

发布构建的 `WinShun.exe` 用 D3D11、200%、临时配置和 `QT_FONT_DPI=96` 做了纯净搜索的生产预览（`--preview-results --pure-search`）；200% 下“搜索框显示行数”的几条不通过和上一版一样（离屏的屏幕放不下 8 行），150% 下只有原有的计时警告，新增的输入法、网页搜索、面板开关检查都通过。

本版新增海报一张，沿用品牌方形模板，1440×1440、JPEG 质量 96、关闭色度抽样（[原图摘要](validation/release028/poster-sources.json)）：“没搜到，网页接着搜”，放进“收藏夹、网页搜索和插件”分组。README 仍只放封面。**没有海报的**：输入法未上屏就出结果（要拍真实输入法的候选窗）、剪贴板的遮住内容和文本文件内容（没有输出图片的预览）、资源管理器的“发送到”（资源管理器自己的菜单）、贴图按键。
