# 配色规则

Win顺 所有颜色都在 `src/app/qml/Theme.qml`（强调色的实心底在 `SystemTheme::accentFill()`）。新加界面时先查这里，不要在组件里写死颜色。2026-10-11 按这份规则把全部 QML 的彩色用法检查过一遍，结果在最后。

## 规则

1. **彩色实心底上的字和图形一律白色**（`Theme.accentText`，两套主题都是 #FFFFFF）。不用 Windows 11 深色模式“浅蓝底配黑字”的做法：用户明确说“蓝色背景黑色字体，很不好”。图形也一样：开关的圆点、对勾、单选点。
2. **蓝色分两种用途**：
   - `Theme.accent`：蓝色的字、图标、细线、下划线、焦点线、选中竖条。深色主题下调亮（`Qt.lighter(强调色, 1.55)`），在深色底上才看得清。
   - `Theme.accentFill`：上面要放白字或白色图形的实心底（高亮按钮、当前子标签、插件命令标签、打开的开关、主题卡的对勾和单选点、剪贴板序号）。由 `SystemTheme::accentFill()` 算：从强调色出发（深色主题先调亮 1.15 倍），不断加深，直到白字对比度 ≥ 4.5:1。用户换成亮黄、亮绿这类强调色也成立。
   - 不要拿 `Theme.accent` 当白字的底：深色下它是 #2B9DFF，白字只有 2.85:1。
3. **红色也分两种**：`Theme.danger` 用于红字和红色图标（深色主题是柔和的 #FF99A4）；`Theme.dangerFill`（#C42B1C，Win11 的红）用于放白字的红底（剪贴板行确认删除的按钮）。不要用 #FF99A4 当底：粉底配什么字都不像删除按钮。
4. **浅色标签**（“随包”“AI”“应用”）：`Theme.badge`（强调色 10–16% 透明）做底，`Theme.accent` 做字。
5. **状态色只用作字和图标**：`success` / `caution` / `danger` 是 Windows 11 的状态色，不当实心底。
6. **灰字三级**：`text` 正文，`subtext` 说明，`faint` 提示和占位文字。`faint` 两套主题都是 #8A8A8A，在卡片上 ≥ 3:1；不要再调淡。
7. **边框**用中性灰 1 逻辑 px（`cardBorder`、`controlBorder`、`windowEdge`），不用蓝边，不用 2 px。选中状态靠底色和强调色竖条表达。
8. **纯图标分段按钮**（如列表／大图）选中时改变图标颜色，配中性底面；不沿用文字分页的下划线。文字分页保留各风格自己的选中标识。预览／菜单入口在打开期间持续标记，不能让标识随鼠标移走而消失；键盘焦点独立保留。

## 对比度（默认蓝 #0067C0；深色卡片 #2B2B2B，浅色卡片 #FBFBFB）

| 组合 | 深色 | 浅色 |
|---|---|---|
| 正文 `text` / 卡片 | 12.8 | 16.7 |
| 说明 `subtext` / 卡片 | 5.9 | 5.6 |
| 提示 `faint` #8A8A8A / 卡片 | 4.1 | 3.3 |
| 蓝字 `accent` / 卡片 | 5.0 | 5.5 |
| 蓝字 / `badge` 标签底 | 3.9 | 4.7 |
| 白字 / `accentFill`（深色 #0076DD，浅色 #0067C0） | 4.5 | 5.7 |
| `accentFill` 底 / 卡片（形状看得出） | 3.1 | 5.5 |
| 白字 / `dangerFill` #C42B1C | 5.7 | 5.7 |
| 红字 `danger` / 卡片 | 7.0 | 5.5 |
| 绿字 `success` / 卡片 | 7.0 | 5.3 |
| 黄字 `caution` / 卡片 | 10.7 | 5.1 |

标准：正文 ≥ 4.5，提示和大字 ≥ 3，实心形状和底色区分 ≥ 3（WCAG 2.1）。

## 2026-10-11 检查结果

改了的（之前不合理）：

- 深色主题下蓝底配黑字/黑图形：启动器 `文件 › 文件夹` 子标签、插件命令标签、高亮按钮（“连接”“创建”）、开关圆点、主题卡的对勾和单选点、剪贴板序号。现在一律白色，底换成 `accentFill`。
- 剪贴板行确认删除的按钮：深色主题下是粉底 #FF99A4 配黑字，现在是红底 #C42B1C 配白字。
- 提示文字 `faint`：浅色 #9A9A9A 只有 2.7:1、深色 #727272 只有 2.9:1，现在都是 #8A8A8A。

检查过、合理的：蓝色链接和蓝色图标、文字分页的强调色下划线、选中竖条、浅色标签（“随包”“AI”“应用”）、红绿黄状态字、标题栏关闭按钮（红底白叉）、键帽（中性灰底）。**2026-11-06 修正**：此前“各种下划线都合理”的表述过宽，纯图标选择不适用，见规则 8。键帽从 2026-10-23 起不描边，只靠灰底（Theme.keycap，浅色 rgba(0,0,0,0.06)，深色 rgba(255,255,255,0.07)）显形，所以底色不能再回到和窗口背景一样的白或近白；选中的芯片和钉住的图钉仍保留 1 px chipBorder，浅色主题下白底的选中块要靠它才看得见。

## 怎么检查

- 改了颜色后用离屏渲染看两套主题：`WinShun.exe --preview-settings <文件夹> --dark --scale 1.5`、`--scale 1.25`（浅色），见 architecture.md。
- 量像素而不是凭眼睛：从截图里取底色和字色（PIL `Counter(crop.getdata())`），按 WCAG 公式算对比度，`relative luminance = 0.2126 R + 0.7152 G + 0.0722 B`（各通道先做 sRGB 线性化）。
- 改了边框、分隔线、卡片或任何尺寸后，边缘有没有落在整像素上，按 pitfalls.md 的“改完界面查像素”过一遍（150%、125%、175% 各数一次四边的粗细）。
