# #138：插件启动、升级恢复与安装体验验证

2026-10-30，针对 [LingCore/WinShun#138](https://github.com/LingCore/WinShun/issues/138)。本次在已有工作区修改上实现和验证，没有提交、推送或发布新版本。

## 采用的方案

继续使用现有插件架构：搜索和可关闭的内置功能保留原有入口，截图等扩展按需安装。此次补齐插件拆分后的启动和恢复体验，不重写截图引擎，也不凭进程数量判断资源是否更少。

- Host 在配置、开关和权限应用完成后排队启动 eager 插件，合并同一轮变化；取消固定十秒等待。未授权、已关闭和退出中的插件不会启动，重新启用不必重启宿主。
- 截图迁移先保存插件设置，再在同一次宿主 INI 更新中移除旧开关并记录插件启用和权限。已有 `capture.ini` 不覆盖，失败保留旧配置；宿主保留 PrtScn 还原记录。
- 升级恢复失败留在“插件 → 已安装”，说明失败功能、设置和数据仍在，提供重试和本地包安装。部分成功时保留失败项；恢复中禁用重复操作。
- 插件库的新插件使用“安装并启用”，仍经过现有权限确认。拒绝后保持关闭；更新沿用原开关，本地包安装不自动启用。
- 修正实际启动遇到的剪贴板对象尚未构造时的访问，以及恢复时重建卡片触发的 `DropMenu` 临时空父项绑定。英文权限长文案按卡片宽度换行。

## 环境与隔离

Windows 11 Pro 10.0.26200；Core i9-14900HX；31.8 GiB RAM；Qt 6.12.0、MSVC x64 Release、D3D11。工作区基于 `20b9af9` 并带有原先未提交修改，结果对应当时的完整工作区，不代表仅这些改动的独立性能对比。

部署目录为 `build/issue138-validation-20261030/app`，没有覆盖用户的安装目录或 `data`。实际启动探针走生产 `App::start`，使用临时配置、单文件索引夹、进程内 HKCU 重定向；停用服务、全局入口、任务栏入口、自动启动接管和更新检查。剪贴板样本只读取当前内容，不写系统剪贴板；报告不保存内容。LocalSend 关闭接收，并在退出后移除本次配置生成的 CNG 身份。

截图验证挑选一个未占用的 `Ctrl+Alt+Shift+F13…F24`，从 Windows `RegisterHotKey` 层面观察注册及退出释放，不触发截图、不接管 PrtScn。原有安装版进程 PID 74088 在验证前后仍运行。

## 实际程序验证

可复用入口：[`tools/verify-plugin-recovery.ps1`](../tools/verify-plugin-recovery.ps1)。需要当前部署好的程序及构建出的 capture、LocalSend 插件，输出目录必须是新目录。

```powershell
./tools/verify-plugin-recovery.ps1 `
  -AppDir ./build/issue138-validation-20261030/app `
  -OutputDir ./build/issue138-check
```

最终完整运行 **12/12 通过**，汇总为 `build/issue138-validation-20261030/checked/results.json`；各用例目录保留 `runtime.json`、`preview.log`，有界面的用例也保存 PNG。

## 界面检查

恢复提示使用真实 SettingsWindow 和 PluginSettings 的静态状态预览，分别检查中文浅色 920×720，以及英文深色 760×420、150% 缩放：忙碌、离线、重试、完成后的隐藏状态和按钮行为。两组均 0 QML 警告，并人工查看 PNG。

英文插件页另按 760 逻辑像素宽、150% 缩放检查安装按钮、权限长文案和设置搜索。检查时发现权限长文案越界，已放到标题下方并按卡片可用宽度换行；预览原先硬编码的中文搜索词也改为使用对应界面的译文，避免把英文界面找不到中文词误报为产品故障。最终检查 0 QML 警告，图片和日志在 `build/issue138-validation-20261030/ui-final-layout`；布局调整后，安装允许／拒绝两条实际流程再次通过，结果在 `install-final-layout/results.json`。英文实际启动的失败提示也有单独用例，使用生产类的翻译上下文，避免静态预览掩盖命名错误。

## 发布前的边界

本次验证针对启动、迁移、恢复和安装权限流程。真实 PrtScn 接管与还原、公开插件库下载、截图／录屏／长截图／OCR 的完整人工操作，以及 HDR、混合 DPI 多屏场景仍需发布前验收。现有 `memoryMB=2048` 对大长截图和 4K 录屏是否足够也没有在本轮测定。具体发布要求仍按 [releasing.md](releasing.md) 执行。
