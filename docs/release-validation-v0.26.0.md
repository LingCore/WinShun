# Win顺 0.26.0 发布验证

2026-11-13，在 Windows 11 x64（150% 缩放）、Qt 6.12.0、MSVC 2022 Release 环境完成构建和相关验证。构建源码为 `09508009`（版本号、发布说明与文档），构建目录 `build/release026`，交付文件在 `dist/release026`。此后的提交只更新海报、截图文档和验证证据，不涉及参与编译的文件。

## 构建与相关回归

- 全新配置，编译主程序及官方可选插件。标准、离线安装器及主程序版本资源均为 `0.26.0`。
- 按本次改动选择 14 项 CTest，全部通过：闲置时保留的内存页（`tst_hotpages`）、程序自己的选文件窗口（`tst_dialogrules`）、云备份插件和宿主的备份工具（`tst_cloudbackup`、`tst_backupservice`）、命令行管理插件（`tst_plugincommands`、`tst_cli`、`tst_wsplugin`、`tst_mcp`）、Directory Opus 菜单（`tst_opusfocus`）、“应用”标签涉及的导航与收藏（`tst_launchernavigation`、`tst_favorites`）、插件（`tst_plugin`）、更新（`tst_updater`）、Scoop 清单（`tst_scoopinstall`）。[CTest 输出](validation/release026/ctest-related.txt)
- 各项功能自己的实测记录在对应目录：“应用”标签（`validation/issue296-apps-tab-20261112`）、云备份（`validation/issue276-cloud-backup-20261112.md`，含真实 WebDAV 服务器、真实 GitHub 私有仓库和真实 Win顺 里的整套流程）、闲置后呼出（`validation/issue-280-20261112`）、资源管理器标签页与程序自己的选文件窗口（`validation/issues-273-272-20261112.md`）、管理员运行时搜索框不接收输入（`validation/issue299-20261112`）、安装被占用文件（`validation/installer-held-files-20261112`）、预览卡住与设置页小点（`validation/issues-306-307-20261112`）、截图指针与首帧（`validation/capture-perf-20261112`）。
- `tst_settings`（搜索框显示行数、“应用”标签开关的读写）在本机约 5% 的运行里因配置文件被别的进程短暂占住而失败，没有放进发布构建的测试集；这两项在功能开发时跑过。`tst_contentpane` 在改动前的代码上也失败，同样没有放进来。

## 安装和升级实测

- **占用文件的实测**（`tools/verify-installer.ps1`，`release.ps1` 打包前自动运行）：5 项全部通过——正常升级、自己的程序还在运行、别的程序加载着库不放、别的程序在读文件、文件被独占打开。[报告](validation/release026/installer-test.json)
- **应用内更新整条链路**（`tools/verify-installed-upgrade.ps1 -Mode InApp`，经用户同意在开发机上做）：本机 Program Files 里装着的 0.25.0（为所有用户安装，带索引服务）从本机的假更新服务检查到 0.26.0，自己下载 `WinShun-0.26.0-x64-setup.exe`、校验、运行安装程序，60.8 秒后新版本启动。升级后：程序版本和卸载项均为 0.26.0，`WinShun.exe` 与交付包里的逐字节相同；新版本以普通权限运行；索引服务在运行，服务程序路径不变；开机自启任务仍在；设置文件还在，历史文件的摘要与升级前相同；程序文件夹里没有留下 `.wsold` 文件。[报告](validation/release026/upgrade-inapp.json)

## 生产界面与海报

部署目录的 `WinShun.exe` 用 D3D11、200% 和临时配置做了生产预览：完整设置窗口（逐页逐标签，55 张，零 QML 警告）、“应用”标签的检查（`--apps-grid`，通过）、程序自己的选文件窗口的设置检查（`--dialog-rule-settings`，配 WPF 替身窗口，通过）。[二进制来源](validation/release026/capture.json)、[海报原图摘要](validation/release026/poster-sources.json)

结果与预览的综合检查（`--preview-results --file-metadata --gallery-image`）**有不通过的项**，如实记录：

- 200% 下两条：“预览窗口盖住了搜索框”（离屏的屏幕在 200% 下放不开两个窗口）和“读不出来的文件没有在限定时间内给出提示”。同一检查在 150% 下这两条都通过。
- 150% 下（跑了两遍，结果相同）两条：“.psd 没有显示成图片”“.psd 的摘要里没有尺寸”。看当时存下的图，预览窗口里是鼠标悬停处的另一张图片，不是 .psd：检查里的“预览跟着悬停走”把画面换走了。同一检查在 200% 下 .psd 正确画成 320×200。
- 判断是检查在这两种缩放下各自的时序和布局问题，不是预览功能的问题，但没有进一步证明；#307 的改动在开发时用 150% 跑过同一检查并通过（见其验证记录）。

本版新增海报三张，沿用品牌方形模板，1440×1440、JPEG 质量 96、关闭色度抽样：

- “按 F2，就地改名”（搜索面板里的重命名输入框）和“预览文档，语法上色”（Markdown 预览），补上 0.25.0 欠下的两张，放进截图文档的“搜文件”分组。
- “自绘窗口，教一次就会”（设置 › 打开 Win顺 › 对话框：程序自己的选文件窗口），放进“对话框和资源管理器”分组。

README 仍只放封面。其余海报沿用旧图。**没有海报的**：

- “应用”标签：图标网格拍出来是本机真实安装的软件，用户决定不公开，这次不做海报。
- 云备份插件：需要真实的服务器和账号才有内容，没有做。
- 剪贴板备注（预览用的数据只有一条“已不存在”的文件记录，不适合做海报）、搜索面板里的快捷筛选小片（截图里提示框压住文字）：仍然欠着，留到下次用演示数据走实机拍摄流程时补。

## 插件库同步

逐一对比官方插件编译用到的源文件（`ninja -t inputs` 列出的输入，与各插件已发布版本所记源码提交到 HEAD 的改动求交集），四个插件有变化，另有一个新插件，均在版本号提升到 0.26.0 之前，从干净的工作副本 `1572a538` 构建发布：

| 插件 | 版本 | 最低主程序 | 变化 |
| --- | --- | --- | --- |
| 云备份 | 1.0.0（新） | 0.26.0 | 设置备份自动传到 WebDAV 或 GitHub 私有仓库；权限：设置备份、网络、通知 |
| 资源管理器标签页 | 1.1.0 | 0.25.0 | 记住并恢复开着的窗口和标签页；权限不变 |
| 截图与录屏 | 1.1.12 | 0.18.0 | 鼠标不动时指针不再消失、复制方式显示、首帧更快、按住鼠标时方向键微调；权限不变 |
| 图片文字搜索 | 1.0.12 | 0.25.0 | 跟进共用代码（窗口边框、闲置内存、搜索核心） |
| 网页搜索 | 2.0.2 | 0.25.0 | 只有说明更新（按 Tab 补全关键词是主程序的功能） |

公开 `index.json` 中五个条目的版本、SHA256 与本地包一致，签名验证通过（`ws-index-2026a`），共 34 个插件。插件库的检查工具同时认识了新权限 `winshun:backup`（要求清单写明最低 0.26.0）和云备份的程序名。其余官方插件（浏览器书签、休息提醒、翻译、语义搜索）的编译输入没有变化，不重新发布；局域网传输 1.0.7 已在 11 月 12 日发布。已发布的 0.25.0 读插件库索引的代码把权限当普通文字、按最低版本判断能不能装，所以它看到云备份只会提示需要更新的 Win顺（读代码确认，没有用 0.25.0 实际打开插件库看）。

## 没有覆盖的

- 真实升级只做了 `-Mode InApp`（为所有用户安装的那份，没有加 `-Hold`）。没有做：`-Mode Setup`、`-Mode Wizard`、`-Mode Portable`（便携版自己更新）、“只为我安装”的升级。本版在 11 月 12 日改安装脚本时这几种都跑过（见 `validation/installer-held-files-20261112`），之后安装脚本和更新程序没有再改。
- “被挪开的旧文件在重启后删除”仍然没有经过一次真实重启来确认。
- 本次发布流程里没有对新功能再做实机键鼠测试，依据的是各功能开发时的实测记录和上面的生产预览检查。其中“应用”标签开发时只做了离屏检查，没有在真实窗口里用鼠标和键盘实测，也没有在 125%／150% 缩放下量像素。
- 程序自己的选文件窗口：本机没有 ArcGIS，ArcMap 和 ArcGIS Pro 都没有实际跑过，用的是原生和 WPF 的替身窗口。
- 资源管理器标签页 1.1.0：没有经过真实的注销或关机再登录。
- #307（预览一直“正在读取”）和 #306（设置页小点）都没有复现；#307 做的是不依赖原因的改进。
- 截图“按下快捷键黑一下”本机没有复现，改动是按症状做的防护。
- 云备份没有在坚果云、Nextcloud 和 NAS 上实测。
- 发布构建开始前，为了重启一次参数写错的构建，结束过本机所有 `cl`、`ninja`、`cmake` 进程；当时如果有别的会话在编译，会被一并结束（没有看到迹象）。
