## #141 后续实现与验证

本次按用户要求继续实现窗口避让与同步选中，保留工作区内其他修改，未提交、推送、安装替换或发布。

- `Placement` 在同一显示器工作区内选择与原窗口重叠最少的位置，优先完整避让，维持用户宽度和正常结果容量；最大化窗口没有外部空间时保留屏幕内位置。避让只对这次打开生效，不把自动移动保存为常用位置，用户拖动后也不会被自动拉回。
- 真实打字入口与验证共用 `App::showFolderSearch`。当前结果变化后，合并短时间内的连续选择，再复用 COM 工作线程同步原资源管理器标签页。只选择原目录的直接子项；子目录及其他位置不触发导航。原目录/标签变化、失去前台、收起或新一次搜索都会使旧请求失效。
- 使用 Shell 的 `SVSI_NOTAKEFOCUS` 选择、设置项目游标并确保可见，保留搜索框键盘焦点。映射盘身份解析留在工作线程，复用现有 UNC 解析逻辑。参考 [Microsoft 的选择标志说明](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-_svsif)。
- 相关目标的 Qt 6.12.0 / MSVC Release 构建通过；最终 11 项 CTest 全通过，11.76 秒。新用例覆盖左右/上下避让、负坐标、部分离屏、最大化与空间不足；真实隐藏窗口检查临时位置、尺寸变化和恢复常用位置。
- 125% 的显示几何检查为 5 通过、0 跳过；200% 为 4 通过、1 跳过。跳过项明确要求主屏能容纳 760 像素搜索框及旁边夹具，该缩放下主屏工作区不足；不把这一项记为通过。下述真实资源管理器 200% 检查在其实际打开的显示器上通过。
- 新增 `--probe-runtime <目录> --folder-typing` 验证入口，真实 `App`、真实 QML、真实临时文件与新建资源管理器窗口共同执行；独立通过 Shell 读取所选项目及项目游标，不用发送信号当作外部选择成功的证据。150% 浅色、200% 深色各 14 项检查全部通过，警告 0：真实文件搜索、首次选中、方向键、快速连按、焦点保留、不重叠、嵌套结果不导航、COM 查询后的取消及关闭前取消均覆盖。
- 150% 时原窗口原生边界为 `(8, 8, 853, 1512)`，搜索框为 `(879, 306, 1140, 497)`，两者不相交；200% 的搜索框为 `(886, 202, 1520, 662)`，仍不相交。截图采集已核对为桌面合成后的两个自建窗口区域。
- 最终真实 Main/Launcher 编号与滚动检查再次通过、警告 0；打字交接及映射路径定向回归为 4 通过、0 跳过，包含真实本机 SMB 合并分支。
- 未逐个实测 Windows 10、其他文件管理器或报告者 NAS 的同步选择；当前同步选择针对 Windows 资源管理器，不自动控制 Opus。用例创建独立临时配置和目录，仅关闭自己新建、未被加入额外标签页的资源管理器窗口，用户 Win顺进程 PID 18540 保持运行。
