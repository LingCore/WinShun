# 录屏浮条重设计与验证（2026-10-30，10-31 修订）

用户反馈录屏界面过大、与 Win顺 风格不协调。本次将常驻操作收成浮条，沿用现有 `Theme`、阿里巴巴普惠体和 Phosphor 图标；高级选项按需展开。

## 2026-10-31：展开区紧凑化（当前实现）

用户再次反馈展开区过大，顶栏按钮底边紧贴分隔线。根因是浮条与选项区之间没有独立的分隔留白，选项区仍按完整设置表单排列：四个开关占两行，档位、按键和操作说明各占常驻行，多个横线又拉开分组。

展开区现为三行：画质；鼠标／倒计时图标和按键显示；保存位置。移除组间横线和常驻说明，档位参数放在对应按钮提示中，操作说明放在开始按钮提示中；只有选择“全部按键”时直接显示输入文字和密码的提醒。四个图标开关保留勾选标记、复选语义、可访问名称和键盘焦点提示；保存路径中间省略，编辑按钮提示包含完整路径。指针、点击和鼠标图标沿用项目自带的 Phosphor 字体，补齐现有 MDL2 映射，不新增字体依赖。

分隔线上下各留 8 逻辑像素，由展开视口统一管理。中文普通展开态从 **561×416** 降为 **561×185**，收起仍为 **561×56**；英文普通展开态为 **604×185**。选择全部按键后中文为 **561×213**。下文 10-30 的 416 像素高度属于旧版历史结果，不再代表当前布局。

本次使用 Qt 6.12.0 / Release / D3D11 的独立插件副本，借用已有部署目录的 Qt 和字体，只写临时输出目录；保留运行中的用户程序和配置。完成以下验证：

- 插件构建通过；`tst_capturesettings`、`tst_commandicons` 通过；重新构建的 `tst_appearance::phosphorIcons` 检查新增映射实际存在于字体中。最后一项使用 offscreen 平台时有 Qt 字体目录提示，图标断言通过。
- 真实录屏预览的中文亮色 100%、中文深色 150%、英文深色 150% 界面检查通过，最终界面日志没有 QML 警告。英文使用包含中英文的长目录，已查看路径省略和末尾编辑按钮。
- 通过真实窗口事件检查所有图标开关、画质和按键单选、GIF 音频禁用、连续展开／收起、空格展开、Esc 收起并返回齿轮焦点。96 逻辑像素的受限视口仍能把最后的目录按钮滚入可见范围；屏幕边缘展开后仍在工作区内。
- 预览新增普通展开高度不超过 200、分隔线两侧留白的检查。留白按最终设备像素测量，150% 为 12 / 12 像素，避免非整数线宽运算的浮点尾差；未放宽实际像素间距。
- 中文深色 150% 完成实际 MP4 倒计时、录制、暂停／继续、保存与再录，生成两段文件；未在本次重复独立解码或验证真实系统按键高亮。界面事件检查不等同于物理键鼠端到端检查。

当前截图、日志及媒体在 [10-31 本地验证目录](../build/recording-compact-20261031/)。`dark150-final/options.png` 为最终中文深色展开态；早期 `light100` 的 Loader 空对象警告及 `dark150-zh` 的浮点几何断言失败已修正，最终 `light100-final`、`dark150-final`、`english150-final` 检查通过。

## 2026-10-30：界面与实现（历史）

| 阶段 | 行为 |
| --- | --- |
| 待录 | 格式、输出尺寸与帧率、系统声音、麦克风、齿轮、开始、取消保持可见；默认不展开设置。关闭声音有静音图形，GIF 的音频操作禁用。 |
| 选项 | 齿轮在原窗口中展开画质、鼠标、按键显示、倒计时和保存位置；重复点击收起，可再打开。第一次 Esc 收起选项并返回入口焦点。 |
| 录制／暂停 | 只显示计时、文件体积、暂停／继续和停止；暂停按钮为两种文案预留同一宽度，防止浮条跳动。“全部按键”的密码提示继续可见。 |
| 保存完成 | 显示时间、体积和文件名，提供播放、复制文件、文件夹、再录和关闭。 |
| 出错 | 保存目录校验失败时展开选项；更换目录后清除旧错误。实际录制失败后提供重新设置，没有文件时隐藏播放／复制；错误内容可选择复制，有界滚动。 |

中文 100% 的实测窗口尺寸：待录 **561×56**，录制与暂停均为 **405×56**，成功 **530×86**，选项展开 **561×416**。尺寸为逻辑像素，英文按内容增加宽度。普通按钮、单选和复选使用 Qt Quick Controls Basic 的语义、焦点与键盘行为；`RecordingButton` 负责现有主题样式，`RecordingOptions` 由 `Loader` 在展开时创建。

窗口尺寸变化后，`Recorder::keepPanelVisible` 按原生 Windows 工作区夹住窗口位置。选项过高时滚动，键盘焦点移到下方选项会自动滚入视口。工具提示使用独立 Qt Popup，只有准备／完成状态启用，切入录制时关闭。

宿主打包的 `windeployqt` 扫描范围由 `src/app/qml` 改为 `src`，纳入共享宿主 Qt 的插件导入，已在独立部署目录验证 `QtQuick.Layouts`。另补齐纯 C++ 的 `tst_foldermenu` 的 `QT_QML_MODULE_NO_IMPORT_SCAN`，与现有同类测试一致，解除该目标阻塞整个 CMake 重配的问题；未改动其业务测试。

## 原生界面验证

在 `--preview-recording --auto` 中验证：

- 100% 中文亮色、150% 英文深色的待录、选项、全部按键提醒、倒计时、录制、暂停、完成和再录。
- 实际点击声音、格式、画质、鼠标和按键选项，检查 `Recorder` 的值与偏好保留；重复点击已选单选项，保持选中；GIF 的音频按钮禁用。
- 对真实 `QQuickWindow` 投递键盘事件：空格展开、Esc 只收起选项且不取消本次录制、焦点返回齿轮。
- 将真实选项视口限制为 160 逻辑像素，聚焦末尾的目录按钮，检查滚动量大于零、整个按钮在视口内。通过窗口的高度上限参数驱动，保留 `Loader.height` 的声明式绑定。
- 窗口放在工作区右下边缘后展开，检查原生窗口矩形仍完整处于工作区内。
- 保存位置指向临时同名文件，实际触发目录校验错误；另用 8×8 区域触发工作进程的输入验证失败，检查错误、禁用操作和重新设置。失败用例有两条预期媒体警告，不作为 Qt/QML 错误。

系统 computer-use 没有枚举出置顶录屏工具窗，因此未据此声称完成物理键鼠端到端验证。上述键盘与鼠标检查来自程序自身真实窗口的事件分发及模型断言；画面来自 `QQuickWindow::grabWindow`，不是示意图。播放、打开文件夹及复制文件的外部动作沿用原有实现，本次检查新按钮及可用状态，未触发这些系统动作。

## 输出文件验证

MP4 实际录制开启系统声音，完成暂停／继续、保存及再录，前一段文件保持不变。使用重新构建的 Media Foundation `recording-probe inspect` 与独立的 PyAV / FFmpeg 解码器检查输出；最终完整解码两段 800×460、30 fps MP4，分别得到 94／22 视频帧及 150528／35840 音频采样。PyAV 仅安装在本次临时验证目录，不是产品依赖。

GIF 实际录制使用英文深色、150% 和点击高亮选项；Pillow 逐帧载入两段 1200×690 GIF，最终分别为 47 帧／3130 ms、11 帧／730 ms，循环标记均为 0。此项验证选项和导出管线，不等同于验证真实鼠标输入高亮。

最终日志、截图、输出及校验记录见 [本地验证目录](../build/recording-ui-validation-20261030/)。文件夹中的每个 JSON 对应具体媒体，不把录制界面显示“已保存”等同于文件已经解码成功。

## 调研与边界

[ShareX 官方变更记录](https://getsharex.com/changelog) 中的录前选项条可作为交互参考，视觉继续采用 Win顺 自身设计系统。[OBS 的 WGC 源码](https://github.com/obsproject/obs-studio/blob/master/libobs-winrt/winrt-capture.cpp) 用于对照采集生命周期。Win顺 当前已经使用 `CreateFreeThreaded`，所提供资料中的线程模型建议不能据此成为本次无首帧问题的既定根因。

本次本机验证不覆盖报告者 AMD 双 GPU／build 26300 环境，也未据此确认 #151 的具体驱动阻塞点；其诊断与验证范围继续见 [#149–#151 验证记录](issue149-151-validation.md)。
