# Win顺 0.30.0 发布验证

2026-11-15，在 Windows 11 x64、Qt 6.12.0、MSVC 2022 Release 环境完成构建和相关验证。构建源码为 `64ca6a6a`，构建目录 `build/release030`，交付文件在 `dist/release030`。此后的提交只更新海报、截图页和本记录。

本版接在 0.29.0（`e750b950`）后面：六个功能（#267、#160、#129、#175、#171、#191）、四个问题（#329、#330、#331、#332）和贡献者的 PR #333。各自的验证记录：[#267、#160](validation/issues-267-160-20261114/README.md)、[#129、#175](validation/issues-129-175-20261114/README.md)、[#171、#191 第一版](validation/issues-171-191-20261114/README.md)、[#191 截图翻译](validation/issue-191-translation-20261114/README.md)、[#329、#330](validation/issues-329-330-20261114/README.md)。

## 构建与相关回归

- 标准、离线安装器及主程序版本资源均为 `0.30.0`。
- 发布构建跑了 34 项相关 CTest，全部通过：`tst_capture`、`tst_capturekeys`、`tst_capturesettings`、`tst_captureui`（两种渲染方式各五种缩放和一项空闲检查）、`tst_ocr`、`tst_pinwindow`、`tst_translate`、`tst_bookmarks`、`tst_clipboard`、`tst_numberhints`、`tst_annotmodel`、`tst_keyrouter`、`tst_settings` 一组、`tst_aisettings`、`tst_plugin`、`tst_explorertabs`、`tst_scoopinstall`。[输出](validation/release030/ctest-related.txt)
- `tst_core` 没有放进发布构建的这一组（原因同 0.29.0：构建目录在 `.worktrees` 下面时有一项与本版无关的测试不过）；本版改到的 `typedWebAddresses`、`searchTyping`、`shortcutAgain` 在开发分支上单独跑过，通过。
- 打包脚本对随包程序和库的依赖检查通过。

## 全新电脑上的首次安装

Hyper-V 虚拟机，Windows 10 企业版 22H2（19045），还原到刚装完系统的检查点（`System32` 里没有 `msvcp140.dll`、`msvcp140_2.dll`，没有装过 Win顺）。用本版的标准安装包（SHA256 与下文一致）静默安装，退出码 0，装上的是 0.30.0，运行库随包带着，索引服务运行；在登录用户的桌面上启动后 25 秒仍在运行。

## 安装和升级实测

- **占用文件的实测**（`tools/verify-installer.ps1`，`release.ps1` 打包前自动运行）：5 项全部通过。[报告](validation/release030/installer-test.json)
- **应用内更新整条链路**（`tools/verify-installed-upgrade.ps1 -Mode InApp`，经用户同意在开发机上做）：本机 Program Files 里装着的正式版 0.29.0（为所有用户安装，带索引服务）从本机的假更新服务检查到 0.30.0，下载、校验、运行安装程序，48.5 秒后新版本在运行；索引服务仍在运行，开机自启任务不变，剪贴板历史文件的摘要升级前后相同。[报告](validation/release030/inapp-upgrade.json)

## 各项改动的实测

开发时的实测见上面几份记录，都是在 Windows 10 虚拟机里用真实鼠标键盘做的。发布构建没有再逐项重做一遍，只做了上面的安装、升级和下面的生产预览。

#331（资源管理器标签页连按两次 `Win+E` 不合并）没有复现：开发机（Windows 11 26200）上用插件自带的实机检查，19 项里前 18 项通过；最后一项“第二个文件夹并成标签页”在这次的环境里不过，原因是脚本打开第二个窗口时第一个测试窗口正在最前，被当成“从资源管理器主动要求新窗口”。同一项用上一版的插件也是时过时不过，和本版的改动无关，但也说明这一项这次没有得到验证。

#332 / PR #333（插件自己改设置）：宿主侧“哪些值可以改”有单元测试；真实插件在搜索框里改设置、设置页跟着变，没有实测（配套的 cursorwrap 新版本还没有发布）。

## 没有覆盖的

- #191：真实的 DeepL、微软翻译、大模型服务（虚拟机里用的是模拟的翻译服务）；照片和渐变底色；竖排文字；125% / 150% 缩放的真实屏幕；多显示器。
- #160：Chrome 本身（虚拟机里是 Edge）。
- #175：输入法正在组字时轻按修饰键。
- #171：按 `Enter` 后浏览器真的打开网址；本地有同名文件时网址排第二。
- #329：Windows 11 上的“此电脑”和“主文件夹”（实测的是 Windows 10 的“此电脑”）。
- #330：报告人实际用的 `` Alt+` ``；“再次按下快捷键时”选“展开为搜索面板”时的组合。
- #331：见上，未复现，修的是按日志推断的原因。
- #332：见上。
- 便携版自己更新、向导安装、“只为我安装”的升级：本版没有改这些路径，没有做。

## 生产界面与海报

发布构建的截图插件用 D3D11、200%、`QT_FONT_DPI=96` 做了“识别文字”窗口带译文的生产预览（`--preview-ocr --translation`），五种状态都出了图，窗口高度和按钮检查通过；预览有一条窗口重建句柄的警告，原有的预览也有，不影响画面。

本版新增海报一张，沿用品牌方形模板，1440×1440、JPEG 质量 96、关闭色度抽样：“截图里的字，直接翻译”，放进截图分组。README 仍只放封面。**没有海报的**：译文盖在贴图上的效果（贴图是原生窗口，没有能出图的预览）、剪贴板的“修改文字”、浏览历史（是本机自己的历史）、点一下遮住一行、字母直达、搜索框里打开网址。
