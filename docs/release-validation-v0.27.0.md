# Win顺 0.27.0 发布验证

2026-11-13，在 Windows 11 x64、Qt 6.12.0、MSVC 2022 Release 环境完成构建和相关验证。构建源码为 `0ce46eda`（版本号、发布说明与文档），构建目录 `build/release027`，交付文件在 `dist/release027`。此后的提交只更新海报、截图文档和验证证据，不涉及参与编译的文件。

本版把四条开发分支并入 main：内容搜索的正则和“任意一个词”（`issue-295`）、解压软件的路径窗口（`dialog-pathbox`）、#316 #314 #294 #267 #234 #185 #244 #319 一组（`issues-316-314-294`），以及此前已在 main 上的截图指定尺寸（#308）、记住以管理员身份运行（#313）；另有两项当时未提交的修改：zxing-cpp 3.1.1（#305）和插件库的“说明”（#304）。合并时 `SearchBar.qml` 有一处冲突（正则标记的显示条件），两边的改动都保留。

## 构建与相关回归

- 全新配置，编译主程序及官方可选插件。标准、离线安装器及主程序版本资源均为 `0.27.0`。
- 合并后先在版本号提升之前构建并跑了 15 项相关 CTest，全部通过；提升版本号后的发布构建再跑同样 15 项加 `tst_updater`、`tst_scoopinstall`，17 项全部通过：内容搜索与搜索核心（`tst_core`、`tst_contentdetails`）、命令行和 MCP（`tst_cli`、`tst_mcp`）、对话框（`tst_pathbox`、`tst_filedialog`、`tst_dialognav`）、收藏与命令（`tst_favorites`、`tst_commandlaunch`）、搜索框位置（`tst_placement`）、设置的 AI 读写与快捷键规则（`tst_aisettings`、`tst_pluginhotkeys`）、插件与插件库（`tst_plugin`）、截图（`tst_capture`、`tst_stage7`）。[CTest 输出](validation/release027/ctest-related.txt)

- 各项功能自己的实测记录在对应位置：#316 #314 #294 #267 #234 #185 #244 #319（`validation/issues-316-314-294-20261113`）、截图指定尺寸（`validation/capture-size-20261113`）、解压软件的路径窗口（`dialog-compatibility.md`，Bandizip 7.36 用真实程序）、二维码（`architecture.md` 里的 142 张真实图片统计；图片不在仓库里）。

## 安装和升级实测

- **占用文件的实测**（`tools/verify-installer.ps1`，`release.ps1` 打包前自动运行）：出包的那一次 5 项全部通过。[报告](validation/release027/installer-test.json)
  - 如实记录：发布脚本第一次运行时这一步**没过**，“文件被独占打开”一项安装程序用了 32 秒才放弃，超过脚本 30 秒的时限（上一版是 13.9 秒），当时没有出包。单独重跑 5 项全过，这一项 28.6 秒（[重跑报告](validation/release027/installer-test-rerun.json)）；出包那次是 25.1 秒。看安装日志，时间都在“准备安装”里查询进程、询问谁占着文件的那一段，其间没有输出。安装脚本自 0.26.0 起一个字没改，判断是本机当天进程多、系统查询变慢，**没有进一步证明**；结果（放弃、说明是谁占着、旧版本完好）三次都对。
- **应用内更新整条链路**（`tools/verify-installed-upgrade.ps1 -Mode InApp`，经用户同意在开发机上做）：本机 Program Files 里装着的正式版 0.26.0（为所有用户安装，带索引服务）从本机的假更新服务检查到 0.27.0，自己下载 `WinShun-0.27.0-x64-setup.exe`、校验、运行安装程序，64.9 秒后新版本启动。升级后：程序版本和卸载项均为 0.27.0，`WinShun.exe` 与交付包里的逐字节相同；新版本以普通权限运行；索引服务在运行，服务程序路径不变；开机自启任务仍在；设置文件还在，历史文件的摘要与升级前相同；程序文件夹里没有留下 `.wsold` 文件。[报告](validation/release027/upgrade-inapp.json)

## 生产界面与海报

部署目录的 `WinShun.exe` 和截图插件的 `WinShunCapture.exe` 用 D3D11、200% 和临时配置做了生产预览：

- 完整设置窗口（逐页逐标签，55 张，零 QML 警告）、命令表单（`--command-form`，通过）。
- 命令先搜文件、记住管理员运行等（`--search-experience`）：第一次运行全部通过；固定字体 DPI 后为拍图重跑的那次有一条“只输关键词时仍是命令本身”不通过，没有再跑第三次确认，按时序波动记录。
- 纯净搜索与范围标签（`--pure-search`）：200% 下“搜索框显示行数”的四条不通过（离屏的屏幕在 200% 下放不下 8 行），150% 下只有原有的计时警告。
- 截图尺寸面板（`--selection-size`）：前三次运行都有两条不通过（“按 Enter 得到 800 × 600，左上角不动”“按 Enter 得到 400 × 300”）。原因查明：这个检查用的是真实全屏窗口，没有选区时在真实鼠标的位置生成选区；当时鼠标停在屏幕靠下的地方，选区变大时被屏幕边界挡住而上移，这是设计行为。把鼠标放到主屏中央后 150% 和 200% 各跑一次，全部通过。

**预览图里图标偏大的问题**：这次拍图时发现预览模式画出来的图标比文字大一倍、互相压住，用 0.26.0 的程序跑同一个预览也一样，而 11 月 12 日同一个程序拍的图是正常的。原因：预览模式关掉了 Qt 的高分屏缩放，图标按“点”定大小，就跟着主显示器的字体 DPI 走；本机当天接着远程用的虚拟显示器，主显示器报的 DPI 比平时高。设 `QT_FONT_DPI=96` 后预览恢复正常，海报原图都是这样拍的（写进了 `tools/screenshots/release027.py` 的说明）。真实窗口开着高分屏缩放，不走这条路；但**没有在真实窗口里截图对比确认**。

本版新增海报三张，沿用品牌方形模板，1440×1440、JPEG 质量 96、关闭色度抽样（[原图摘要](validation/release027/poster-sources.json)）：

- “截图，指定大小”（尺寸面板：宽高输入框、锁、预设列表），放进“截图、录屏和贴图”分组。
- “自己的命令，先搜再开”（关键词后面的字搜到的文件），放进“收藏夹、网页搜索和插件”分组。
- “范围标签，合成一个”，放进“搜文件”分组。

README 仍只放封面。其余海报沿用旧图。**没有海报的**：内容搜索的正则（没有合适的预览数据）、解压软件的路径窗口（要拍别的程序的真实窗口）、插件库的“说明”和新卡片（预览里列的是示例插件，且带一条本机环境的提示）、在桌面上直接打字；以及上一版欠下的云备份、剪贴板备注、快捷筛选小片，仍然欠着。

## 插件库同步

逐一对比官方插件编译用到的源文件（`ninja -t inputs` 列出的输入，与各插件已发布版本所记源码提交到 HEAD 的改动求交集），两个插件有变化，在版本号提升到 0.27.0 之前从提交 `a8a16f49`（工作区没有改动参与编译的文件）构建发布：

| 插件 | 版本 | 最低主程序 | 变化 |
| --- | --- | --- | --- |
| 截图与录屏 | 1.1.13 | 0.18.0 | 指定选区尺寸、锁定比例、尺寸预设（#308）；zxing-cpp 3.1.1 和放大重读（#305）；权限不变 |
| 图片文字搜索 | 1.0.13 | 0.26.0 | 跟进共用代码（搜索核心、界面部件） |

公开 `index.json` 中两个条目的版本、SHA256 与本地包一致，签名验证通过（`ws-index-2026a`），共 34 个插件。其余官方插件（浏览器书签、休息提醒、云备份、资源管理器标签页、局域网传输、语义搜索、翻译）的编译输入没有变化，网页搜索的包也没有变化，不重新发布。

插件库本身的改动（#304 需要）：`index.json` 的每个条目多了 `readme`、`readmeSha256` 两个字段，每个包里的 README 作为 `readme-<id>-<版本>.md` 放在 `index` 这个 Release 上。34 个插件都有；抽查两个，下载到的文件与索引里的摘要一致。旧版 Win顺 忽略这两个字段。**没有在 0.27.0 的真实设置窗口里对着线上索引点一次“说明”**，依据的是 `tst_plugin` 和开发时的检查。

## 没有覆盖的

- 真实升级只做了 `-Mode InApp`（为所有用户安装的那份，没有加 `-Hold`）。没有做：`-Mode Setup`、`-Mode Wizard`、`-Mode Portable`、“只为我安装”的升级。本版没有改安装脚本和更新程序。
- 本次发布流程里没有对新功能再做实机键鼠测试，依据的是各功能开发时的实测记录、合并后的测试和上面的生产预览检查。各功能自己没覆盖的仍然没覆盖：
  - 7-Zip 和 WinRAR 的解压窗口只用替身窗口验证（本机没有装）。
  - 范围标签合成的按钮没有用真实鼠标点过；“加备注”在钉住时打字、录制 `Shift+Space` 没有实机走一遍。
  - 命令先搜文件：没有真的从搜到的那一行启动过命令。
  - 资源管理器里打字的黑块没有逐帧抓图确认，也没有在 Windows 10 上跑。
  - 截图指定尺寸：多显示器、不同缩放混用只有几何单元测试；没有用安装版按真实快捷键截图。
  - 内容搜索的正则不覆盖“图片文字搜索”“按意思搜索”两个插件的结果。
- 三条开发分支合并后的组合（比如正则模式的标记和合成的范围按钮同时出现）只有编译、测试和预览检查，没有专门的实机检查。
- 用户反馈的“对话框下面的搜索框打字有点慢”本机没有复现，本版只加了测量手段，没有改动。
