# Win顺 截图：阶段 4 及以后的路线

2026-10-20。依据：同目录下 6 份参考报告（snow-shot、snow-draw-engine、sharex、flameshot、ksnip、quickshot）、`docs/design-capture.md`、`src/capture/` 和 `CaptureOverlay.qml`、`OcrPanel.qml` 的现状。本文只是设计，没有改仓库。

2026-10-26 更正：#83 获用户确认，新增短时区域录屏（MP4、30 fps、暂停、可选声音）；原先“不做录屏”的取舍已调整。此文的旧对照表不代表当前录屏范围，实现见 architecture.md。

- 许可：ShareX、Flameshot、ksnip、QuickShot 和 snow_shot 的 GPL 部分只学思路；kImageAnnotator（LGPL）不用；snow_draw_engine_qt（Apache-2.0）不整体引入。实现时照本文和报告写，不打开 GPL 源码对着抄。
- 不写工期，只排先后、说收益。
- 单位：“图像 px”= 冻结截图里的一个像素，也就是屏幕的物理像素；“逻辑 px”= Qt 的逻辑单位（图像 px × `CaptureScreen::scaleX`）。

## 0. 一页看完

| 阶段 | 做什么 | 一句话理由 |
|---|---|---|
| 4a | 遮罩里直接标注：9 种工具、撤销重做、按工具记样式；复制时把可再编辑的项目存在历史条目旁边 | 用户第一需求；遮罩已有选区和 1:1 像素 |
| 4b | 一个复用的编辑窗口：历史截图再编辑（jt、剪贴板窗口）、贴图再编辑、裁剪、缩放 | 4a 的模型换个外壳；阶段 6、8 都要用它 |
| 5 | 打码加强：智能打码（OCR 文字框 + 规则）、涂抹打码、抹平 | 复用 4a 的打码对象和现成的 OCR |
| 6 | 长截图：自动滚动（带退路）+ 手动滚动 + 拼接 + 诊断 | 最难的一块，结果直接进 4b 的编辑窗口 |
| 7 | 贴图增强（旋转、收起、贴图上选字等）+ 小功能（上次选区、延时、带鼠标指针、取色格式、二维码） | 抱怨多、成本低 |
| 8 | 多选区：合成一张，吸附对齐 | 要 4b 的排版画布 |
| 9 | 美化导出（背景、圆角、阴影，默认关） | 纯输出样式，日常收益最低 |

贯穿全篇的三条硬规则：

1. 屏幕和导出用同一段 CPU 合成代码（QPainter 画进瓦片），所以导出和屏幕逐像素相同（§3.3、§3.11）。
2. 标注的坐标、线宽、字号都按图像 px 存；屏幕上 1 图像 px = 1 设备像素（§3.4）。
3. 打码只从区域外面取像素，区域里的原像素从不参与计算，所以不可还原（§3.10）。

和用户给的顺序比，前三步（标注 → 智能打码 → 长截图）不变，改了三处：

- **标注拆成 4a 和 4b。** 4a 先把“截图时标注”做扎实，并且从第一天就存项目，4a 期间标过的图到 4b 都能再打开改。4b 是第二个宿主（普通窗口），风险点不同（缩放、大图、窗口复用的内存），分开验收。
- **打码阶段带上涂抹打码和抹平。** 它们和智能打码共用一个填充算法和同一种“打码对象”，一起做最省。
- **后三项排成 贴图 → 多选区 → 美化。** 贴图在每个参考项目的 issue 里都是高频抱怨（旋转、收起、选字、管理），贴图编辑在 4b 已经做好，剩下的都是小改动。多选区要 4b 的排版画布和一套吸附规则，我们的用户还没提过。美化面向分享，对效率工具的日常用法收益最低，默认还要关着。

## 1. 取舍总表

说明：

- **难度**：低 = 在现有结构上加一点；中 = 新组件，但路子清楚；高 = 新组件，而且有不确定点（要探针或反复调）。
- **档位**：“下一阶段·4a/4b”= 阶段 4；“之后·N”= 排进阶段 N；“之后·看反馈”= 不排期，等用户要；“不做”= 有理由不做。
- **做法**：只有两种，照思路自己写、借 Apache 代码。许可上能借 Apache 代码的几处（压力笔宽、AVX2 滤镜内核、箭头几何、折线简化、二维码库）表里逐条写明借不借；真要借的只有二维码库。“—”= 不做，不用选做法。
- 报告里提到、我们已经有的，不列：放大镜取色（C）和放大镜里的十字、方向键微调选区、尺寸显示、整屏、点选窗口和子控件（Win32 子窗口）、滚轮把选区扩到整个窗口、悬停时不压暗只描轮廓、WGC 常驻、每屏遮罩 1:1、显示器变化时重建遮罩、贴图的拖动 / 滚轮缩放（总从原图重采样）/ 透明度 / 置顶 / 穿透（托盘能取消所有穿透）、关闭全部贴图、贴上最近一次截图、截图历史和 `jt`。

## 2. 阶段划分

### 2.0 每个阶段都要过的验收

- **真实输入**：用提权的 SendInput 测试脚本，每次按键前确认前台是遮罩或目标窗口；不发 Ctrl+1/2/3（PixPin 的全局热键）。
- **读数**：屏幕像素用 BitBlt 或 WGC 抓整屏后按区域比；导出读剪贴板里的图；对象状态读项目文件里的 `doc.json`（直接读状态，不靠猜）；文字用 OCR 读导出的图。
- **缩放矩阵**：单屏在 100%、125%、150%、175% 下各跑一遍（改系统缩放）。混合 DPI 要第二块屏或虚拟显示器；没有就列为“待外部测试”，不算通过。
- **速度不退步**：只截图不标注时，热键到遮罩可见仍是现在的 40–48 ms（architecture.md 截图一节的实测），Enter 到剪贴板有图不比现在慢。
- **内存**：连续 20 次“截图 + 标注 + 复制”，空闲 1 分钟后，私有字节和 commit 回到第 1 次之后的水平，多出的不超过 30 MB。
- **动画**：新出现的面板、提示，动画不长于 200 ms（Windows 开始菜单约 200 ms）；关闭立刻开始。
- **样式**：边框 1 逻辑 px 中性灰（Theme.windowEdge）；彩色底上的字和记号用白色（浅色底上用深色）。
- **文档**：每个阶段收尾时更新 `docs/design-capture.md`、`docs/architecture.md` 的截图一节、`docs/pitfalls.md`（新坑）和使用说明。

### 2.1 阶段 4a：遮罩里标注 + 存项目

**做什么**

- 选好区域后，工具条多出 9 个工具：矩形、椭圆、箭头、直线、画笔、荧光笔、文字、序号、打码（马赛克 / 模糊 / 纯色）；撤销、重做；第二行是样式面板。
- 对象能选中、移动、改样式、删除、调层；手柄改形状。
- 按工具记样式（写进 ini）。
- 文字能用输入法，拼音过程看得见。
- 序号自动重排，起始值可改，单个号可改，可另起一组。
- 打码不可还原。
- Esc 阶梯、热键退出时留草稿（决定 3）。
- 复制时：剪贴板和历史里是合成图；有标注的截图另存一份项目（`projects/<id>.wsedit`），给 4b 再编辑用。
- 保存（Ctrl+S）、贴图（F3）、识别文字都用合成图。

**为什么在这**：用户第一需求。遮罩已经有选区、1:1 像素和输入状态机，标注叠在冻结画面上最快、不多开窗口（每个 D3D 窗口约 +37 MB commit，见 design-capture §6 阶段 0）。项目从 4a 就存，4a 期间标过的图到 4b 都能打开改。

**验收**（150% 为主，其余缩放各一遍）

1. **所见即所得**：矩形、椭圆、箭头、直线、画笔、荧光笔、文字、序号、马赛克各画一个，取消选中。抓屏取选区，去掉选区边框线和 8 个手柄实际占的矩形（位置从 QML 读出来），其余部分和 Enter 后剪贴板里的图比：0 个像素不同。
2. **清晰**：宽 2 逻辑 px 的矩形，四条边沿垂直方向数颜色游程：正好 3 px 纯色，两侧没有半透明像素；宽 4（6 px）同理；水平、竖直的直线和箭头杆同理。
3. **输入法**（微软拼音，中文模式）：
   - 按 T，点一下，打 nihao：框里看得到带下划线的拼音（抓屏，框内有非底色像素）。
   - 候选窗贴着光标：候选窗矩形和光标矩形相距不超过 60 逻辑 px。
   - 选“你好”，再打 shijie 选“世界”，按 Esc：OCR 读导出的图得到“你好世界”。
   - 输入法开着中文时按 R：直接选中矩形工具，不出现拼音串。
4. **撤销**：随机做 10 步（加、移、改色、改字、删）。Ctrl+Z ×10 → 选区和冻结图 0 差；Ctrl+Y ×10 → 和撤销前 0 差。
5. **序号**（读 `doc.json`，再用 OCR 抽查）：
   - 放 1、2、3，删掉 2 → 剩下显示 1、2；Ctrl+Z → 1、2、3。
   - 起始值改成 5 → 5、6、7。
   - 双击第二个改成 10 → 5、10、11。
   - “另起一组”后再放一个 → 1。
6. **打码不可还原**：记事本里写 SECRET-4821，用马赛克、模糊、纯色各盖一次，复制。OCR 读不出 SECRET，也读不出 4821。（单测另有“改区域内的底图，导出逐位不变”，§3.14。）
7. **Esc 和热键**：
   - 拼音输入中按 Esc：只取消拼音串，文字框还在。
   - 编辑文字时按 Esc：文字保留，结束编辑。
   - 画到一半按 Esc：只取消这一笔。
   - 有标注时按 Esc：选区和标注一起放下，边上出现“已放弃这次的标注 · Ctrl+Z 恢复”；按 Ctrl+Z 后和之前 0 差；再按 Esc 退出。
   - 有标注时按截图热键：立刻关闭；托盘出现“找回刚放弃的标注”，点它贴回原处，和关闭前的合成图 0 差。
8. **记样式**：箭头改成蓝色、宽 7，矩形不动。下一次截图：箭头默认蓝 / 7，矩形仍是红 / 4；ini 的 `[Capture] AnnotateStyles` 里读得到。只选中一个旧对象，不改默认。
9. **让位**：选区几乎占满屏幕（工具条在选区里面），从工具条底下拖一个矩形。拖动中抓屏：工具条那块显示的是冻结画面；松开后工具条回来。H 能隐藏和显示工具条。
10. **流畅**：2560×1600、150%，50 个对象加 5 个马赛克。用 SendInput 拖一个大矩形、画一笔长画笔，按 `frameSwapped` 的时间戳算帧间隔：p95 ≤ 16.7 ms（60 Hz 屏）。
11. **项目文件**：
    - 标过的图复制后，`projects/<id>.wsedit` 存在，`doc.json` 里的对象数对。
    - 在剪贴板窗口删掉这一条，过了撤销期 → 文件没了。
    - 超过条数上限被修剪 → 文件没了。
    - 手动放一个 `99999.wsedit` → 下次启动被清掉。
    - 没标注的截图 → 没有项目文件。
    - 同样的像素再复制一次 → 条目移到最前，不新增。
12. **原有出口**：Ctrl+S 存的是合成后的普通 PNG；F3 贴的是合成图；“识别文字”识别的是合成图。

### 2.2 阶段 4b：编辑窗口

**做什么**

- 一个普通的 Qt Quick 窗口，第一次用时建，之后隐藏复用。窗口里装的是和 4a 同一套模型、画布、工具条和面板。
- 加上缩放（Ctrl+滚轮、Ctrl+加号 / 减号、Z 在“适合窗口 / 100%”之间切换）、空格拖动、裁剪（拖画布边框，进撤销）、多选、Ctrl+D、吸管（I）、恢复默认样式。
- 入口：
  - `jt` 结果行的第三个动作“编辑”（Shift+Enter）；
  - 剪贴板窗口里图片条目的右键“编辑”（任何图片都行，没有项目就以这张图为底图、空文档）；
  - 贴图右键菜单“编辑”。
- 出口：Enter 复制（新条目带新项目，原条目不动）；Ctrl+S 保存；F3 贴图；从贴图进来时 Enter 是“完成”，直接换掉贴图里的图。

**为什么在这**：模型和合成器在 4a 定型以后，第二个宿主只是换个外壳。它是历史再编辑、贴图编辑、长截图结果（阶段 6）、多选区排版（阶段 8）的共同前提，所以紧跟 4a。

**验收**

1. **再编辑 0 差**：jt 里选一张标过的截图，按 Shift+Enter → 编辑窗口打开，100% 下画布和该条目的 PNG 0 差。不改直接按 Enter → 剪贴板窗口里没有新条目，原条目移到最前，PNG 文件字节不变。
2. **改一处**：把一个箭头改成蓝色，按 Enter → 新条目在最前，原条目还在；新条目的项目能再打开，打开后箭头是蓝的。
3. **没有项目的图**（别处复制来的图片）也能编辑：底图 = 这张图，空文档。
4. **贴图编辑**：
   - 贴图菜单选“编辑” → 有空间时画布正好落在贴图原位（抓屏 0 差）。
   - 改完按 Enter（完成）→ 贴图换成新图，位置和缩放不变。
   - 再点“编辑”能接着改。
5. **裁剪**：
   - 拖画布边框裁掉一圈，按 Enter：导出尺寸 = 裁剪框。
   - Ctrl+Z 能撤回裁剪。
   - 重开项目后，还能把裁掉的部分放回来。
6. **大图**：打开 1080×30000 的图。滚动、缩放时帧间隔 p95 ≤ 16.7 ms；只为看得见的区域建瓦片（瓦片数不超过可见区域的瓦片数加一圈）；100% 时和原图 0 差。
7. **窗口复用**：编辑窗口开关 20 次，第 20 次后的 commit 不比第 1 次后多 5 MB 以上；关闭 1 分钟后，私有字节回到打开前，多出的不超过 30 MB。
8. **换屏**：编辑窗口从 150% 的屏拖到 100% 的屏，100% 缩放下仍然 0 差（单屏机器上用改系统缩放代替）。
9. **Esc**：有改动时按 Esc → 撤回全部改动，提示“已放弃修改 · Ctrl+Z 恢复”；再按 Esc 关闭。

### 2.3 阶段 5：打码加强

**做什么**

- 智能打码：OCR 文字框 + 规则（§4.1）。
- 选好区域后后台预扫，工具条边上提示“发现 N 处”，点一下全部打上（决定 5）。
- 涂抹打码（按笔迹打码）。
- 打码的第四种样式“抹平”。
- `PaddleOcr` 加上每个字的位置（readPieces）。

**为什么在这**：用户排第二。它要的东西都在 4a 有了：打码对象、合成器、一次加 N 个对象的批量命令。再加上现成的 PP-OCRv6，只需要给 OCR 补字的位置。涂抹打码和抹平和它共用一个填充算法。

**验收**

1. **测试页**：本地 HTML 页里放这些内容：
   - 手机号（带空格的、带 +86 的）；
   - 真、假身份证各一（假的校验位错）；
   - 真、假银行卡各一（Luhn 校验）；
   - 邮箱；
   - sk-、ghp_、AKIA 开头的密钥，和 `password=...`；
   - 含本机用户名的路径、电脑名；
   - 占位符（`$TOKEN`、`****`、`<your-key>`）。

   框选整页 → 工具条边上出现“发现 N 处”，N 等于真阳性数 → 点它 → 一次加上 N 个打码。OCR 读导出的图：真阳性一个都读不出；假身份证、假卡号、占位符都还读得出。Ctrl+Z 一次全部撤掉。
2. **框的准度**（单测）：QPainter 画“电话 13812345678 转 8”（微软雅黑和 Consolas，12–24 px，100% 和 150%）。打码框盖住这串数字，误差 ≤ 2 px，不盖“电话”。
3. **涂抹打码**：沿一行斜着的字涂一笔 → OCR 读不出；改区域内的底图，导出逐位不变。
4. **抹平**：白底黑字涂掉后，区域内每个像素和周围底色的差 ≤ 3。
5. **速度和内存**：2560×1600 的选区，从点“打码”到画面更新 ≤ OCR 耗时 + 50 ms。模型只加载一份，60 秒不用就释放，私有字节回落。
6. **历史里搜不到被打码的字**：历史条目的 OCR 文字来自合成图，`jt` 搜被打码的手机号搜不到。

### 2.4 阶段 6：长截图

**做什么**（§4.2）

- Ctrl+L 或工具条按钮进入长截图。
- 自动滚动按阶梯试：投递滚轮消息 → SendInput 滚轮 → UIA → 请用户手滚。
- 连续取帧，拼接，显示进度。
- 诊断：复制诊断信息，也写进诊断包。
- 完成后结果进 4b 的编辑窗口。

**为什么在这**：用户排第三。它最难、最不确定（每个程序的滚动行为都不一样），要独立的取帧器、拼接器和诊断；结果要能标、能裁，正好用 4b 的编辑窗口，所以排在 4b 和 5 后面。

**开工前的探针**（都不进主程序）

- `WDA_EXCLUDEFROMCAPTURE` 对 UpdateLayeredWindow 的分层窗口、对 Qt Quick 窗口，在 WGC 整屏捕获里是否生效。
- 投递 WM_MOUSEWHEEL 在 Edge / Chrome、VS Code、记事本、资源管理器、设置（WinUI）里是否会滚。
- 自由线程帧池在页面滚动时的实际帧率。

**验收**

1. **离线回放**（单测）：合成一张长页面（吸顶栏、吸底栏、固定的“回到顶部”按钮、渐显的图片、斑马纹的重复行、往回滚、到底反弹），切成视口帧喂给拼接器。结果和原页面逐像素差 ≤ 1（浮动按钮除外），每一步的位移都准。
2. **本地 HTML 测试页**（300 行“第 001 行”……，带吸顶栏和浮动按钮）：自动滚动截完，OCR 读结果：001–300 每个号恰好出现一次、按顺序；吸顶栏只在最上面出现一次。
3. **真实程序矩阵**（自动、手动各一遍）：Edge、Chrome、VS Code 编辑器、资源管理器详细信息视图、记事本、Word、设置（WinUI）、微信聊天窗（装了的话）、一个以管理员身份运行的窗口。每个记下：用了哪种滚动办法、成没成、多高。管理员窗口要提示“这个程序以管理员身份运行，请手动滚动”，诊断里有“拒绝访问”的记录。
4. **自己的东西不进图**：结果里找不到边框和面板的颜色。
5. **内存**：截 3 万像素高后结束，1 分钟内 commit 回到开始前，多出的不超过 30 MB。
6. **诊断**：“复制诊断信息”的文字里有每一步的滚动办法、位移、分数、状态；导出的诊断包里也有。
7. **结果进编辑窗口**：完成后自动打开编辑窗口；Enter 复制、Ctrl+S 保存、F3 贴图都能用，能裁剪。

## 3. 标注的详细设计（可以直接交给实现子代理）

### 3.1 在哪里标

候选有三个：冻结遮罩、贴图、单独的编辑窗口。

**结论**：4a 只在遮罩里标；4b 加一个编辑窗口，同时负责“历史再编辑”和“贴图编辑”；贴图本身不加标注界面。

理由：

1. **遮罩**：选区、1:1 像素、输入状态机都是现成的，不多开窗口；Snipaste、PixPin、Flameshot、Snow Shot 都在这里标，用户习惯如此。
2. **遮罩的局限**：只能标一块屏以内的图；不能重开历史；贴图不是 Qt Quick。
3. **贴图上直接标**：贴图是原生分层窗口（UpdateLayeredWindow），没有 Qt Quick，也就没有 TextEdit 和输入法。在那里再做一套绘制和输入，等于第二套实现。所以“贴图编辑”= 编辑窗口在贴图原位打开，画布正好盖住贴图，看起来就是贴图变得能编辑；完成后把新图交回贴图。
4. **编辑窗口**：普通窗口，能 Alt+Tab 切走，能缩放，长图也装得下。

考虑过但没选的：用遮罩做再编辑（在当前屏上全屏显示一张图，当成选区）。长图装不下，而且全屏置顶会挡住别的工作。

三处共用同一套部件：

- `AnnotationModel`：文档 + 命令栈 + 工具和选中状态；
- `AnnotationCanvas`：画布；
- `AnnotateLayer.qml`：选中框、手柄、文字编辑框、提示；
- `AnnotateToolbar.qml`、`AnnotateStylePanel.qml`：工具条和样式面板。

**坐标**

- 遮罩里，对象坐标是那块屏冻结图的图像 px，不是相对选区的。选区只是裁剪框（`doc.crop` 跟着选区走）。所以挪选区、改选区大小时，对象还待在它标的内容上。
- 复制时转成项目：
  - 底图 = 选区里的像素；
  - 对象平移“负的选区左上”；
  - 完全落在选区外的对象丢掉。
- 编辑窗口里，对象坐标是项目底图的图像 px。裁剪只改 `doc.crop`，底图不删，所以裁掉的还能放回来。

### 3.2 数据模型（C++）

```cpp
// src/capture/Annotation.h（wscapture 静态库：只依赖 QtGui，单测直接链接）
namespace ws::capture::annot {

enum class Kind : quint8 { Rect, Ellipse, Arrow, Line, Pen, Marker, Text, Number, Redact };
enum class Fill : quint8 { None, Soft, Solid };                 // 柔和 = 同色、20% 不透明
enum class RedactMode : quint8 { Mosaic, Blur, Solid, Smooth }; // Smooth（抹平）在阶段 5
enum class RedactShape : quint8 { Box, Brush };                 // Brush（涂抹）在阶段 5

struct Style {
    QRgb color = qRgb(0xE5, 0x39, 0x35);
    int width = 6;          // 线宽，图像 px
    Fill fill = Fill::None;
    int fontPx = 27;        // 文字、序号的字号，图像 px
    bool bold = false;
    bool boxed = false;     // 文字底框：彩色块 + 白字
    RedactMode redact = RedactMode::Mosaic;
    RedactShape shape = RedactShape::Box;
    int cell = 18;          // 马赛克格子，图像 px
    bool operator==(const Style&) const = default;
};

struct Item {
    quint32 id = 0;              // 文档内唯一，只增不复用
    Kind kind = Kind::Rect;
    quint32 seq = 0;             // 创建顺序；序号按它编
    QList<QPointF> points;       // 图像 px，取整规则见 §3.4
    Style style;
    QString text;                // Text
    quint32 series = 0;          // Number：属于哪一组
    std::optional<int> pinned;   // Number：手动定的号，后面的接着数
    quint64 seed = 0;            // Redact：噪声种子，建对象时取随机数，存进项目
    bool operator==(const Item&) const = default;
};

struct Series {
    quint32 id = 1;
    int start = 1;
    bool operator==(const Series&) const = default;
};

struct Document {
    static constexpr int kVersion = 1;
    QSize canvas;                    // 底图大小，图像 px
    QRect crop;                      // 导出范围；遮罩里 = 选区
    qreal dpr = 1.0;                 // 截图那块屏的缩放：面板显示的逻辑值、新对象的样式都按它换算
    QList<Item> items;               // 从下到上；Redact 永远在最前面一段
    QList<Series> series{Series{}};  // 至少一组
    quint32 currentSeries = 1;
    quint32 nextId = 1;
    quint32 nextSeq = 1;
    bool operator==(const Document&) const = default;
};

// 纯函数：不碰 Qt Quick，单测直接测
QRectF bounds(const Item&);   // 含线宽、箭头头部、文字框；导出、脏区、命中都用它
std::optional<quint32> hitTest(const Document&, QPointF p, qreal tolerance); // 从上往下找
QList<QPointF> handles(const Item&);
Item reshaped(const Item&, int handle, QPointF to, bool constrain);         // Shift 的约束在这里
QHash<quint32, int> numbers(const Document&);   // 序号推导，§3.9
int redactionEnd(const Document&);              // 打码段结束的下标
}
```

各类对象的 `points`：

| 对象 | points |
|---|---|
| 矩形、椭圆、打码框 | 两个点：左上角和右下角的像素边界（整数；右下不含） |
| 箭头、直线 | 起点、终点（像素中心，整数 + 0.5） |
| 画笔、自由荧光笔 | 稳定后的折线；起终点为像素中心，中间锚点保留亚像素 |
| 涂抹打码 | 折线（像素中心） |
| 文字 | 一个点：文字框左上（整数） |
| 序号 | 一个点：圆心（像素中心） |

规则：

- **图层**：打码类永远排在 `items` 最前面一段（最下层），其余按创建先后；调层只在各自那一段里调。打码是“改底图”，后加的打码不该盖住已有的箭头和文字（Snow Shot #2041 的教训）。
- **id 和 seq**：`id` 只增不复用；`seq` 是创建顺序，序号按它编，复制出来的对象拿新的 seq。
- **没有公开的 setter**：改文档只能通过命令（§3.7），撤销就不会漏。
- **命中**：线类按“到折线的距离 ≤ 半线宽 + 4 逻辑 px”；有填充的框按“在里面”；没填充的框按“靠近边”；文字、序号按框；打码按区域。从最上面的对象往下找，打码段最后找。
- **箭头**：头长 = max(4 × 线宽, 12 逻辑 px)，头宽 = 头长 × 0.9，实心三角；杆在头根结束，不穿出尖。
- **画笔**：松开后用 RDP 简化（容差 0.75 px），过中点画二次曲线做平滑。

### 3.3 绘制方式

| 方案 | 怎么画 | 好处 | 问题 | 结论 |
|---|---|---|---|---|
| Qt Quick Shapes（Shape + ShapePath） | 每个对象一个 Shape，GPU 三角化或曲线渲染 | 声明式、矢量、GPU | 抗锯齿靠 MSAA 或曲线渲染，和导出用的 QPainter 光栅化不是一套，屏幕和导出会差几个像素；做不了正片叠底（荧光笔）；马赛克要另做纹理；对象多了节点多 | 不用 |
| Canvas（QML 的 2D 画布） | JS 命令画进一张纹理 | 写起来快 | 整屏一张大纹理，每次全画；JS 慢；DPR 处理有坑；导出要再 grab 一次 | 不用 |
| QQuickPaintedItem | paint(QPainter*) 画进纹理 | 和导出同一套 QPainter | paint 在渲染线程；纹理大小按 DPR 隐式缩放，取整方式和遮罩的 bufferScale 不保证一致，1:1 没法保证；每次整块重画；超过 16384 的长图画不了 | 不用 |
| **自定义 QQuickItem + 瓦片** | CPU 用 QPainter 把“底图 + 对象”画进 256×256 的瓦片，每块一个 QSGImageNode | 和导出是同一段代码，0 差；只重画脏瓦片；没有纹理上限；正片叠底、马赛克在 CPU 上随便做；遮罩现有的 CaptureImage 已经证明这条路 0 差 | 拖大对象时 CPU 要重画多块瓦片；瓦片和纹理要自己管 | **选它** |

做法：

1. **瓦片的内容**：底图那一块 + 所有和它相交的对象，用 QPainter 画进一张不透明的 32 位 QImage（和冻结图同格式，省一次转换）。
2. **节点**：每块一个 QSGImageNode：`Nearest` 过滤、不要 mipmap、纹理带 `TextureIsOpaque`（GPU 不做混合）；节点矩形 = 瓦片的图像 px 矩形 × scale。遮罩里 scale 就是 `CaptureScreen::scaleX/scaleY`，和 CaptureImage 同一套映射，已验证 0 差。照抄 `CaptureImage.cpp` 建节点的写法。
3. **遮罩里只画有对象的瓦片**：别处露出下面的 CaptureImage。瓦片里的底图和 CaptureImage 是同一张图的同样像素，接缝看不出来。
4. **编辑窗口里按视口画**：没有 CaptureImage，底图整张由瓦片组成；只给可见区域加一圈建瓦片，滚出去的丢掉。3 万像素高的长图也碰不到 16384 的纹理上限。
5. **线程**：
   - 命令产生脏矩形 → 标记脏瓦片 → `polish()`；
   - `updatePolish()`（GUI 线程）里用 QPainter 重画脏瓦片；
   - `updatePaintNode()`（渲染线程）只为换过的瓦片建新纹理（`createTextureFromImage`，节点 `setOwnsTexture(true)` 释放旧的）。
   - 渲染线程上不跑 QPainter。
6. **绘制顺序**：先底图，再按 `items` 的顺序画。打码段在最前，所以打码盖不住箭头和文字。荧光笔用 `CompositionMode_Multiply`，一笔是一条路径（自己不叠深）。
7. **缓存**：总预算约 32 MB，按最近使用淘汰；只在截图或编辑进行中存在，结束时全部释放（§2.0 的空闲内存验收管着）。只缓存两样贵的：
   - 打码块：每个打码对象一张图，键 = 对象 + 底图版本 + 采样范围 + 打码并集的形状；
   - 文字排版：QTextLayout，键 = 文字 + 字体 + 字号。

   矩形、箭头、画笔这些便宜的，每块瓦片带裁剪直接重画。
8. **拖动的开销**：拖一个大矩形时，脏区 = 旧包围盒 ∪ 新包围盒，最多二十来块瓦片，每块 = 拷底图 + 画相交的对象。验收看帧间隔的 p95（§2.1 第 10 条）。
9. **关键单测**：“逐块画再拼起来 == 一次画整张”，0 差（§3.14）。它保证屏幕 = 导出。
10. **这条单测过不了时的退路**（QPainter 某些路径在不同裁剪下光栅化不一致）：
    - 出问题的对象类型，先整个画进一张自己包围盒大小的图（对象层），瓦片只贴这张图；
    - 正在拖的那个对象单独做一个节点，松开后再并回瓦片。
11. **界面装饰不进瓦片**：选中框、手柄、悬停描边、文字编辑框都是 QML 项，画在画布上面，所以导出里不会有。

遮罩里从下到上：CaptureImage → AnnotationCanvas → 选区外的压暗 → 选区边框和手柄 → 对象的选中框和手柄 → 文字编辑框 → 工具条和面板 → 放大镜。

### 3.4 150% 下也清晰的规则

1. **1 图像 px = 1 设备像素**：遮罩永远是 100%；编辑窗口在 100% 时也是。
   - 编辑窗口画布的原点按设备像素取整：逻辑坐标 = round(x × 缓冲比例) / 缓冲比例。缓冲比例 = 窗口真实的设备像素宽 / 逻辑宽，和遮罩的 bufferScale 是一个思路。
   - 窗口换屏（DPR 变了）时，重算画布的逻辑大小。
2. **点的取整**：鼠标给的是物理整数像素（CaptureSession 已经换算）。
   - 箭头、直线、荧光直线、涂抹存像素中心（整数 + 0.5）。画笔／自由荧光笔的起终点也如此；中间防抖锚点保留亚像素，避免每次输入都取整造成阶梯。2026-11-01 修正了此前“所有线类点都取整”的约定。
   - 框类（矩形、椭圆、打码框）存像素边界：按在像素 a、拖到像素 b → 框 = [min(a, b), max(a, b) + 1)，都是整数。
3. **线宽**：`w = max(1, lround(逻辑宽 × dpr))`，按图像 px 存。150% 下 2 / 4 / 7 逻辑 px → 3 / 6 / 11 px。
4. **框类用内描边**：描边整个落在框里，外沿正好是拖出来的边。中心线在 `a + w/2`：w 是奇数时落在像素中心，是偶数时落在整像素，两种都不糊。
5. **水平和竖直的线**（包括 Shift 约束出来的）：w 是奇数，中心线放在像素中心；w 是偶数，中心线挪到整像素。斜线、曲线、椭圆照常抗锯齿。
6. **文字**：字号取整数图像 px（`QFont::setPixelSize`）；用 `QFont::NoSubpixelAntialias`，图里不要 ClearType 的彩边，贴到哪里都一样；文字框左上取整数。
7. **编辑窗口不在 100% 时只是预览**：放大用 Nearest，缩小用 Linear；导出永远按 1:1 合成。
8. **文档记下截图时的 DPR**：面板显示的“宽 4”= `w / dpr` 取整。在别的屏上重开，新画的对象仍按原来的 DPR 换算，和原有对象一致。
9. **验收**：用游程计数（§2.1 第 2 条）。

### 3.6 鼠标和键盘怎么分

**Selected 阶段按下左键**：按顺序问，谁先认领就归谁。

1. 正在编辑文字，按在文字框外 → 提交文字，这一下不做别的。
2. 有选中的对象，按在它的手柄上 → 改形状。
3. 按在选区边框的 8 个手柄上 → 调整选区（现有逻辑）。
4. 有工具时：
   1. 按在选中对象身上 → 挪它（刚画完的对象不用换工具就能调）；
   2. 文字工具按在已有文字上 → 编辑它，光标放在按的位置；
   3. 序号工具按在已有序号上 → 选中它，拖动就挪；
   4. 其余：按在选区里面 → 开始画新对象（拖动中的点夹在选区里）；按在选区外面 → 不做事。
5. 没有工具时：
   1. 按在对象上 → 选中它，拖动就挪；
   2. 选区里的空白处 → 照旧挪选区，对象留在原来的内容上，不跟着走（编辑窗口里没有选区可挪，4b 起这里是框选）；
   3. 选区外 → 没有标注时照旧（拖动画新选区，点击保留原选区）；有标注时不画新选区，边上提示“已有标注：拖边框调整选区，Esc 放弃标注”。

`CaptureSession::pointerPress` 里的走法：

```cpp
// Selected 阶段
if (m_annot && m_annot->pressFirst(p, mods))  { m_phase = Phase::Annotating; return; } // 第 1、2 步
if (handle != Handle::None && handle != Handle::Move) { /* 现有的 Adjusting */ return; } // 第 3 步
if (m_annot && m_annot->pressSecond(p, mods)) { m_phase = Phase::Annotating; return; } // 第 4、5.1 步
// 第 5.2、5.3 步：现有逻辑；有标注时不在选区外画新选区
```

**其他输入**

- **双击**：没有工具、点在空白处 → 复制（现有）；点在文字上 → 编辑文字；点在序号上 → 改号（小输入框，清空 = 取消手动号）。其余情况不复制。
- **右键**：等于 Esc，走下面的阶梯。
- **滚轮**：Hover 阶段照旧（窗口链）；Selected 阶段有工具或有选中对象时改粗细；都没有就不做事。
- **光标**：画图工具是十字，文字工具是 I 形，对象身上是四向箭头，手柄上是对应的缩放箭头。

**新阶段**：CaptureSession 加 `Phase::Annotating`，表示标注手势正在进行（画、挪、改形状）。它和 Adjusting 不同：不把 `adjusting` 置真，所以工具条不消失，只按 §3.5 让位。松开后回到 Selected。

**Esc 阶梯**（右键同样）

1. 输入法正在拼（`TextEdit.inputMethodComposing`）→ 不管，交给输入法（通常按键也到不了我们这里）。
2. 正在编辑文字 → 提交（空文字就丢掉），回到 Selected。
3. 手势正在进行 → 取消这一笔或这一次挪动（命令 revert 后丢掉）。
4. 有选区、有标注 → 选区和标注一起放下（回到 Hover），存下“放下前的状态”；边上提示“已放弃这次的标注 · Ctrl+Z 恢复”；在 Hover 阶段按 Ctrl+Z 原样恢复（选区、对象、撤销栈都在）。
5. 其余照旧：有选区就放下选区，没有就退出。

所以有标注时最多两下 Esc 就退出（放下、退出），开着工具不多占一下（Snow Shot #1973 嫌要按两次）。

**截图热键（再按一次就关）**：不管有没有标注都立刻关。有标注时，这次的标注留成草稿：底图（选区那块）+ 文档，只放内存，到下一次截图开始或 10 分钟后丢掉。托盘“截图”菜单里出现“找回刚放弃的标注”，点它在原处贴出合成图（带项目，4b 起能编辑）。用 Esc 退出时同样留草稿。（决定 3。）

**焦点和输入法**

- 遮罩的根项（`Item { focus: true }`）处理按键。它不接受输入法（没有 `ItemAcceptsInputMethod`），所以中文输入法开着时，R、T、1 这些键也直接到我们这里，不会变成拼音。只有文字编辑框接受输入法。
- 开始编辑时 `forceActiveFocus()` 给 TextEdit，结束后还给根项。

**按键先给谁**

- Selected 和 Annotating 阶段，`CaptureSession::key` 先问 AnnotationModel：工具键、撤销、删除、有选中对象时的方向键、`[` `]`、Ctrl+[ / Ctrl+]。没认领的再走现有逻辑。
- 编辑文字时按键在 TextEdit 里：Enter 换行，Ctrl+Enter 提交；Ctrl+S、F3 先提交文字再执行。

### 3.7 撤销与重做：差异命令栈

```cpp
// src/capture/AnnotationCommands.h（wscapture）
namespace ws::capture::annot {

struct Change {
    QList<quint32> ids;       // 变了的对象：缓存按它失效
    QRectF dirty;             // 要重画的区域（图像 px）= 旧包围盒 ∪ 新包围盒
    bool numbers = false;     // 序号要重推
    bool redactions = false;  // 打码的形状变了：所有打码块重算
    bool crop = false;
};

class Command {
public:
    virtual ~Command() = default;
    virtual Change apply(Document&) = 0;   // 第一次做，以及重做
    virtual Change revert(Document&) = 0;  // 撤销
    virtual bool absorb(const Command&) { return false; } // 合并：同一批对象的 Move、Restyle、Reshape
    QString label;                         // 提示里的“撤销 移动”
};

// 具体命令，各自存“之前”和“之后”：
//   AddItems{items, at}      RemoveItems{items, at}   MoveItems{ids, delta}
//   Reshape{id, before, after}   Restyle{ids, before, after}   Retext{id, before, after}
//   Renumber{id, before, after}  Reorder{id, from, to}
//   SetSeries{id, before, after}（新建一组时 before 为空）   SetCrop{before, after}
//   Batch{steps}（智能打码一次加 N 个、多选删除）

class CommandStack {
public:
    static constexpr int kLimit = 200;
    static constexpr qint64 kMergeMs = 700;
    Change push(std::unique_ptr<Command>, Document&, qint64 nowMs); // 应用并入栈；能合并就合并
    void pushApplied(std::unique_ptr<Command>, qint64 nowMs);       // 手势结束时：命令已经应用过
    Change undo(Document&);
    Change redo(Document&);
    bool canUndo() const;
    bool canRedo() const;
    void clear();
};
}
```

- **手势**：按下时建命令；每次移动先 revert，改参数，再 apply（同一条命令反复改，画面实时更新）；松开时 `pushApplied`；按 Esc 就 revert 后丢掉。画笔是一个点在增长的 AddItems，同样处理。
- **合并**：同一批 id 的 MoveItems（方向键）、Restyle（滚轮、`[` `]`）、Reshape，在 700 ms 内合成一步（QuickShot 的 coalesceKey）。
- **范围**：撤销栈不进项目；截图结束时清掉；编辑窗口每次打开一个新栈。

**为什么不用快照**（Flameshot、ShareX、QuickShot 都存整份对象列表）：

1. **内存**：每步一份全量拷贝，画笔的几百个点和文字都跟着复制 200 次；差异只存改了的部分。
2. **缓存**：换一整份列表后，没法知道哪个对象变了，打码块和文字排版的缓存只能全丢，或者再逐个比较；差异命令直接给出变了的 id 和脏区，画布只重画受影响的瓦片。
3. **不会漏**：快照的好处是“任何改动都自动可撤销”，我们用“文档只能经命令修改”得到同样的保证。
4. **合并和提示**：同一对象连续改动的合并、“撤销 移动”这类提示，命令里很自然。
5. **反例**：Flameshot 每次撤销要重画两次整图（代码里写着临时绕过），撤销还和文字编辑状态纠缠（#2499）；ShareX 每步克隆整个列表，对象多了就慢。

快照也有道理：实现最简单，几十个对象时内存不是问题。我们选差异，主要是为了第 2 条（瓦片画布要精确的脏区）。

**单测**：随机生成命令序列作用在随机文档上，全部撤销后 == 初始文档，全部重做后 == 最终文档（`Document::operator==`）；再打乱“做、撤销、重做”的交错，结果一样。

### 3.8 文字和输入法

**做法 A（先做）**

- 编辑时，在对象位置放一个 QML `TextEdit`：
  - `textFormat: TextEdit.PlainText`、`renderType: Text.NativeRendering`、`wrapMode: TextEdit.NoWrap`；
  - `font.pointSize = fontPx × scaleX × 0.75`。TextEdit 的 `font.pixelSize` 只能是整数逻辑 px：150% 下 27 px 是 18 逻辑 px，能整除；28 px 就不行，所以用 pointSize 绕开；
  - 颜色、粗体和样式一致。
- 编辑中这个对象不进瓦片（画布跳过它）。底框由画布按 TextEdit 的 contentWidth / contentHeight 画，免得底框跳动。
- 提交后，文字交给画布用 QPainter 画（同字体、整数像素字号、NoSubpixelAntialias）。
- 按键：Enter 换行；Ctrl+Enter、Esc、点框外 → 提交。输入法正在拼（`inputMethodComposing`）时，Esc 和 Enter 都不提交。提交空文字 = 丢掉（新建的不进撤销，旧的变成一次删除）。
- 拼音：TextEdit 自己显示 `preeditText`（带下划线），并通过 `cursorRectangle` 告诉输入法光标在哪，候选窗跟着光标。ksnip 就栽在这里：它只处理上屏的字，看不到拼音，候选窗也不跟。
- 再编辑：文字工具点已有文字，或任何时候双击文字。
- **跳变检查**（实现时先做）：编辑中和提交后各抓一次屏，比文字区域。
  - 0 差，或只差几个灰阶 → 用做法 A。
  - 字重、字形明显不同 → 改用做法 B。

**做法 B（退路）**

- TextEdit 照样在那里接管输入和输入法，但文字颜色设成透明（光标和选中底色照常显示）。
- 画布实时画“已输入的文字 + 在光标处插入的 `preeditText`（带下划线）”。编辑中和提交后是同一段 QPainter 代码，所以不会跳。
- 要求画布的排版和 TextEdit 一致：同字体、同字号、不折行。单测比较 `positionToRectangle(i)` 和 QTextLayout 的 `cursorToX(i)`，相差 ≤ 0.5 px。

**外观**

- 文字框左上取整数图像 px。
- 底框：内边距 0.3 × 字号，圆角 0.25 × 字号；底色 = 样式颜色，字是白色（黄、白底框上用 #212121）。
- 字体和 Win顺 其他界面一致，中文落到微软雅黑。

### 3.9 序号

- **推导，不存计数器**：`numbers(doc)` 对每一组，把组里的序号对象按 seq 排好；从组的 start 开始，遇到手动号就用手动号，然后每个加 1。删掉一个、撤销、重做后，号自动重排（ksnip 的 UpdateAllNumbers 思路）。Flameshot 用“最大值 + 1”，删了中间的会留下 1、3 这样的洞。
- **起始值**：面板里的“起始值”改当前组的 start（SetSeries 命令）。
- **单个号**：双击序号，输入数字 → 手动号（Renumber 命令），后面的接着数；清空 → 取消手动号。这正好解决 QuickShot #19：补回删掉的 1、换个颜色从 1 重新开始。
- **另起一组**：面板上的按钮。新组 start = 1，之后放的序号都属于新组，颜色可以不同。
- **外观**：实心圆，直径约 1.5 × 字号；两位数以上变成胶囊形；数字粗体白色，黄色和白色底时用 #212121；白色圆加 1 逻辑 px、30% 不透明的 #212121 描边，免得在白底上看不见。
- **点一下放一个**：不用拖（ShareX #8634 嫌步骤多）。

### 3.10 马赛克、模糊、纯色：不可还原

**原则**：从底图取像素，但只取“所有打码区域的并集”之外的像素，区域里的原像素从不读。所以格子再小、模糊再轻，也还原不出来。Flameshot 的理由：普通像素化能被 unredacter 一类的工具还原。

输入：底图 B、采样范围 S、打码并集 U（所有打码对象的框和笔迹）、本对象的区域 R、格子大小 c、样式、种子。

- **采样范围 S**：遮罩里 = 选区；编辑窗口里 = 整张底图（不随裁剪变）。遮罩里看到的，和转成项目后重开看到的，算出来完全相同（项目的底图就是选区）。
- **马赛克**：
  1. 格子从 R 的包围盒左上开始排，所以格子跟着对象走。
  2. 每格取中心点，往左、右、上、下四个方向找最近的“在 S 里、不在 U 里”的像素，按距离的倒数加权平均。
  3. 四个方向都找不到时，用 S 里 U 外所有像素的平均色；还没有就用 #808080。
  4. 每格加亮度噪声 ±16（同一个数加到 R、G、B），噪声 = hash(种子, 格的 x, 格的 y)。
- **模糊**：同样的方向填充，但在更细的网格上算（步长 max(4, c/2)），格点之间双线性插值，再加每像素 ±4 的细噪声，免得出色带。
- **纯色**：直接填样式颜色（默认 #212121）。
- **抹平**（阶段 5）：每个像素都做方向填充、不加噪声，看起来像那块被擦掉了（ShareX 智能橡皮的效果）。
- **涂抹**（阶段 5）：R = 笔迹描边出来的形状；边界不抗锯齿，每个像素要么是填充、要么是原图。
- **随机数**：自己写（splitmix64 一类的整数哈希），不用 `std::normal_distribution`：各家标准库的结果不一样，项目换台机器重开会变。种子在建对象时取随机数，存进项目。
- **格子下限**：智能打码加的框，格子至少是框高的 30%（QuickShot 的经验：大字也看不出来）。
- **速度**：
  - 方向填充按行、按列各扫一遍，得到每个位置“左右上下最近的 U 外像素”，整体是 O(面积)。
  - 打码块按对象缓存。任何打码对象的形状变了，所有打码块都重算（并集变了，别的块可能受影响）。
  - 拖动中超出帧预算时，只重算正在拖的那一块，其余松手后重算。静止时屏幕和导出仍然完全一致。
- **关键单测**：把 R 里的底图像素随便改，导出逐位不变；同一个种子算两次结果相同；底图均匀时对象平移，打码块跟着平移、内容不变。

### 3.11 导出和屏幕一致

- 导出 = `Compositor::exportImage`，内部和瓦片是同一个函数（瓦片就是合成一小块），输出不透明 32 位图（PNG 编成 RGB，体积小）。
- 选中框、手柄、悬停描边、编辑中的文字框都是 QML 项，不在合成里。正在编辑的文字，导出前先提交。
- 遮罩里，复制、保存、贴图、识别文字、热键草稿，都先合成再走原来的路：`Capture::finish` 现在是 `image().copy(rect)`，有标注时换成合成图。
- 没有标注时不走合成，直接 copy，保持现在的速度和 0 差。
- 验收：§2.1 第 1、2 条，加上单测“瓦片 == 整张”。

### 3.12 项目：格式、存放、生命周期

**格式**：`.wsedit` 是一个 zip（用 miniz，仓库里已有，已经链进 WinShun），里面两个文件：

- `doc.json`：deflate 压缩；
- `base.png`：store，不再压一遍。

为什么用 zip：一个文件就是一个生命周期，用 QSaveFile 原子地写；以后能往里加东西（缩略图、长图分块），外壳不用改。

为什么不用“合成图 PNG 里嵌 JSON”：历史条目的 PNG 必须是合成图（粘贴、jt、OCR、MCP 都用它），底图是另一张图，塞不进去。

`doc.json` 示例（样式只写和默认不同的字段；点的单位是图像 px）：

```json
{
  "format": "winshun-annotation",
  "version": 1,
  "canvas": [1282, 841],
  "crop": [0, 0, 1282, 841],
  "dpr": 1.5,
  "series": [{"id": 1, "start": 1}],
  "currentSeries": 1,
  "nextId": 4,
  "nextSeq": 4,
  "items": [
    {"id": 3, "kind": "redact", "seq": 3, "points": [[100, 40], [380, 72]],
     "style": {"redact": "mosaic", "shape": "box", "cell": 18}, "seed": "9f1c2a7d4e5b6c80"},
    {"id": 1, "kind": "arrow", "seq": 1, "points": [[520.5, 300.5], [700.5, 180.5]],
     "style": {"color": "#E53935", "width": 6}},
    {"id": 2, "kind": "number", "seq": 2, "points": [[760.5, 160.5]],
     "style": {"color": "#E53935", "fontPx": 27}, "series": 1}
  ]
}
```

**版本**

- `format` 不对 → 不认。
- `version` 比我们旧 → 逐级迁移（`migrate1to2` 这样的函数，每个都有单测和固定的样例文件）。
- `version` 比我们新 → 不打开，提示“这张图是新版 Win顺 存的，升级后才能编辑”；合成图照常能粘贴。
- 同一个版本里不认识的字段，忽略。

**存放**

- 放在历史库 `images/` 旁边的 `projects/<id>.wsedit`。
- 单独一个文件夹，是因为 `ClipStore::open()` 会删掉 `images/` 里名字不是整数 id 的 `*.png`；混放容易误伤，分开以后清理规则各管各的。
- ClipStore 把项目当成不透明的字节，不解析。

**ClipStore 要改的地方**（每一条都要有单测）

1. **列**：`clips` 加 `project INTEGER NOT NULL DEFAULT 0`（照 ocr、rank、screenshot 的做法：`PRAGMA table_info` 里没有就 `ALTER TABLE`）；`Clip.project`（bool）；`ClipCapture.project`（QByteArray，空 = 没有）。
2. **写**：Writer 线程先写 PNG，再写项目，都用 QSaveFile。
3. **去重**：同像素哈希命中旧条目时，新来的带项目 → 覆盖旧条目的项目文件，置 project = 1；不带 → 留着旧项目。
4. **删除和恢复**：`remove()` 和图片一样先留着文件（撤销要用）；`restore()` 的 INSERT 列表加 `project`。
5. **清理**：`discardImages()`、`dropRows()`、`prune()` 里删 PNG 的地方，一并删项目。
6. **孤儿**：`open()` 也扫 `projects/*.wsedit`，名字不是整数 id、或 id 不在表里就删。
7. **读**：新增 `projectPath(id)`、`project(id)`（读文件，给编辑窗口）。条目标着有项目、文件却不在（两次写之间崩了）或读坏了 → 当没有项目，以合成图为底图打开，并把这一条的列改回 0。
8. **清空历史、关掉“记住”**：和图片同样处理。

**谁能读到什么**

- 粘贴、`jt`、OCR、MCP 的 screenshot_history：只看合成图，永远看不到项目和底图。
- 历史条目的 OCR 文字：从合成图（打码后的）识别，所以被打码的字搜不到。
- Ctrl+S 存的文件：合成后的普通 PNG，不带项目。
- 项目里的底图是原图，包括被打码和被裁掉的部分：只在本机，和条目一起删（决定 2）。
- 已核对，两条会把文件带出本机的路都不含它：设置备份（`BackupFiles.cpp`）只带 `WinShun.ini`、`favorites.json`、`dialog-pins.txt`、`icons/web/custom` 和 `plugins`；诊断包（`Diagnostics.cpp` 的 `exportArchive`）只带运行日志，代码里写明不含剪贴板。以后改备份范围时，不要把剪贴板文件夹加进去。打码的自定义词存在 ini 里，会跟着设置备份走。

**时机**

- 复制时，先编码合成图并放进剪贴板（剪贴板到图的时间不变），再在同一个编码线程里打包项目（底图 PNG + JSON），交给 Writer。
- 只有带标注的截图才有项目，没标注的不写。

**编辑后的规则（4b）**

- 改了再复制 = 新条目（带新项目），原条目不动，像“另存一份”。
- 没改直接复制 = 把原条目重新复制（移到最前），不重新编码。
- 合成结果和某条已有条目像素相同 → 沿用那一条，项目换成最新的。

**保存和贴图也进历史吗**：现在只有复制会记一条历史。决定 1 建议保存（Ctrl+S）和贴图（F3）也记一条：不碰系统剪贴板（`Clipboard::recordImage`），同样受“记住”开关管。这样用这两种出口标过的图，也能再编辑、能被 jt 搜到。

## 4. 智能打码和长截图

### 4.1 智能打码（阶段 5）

**流程**

1. **触发**：
   - 打码工具面板里的“智能打码”按钮（也可以按 Shift+B）；
   - 预扫（决定 5）：选区停稳 300 ms 后，在后台 OCR 线程识别选区；找到 N 处就在工具条边上显示一个小提示“发现 N 处 · 点此打码”，没找到就什么也不显示。用户先按了 Enter 也不等它，不挡任何出口。选区一变，结果作废重来。
2. **拿到每个字的位置**：给 PaddleOcr 加 `readPieces`（见下）。
3. **跑规则**：找出敏感的那几段字（表见下）。
4. **算框**：把匹配到的字换成框，外扩、合并。
5. **应用**：一个 Batch 命令加 N 个打码对象，一次 Ctrl+Z 全部撤掉。

**每个字的位置**

PaddleOcr 现在的 `read()` 只返回文字行，但内部已经有每行的四边形（minAreaRect + unclip 1.6）。识别时，一批行按最宽那一行补齐成同一宽度，CTC 输出的 `steps` 个时间步覆盖整个补齐宽度；每一行左对齐，实际宽度是 w。

- 一个字在 CTC 输出里是一段连续的同类时间步。取这段的中点 s，它在行图里的横坐标 x = (s + 0.5) × (补齐宽度 / steps)，在这一行上的比例 f = x / w（夹在 0–1）。
- 用行四边形的上边和下边各按 f 插值，得到这个字的竖直中线；相邻两个字中线的中点当作字的边界，首尾的字各补半个平均字距。
- 最后除以 CaptureOcr 的放大倍数（DPR 低于 1.5 时会放大再识别），回到截图的图像 px。
- 退路：字数对不上时，按字符宽度比例切（全角算 2、半角算 1）。QuickShot 就是这么做的，在等宽的终端里很准。

**规则**（按公开的格式自己写，不抄 QuickShot 的正则表）

| 类别 | 默认 | 怎么认 | 防误报 |
|---|---|---|---|

| 密钥 | 开 | 已知前缀：sk-、sk-ant-、ghp_、gho_、github_pat_、glpat-、xoxb-、xoxp-、AKIA 加 16 位、AIza、eyJ 开头的三段式 JWT、`-----BEGIN … PRIVATE KEY-----`；还有“键 = 值”“键: 值”，键是 password、passwd、pwd、secret、token、api_key、apikey、access_key、密码、口令、令牌、密钥 | 值是占位符（`$VAR`、`${VAR}`、`%VAR%`、`****`、`xxx`、`<...>`、`process.env.X`）不算；密钥一直盖到这一行末尾（OCR 常把尾巴认错） |
| 本机身份 | 开 | 本机用户名、电脑名、用户目录（`C:\Users\<名字>`） | 短于 3 个字符的名字只在路径或命令提示符里才算 |
| IP、MAC | 关 | IPv4、IPv6、MAC | “版本 1.2.3.4”这种跳过 |
| 全部文字 | 关 | 每个文字框都打 | — |
| 自定义词 | 空 | 设置里填的词，整词匹配 | — |

- 匹配前先折叠形近字：O、o → 0；l、I、竖线 → 1；全角数字和字母 → 半角；中文标点 → 英文标点。折叠一对一，下标不变。
- 所有规则都在 `findSensitive` 里，单测覆盖真、假身份证，Luhn 真、假卡号，带分隔符的手机号，各种密钥前缀，占位符，形近字，短用户名。

**框**

- 一个匹配的框 = 它覆盖的字框的并集。
- 左右外扩 max(2 px, 0.15 × 行高)，上下外扩 0.1 × 行高。
- 同一行上重叠、或相距不到半个行高的框合并。
- 已有打码盖住 80% 以上的框跳过，所以再点一次不会重复加。

**应用**

- 样式 = 打码工具记住的样式（默认马赛克），格子至少框高的 30%。
- 边上提示“已打码 N 处 · Ctrl+Z 撤销”；没找到就提示“没找到要打码的内容”。
- 第一次用时，提示里多一句“自动找的可能有漏，发出去前再看一眼”（QuickShot 也这么写）。

**线程和内存**

- OCR 走 CaptureOcr 的同一个工作线程和同一份模型，不加载第二份；60 秒不用就释放。
- 规则在 OCR 线程上跑完再回 GUI 线程。
- 历史条目的 OCR 照常对合成图做，不复用打码前的识别结果，免得被打码的字被搜到。没有任何标注时，可以直接复用预扫的结果，省一次 OCR。

**隐私**：识别和匹配都在本机；诊断里只记每类的个数，不记文字。

**涂抹打码和抹平**

- 打码面板加“形状：框 / 涂抹”和第四种样式“抹平”。
- 涂抹的笔宽 16 / 24 / 36 逻辑 px（和格子大小分开设）。
- 两者都用 §3.10 的同一个填充算法。

### 4.2 长截图（阶段 6）

**流程**

1. **进入**：遮罩里选好区域后按 Ctrl+L，或点工具条的“长截图”。选区就是要滚动的那块（比如浏览器的内容区）。已有标注时不进，提示“先完成或放弃标注”。
2. **换上长截图的界面**：遮罩全部隐藏（冻结画面用不上了）。
   - **边框**：一个原生分层窗口，在区域外面画一圈框：1 逻辑 px 中性灰，外侧再加 1 px 半透明白。这是对“边框 1 px 中性灰”的一处例外：这圈框是画在别人内容上的记号，不是我们窗口的边，只有灰线的话在灰色背景上看不见。面板窗口自己的边仍是 1 px 中性灰。窗口样式 `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST`，鼠标穿透。
   - **面板**：一个 Qt Quick 窗口，第一次用长截图时建，之后隐藏复用；不抢焦点（`Qt::WindowDoesNotAcceptFocus`，即 `WS_EX_NOACTIVATE`）；按 placeBeside 的规则放在区域旁边。上面有实时缩略图、状态（等待 / 拼接中 / 往回滚了 / 跟丢了 / 到上限）、高度、自动滚动开关、完成、取消、复制诊断信息。
   - 两个窗口都放在区域外面，并且都设 `WDA_EXCLUDEFROMCAPTURE`（探针确认对分层窗口有效），双保险。
   - 焦点留在目标程序上，滚轮和键盘照常。我们临时注册两个全局热键：Esc = 取消，Enter = 完成，结束就注销；截图热键这时也等于完成。
3. **取帧**（ScrollGrabber）：
   - 复用常驻的 WGC 设备和那块屏的 capture item，开一个 `CreateFreeThreaded` 帧池；
   - 每帧在 GPU 上裁到区域（CopySubresourceRegion 到区域大小的 staging 纹理）再读回；不带鼠标指针；
   - 只留最新一帧（mailbox），旧的直接丢；
   - WGC 只在画面变化时给帧，静止时不费电。
4. **自动滚动**（ScrollInput）：每一步按阶梯试，记住哪一种在这个程序上管用。
   1. **投递 WM_MOUSEWHEEL**：从 Z 序顶部找区域中心下面第一个“不是本进程、也不是分层 + 透明”的窗口，用 `ChildWindowFromPointEx`（CWP_SKIPINVISIBLE、CWP_SKIPDISABLED、CWP_SKIPTRANSPARENT）一层层找到最深的子窗口，`PostMessage`（wParam 高位 = −120 × 格数，lParam = 区域中心的屏幕坐标）。不动用户的鼠标。
   2. **SendInput 滚轮**：投递后连续 2 次看不到画面动，就换这个。只在鼠标已经在区域里时用（不替用户挪鼠标），否则面板提示“把鼠标放到要滚动的区域上”。
   3. **UIA**：还不动，就从区域中心的元素往上找支持 ScrollPattern 的，调 Scroll（小步）。
   4. **手动**：都不行时，面板提示“自动滚动不起作用，请自己滚动”，我们只管拍和拼。
   - **管理员窗口**：目标程序以管理员身份运行时（我们不提权），PostMessage 会被拒绝、SendInput 被 UIPI 挡住 → 直接进手动模式，提示“这个程序以管理员身份运行，请手动滚动”，诊断里记一笔。
   - **步调**：每滚一步，等画面动了又停住（连续两帧位移相同，或 80 ms 没有新帧）再滚下一步。前几步量出“一格滚多少像素”，之后每步的格数让滚动距离不超过可滚动区高度的 60%，保证有重叠（ShareX 社区在 #8837 里提的“滚完等稳了再拍”）。
   - **停**：连续 3 次滚了不动（到底了）、到上限，或用户按完成。
5. **拼接**（ScrollStitcher，纯 C++，单测直接喂帧），照 QuickShot 的思路自己写：
   - **只比相邻两帧**，求“内容往上移了多少行”（dy）。原地变化的内容（懒加载、淡入、时钟、悬停高亮）不会让参照物过期。
   - **固定带**：两帧逐行比，顶部和底部一模一样的行是吸顶栏、吸底栏，不参与搜索；左右一模一样的列（固定侧栏）也排除；右边一条（约 16 逻辑 px）总是排除，留给覆盖式滚动条。
   - **行签名和投票**：每行切成 16 段，每段算亮度的量化值（容差 24）。对每个候选 dy，统计“当前帧第 y 行第 k 段 == 上一帧第 y + dy 行第 k 段”的票数；分数 = 一致的段 / 比较的段。分数 ≥ 0.6 且票数 ≥ 24 才算数。
   - **平手**：先看票数，再看和上一步滚动速度的接近程度；跟丢几次后放宽阈值恢复。
   - **状态**：等待（还没有帧）/ 追加（加了新行）/ 没动 / 往回滚（不添加）/ 跟丢 / 到上限。
   - **画布**：以第一帧为坐标；新露出的行追加在下面；同一段里后到的帧覆盖先到的（懒加载的图能补上，浮动按钮只留在最后见到的位置）；但画布顶部的六分之一不覆盖（只在往下滚时才出现的吸顶栏不会盖到上面）。
   - **页眉页脚**：页眉取第一帧的固定顶栏，页脚取走得最远那帧的固定底栏，最后拼成“页眉 + 内容 + 页脚”。
   - **兜底**：找不到重叠时，按前几步的平均速度预测 dy 拼上，结果标成“部分成功”，诊断里记一笔（ShareX 的做法）。
   - **存储**：按 256 行一块分块，用 VirtualAlloc 申请、结束就 VirtualFree；上限 3 万像素高、6000 万像素，到了就停在“到上限”。
6. **完成**：结果直接在 4b 的编辑窗口里打开（拿焦点）。Enter 复制、Ctrl+S 保存、F3 贴图，也能标注、裁剪（ShareX #8690 要的）。长截图不用另做一套出口界面，Enter 一下仍然就能复制。

**诊断**

- **事件环形缓冲**：只在内存里，最近 2000 条。每一步记：滚动办法和结果码（含“拒绝访问”）、帧数、dy、分数、票数、状态变化、用没用兜底、耗时。
- **看门狗**：5 秒没有新帧，就记一笔，并在面板上提示。
- **只记几何和计数**：不记像素，不记窗口标题，只记目标程序的 exe 名。
- **复制诊断信息**：面板上的按钮，把这些整理成一段文字放进剪贴板，用户贴到 issue 里就行。
- **诊断包**：同时写进现有的诊断日志（`ws::diagnostics::record`），所以设置里导出的诊断包（`diagnostics::exportArchive`）也带着。
- **开发用**：设了环境变量 `WINSHUN_SCROLL_DUMP=<文件夹>` 时，把每帧 PNG 和位移落盘；`wsbench --scroll-replay <文件夹>` 用拼接器重放，打印每一步的状态。只用于我们自己复现，正式界面上没有。

## 6. 要用户拍板的决定

1. **保存（Ctrl+S）和贴图（F3）也记进截图历史吗？**（不碰系统剪贴板，同样受“记住”开关管）
   - **推荐：记。** 用这两种出口标过的图，以后也能再编辑、能被 jt 搜到；“截图历史就在剪贴板历史里”是 design-capture §7 第 5 条定下的，所有出口一致更好懂。
   - 代价：历史里多几条。不记的话，只有按 Enter 复制的图能再编辑。

2. **项目里保留原图吗？**（包括被打码和被裁掉的部分）
   - **推荐：保留，只在本机。** 以后再编辑时能挪动、撤掉打码，能把裁掉的放回来；粘贴、jt、OCR、MCP、Ctrl+S 存的文件都只有合成图；设置备份和诊断包都不带它（已核对代码）；项目和历史条目一起删。
   - 另一种：存项目时把打码“烧”进底图、裁掉的部分丢掉。电脑给别人用时更稳妥，但再编辑时打码就挪不动了。也可以以后加一个设置项，让在意的人选这一种。

3. **有标注时退出（再按截图热键，或 Esc 两下）怎么办？**
   - **推荐：立刻关，不弹确认；这次的标注留成草稿**（只在内存，到下一次截图或 10 分钟后丢）。托盘“截图”菜单出现“找回刚放弃的标注”，点它贴回原处（4b 起能接着编辑）。“再按一次就关”的规矩不变，标了半天也不会白丢。
   - 另两种：弹确认框（慢，而且违背“Esc 直接关、不弹确认”）；直接丢掉（容易误丢）。

4. **工具键用“字母 + 数字”吗？**（R E A L P M T N B 和 1–9；再按一次关掉；C 仍是复制颜色；H 隐藏工具条；`[` `]` 改粗细；不用 Ctrl+数字和 Alt）
   - **推荐：用。** 字母沿用 ShareX、Flameshot、ksnip 的习惯，从别的工具过来不用重学；数字和工具条的顺序一一对应，好记。输入法开着中文时也不会被拼音吃掉（§3.6）。
   - 另两种：只用数字（以后加功能更不容易撞键，但难记）；只用字母。工具键可自定义，等有人要再做。

5. **智能打码要不要预扫？**（选区停稳 300 ms 后后台识别，工具条边上提示“发现 N 处”，不点就什么都不打）
   - **推荐：要。** 大多数人想不到要打码，提示放在边上、一点就打，正合“默认精简、提示放边上”的规矩；复制时本来就要跑一次 OCR，模型是同一份，没有标注时还能直接复用预扫的结果。
   - 代价：每次选好区域后台多跑一次 OCR（低优先级线程，不挡任何出口）；可以在设置里关掉。不预扫的话，只有点“智能打码”按钮才识别。

用户拍板后，把阶段顺序和这些决定抄进 `docs/design-capture.md` 的 §6 和 §7。
