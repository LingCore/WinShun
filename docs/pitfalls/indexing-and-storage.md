# 索引、存储、内容搜索与网络共享踩坑

## NTFS 索引、USN 日志、目录链接与外接磁盘

- **小簇分区 MFT 记录跨区段/跨块**：FAT32 转换、老分区或 `format /L`（4 KB 记录配 512–2048 B 簇）不满足单簇装单记录 → 读缓冲前预留一条记录空位，将上块末尾半条记录拷前拼接解析；测小簇须用 `.vhd`（`.vhdx` 物理扇区固定 4 KB，格不出更小簇）。
- **MFT `$BITMAP` 不一定在 0 号记录**：大 MFT 改用（可能非常驻的）`$ATTRIBUTE_LIST`，将 `$BITMAP` 搬到扩展记录甚至拆成多段 → 解析 `$ATTRIBUTE_LIST`，按起始 VCN 与所在记录逐段拼接区段表；读不到时回退全读以免漏项。
- **经服务读 MFT 丢失重解析标签**：`volproto::BlockWriter` 精简记录原先不含 `$REPARSE_POINT` 标签，无法区分联接/符号链接与 OneDrive 云目录 → 记录标志字节增加 `kRecordNameSurrogate`，服务端与主程序必须同步更新。
- **`mklink /j` 联接在 USN 日志里不可见**：`mklink /j` 先建空目录再设重解析点，第二步原因码为 `USN_REASON_REPARSE_POINT_CHANGE`（`mklink /d` 一步建成不受影响） → 将 `USN_REASON_REPARSE_POINT_CHANGE` 加入 `kReasonMask`。
- **递归删含联接目录会顺着删掉目标**：`QTemporaryDir` 析构调 `QDir::removeRecursively()` 会穿过联接删除目标内容 → 测试建的链接登记到 `MadeLinks`（`tests/TestJunction.h`）且声明在 `QTemporaryDir` 之后，先 `RemoveDirectoryW` 仅删链接；手工清理先 `[IO.Directory]::Delete(链接, $false)` 删 `ReparsePoint` 再递归删。
- **排除整个盘符（`X:\`）仍被列卷遍历**：`X:\` 规整为 `X:` 后，子目录检查从首个 `\` 后开始且 `removeExcluded` 跳过卷根 → `IndexService::run` 列卷后直接剔除根被排除的卷（由 `dropStaleRoots` 清理索引与内容索引），`Crawler::isExcludedPath` 先查盘根，且 `applyRuleChanges` 不探裸 `X:`（那是该盘当前目录）。
- **排除目录内保留子目录（`keptPaths`）**：`Settings::crawlRules` 整目录排除数据目录（防 `index.bin`/日志反复脏化索引）会一并藏掉 `plugins\<id>` → 通过 `CrawlRules::keptPaths` 声明例外（仅恰好被一条排除规则包住时生效，用户自排优先）；中间层级仅作通路不收自有文件与其他子目录（`isExcludedDir`/`addToListing`/`UsnApplier::holdsNoFiles` 先按名筛再拼路径），变更时整盘重读（快照 v10 存该集合），`plugins` 同步进 `lowPriorityPaths`。
- **外接移动硬盘误判固定盘导致弹出被占**：仅判 `GetDriveTypeW == DRIVE_REMOVABLE` 会漏掉上报为固定盘的 USB 移动硬盘/固态 U 盘，关外接开关后仍被 `VolumeNotifier` 持卷句柄拦截安全弹出 → 选盘、磁盘列表与补搜统一用 `isExternalVolume`：固定盘再查总线类型，USB/1394/可拔介质算外接，排除 SD/MMC（eMMC）与 NVMe，Windows 系统盘所在物理盘永不算外接（测试用 `WINSHUN_EXTERNAL`）。
- **列目录返回写入中文件的旧大小**：`FindFirstFile`/`QDir` 读目录项缓存，追加写入中的文件（如 `.texts`）在 `FlushFileBuffers` 或关句柄前大小不更新 → 需准确大小时按路径（`GetFileAttributesEx`/`QFileInfo`）或句柄（`GetFileSizeEx`）查；`CopyFileEx` 可直接复制被其他句柄打开写入的文件。
- **普通用户模式：服务登录竞态与状态覆盖**：WinShun 先于服务启动，在 `awaitAccess` 前按文件夹模式剪卷会清空他盘快照并致服务就绪后全盘重读 MFT；早于 `scope.json` 恢复标“盘不在”会被覆盖，排除盘误显“盘不在” → `Settings::foldersInEffect` 在服务已装未停用时一律整盘，`IndexService` 等完 `awaitAccess` 再算 `foldersOnly` 与剪卷；离线/整盘状态在恢复 `scope.json` 与等完服务后才标且先查 `isExcludedPath`；`ACCESS_DENIED` 判 `Unknown`，停用但在跑判 `Running`（用 `WINSHUN_SERVICE=none|disabled|stopped` + `WINSHUN_PIPE` 模拟）。
- **普通用户模式：监视子目录锁死上级改名与 62 路上限**：直接对子目录开 `ReadDirectoryChangesW`（即使带 `FILE_SHARE_DELETE`）会阻止上级目录改名或删入回收站（`ERROR_ACCESS_DENIED`）；`WaitForMultipleObjects` 超 64 句柄（含 2 内部事件）返 `WAIT_FAILED` 会令监视线程静默退出 → 默认按卷根监视并在 `changesInScope` 过滤范围外事件，仅卷根无权开时退回 `ChangeWatcher::Fallback`；硬上限 `kMaxWatches = 62`（先卷根后回退目录，超出无实时更新；去上限需改 IOCP）。
- **普通用户模式：1 MB 监视缓冲退化与定探唤醒休眠盘**：1 MB 卷根缓冲不仅挂起可能失败，读或重挂时也会因锁页内存不足失败而反复触发重走；每 5 min `probeService` 调 `applyIndexScope` 触发 `GetLongPathNameW` 会反复唤醒休眠盘 → 非 `DRIVE_REMOTE` 卷根用 1 MB，共享/子目录/插件用 64 KB，大缓冲读或重挂失败（除 `ERROR_NOTIFY_ENUM_DIR`）经 `ChangeWatcher::bufferAfter` 退回 64 KB；连续溢出按 3 s→30 s→5 min 退避（`LostEventsBackoff`）；`applyIndexScope` 仅在模式翻转时重算路径。
- **普通用户模式：Unicode 大小写、仅改大小写先报删除与停止响应**：`FileIndex::findPath`/`findChild` 仅折叠 ASCII 大小写，非 ASCII 大小写差异或 8.3 短名会令 `walkFolders` 每 3 s 死循环；8.3 卷仅改上级大小写会先单发 `FILE_ACTION_REMOVED` 再发 `RENAMED`，直接删子树会白重走；`prepareScope` 碰盘忽略取消会卡住弹出与改设置 → `findFolder` 回退逐级解码并用 `win32::equalsIgnoreCase`（`CompareStringOrdinal`），本轮 `m_placed` 仍缺则标不可读；未配对上级 `REMOVED` 先 `presenceOf` 核盘仍在即忽略，上级内改名走 `moveOnly`；`prepareScope` 每目录前查 `stop_token`（未完项留 `m_verifyOwed`）。
- **普通用户模式：附属文件清单、默认文件夹与收尾核对竞态**：未登记 `IndexFolder.cpp` 的附属文件会在迁移/删除时遗漏，老版重写快照会留过时 `scope.json`；首读设置即写回 `Index/Folders` 会固化旧 KnownFolder（忽略后续 OneDrive 接管）；收尾先查 `m_verifyOwed` 再清 `m_running` 会丢最后一刻“立即核对” → 附属文件（含 `scope.json`）登记进 `IndexFolder.cpp`，快照成功后写 `scope.json` 并校验 `index.bin`，整盘模式见 `stale` 须重走遍历盘（`staleScopeFileWholeDisks`）；缺键动态算不落盘（`indexFoldersChosen == false`），首次实际进入文件夹模式或用户/AI 改过才固化；收尾 `passOver` 先清 `m_running` 再查 `m_verifyOwed`。

## 内容索引、直读（bulk）与文档提取（`WinShunExtract`）

- **三字片段过宽误报与扩展名记录双重解码**：只记词内三字片段会命中大量代码通用串与超大 `.min.js`/JSON，触发海量 Defender 扫描；`extLength` 迁入名字记录后先查 `extLength` 再读 `name` 会解码两遍 → 片段纳入空格与标点并按类型设大小上限，`Collector` 与 `ofPhrase` 必须共用同一拆词规则，改动必升 `kStateVersion` 并以 `wsbench --content-index --verify` 验证零漏检；`ContentFilter::accepts` 先判标志位，再用 `FileIndex::fileName(e, extLength)` 一次读出。
- **线程/进程后台模式拖垮吞吐**：`THREAD_MODE_BACKGROUND_BEGIN` 将磁盘 I/O 降至极低，连带让打开文件时的 Defender 扫描排到队尾（加线程无效）；`PROCESS_MODE_BACKGROUND_BEGIN` 还对 `WinShunExtract` 施加 32 MB 工作集硬上限，并发建索引时反复换页慢近 4 倍（单独微基准测不出） → 读线程用普通优先级，靠并发数限流（活跃 1/4 核、空闲 1/2 核 `readers`，机械盘 ≤2；用 `GetSystemTimes` 衡量含 `MsMpEng` 在内的整机 CPU），文档给独立读线程不与文本争名额；`WinShunExtract` 仅设 `IDLE_PRIORITY_CLASS` + 句柄 `IoPriorityHintLow`，禁用进程后台模式。
- **小段合并等读线程排空与多线程合并负载偏斜**：小段合并（`mergeTails`）等待在途慢 PDF 排空会干等十几秒；整体合并按压缩字节或单一内存段切分时，高频英文片段字节小却倒排极长导致严重偏斜 → `mergeTails` 保留段内全部内容号（回收留给整体合并），实现边读边合；整体合并按倒排计数（`Segment::work`：个数 + 8）跨全部段与内存联合抽样切分（`ContentIndex::splitKeys`），每线程分 8 份。
- **写段移出锁后的拒收、去重查表与合并代数竞态**：写段放锁后快读打爆 400 万对上限会令 `ContentIndex::add` 返回 false 静默丢文件；整体合并重编号期间在途写段完成装入会带入旧号 → 缓冲超两段量时等 `m_flushed` 而不拒绝，凡可能放锁的步骤全置 `add()` 开头；去重查表移至共享锁下凭 `m_generation` 校验并在独占锁内补查内存；整体合并装入时递增 `m_generation`，在途写段见变化即丢弃，待刷计数按 `m_memory + m_writing` 算。
- **写段缓冲缺页膨胀与内容号重排导致短列表变大**：每段新申请 8 MB 排序/草稿缓冲触发约 4000 次清零缺页抵消多线程提速，分片临时缓冲令常驻堆多 20 MB；递归图二分重排内容号使长文档失去小号，≤4 项 LEB128 短列表反膨胀 → 用 `ContentIndex::FlushBuffers` 跨段复用缓冲至整体合并后释放；整体合并段文件（v5）另存按频次排序的 1.6 万内容号词典表，短列表改存表内下标。
- **换格式升级空跑休眠 15 min / 关选项延迟 2 min**：快照加载完即标 Ready 而 `contentVolumes` 未登记，换格式后按首次运行跳过 30 s 延迟即跑出 0 盘并睡 15 min；关掉某位置内容搜索醒来仍等 2 min `gather` 攒批 → 内容索引就绪须额外等 `m_volumesKnown` 并在登记卷后唤醒；位置变更时 `IndexService::setOptions` 调 `ContentIndexer::volumesChanged()` 跳过攒批立即清理。
- **USN 断链后机械盘逐路径核对耗时十几分钟**：重读 MFT 后几十万文件标 `IndexService::contentUnsureOf`，机械盘逐路径 `GetFileAttributesExW` 寻道约 1.1 ms/个且堵住新文档 → 单卷待核对 ≥ `kBulkCheckThreshold`（2000）时开批量直读，顺序扫 MFT `$STANDARD_INFORMATION` 确认未变项并直读已变文本，异常/压缩加密及 5 min 内写过文件（`kBulkRecent`）回退按路径查；同物理机械盘串行扫 MFT（`BulkVolume::scanning`）。
- **卷直读（bulk）：Defender 边界与 ~200 ms 磁盘脏窗口**：`GENERIC_READ` 读数据触发 Defender（~6.24 ms/文件），而 `FILE_READ_ATTRIBUTES | READ_CONTROL` 仅 ~0.06 ms；卷直读不走缓存，新记录约 200 ms 才落盘，`FSCTL_GET_NTFS_FILE_RECORD` 亦可能答旧常驻数据且返回记录已应用 fixup（不含 USA） → 权限检查用 `OpenFileById(READ_CONTROL)` + `GetSecurityInfo`（不解析 `$Secure`）；三道防脏：跳过 5 min 内文件（`kBulkRecent`）、会话前取 `ContentIndex::changeSequence()` 对期间写入标 `m_changedWhileReading`、后续写事件重读（勿依赖重开卷句柄刷盘）；`BulkReader::readRecordCached` 须兼容有无 USA 的记录。
- **卷直读（bulk）：队列超额/大文件死锁、VDL 尾垃圾与 8.3 硬链接数**：多卷先检 `queued + batch <= limit` 再取字节会在队列上叠加超额，单文件超上限永远卡死；`$DATA` 末簇 VDL（`initialized`）至 `want` 盘面为垃圾字节；记录头 `0x12` 链接数计入 DOS 8.3 短名（命名空间 2） → 放行即记入 `comingBytes`（送达/批末扣减），队列+在途均为 0 时放行任意大单文件，设 `kBulkQueueBytes`（64 MB）/ `kBulkBatchBytes`（16 MB）；`readAll`/`deliver()` 清零 `[initialized, want)`；硬链接数改数命名空间 ≠ DOS 的 `$FILE_NAME`（`FileInfo::names`）。
- **`WinShunExtract`：大 PDF 触顶 `0xE0000008` 与并发大文档内存叠加**：大矢量图 PDF 瞬时内存超 1 GB 触发作业对象下的 PDFium/Chromium OOM 退出码 `0xE0000008`；8 个复用进程并发读大 PDF 叠加数百 MB 私有内存并持有至 30 s 空闲退出 → 作业对象单进程上限放宽至 2 GB（不预占），仍超限者记读不出至文件改动；≥ 16 MB 文档入并发 1 优先队列（占文档队列 1 名额，`DocExtractor` `alone` 把关）且读完立即结束该子进程归还内存；用户实时搜索触发的提取不排队。
- **`WinShunExtract`：PDFium 堆分配瓶颈与 `SegmentHeap`**：PDF 提取耗时约 94% 在 `FPDF_LoadPage`（66%）和 `FPDFText_LoadPage`（28%），文件读 `m_GetBlock` 仅 2%，其中 `ntdll` `HeapAlloc` 占 ~27%（静态 CRT 千万级小分配） → 清单启用 `heapType=SegmentHeap`（提速 5–7% 且输出逐字节一致）；不做整文件预读 `FPDF_LoadMemDocument64`、不换字体映射（防改字宽/文本）、不钩 `HeapAlloc`（失堆加固）。

## 网络共享（SMB）、WebDAV 与 WSL

- **TUN 代理假在线、主机名无超时与多地址顺序阻塞**：TUN 代理/VPN 本机接管所有 TCP `connect` 致死地址 1 ms 假成功；`GetAddrInfoW` 无超时会经 DNS/LLMNR/NetBIOS 卡死界面数秒；分离线程用函数内静态表在退出时析构后使用；多 IP（如不通 IPv6 在前）顺序 `connect` 耗尽 1.5 s 超时 → 连通后必等协议回包（SMB `NEGOTIATE`，WebDAV HTTP `OPTIONS` 或 TLS `ClientHello`）；解析放独立线程经 `shared_ptr` 交回并计入总期限，缓存表 `new` 分配不析构；并发非阻塞 `connect` + `select` 竞速最多 16 个地址（`share::probe`、`webdav::race`）。
- **仅支持 SMB1 的老 NAS 被误判离线**：直发 SMB2 `NEGOTIATE` 会被 SMB1 服务器挂断，未装 SMB1 客户端的 Win11 只报错误 64 而非 `ERROR_SMB1_NOT_AVAILABLE`（384） → 探测改发含 `NT LM 0.12`/`SMB 2.002`/`SMB 2.???` 的多协议 SMB1 `NEGOTIATE`（按 `\xFESMB`/`\xFFSMB` 区分，挂断再补纯 SMB2）；仅 SMB1 探测阶段仍算在线，列共享失败且探测确认为 SMB1 才报 384。
- **来宾共享错误码掩盖与无网络密码账户先报 1326**：Win11 禁用来宾（`EnableInsecureGuestLogons=0`）时，`NetShareEnum` 走 `IPC$` RPC 会把 1272 掩盖为 53；无网络登录密码（如 PIN 登录）的账户在 NTLM 质询后断开先报 1326，且 Windows 短暂负缓存失败 IP → `NetShareEnum` 非鉴权失败时补查 `GetFileAttributesW("\\服务器\IPC$")` 取真错误码（1272/1326 等）；允许 1326→输任意用户→1272 的来宾提示流转；测试负缓存须换新 IP。
- **提权会话用不上资源管理器未记住的 SMB 凭据**：SMB 连接按登录会话隔离，`EnableLinkedConnections=0` 时资源管理器未勾选“记住”输入的密码对提权 WinShun 不可见 → 凭据管理器按用户共享（两会话通用）；“登录…”弹系统凭据框经 `WNetAddConnection2` 连接，勾选记住后按服务器名/IP 调 `CredWrite` 持久化；后台核对不弹窗。
- **SMB 变更通知 64 KB 上限、Samba 局限与内容修改重读**：网络路径 `ReadDirectoryChangesW` 缓冲 >64 KB 报 `ERROR_INVALID_PARAMETER`；Samba 仅推送经 SMB 的修改（本机修改非递归仅根目录层有效，`change notify = no` 静默无事件）；只听文件名变化会令改内容 1 h 后才重读 → 固定 64 KB 仅当加速，以 `[Network] VerifyHours`（默认 1 h，慢共享放宽至耗时 60 倍）兜底；SMB 监听加 `FILE_NOTIFY_CHANGE_SIZE | LAST_WRITE`（`ChangeWatcher::Tell::Writes`），合并 `Modified` 在锁外 `GetFileAttributesEx` 刷戳，持续写文件首次即读后 10 min 限频（`ShareContent::kReadAgain`），并用 `remotecontent::stampAfterRead` 防半写脏读。
- **界面线程查网络文件卡死与 NAS 重启/慢响应永久离线**：界面线程 `QFileInfo::exists` 在断联共享上因 SMB 超时卡死 10–45 s（刚失效的缓存也卡 6 s）；仅靠 1.5 s 探测令慢响应 NAS 永不恢复，同步撤除 `ChangeWatcher::setRoots` 会在断电服务器上卡 1–2 min 拖住其他共享 → 界面动作前每次实测 `share::reachable`（1.5 s 封顶、多选按服务器去重、不用旧缓存）；共享线程探测放宽到 5 s，不通时独立线程经 `share::openRoot` 试开（15 s 封顶，晚到成功亦唤醒）用于标离线前、离线每 15 min 与“立即核对”；探测按 1/2/4/5/5… min 退避（`share::Retry`）；监听设置放独立 `watchLoop` 线程。
- **退出卡在内核网络调用与禁用 `CancelSynchronousIo`**：服务器断电或 WebDAV 扣包时同步 `CreateFileW`/列目录卡在内核（WebClient `SendReceiveTimeoutInSec` 默认 60 s 且还会再 `PROPFIND` 上级 60 s），`taskkill /F` 也杀不掉进程外壳；调 `CancelSynchronousIo` 常令**调用方自己**卡死在 `ZwCancelSynchronousIoFile` → 退出先 `requestStop()` 停发新请求、先存索引再 `m_shares->stop()`；远端内容读文件放独立线程（`remotecontent::readFile`）退出不 join 以立刻释放窗口和单实例互斥量（更新器预留 90–120 s 重试）；绝不在界面线程或持锁时调 `CancelSynchronousIo`。
- **WebDAV 路径识别、非持久盘符与规范化去重**：WebClient 使用 `\\主机@SSL@端口\路径`（根 `DavWWWRoot`），走 SMB 445 探测必失败；`HKCU\Network\<盘符>\RemotePath` 仅记持久映射且 WebDAV 存 URL（`WNNC_NET_DAV` 0x2E0000）；`DavWWWRoot`/`@80`/`@SSL@443`/大小写混写会重复添加索引两遍 → 盘符先查 `RemotePath`（URL 转 UNC）再回退 `WNetGetConnectionW`（纯本地表）；全部入口经 `unc::canonical` 规范化（主机小写、`@SSL`、除 443 外显式端口含 `@80`、剥前置 `DavWWWRoot` 除非根或同名子目录），并用 `webdav::rootHolds` 与 `ShareIndexer::distinct` 去重。
- **WebDAV 列目录尾 NUL 与 50 MB 整份下载上限**：`GetFileInformationByHandleEx(FileFullDirectoryRestartInfo)` 在 WebDAV 上名字长度多算结尾 `\0`；WebClient 打开即整份下载到缓存，超 `FileSizeLimitInBytes`（默认 50 MB）直接报 223（`ERROR_FILE_TOO_LARGE`） → WebDAV 与 WSL 均走 `FindFirstFileExW`（`listWithFind`），句柄列目录也防御性去尾 NUL；内容读上限取 `min(用户上限, webdav::fileSizeLimit, 文本 kMaxTextBytes)`，超限只收文件名不重试。
- **WebDAV/WSL 无变更通知与轻量探活**：WebDAV 与 WSL（9P）调 `ReadDirectoryChangesW` 均报 1（`ERROR_INVALID_FUNCTION`），WebDAV `getlastmodified` 仅精确到秒且有短缓存，停服后最长 1 h 仍显在线 → WebDAV/WSL 不挂监听，按核对间隔同步且戳比对到秒（`remotecontent::stampOf`）；在线 WebDAV 每 5 min 轻量 `OPTIONS`/TLS `ClientHello` 探活（`webDavPoll`，HTTPS 不发 HTTP 请求防耗服务商配额），打开启动器距上次 >1 min 异步补探（`ShareIndexer::lookedAt`，网络刚变 5 s 内跳过）。
- **WebClient 未启动误判文件不存在**：`WebClient` 默认手动靠 ETW 触发器启动，文件 API 不会唤醒它而是毫秒级报 3（`ERROR_PATH_NOT_FOUND`）或 53（`ERROR_BAD_NETPATH`），导致历史记录被误删 → 访问 WebDAV 前经 `webdav::startClient` 以普通用户写服务触发器 ETW 事件（`EventRegister` + `EventWrite`，GUID 从触发器读）唤醒并等待就绪；服务起不来或问完又停时，3/53 一律不当作文件缺失（`share::actionSteps`）。
- **HTTP WebDAV 鉴权拒绝码误显“在线 · 0 项”**：HTTP 在默认 `BasicAuthLevel < 2` 下若 `OPTIONS` 回 401，WebClient 直接报 50（`ERROR_NOT_SUPPORTED`）且不发 `PROPFIND`，原先根目录忽略未知错会显“在线 · 0 项”（403→1920，500→31，Digest/NTLM→5） → 根目录 50/1920/31 均判列目录失败（`share::davRefusal`）；HTTP 50 且 `BasicAuthLevel < 2` 时发 `PROPFIND`（`webdav::wantsClearPassword`）区分“仅 Basic 需改 HTTPS”与其他登录/403/500 提示及对应退避。
- **远端内容索引：根比对、合并冲突、半读断网与 `changed` 风暴**：大小写、`\\wsl.localhost\`/`\\wsl$\` 与 `FileIndex::wpath` 尾 `\` 会导致字符串找不到根；整体合并（含空闲 `tidy`）期间远端提交会因文件数变化令合并白做；预读断网不交回错误会把残片永久记成无文字；`ShareIndexer::Callbacks::changed` 频繁触发重扫会反复长持读锁 → 根比对一律 `unc::equal`、路径取 `index.name(root)`；`ContentIndexer::mayReadRemote()` 在 `m_merging`（含 `tidy`）期返 false；`HardDisk::remote` 预读出错返 `FileText::error` 留待重试；`changed` 改调 `remotecontent::Indexer::statusesChanged()` 仅唤醒线程，由内容线程自查状态/根/索引/开关（避锁嵌套）并保固定周期截止时间不被推迟。
- **Win10 LTSC 1809 缺少 `NotifyNetworkConnectivityHintChange`**：`NetworkNotifier` 静态导入 `iphlpapi.dll` 的该函数（Win10 2004 起才有，`_WIN32_WINNT=0x0A00` 拦不住）导致 1809 启动直接报错 → 高于 1809 的系统 API 一律 `GetProcAddress` 动态获取、缺则降级跳过（网卡与地址变化照常报），发布前用 `dumpbin /imports` 审计导入表。

## 搜索调度、查询语义、Everything 兼容与系统入口

- **名字搜索排在内容扫描之后与 `UsnApplier` 隐藏锁链**：单线程 `SearchEngine` 会把名字搜索堵在慢内容扫描（卡在 Defender/HDD/`WinShunExtract`/读盘 `lookup`，仅文件间检查取消）与可移动盘查询后；分线后若 `UsnApplier::apply` 持 `FileIndex` 写锁调 `ContentIndex::markChanged`，仍会被旧扫描 `lookup` 的 `ContentIndex` 共享锁拖住而堵死名字读锁 → `SearchEngine::Lane` 拆成名字、内容/走盘、可移动盘（`drivesLoop` 跟踪 `m_latestNames` 不被“全部”后续内容请求冲掉）三线程并共用 `m_latest`；`UsnApplier::apply` 先释放 `FileIndex` 写锁再调 `markChanged`（`readJournal` 仍持日志锁保证不压缩、ID 不变）。
- **长读锁在 SRWLock 下被写者截断与多搜索框争用引擎**：Windows 上 `std::shared_mutex`（SRWLock）一旦有写者排队就拦新读者，快照保存/内容全扫持读锁遇 USN 写入会卡搜索；启动器与对话框旁搜索框共用同一引擎时 `submit()` 互废请求致结果长灰 → 长读操作（保存快照、内容全扫、`contentUnsureOf`）改用 `FileIndex::longReadLock()`（先共享锁写者门再拿读锁，`writeLock()` 先独占写者门），让写者候在门外、搜索畅通且长读间仍并发；对话框搜索框独立懒建 `App::m_dialogEngine`。
- **搜索线程碰盘卡死与忙机下慢盘重复等满 100 ms**：搜索线程直接 `QFileInfo::exists` 查最近项遇断联共享或休眠移动盘卡 10–15 s；仅按盘线程开始干活时刻（`busySince`）判慢，CPU 忙导致新线程延迟启动时会反复等满 100 ms → 搜索线程不碰盘，`RecentOnDisk` 按盘/共享拆独立线程探测，搜索最多等 100 ms，超时记 `missedWait` 在该盘回答前不再等待（用缓存或暂不列），回答后再看 `lastTook`；测试用 `WINSHUN_SILENT_SHARES` 绕开 Windows ~30 s 负缓存，用排队连接 + 请求号代替 `QSignalSpy::wait()`。
- **刚打字按 Tab 误入旧结果与自动选中抢 Tab**：后台出新行前（`m_replacePending && searching()`）屏幕仍显旧行，立刻按 Tab 会拿旧第一行补全或误切范围；`ListView.currentIndex` 分不出自动选中还是用户选中 → `Launcher::rowsComing()` 为真时路径补全不算数，`autocomplete` 记 `m_tabHeld` 待 `showRows` 换新行且查询未变时排队重按（输入/换范围/重开清空）；用户按键/点击/右键由 QML 显式调 `Launcher::chooseRow` 记录路径。
- **路径排序慢、早期纪元时间戳与 `FileSize` 解包进位**：MFT 记录号不按目录连续，分片内反复拼路径排序耗时 5 s；解压包/npm 的 `1970-01-01`/`1980-01-01` 时间霸占“最早在前”；float 位打包的 `FileSize` 解包写 `f + 0.5f` 会把 `16777215` 进位成 `16777216` → 路径排序前经 `NameSearch.cpp` `folderRanks` 给全部目录按树序整型编号，比较只比整数与名字；`1980-01-02 00:00 UTC` 前由 `knownTime` 视作未知（排序垫底、不入最近、不显日期，索引存原值）；`FileSize` 先转 `double` 再 `+ 0.5` 取整（排序筛选直接按无符号整数序，`0xFFFFFFFF` 表未知）。
- **优先文件类型排序/性能与 `QSettings` 空列表 `@Invalid()`**：同名组仅靠加分翻不过文件夹或程序目录 `-35` 扣分，且用最大加分预筛 `heap.mayAccept` 因分片堆（`kSliceSize=16384`）门槛低放进过多条目反而更慢；`QSettings` 将空 `QStringList` 存成 `@Invalid()` → 同名组用 `exactFirst` 优先排，其余匹配加 `PreferredTypes::kBonus`（12），完全同名优先类型还回程序目录扣分；直接用定长表 `PreferredTypes` + `FileIndex::fileName(e, extLength)` 一次查清；读列表靠 `readOrDefault` 检查 `contains(key)` 区分“用户清空（`@Invalid()`）”与“未设置”。
- **输入 `~$` 搜不出被跳过文件**：默认跳过规则为 `~$*`，但查询语法把词尾 `$` 当行尾锚点（只剩 `~`），配不上跳过规则无法反显 → `SearchEngine.cpp` 的 `hiddenOf` 用同一通配符比对输入词（支持 `^` 开头或带引号 `"~$"`），匹配即取消跳过。
- **Everything IPC 路径前缀搜索语义**：Everything 规则下含 `\` 的词与完整路径比对，盘符/UNC 起头无尾 `\`（如 `file:"D:\images"`）匹配路径前缀（含 `images2`、`images.jpg`），尾 `\` 才限定目录内 → `EverythingIpc::translate` 将盘符/UNC 起头且无通配词收入 `Search::pathStarts`，`find` 定位父目录取末段前缀匹配子项作 `NameSearchOptions::within` 交 `NameSearch`（多前缀须互为前缀否则空集）；仅末段通配（`D:\images\*.jpg`）拆目录 + 名字通配，排除项（`!D:\x`）沿用原逻辑。
- **Windows 设置清单的 URI、安全中心、关键词归属与正则开销**：`PolicyIds` 按字母序排、首项未必是页面本身；安全中心条目写包系列名致 `SHLoadIndirectString` 失败，换完整包名（`GetPackagesByPackageFamily`）在中文系统仍只给英文；补充词加到所有任务条时同分会选到名字最短的子任务；循环现建 `QRegularExpression`（~3000 次）多花 1.5 s → `choosePageUri` 优先页面 ID 匹配、次选前缀、最后取首项；安全中心按 HostID 跳过，在 `places.txt` 维护中文名与 `windowsdefender://`；补充词只加在 `AAA_<页面 ID>` 本体条目上；切分用 `static const` 正则或手写 `splitKeywords`。
- **MSIX 应用名随首选语言而非显示语言**：商店/MSIX 应用名按“首选语言列表第一项”而非系统显示语言取值（`SHLoadIndirectString` 无视 `SetThreadPreferredUILanguages`，读 PRI 报 `0x80070490`，无包标识调 WinRT `ResourceManager.Current` 报 `0x80070002`） → 自带应用在 `src/core/apps.txt` 按 AppUserModelID 记中英双名（含拼音匹配，按命中语言显示）。
- **已删程序残留 `shell:AppsFolder` 且复查不能唤醒机械盘**：手删程序后只要开始菜单 `.lnk` 还在，`shell:AppsFolder` 仍会列出且开始菜单指纹（`installedAppsFingerprint`）不变 → `AppCatalog` 后台核查本机固定盘桌面应用目标（`presentApps`/`appTargetGone`），仅 Windows 明确报文件/路径不存在时过滤（缺盘/可移动/网络/拒绝访问一律保留）；不在每次开搜索框时查以免唤醒机械盘，仅在重读发布前、打开失败（`checkPrograms`）及最多每 5 min（`programsCheckDue`，不改 `m_loadedAt` 以保 10 min 强制重读）核查，“重建索引”同步重读应用列表。
