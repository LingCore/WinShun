# 全局输入、剪贴板、对话框与资源管理器踩坑

## 双击触发、全局快捷键、低级钩子与前台切换

- **键盘 Raw Input 与链头 `WH_KEYBOARD_LL` 互斥导致钩子整体静默（#4/#10/#175）**：本进程登记了键盘 Raw Input（无论 `RIDEV_INPUTSINK`/`EXINPUTSINK`/无标志）且自家窗口在前台、自有 LL 钩子排链头时，Windows 不仅跳过本进程钩子，还会跳过整条链后续他进程钩子（如 AHK）；`RIDEV_NOHOTKEYS` 会误伤含自家在内的全部全局热键 → 凡本进程窗口在前台期使用 LL 钩子（`ShortcutCapture`、`TypeToSearch` 持键、`numberkeys::Hook`），须统一经加锁引用计数的 `KeyboardRawInputAside` 暂撤键盘 Raw Input 并在结束时归还（与 `KeyListener` 自身增删共锁；`GetRegisteredRawInputDevices` 查个数须兼容返回 `0` 与 `-1` + `ERROR_INSUFFICIENT_BUFFER` 并重试最多 4 次；钩子线程禁止写文件日志）。
- **鼠标 Raw Input 按进程单份覆盖**：`RegisterRawInputDevices` 对同一 HID 用途是进程级登记，另窗登记会直接覆盖、`RIDEV_REMOVE` 会一并全撤 → 仅由 `KeyListener` 统一登记鼠标 Raw Input，把同一条 `WM_INPUT` 分发给 `DoubleTapDetector` 与 `DoubleClickDetector`（改设置先撤旧再重建）。
- **严禁在 `win::bringToFront` 中用 `AttachThreadInput` 强抢前台（#111）**：连接原前台线程会把 `SetForegroundWindow` 变成同步 `SendMessage`，原线程忙 2–5 s（未到 `IsHungAppWindow` 5 s）或慢处理 `WM_ACTIVATE` 会把 Win顺 界面线程彻底冻住（子线程连也无效） → 彻底禁用 `AttachThreadInput`，改异步激活。
- **先探前台权限再激活，避开被拒的后台假激活（#111）**：被拒的 `SetForegroundWindow` 仍会在本线程同步派发 `WM_NCACTIVATE`/`WM_ACTIVATEAPP`/`WM_ACTIVATE`/`WM_SETFOCUS` 做后台假激活（耗约 14 ms） → 先调 `AllowSetForegroundWindow(GetCurrentProcessId())` 探测，返回 `FALSE` 则先发空输入再激活，返回 `TRUE` 直接激活（被拒再补空输入）；启动器显示 1.5 s 内失活不强抢，记录 `Launcher: lost the front`（含抢占窗类、进程及期间有无输入）供排查。
- **窗口迟到时二次触发反把刚出的窗口关掉（#111）**：仅按处理时刻窗口可见判“再按关闭”，会把窗口出现前排队的第二次触发当成关闭；双击若按第二下抬起算仍留有约 300 ms 空子 → 每次触发携带 64 位事件时间（双击记**第一下按下** `Tap::firstPress`，服务通过 `kTap` `lParam` 高 32 位传间隔；热键用 `GetMessageTime()` 并防 49.7 天回绕），仅在真正解除遮罩（`m_*RevealedAt`）满 200 ms（`kSeenBeforeMs`）之后按的才算关闭/展开，之前仅 `ShortcutAction::Raise`。
- **全屏程序“打字时隐藏指针”误判为游戏（#111）**：系统开启 `SPI_GETMOUSEVANISH` 时打字会隐藏光标，与游戏藏光标同为 `CURSORINFO.flags == 0` → `GameGuard` 对锁/捕获鼠标（`ClipCursor`/`hwndCapture`）照旧拦截；仅铺满屏幕且隐藏时由 `PointerWatch` 听 `EVENT_OBJECT_SHOW`/`HIDE`，满足系统开启该选项、隐藏前 100 ms（`kTypingHideMs`）内有新非修饰键按下（`KeyPresses` 滤除自动重复，1.5 s 超时重置防丢抬起，保留 10 s 内最多 256 条并在双击时复判防主线程忙挤掉）、无鼠标键按下、藏后指针未动即判打字藏光标放行。
- **反作弊护着的游戏读不出程序名，名单与全屏判断全部失效（#121）**：对战平台（网易、11、KK 等）启动的 `War3.exe` 这类游戏由反作弊驱动拦下对它的句柄，`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 被拒或拿到的句柄读不了 `QueryFullProcessImageNameW`，程序名为空；`GameGuard` 把空程序名当作桌面或 Win顺 自己的窗口直接放行，于是“在这些程序里不响应”、全屏与游戏判断一起失效 → `foreground::programOfProcess(pid)` 打不开就从 `CreateToolhelp32Snapshot` 的进程列表按 PID 取文件名（不需要任何进程句柄），`tst_appearance` 的 `programOfGuardedProcess` 用空 DACL 建的进程覆盖。路径缓冲按长路径（32768）给，`MAX_PATH` 装不下的程序同样会读空。
- **UIAccess 监听进程晚报、工作集修剪与休眠唤醒硬缺页（#111）**：跨进程双击报告可能晚于 1 s 被丢，休眠清备用列表后 `IdleTrim` 交还的页会造成 5000+ 次硬缺页 → 本地 Raw Input 认出双击先暂留 `kBackupMs`（120 ms），服务未到即走 `own-backup` 兜底并按事件时间永久去重（仅防 24.8 天回绕），晚报 1–3 s 仅在之后无新输入（`GetLastInputInfo`）且未切前台时采用（管理员前台受 UIPI 限制只能等服务）；监听进程设 `SetProcessWorkingSetSizeEx(..., QUOTA_LIMITS_HARDWS_MIN_ENABLE)` 硬下限（≤16 MB，挡系统修剪但不对抗 Mem Reduct 等外程序 `EmptyWorkingSet`）；唤醒（`PBT_APMRESUMEAUTOMATIC` 或 `GetTickCount64` 与 `QueryUnbiasedInterruptTime` 差 >10 s 提前检测）后 5 s/6 s 预热启动器与剪贴板，醒后首次使用前暂停 `IdleTrim` 且把不激活剪贴板/钉住启动器/对话框栏计为在用。
- **外部慢 LL 钩子把第一下拖成“长按”（#111）**：他程序界面线程慢 `WH_KEYBOARD_LL` 卡住第一下按下后，松开与第二下按下排在后面同批打时间戳，使第一下时长超过 `maxPressMs`（300 ms） → `DoubleTapDetector` 对第一下超时但松开与第二下按下间隔 ≤16 ms（单时钟跳）、同键且鼠标未动的情形判为钩子排队（记录 `queued_ms`）照常触发；两下都慢则记 `held` 供诊断。
- **录制 `Alt+Space`/占用热键与录制焦点残留（#4）**：Qt 6.12 `qwindowskeymapper.cpp` 将纯 `Alt+Space`/`Alt+Tab`/`Alt+Esc`/`Alt+F4` 留给系统不生成 `QKeyEvent`，被他程序 `RegisterHotKey` 占用的组合也收不到；`HotkeyRecorder` 隐藏或失活时不自动清 `focus`，窗口回来继续吞 `Win` → 录制期间由 `ShortcutCapture` 装 `WH_KEYBOARD_LL`（并经 `KeyboardRawInputAside` 暂撤键盘 Raw Input）提前拦键后在主线程发 `QKeyEvent`，只吞录制开始后按下的键及对应抬起（`Win` 全吞防弹开始菜单）；`HotkeyRecorder` 在不可见或窗口非 active 时按 `focus` 判停，`clearFocus()` 直接把 `activeFocusItem.focus = false`。
- **接管他程序占用的数字快捷键与抬起/重复排空（#175）**：第三方 `RegisterHotKey`（如 PixPin `Ctrl+1`）先于前台窗口收键；选行关窗时立刻卸钩子会让未松手的自动重复落给对方触发其热键 → 自家窗口在前台且存在冲突时由 `numberkeys::Hook` 临时装钩子（同时暂撤键盘 Raw Input，放行键转交给 `KeyListener::hookedKey` 拼 `RAWKEYBOARD` 保双击/拖放可用，拿走的数字换掩护键防修饰键算单按）；关窗走 `Hook::drain()` 停拦新键但继续吞已拦键的重复与抬起至全松（上限 2 s）再卸钩子还 Raw Input；自家快捷键仍让出并加删除线。
- **钩子切勿按 `LLKHF_INJECTED` 一刀切放行**：放行所有注入键会漏掉 AutoHotkey、PowerToys 改键、屏幕键盘及自动化测试输入 → 所有 Win顺 自己发出的模拟键（含 `closeShellFlyout` 的 `Esc`）统一标记 `dwExtraInfo = kOwnInput`，钩子只放行带该标记的键。
- **常驻窗口系统关闭销毁 HWND 与跨线程首帧竞态（`FrameReveal`）**：主搜索、剪贴板、`DialogBar`、图片编辑与 OCR 窗口仅创建时绑定 `WindowFrame`/`Placement`/`WindowLogo` 或同伴句柄，走 `QWindow::close()` 会销毁 HWND；渲染线程 `frameSwapped` 早于界面线程解除 cloak 清标志或无代号校验会导致旧帧误解新一轮 cloak；Qt 判可见而原生隐藏时重复 `show()` 无效 → 常驻窗口拦截系统关闭改走业务隐藏保留 HWND；跨渲染线程显隐经 `FrameReveal`（及 `DialogBarVisibility`）在同步帧时记显示代号，由界面线程核对代号后完成状态转换并解除 cloak，所有隐藏路径无条件清理 Logo 与等待状态。
- **`QAbstractNativeEventFilter` 投递消息时 `result` 为空指针**：`WM_DROPFILES`、`WM_HOTKEY` 与线程消息经消息队列派发时 `result == nullptr`，无条件 `*result = 0` 直接触发 `0xc0000005` 崩溃 → 所有原生事件过滤器写 `*result` 前必判非空。
- **独立探头图标拖动滞后、`QVariantAnimation` 跳变与帧等待死锁**：独立 `WindowLogo` 接 Qt `xChanged`/`yChanged` 在系统移动循环里晚一帧；`QVariantAnimation` 停在终点时改起止值会按旧进度发 `valueChanged` 瞬移窗口；`DCompositionWaitForCompositorClock` 在显卡重置或 RDP 断开后可能内核永久卡死 → 给宿主窗口 `SetWindowSubclass` 在 `WM_WINDOWPOSCHANGED` 内按 `GetDpiForWindow` 当场挪动 Logo（动画期由 `WindowLogo::follow(Placement*)` 同步位移透明度）；重设 `QVariantAnimation` 用 `QSignalBlocker` 挡信号后手动走第 0 步再 `start()`；帧同步改独立线程 `DwmFlush`（无显示器连续瞬返时改 `Sleep(15)` 防空转）。
- **控制台程序因父进程为 `explorer.exe` 闪退与桌面从 `ShellWindows` 脱落（#139）**：Go cobra/mousetrap 等 CLI 工具检测到父进程为 `explorer.exe` 会提示后直接退出；久开 `explorer.exe` 的桌面从 `ShellWindows` 脱落（`FindWindowSW(SWC_DESKTOP)` 返回 `S_FALSE`）时，`rundll32 ShellExec_RunDLL` 对文件夹/`shell:`/URI 静默返回 0 什么也不开且不认 `/` → `executeUnelevated` 检测 PE 子系统（含 `.lnk` 与 `shell:AppsFolder` via `PKEY_Link_TargetParsingPath`），控制台程序绕开 explorer 走 `rundll32 ShellExec_RunDLL`（`/`→`\`，配 `CreateEnvironmentBlock` 重建环境防继承 Win顺 私有变量；需 `CREATE_NO_WINDOW` 时由 `WinShun.exe --run-hidden` 中转），GUI 程序照走 explorer（满足 Foxit 调用者检查）；桌面脱落时借 `ShellWindows` 任一文件夹窗口 `Application::ShellExecute`，全无时用外壳令牌起 `explorer.exe "目标"`（盘根 `D:\` 不加引号防 `\"` 转义，普通 exe 仍走 `rundll32` 避免工作目录变 System32）。

## 剪贴板历史、按键路由、粘贴与 UIAccess 显示

- **`Win+V` 被资源管理器占用（错误 1409）**：`explorer.exe` 启动时注册 `Win+V`/`Win+Shift+V` → 写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\DisabledHotkeys` 加 `V` 并重启资源管理器生效，不装常驻 LL 钩子硬抢。
- **重启资源管理器不能指望 `AutoRestartShell`**：Winlogon 只重启登录时它拉起的原外壳，曾被重启过的 `explorer.exe` 结束后不会再起；用管理员令牌启动又会使外壳及子程序全部提权 → `winv::restartExplorer` 结束前先复制原外壳普通权限令牌，3 s 无新外壳则用 `CreateProcessWithTokenW`（失败退回以普通 `sihost.exe` 为父进程）拉起未提权外壳。
- **SQLite 空串变 NULL、空间不回收与大条目阻塞主线程**：`QString()`（null）绑进 SQLite 报 `NOT NULL` 失败；`PRAGMA incremental_vacuum` 在 Qt `QSqlQuery::exec` 下因无结果列每次只释放 1 页；大文本/RTF/HTML 在主线程写库卡 ~150 ms → 文字列绑前转 `""`，空二进制显式绑空 `QVariant(QByteArray)`；建库在 `journal_mode=WAL` 之前设 `auto_vacuum=FULL` 并配 `journal_size_limit`（1 MB），旧库检查 `PRAGMA auto_vacuum != 1` 后执行一次 `VACUUM`；数据库连接移至 `ClipStore` 独立写库线程（内存沿 `sqlite_sequence` 预分配 id，读盘入同队列保序，失败经 `Listener::lost` 撤回）。
- **禁止 Qt 默认剪贴板监听与自身写后重读抢锁**：Qt 内置监听会在剪贴板每次变动时让每个 QML `TextInput`/`TextEdit` 在主线程读剪贴板更新 `canPaste`，撞锁触发 `Sleep(50)`×3 卡主线程并刷 `Retrying to obtain clipboard.`；粘贴写剪贴板后 Win顺 自己 40 ms 监听再打开也会撞上目标 `Ctrl+V` 导致贴空 → `main.cpp` 调 `QGuiApplication::clipboard()->blockSignals(true)` 改统一走后台 `ClipboardWatcher`；写完即记 `GetClipboardSequenceNumber()`，监听见同序号跳过，置顶由 `writeNow` 直接通知。
- **划词翻译（有道词典）借剪贴板复制文件/图片，排除进程拦不住**：有道对非文本控件发模拟 `Ctrl+C`，此时剪贴板所有者是前台程序（DOpus/微信），排除有道只能拦约 1.1 s 后它超时放回的那一下 → `ClipboardWatcher` 40 ms 照常读取（防连复制覆盖），但无文字条目先暂压 `kHoldMs`（1.5 s）；期间剪贴板被既非原复制者、非前台、非 Win顺 的第三进程改写即判借用放回并丢弃，打开面板时 `recordHeldNow` 立即吐出。
- **不抢焦点剪贴板与 `KeyRouter` 交互细节（#9/#42）**：激活面板会关掉 VS Code 命令面板与浏览器下拉框；不激活窗拖 `HTCAPTION` 会触发系统先激活使 `routedForeground` 误停路由；`QKeyEvent::modifiers()` 会对修饰键自身位异或翻转；过早卸钩子让 `Enter`/`Esc` 孤立抬起落进目标；链头钩子直接返回 1 会拦截下游 AutoHotkey → 在他程序上不激活开窗并由 `KeyRouter` 转发；`WindowFrame` 截 `WM_NCLBUTTONDOWN(HTCAPTION)` 改 `DefWindowProc(WM_SYSCOMMAND, SC_MOVE | HTCAPTION)`，`routedForeground` 复核 `GetForegroundWindow()`；修饰键事件传按下前状态；收起走 `KeyRouter::drain` 拦完已吞键抬起（上限 2 s）再卸；`handleKey` 先 `CallNextHookEx`（之前不改状态防下游 `SendInput` 嵌套重入），返回非 0 说明被下游拿走则放手，返回 0 才吞并返回 1（已吞键重复/抬起亦先传下游）。
- **剪贴板开着却不接键的三类失效与自愈（#86）**：（1）LL 钩子超时迟到后系统把按下给前台，再吞抬起会让系统以为键卡住致下次走 `already_held` 再漏 → 抬起时见系统键仍按着即连带放行（`late_answers`）；（2）钩子停摆无失效通知 → 路由线程每 250 ms 比对 `GetLastInputInfo` 与钩子进/出时间戳，落后 >500 ms 且目标仍在前台即先装新钩子再卸旧钩子（`hooks_recovered`），同时搜索框用被动 `TapHandler` 接点击调 `KeyRouter::refresh`（不清空/全选，退休后忽略）；（3）`showClipboard` 等文字光标（≤100 ms）期间若前台已切，后装钩子收不到切换事件而永卡 `OtherForeground` → 等完光标重读 `GetForegroundWindow()` 建路由，钩子线程装好后复核，每次 `OtherForeground` 放行时复核并报 `foreground_missed` 收起面板。
- **不抢焦点打中文与有焦点 IME 组字拦截（#42）**：`KeyRouter` 不经输入法，切焦点打中文会关命令面板；`activateClipboard` 若未核对激活成功就停转发会两头落空；有焦点且 `preeditText` 非空时 `Alt+5` 的 `WM_SYSCHAR` 会被 Qt `QQuickTextInput` 误插成字 → 维持不抢焦点 + 拼音搜索，中文布局单按 `Shift` 补 `vkE8` 后不改窗高地提示拼音；`activateClipboard` 仅在 `GetForegroundWindow()` 确为自身才停转发；有焦点组字期间普通键留给 IME，带 `Ctrl`/`Alt` 的按键显式吞掉。双拼、五笔用户打不了拼音字母，转发模式下搜不了中文 → 打开时仍不抢焦点，但**点搜索框即 `Clipboard::wantFocus`**（先刷新路由再 `focusNeeded`，被系统拒绝时路由照旧），窗口拿到焦点后输入法正常组字，`Enter` 照常激活原窗口粘贴；`Shift` 提示时框内占位语仍只说拼音（框在按钮之间只放得下十来个字，再长就被省略号截断），底部提示行说明“点一下搜索框用输入法”，探针对两处都查 `truncated`。验证：`--probe-runtime <dir> --field-focus-check`（真实点击 + `KEYEVENTF_UNICODE` 打汉字 + `Enter` 粘贴进另一进程的文本框）。
- **按住剪贴板快捷键连按：消息配对、修饰键防误触与粘贴防打断（#107）**：`WM_HOTKEY` 的 `GetMessageTime()` 可晚于钩子 0–16 ms 不能按时间配对；热键吞掉按下后先松 `Alt`/`Shift` 对前台形成单按触发菜单栏或切输入法；松手 80–90 ms 后发 `Ctrl+V` 过钩子链期间用户再按 `Ctrl` 会被粘贴最后的 `Ctrl` 抬起清空键态 → 仅在不激活剪贴板时装 `HoldWatch`，利用同线程队列 FIFO 在钩子里先 `PostMessage` 给紧随的 `WM_HOTKEY` 消费；装钩子含 `Alt`/`Shift`/`Win` 立即补 `vkE8`；粘贴前目标修饰键已按着则省发其按下/抬起，按住连按模式经 `guardPaste` 盯住粘贴键过钩子链（含 `CallNextHookEx` 返回后二次校验 `Guard::agrees`），途中收用户真实修饰按下即拦自身修饰抬起，其他已按修饰键先补 `vkE8` 临时抬起、粘贴完按回（中途松手则拦按回）；非按住模式不装钩子不抬起其他修饰键，写剪贴板前等修饰键松开（上限 1.5 s）。
- **粘贴时机竞争、自家输入框粘贴与管理员目标粘贴（#8/#277）**：目标刚回前台焦点未落稳（UWP 跨进程 `GetGUIThreadInfo` 不准），钉住连点时第三方剪贴板监听正占锁；自家输入框切剪贴板页会丢 `TextInput` 选区；普通权限 `SendInput` 发往高完整性窗口会被 UIPI 静默丢弃 → 无论是否切前台均走 `m_focusTimer` 等 `kSettleMs`（60 ms），若 `GetOpenClipboardWindow()` 非空继续等（上限 300 ms）再发粘贴键（钉住时接管键盘全选搜索框、粘贴完清多选）；自家框打开剪贴板前保存光标与选区，粘贴切回并在全选后恢复选区，用 `QInputMethodEvent` 直写；管理员目标经 `servicepaste::paste` 请索引服务拉起 UIAccess 助手 `--paste-keys <hwnd>`，仅对最前管理员窗口按单次粘贴键，不传自定义键值/内容，不碰普通/SYSTEM 窗口与管理员文件对话框（#57）。
- **Photoshop / Illustrator 只在被激活时读剪贴板，粘贴前要让它“重新激活”（#432）**：这两个程序在来到前台时读一次剪贴板并缓存，之后的 `Ctrl+V` 贴的是缓存；不抢焦点的剪贴板窗口从不让它们离开前台，于是每次贴出的都是上一次读到的图（Windows 自带 `Win+V` 同样如此）→ `paste::readsClipboardOnActivation` 按进程文件名（`Photoshop.exe`、`Illustrator.exe`，忽略大小写）认出目标，`paste::reactivate` 先把前台交给 Win顺 自己一个看不见的 1×1 工具窗口（屏外、无任务栏按钮），剪贴板写好后立刻交回，再等 `kReactivatedSettleMs`（150 ms）才发 `Ctrl+V`；目标保持前台的两条路都要走（路由键或钉住的剪贴板窗口、直接粘贴：按住连按与纯文本粘贴），剪贴板窗口拿过焦点（点了搜索框）后回到目标的那条路同样等 150 ms；**只复制不粘贴**（条目上 `Ctrl+C`、右键“复制”，用户随后自己在 Photoshop 里按 `Ctrl+V`）时，复制完若前台就是这类程序也立刻重新激活一次（0.45 后的 #432 复现，修前贴出旧图）。重新激活时前台短暂落到替身窗口，`App::routedForeground` 须按 `paste::isStandIn` 忽略，否则路由中的剪贴板会当作“切到别的程序”而关掉。别的程序焦点始终不动。验证必须用真 Photoshop：`docs/validation/issue432-photoshop-paste/harness/photoshop-paste.ps1`（探针 `--probe-runtime --activation-paste-check <hwnd> --renderer d3d11`，`-ClickClipboard` 先点搜索框、`-CopyFirst` 走复制再自己粘贴）；本机等待 0/40/80 ms 都能贴对，150 ms 是给慢机器的余量。探针不带 `--renderer d3d11` 时是软件渲染的分层窗口，空白处会被点穿（见 ui-qml-and-windows.md 的 Mica 条），点击类检查一律带上。`tst_paster` 只覆盖程序名规则与重新激活流程。

- **独占全屏游戏上打开剪贴板，面板一闪就没或根本看不见（#452）**：独占全屏的画面上放不了别的窗口，而“不抢焦点地显示一个置顶窗口”在各系统上结果不同：Windows 11 会让游戏退出全屏（游戏随即自己最小化，前台落到它后面的窗口，`routedForeground` 曾把这当成“用户切到别的程序”收起面板）；Windows 10 22H2 则让游戏继续独占屏幕，面板已显示却看不见，`KeyRouter` 还在暗中拿走游戏的按键（诊断包里是 `trigger show` 后 2 s 内没有 `screens` 变化，`clipboard-hidden` 的 `target_minimized=false`）→ 打开时前台是独占全屏的程序（`panelTakesFocus`，`GameGuard.h`，`tst_core` 覆盖）就**不走转发、直接拿焦点**（`m_clipOver.focusTaken`，记 `clipboard-over-exclusive`），游戏因失去焦点退出全屏，两个系统行为一致；也不再为它等文本光标。拿不到前台（`front=false`）就收起（`why=front-refused`），不留一个看不见的面板。未被识别成独占全屏、但面板一显示就自己最小化的全屏窗口仍由 `leftFullScreenForPanel` 兜底（铺满显示器、目标已最小化、打开后没按过非修饰键、`kFullScreenExitMs` 3 s 内 → 停路由接过焦点，记 `clipboard-kept`）。之后把游戏带回来时面板必须先走：粘贴时（`m_targetLeft` 或目标已最小化）先 `dismissRequested` 再 `paste::activate`，这种收起不留淡出画面（`fadeOutCopy` 的置顶小窗会在游戏重新全屏时又盖住它一次，实测游戏再次最小化、粘贴落空）；`Esc` 或再按一次快捷键关面板同样把游戏带回前台（`Clipboard::dismiss`，游戏没最小化、只是退到后面时也一样）。游戏退出全屏本身是系统行为，不去拦。验证：`--probe-runtime <dir> --full-screen-game-check <hwnd>` 配替身游戏 `docs/validation/issue-452/fsgame.cpp`（真显卡上系统报告为独占全屏、失去焦点后窗口仍留在原地，回到前台会重新进全屏；虚拟机没有真显卡，只能走“被置顶窗口盖住即自己最小化”的模拟路径；带分辨率切换的真实游戏两处都测不到，靠反馈者的诊断包确认）。
- **控制台光标定位、预览展宽防移位与开合动画（#377）**：经典控制台 `GetWindowThreadProcessId` 返回内部进程而非 `conhost.exe` 致 `GetGUIThreadInfo` 失败；预览展宽左挪窗口会把鼠标下的眼睛按钮移成固定按钮；关闭剪贴板需立即还焦点粘贴不能等 120 ms 淡出 → 前台窗口 `GetGUIThreadInfo` 失败改调 `GetGUIThreadInfo(0, ...)`，UIA 焦点元素按光标落窗核对而非 PID；`Placement::roomRight` 在 280–400 逻辑像素自适应预览宽，余量够时不挪窗；打开在 `uncloakClipboard()` 前先 `Placement::slideIn()` 避免首帧闪不透明，关闭由 `win::fadeOutCopy()` 用 `BitBlt(SRCCOPY)` 截含阴影画面进分层穿透小窗淡出，真窗立刻隐藏（验证须比对关闭前后同区像素差）。
- **Word/WPS 公式对象与复制文件进 WPS 变路径（#58/#130）**：Word 公式含 `MathML`/RTF（`\moMath`）/EMF 无 HTML，嵌入公式对象含 `Embedded Object`/`Object Descriptor`/RTF（`\objdata`）/EMF/PNG 无纯文本，只存 PNG 会粘成死图；`QMimeData::setUrls` 在 Windows 附带 `UniformResourceLocatorW` 加 `setText` 路径，WPS 优先认文字致图片粘成路径 → 原样保存公式/嵌入对象格式并用 EMF 绘预览；结果列表复制文件用 `dragout::fileNamesObject` 经空 Shell 数据对象只写 `CF_HDROP` 与 `Preferred DropEffect` 后 `OleFlushClipboard`（不用会调 `SHParseDisplayName` 致离线网络路径卡主线程的 `dragout::dataObject`）。

## “打开 / 保存”对话框与第三方文件管理器

- **地址栏输入框懒创建、不感知 DPI 建出即隐藏与坐标换算（#104）**：新式对话框地址栏平时只有面包屑（`Breadcrumb Parent` > `ToolbarWindow32`），`ComboBoxEx32`→`Edit` 首次单击空白才建、之后隐藏；不感知 DPI 对话框在 150% 下单击建出的输入框 `IsWindowVisible` 恒假，且按物理像素投坐标会点到窗外 → `addressBox` 不要求可见，取坐标前用 `SetThreadDpiAwarenessContext(GetWindowDpiAwarenessContext(面包屑))` 切到目标坐标系（用完还原），不存在时才投 `WM_LBUTTONDOWN`/`WM_LBUTTONUP`（等 ≤300 ms、最多试 3 次），核对为文件夹后 `WM_SETTEXT` 填 `文件夹\`（防 `a.txt` 类名文件夹误判）、读回核对并 `SendMessage(WM_KEYDOWN, VK_RETURN)`（`FileDialog.cpp` 与提权 `DialogNav.cpp` 统一；`FakeFileDialog` 单测需把导航放 `std::async` 线程防主线程 `WM_GETTEXT` 死锁）。
- **不要往文件名框填文件夹再按确定**：选文件夹对话框（`FOS_PICKFOLDERS` / `edt1`）填路径确定会直接选中关闭，另存为会冲掉已填文件名 → 仅 XP 风格对话框（无地址栏）或新式打开/另存为地址栏彻底失效时退回文件名框（先备份原名、填 `文件夹\` 确定、等面包屑变化后填回原名）；`FOS_PICKFOLDERS` 绝不退回文件名框。
- **对话框晚显示、MRU 改大小、最大化卡死与差 1 像素换边（#104）**：`EVENT_SYSTEM_FOREGROUND` 到达时对话框常尚未 `WS_VISIBLE`、控件滞后 1.5–4 s 建出，且不可见时按 `ComDlg32\CIDSizeMRU` 重设尺寸；被记成 `WS_MAXIMIZE` 又无 `WS_MAXIMIZEBOX` 会占满工作区且拖不动；不感知 DPI 逻辑步进与 Qt 物理取整会差 1 px 导致换边或越界 → `DialogJump::await` 挂对话框线程钩子（`EVENT_OBJECT_CREATE`–`FOCUS` 及 `REORDER`）配合 30→800 ms 退避等满 5 s；等 `EVENT_OBJECT_SHOW` 可见后再 `DialogBar::makeRoom`（多留 1 逻辑像素，`place()` 按 Qt 物理边夹进工作区）；无最大化按钮却已最大化的先 `ShowWindowAsync(SW_SHOWNOACTIVATE)` 还原，等解除最大化后再量；点进搜索框时等 `MouseButtonRelease`（60 ms 兜底）再展建议列表，防向上展开误点第一行。
- **前台事件提前、资源管理器误发前台事件与过渡窗打断自动转（#7/#104）**：`EVENT_SYSTEM_FOREGROUND` 回调瞬间 `GetForegroundWindow()` 常仍是旧窗；后台资源管理器 `Navigate2` 会误发自己前台事件；后台弹出的对话框被调上来因已是线程 `hwndActive` 不发前台事件只发桌面 `EVENT_OBJECT_REORDER`；`Alt+Tab`/任务栏切换经过渡窗口会打断相邻判定 → `onForeground` 一律以 `GetForegroundWindow()` 为准，事件窗不在前台不直接丢弃而交 `await` 听 `REORDER`；自动转记 `m_lastDialog` 与 `m_wentToManager` 跨过过渡窗（仅遇自家同伴取消）。
- **跳转前后地址栏空、焦点未恢复与跳后停面包屑**：刚出现时面包屑文字为空；从搜索框还前台后对话框尚未处理完激活，此时读焦点为空；回车后焦点停在面包屑 → 自动转前先 `filedialog::waitForLocation` 等面包屑 `TB_BUTTONCOUNT > 0` 且文字非空（≤1.5 s）；操作前 `waitForFront` 等成前台且 `GetGUIThreadInfo` 有焦点控件（≤1 s）并记录原焦点；回车等输入框隐藏后 `SendMessage(对话框, WM_NEXTDLGCTL, 原控件, TRUE)` 归还（原在地址栏不还）。**只归还还留在地址栏里（或落空）的焦点**：等面包屑变化最长 1.5 s，慢文件夹期间用户已点进文件列表的，焦点是用户的，再抢回文件名框会让那次点击白点（“Ctrl+G 后文件要点好几次”的反馈，`FileDialog.cpp` 与 `DialogNav.cpp` 同步；`tst_shelllaunch` 的 `realDialogFocusAfterGoingToAFolder` 用真对话框验证两种情况）。每次转到文件夹在诊断日志记 `dialog-move`（方式、程序、对话框类型、耗时、结束时前台/焦点/鼠标捕获的窗口类名，不含路径）。
- **搜索框严禁以他程序对话框为原生 owner（#95）**：跨线程设 `GWLP_HWNDPARENT` 会合并两线程输入队列，对话框卡顿会拖死搜索框按键；UIPI 禁普通进程以提权窗为 owner；Qt 首次 `show()` 会清原生 owner；且用户操作别程序时 `SetWindowPos(HWND_TOPMOST/HWND_TOP)` 会静默返回 TRUE 却失效 → `win::followDialog` 不设外部 owner，仅对话框自身置顶或提权时置顶，否则插到 `GetWindow(对话框, GW_HWNDPREV)` 之后（不带 `SWP_NOOWNERZORDER` 以带起同线程 `win::followOwner` 的 Logo/菜单；撤子窗置顶前先解 owner 再挂回），在对话框前台/显示/移动结束及 `EVENT_OBJECT_REORDER`（`hwnd == desktop`, `idObject == OBJID_CLIENT`）时重插；回归测试先自测自身窗口能否置顶/提前，被拒即 `QSKIP`。
- **拖动对话框卡顿：自家选择框独立 STA 线程与拖动期隐藏搜索框（#90）**：自家 `shell::pick*` 原在 Qt 界面线程跑模态循环与 `DialogBar` 互卡；即便跨进程，每次 `SetWindowPos` 占约 2 ms 内核全局锁（换线程/合并事件均无解）拖慢对话框移动 → `shell::pick*` 放独立 STA 线程运行，`DialogJump` 仅排除本进程 GUI 线程窗口；`DialogBar` 挂 `EVENT_SYSTEM_MOVESIZESTART`/`END`，拖动/缩放期间隐藏搜索框，结束再于新位置显示（Win+←/→ 贴边仍跟随）。搜索栏排查输入顿挫重点看结果行数骤变改高与主线程慢事件（IME 组字期不搜属设计）。
- **WPS 对话框（`KcfdFileDialog`）的约束与冷启动竞态**：提权 WPS 对普通权限 UIA 不可见（UIPI）；Qt 无障碍冷唤醒初期只吐 `Qt*`/空类名，若立刻缓存为 `None` 会令该窗终身失联；Qt 对话框关闭常只隐藏不销毁，复用 HWND 若不清理已见状态会导致二次打开不触发自动转；Qt 单 HWND 投 `VK_RETURN` 交给当时焦点控件，`SetFocus` 后立即判焦易遇焦点未落稳，落在文件名框会直接保存；不存在路径弹模态 `KcfdMessageDlg` 锁窗 → 需同权/提权；不读 `currentFolder`/`fileType`，仅以地址框收起判跳转完成；UIA 冷唤醒等 ≤1 s 且未初始化时不缓存 `None`（`DialogJump` 按需 500 ms 重试一次），`EVENT_OBJECT_HIDE`/不可见时清理复用框的 `m_seen`/`m_wentToManager`/`m_sentTo`；跳前 `GetFileAttributesW` 校验确为目录，前台设焦后等 ≤250 ms（失败前台复核重试一次）并前后两次核对 `GetFocusedElement` 类名为 `KcfdLocNavigationLineEdit` 且同进程才投回车。
- **第三方压缩软件路径框（Bandizip / 7-Zip / WinRAR，`PathBoxDialog`）**：`WM_SETTEXT` 不触发 Bandizip 目录树联动；回车即确认开始解压并关窗；7-Zip `OnOK` 在组合框有列表选中项时读选中项盖过文字；Bandizip 展开大目录阻塞消息循环数秒；搜索框在前台时 `BM_CLICK` 因对方非激活无效 → 写框前先 `CB_SETCURSEL(-1)`，只写框绝不发回车，用 `PostMessage` 投 `CBN_EDITCHANGE` 勿同步等；按对方按钮向其父窗口发 `WM_COMMAND` + `BN_CLICKED`；跨进程读文字测试必用 `SendMessageTimeout`。
- **Tessoa 接管的打开/另存为窗口无法驱动**：Tessoa 0.31+ 的“接管打开 / 另存为窗口”在 HKCU 把 FileOpenDialog/FileSaveDialog 的 `InprocServer32` 换成它的 DLL，调用方（微信等）弹出的是 tessoa.exe 的自绘窗口（类 `Window Class`，owner 为调用方窗口，无子控件无 UIA）；查询管道对它回空，`--open-window=<夹> --in-tab=<它>` 退出码仍为 0 却在主窗口开新标签，它的文件名框拒收文件夹 → 不要把 `--in-tab` 的 0 当成功；`filedialog::isTessoaPicker` 认出后只复制路径（不注册 `Ctrl+G`、不自动转），日志与诊断 `tessoa-picker` 记录。实测接管需安装版 Tessoa；测完 `CLSID` 与 `WOW6432Node\CLSID`（32 位）下各两个键都要删，并核对还原。详见 [dialog-compatibility.md](../dialog-compatibility.md#tessoa-自己的打开另存为窗口2026-11-24)。
- **Listary 钩子冲突**：Listary 用钩子拦 `Ctrl+G` 不受 `RegisterHotKey` 阻挡，且从资源管理器切回时会强制自动转 → 产品提示二选一，自动化测 `Ctrl+G` 改投 `WM_HOTKEY` 给 `WinShun.MessageWindow`，测自动转前退出 Listary 钩子进程。
- **Directory Opus、Total Commander 与 XYplorer 路径通信**：管理员直接运行 `dopusrt.exe /info` 因 UIPI 收不到普通权限 Opus 回信永久挂起，无窗口时调 `/info` 会拉起 Opus，传手册外类型（如 `selected`）直接令 `dopus.exe` 崩溃；Opus `Go` 异步，紧跟 `Select` 列表尚空；TC 首次模态提示/配置窗禁用主窗致 `/O` 无效，而 `WM_USER+50` 高权发低权不受 UIPI 限制；XYplorer 32 位（VB6）与 64 位（twinBASIC 28.x）主窗均为 `ThunderRT6FormDC`（属 `ThunderRT6Main`），但 Free 版无脚本、弹窗期脚本空返、提权时 UIPI 同时拦截 `WM_COPYDATA` 与 `WM_GETTEXT`，且 `DialogBar` 与 `DialogJump` 双工作线程并发发脚本会重入其单线程脚本引擎，x64 传句柄未截 32 位会遇高位符号扩展，`\\?\` 前缀若先按 `?` 截断会误删整条路径 → Opus 普通权限运行 `dopusrt`（3 s 超时，无窗口不问，定位用单条 `Go "完整路径" OPENCONTAINER`）；XYplorer 匹配 `XYplorer*.exe`（排除 `XYcopy.exe`），`askXYplorer` 加互斥锁串行并用 `HandleToULong` 传句柄，先剥 `\\?\`/`\\?\UNC\` 再截 `?` 快速搜索，脚本无答时按“最宽可见地址栏 `Edit`（含主地址栏特殊目录别名，避免右侧实时筛选框误判）→ 顶层窗口标题 `GetWindowTextW`（跨 UIPI 可读）”三级降级。

## 资源管理器集成、文件夹菜单、拖放圆盘与粘贴为文件

- **Win11 资源管理器多标签、`SHELLDLL_DefView` 层次与右键动词注册**：所有 `ShellTabWindowClass` 均带 `WS_VISIBLE`，当前标签是 `FindWindowEx` 排 Z 序最前者（与 `IShellBrowser::GetWindow` 一致）；`SHELLDLL_DefView` 非标签直接子窗须 `EnumChildWindows` 找；`Directory\Background\shell` 绝不可写 `MultiSelectModel=Single`，否则无选中项时空白处右键隐藏动词（仅 `Directory`/`Drive` 写）。测试勿用提权进程直接拉 `explorer.exe`（会因 `integrity::higherThanOurs` 被忽略，须 `runas /trustlevel:0x20000`），多标签窗单次 `WM_CLOSE` 只关当前标签。
- **资源管理器打字搜索焦点判定与菜单放行（#37）**：`WH_KEYBOARD_LL` 在 `TranslateMessage` 前拿到真 `vkCode`（非 `VK_PROCESSKEY`）；文件列表焦点恒为 `SHELLDLL_DefView` 下 `DirectUIHWND`（F2 重命名 `Edit`、地址栏与 Win11 新式右键菜单焦点进 XAML `InputSiteWindowClass`，自动排除）；但经典右键菜单（`#32768`）打开时焦点仍在 `DirectUIHWND` → `searchtyping::focusOf` 须同时检查 `GetGUIThreadInfo().flags` 不含 `0x4`/`0x8`/`0x10`（菜单模式）才截键。
- **打字搜索持键乱序、开始菜单抢前台、前台被拒降级与后台窗口无事件（#39/#66/#203）**：（1）重发前过早结束持键会让后续手打键夹进 `SendInput` 序列变“zq”，开始菜单冷启动期不理 `Esc` 抢回前台致重发键进 Windows 搜索，启动器到前台若未撤键盘 Raw Input 会致钩子静默变“dbaiu” → 持键伊始即 `KeyboardRawInputAside` 暂撤键盘 Raw Input，重发前核对 `GetForegroundWindow()` 确为 Win顺 窗口（仍是开始菜单且未输入满 600 ms 则再请启动器最多 2 次），并等所有带 `kOwnInput` 的重发键过完钩子链（`Hold::ownPassed`/`Retyped`，1 s 超时）发 `kPassedMessage` 才结束；（2）机器全面拒 `SetForegroundWindow` 与 `SendInput` 时，启动器降级走 `KeyRouter` 无激活接管（`App::startLauncherRouting`），持键按原窗布局直转字符（`Hold::handOver`）而不重打；（3）后台打开的文件夹窗口因已是线程 `hwndActive`，点到前台不发 `EVENT_SYSTEM_FOREGROUND` → 事件中遇不在前台的资源管理器窗口及启动时 `EnumWindows` 扫描所得均记入 `m_explorerBehind` 并保持钩子，首键复核真实前台。
- **打字搜索框定位（Opus 与资源管理器，#82/#203）**：居中大窗四边放不下时最小重叠策略会落到屏幕左上角 (0,0)，Opus 窄栏从左上角起会伸进查看栏 → 仅整框完全不挡原窗口时放旁边（`clearOf`），否则进焦点文件列表右下角（`inList`：临时收窄宽至下限 640 不保存、限高至列表底上 12 px，依次外扩至全部可见栏/lister/工作区；资源管理器取当前标签最大可见 `SHELLDLL_DefView`）。
- **Opus、Clover、360文件夹窗口层次与开关适配（#82/#311/#416）**：Opus `dopusrt /info` 的 `tab` 是 `dopus.filedisplaycontainer` 而焦点是子窗 `dopus.filedisplay`，对“此电脑”/虚拟目录整条不列，自绘菜单 `dopus.button.display.popup` 不置菜单标志需查 `hwndCapture` 与线程可见菜单窗；Clover 嵌入 `CabinetWClass` 不加 `WS_CHILD` 致 `GA_ROOT` 失效；360文件夹不在 `ShellWindows` 且二者均默认“双击返上层” → Opus 按父容器+lister 匹配 XML、`opusPlace` 用 `std::optional` 区分无应答与有效应答未列（空串弹全局搜索）；Clover 用 `folderview::frameOf` 沿 `GA_PARENT` 找首个无 `WS_CHILD` 窗；360 靠标题 + UIA 前 16 个名匹配索引推断路径；二者开双击返上层时 `FolderMenu` 主动让出（Clover 读 `config.ini`，退出才落盘；360 读 `dbclick_to_parent`，缺省为开）。
- **Opus 空白处双击/中键菜单与安全改写 `prefs.oxc`（#416）**：`dopus.filedisplay` 不向 MSAA/UIA 暴露行，外部无法判空白；运行中 Opus 不重读 `prefs.oxc` 且首选项点确定会覆盖磁盘；`{sourcepath$|noterm}` 带 `$` 会让“此电脑”不触发 → 借 Opus 背景事件 `id="0"`（左双击）与 `id="4"`（中键 + `single_middle_click="yes"`）调 `WinShunSearch.exe --folder-menu[-middle] "{sourcepath|noterm}"`（去 `$`、`|noterm` 去尾 `\` 防转义引号，stub 补 `C:`→`C:\`，`WM_COPYDATA` `WSFM`/`WSMC` 通知）；改 `prefs.oxc` 前先 `dopusrt /cmd Close PROGRAM` 等退出（≤15 s），备份原文件与旧值后再重启（原无窗口则 `WM_CLOSE` 新出默认 lister 回托盘），卸载时禁用指向本副本条目。
- **文件夹菜单空白判定、自家窗呼出、多列接缝与弹前布局（#22/#25/#348）**：资源管理器分组视图行缝与组标题 `accHitTest` 均是 `GROUPING` 且 UIA 转换失败；在自家窗口前台按快捷键呼出菜单撞 Raw Input 致 `KeyRouter` 静默；`Column.implicitHeight` 延迟更新致底边不翻转；读最近 `.lnk` 耗 100+ ms；多列 `QWindow` 150% 逻辑坐标舍入产生 3 px 接缝、`ShowWindow` 不改 Z 序遮挡提示、`Item` 自带 `left/right/top/bottom` 禁同名信号、离屏窗 `contentItem` 0×0 → 分组查 `AccessibleChildren(obj, 0, 1)` 首子对象仍是同名 `GROUPING` 才算空白；自家搜索框/启动器在前时先还前台给对话框或先收起启动器再弹菜单；最近文件夹后台预读，弹出前 `content.forceLayout()`；多列由 `placeColumn` 按设备像素 `SetWindowPos` 扣 `DWMWA_VISIBLE_FRAME_BORDER_THICKNESS` 拼缝，提示框每显每加列都 `raise()`，列尺寸直绑窗口，`closeAfter` 先改 `highlighted` 再截 `pages`，滚动后 `rest()`。

- **拖放圆盘（`DropPie`）：OLE/TC 检测、代启拖动与按键防漏**：OLE 拖放期来源线程 `hwndCapture` 类名为 `CLIPBRDWNDCLASS`，TC 11 窗内拖放自捕获 `TTOTAL_CMD`、自管消息循环会把触发键打进命令行、不认 `SetCursorPos` 且拖动门槛约 +18 物理像素 → 将无 `GUI_INMOVESIZE`/菜单标志的 `TTOTAL_CMD` 一并视作拖动候选；按住未动时用 `SendInput`（绝对坐标 + `MOUSEEVENTF_VIRTUALDESK` + `kOwnInput`）分 4 步移 6 倍拖动矩形启动拖动再 `SetCursorPos` 归位；拖动开始后按前台布局临时注册触发键及 `Shift`/`Ctrl`/`Ctrl+Shift` 热键（`MOD_NOREPEAT`）拦在 TC 输入法前，注意注册热键后 Raw Input 收不到该键须改由 `WM_HOTKEY` 触发，松开主键即注销。
- **拖放圆盘：接管放下目标、双渲染命中反转、SysDragImage 遮挡与整像素缩放（#150）**：Qt 建窗已注册 `QWindowsOleDropTarget` 致 `DRAGDROP_E_ALREADYREGISTERED`；D3D11 透明像素整矩形命中（会挡下层窗口），**软件渲染下全透明像素完全不命中**致等 `DragEnter` 才画的圆盘永不出现；调 `IDropTargetHelper` 会令 SysDragImage 缩略图盖住胶囊文字；逻辑尺寸乘缩放非整数会重采样发虚 → 先 `RevokeDragDrop` 再注册并随 `winId()` 重接管；软件渲染（按 `GraphicsInfo.api`）在淡入层外铺满窗 `1/255` 不透明度底，指针离开胶囊 `reach` 外扩 36 逻辑像素立刻隐藏并返回 `DROPEFFECT_NONE`；彻底不碰 `IDropTargetHelper`（提早收起先 `leaveEarly`）；显示/收起后原地 `SetCursorPos`（`nudge`）促发 `DragEnter`，靠边时等 `DragEnter` 确认文件后再移越界指针至圆心；`pie::windowRect` 从显示器左上角向外凑到乘缩放为整设备像素的逻辑值。
- **拖放圆盘：短命数据、`DROPEFFECT_NONE`、线程归属与 `RUNASADMIN` 740**：7-Zip/WinRAR/Bandizip 的 `%TEMP%` 副本在 `DoDragDrop` 返回即删、读 `CF_HDROP` 可能触发同步解压；自移持久文件若回 `DROPEFFECT_MOVE` 会致来源删源冲突；`FileOperations` 归圆盘析构会卡主线程等替换弹窗；勾选兼容属性 `RUNASADMIN` 时外壳令牌 `CreateProcessWithTokenW` 起自身普通权限助手报 740 → `DragEnter` 有 `CFSTR_SHELLIDLIST` 时只读它，非持久文件（无路径/回收站/临时目录）同步转发目标 `IDropTarget`，持久文件后台 `IFileOperation`（异步来源配 `StartOperation`/`EndOperation`）且 `Drop` 一律返回 `DROPEFFECT_NONE`；`FileOperations` 归 `App`；`shell::startUnelevated` 对本目录遇 740 注入 `__COMPAT_LAYER=RunAsInvoker` + `WINSHUN_AS_INVOKER` 重试，`main()` 首行用 `_wputenv_s`（同时清 CRT 与 Win32 环境）移除两变量防传染孙进程。
- **粘贴为文件（`PasteAsFile`）：拦截边界、重命名竞态、压缩包与编码**：资源管理器 `IDropTarget` 仅认 `CF_HDROP`/`Shell IDList Array`/`FileGroupDescriptor`；写完即调 `SVSI_EDIT` 视图未列新文件会丢重命名；`IFileOperation` 进度窗一闪即抢前台断重命名且 `FOF_RENAMEONCOLLISION` 命名是“- 副本”；资源管理器 `Ctrl+Z` 撤销栈进程私有无法跨进程；压缩包 `.zip` 带 `SFGAO_FOLDER|FILESYSTEM|STREAM` 非目录；cmd 按 `CP_OEMCP` 读 `.bat` 非中文区域写不下中文；腾讯“桌面整理”（`TXMiniSkin`）盖在 `Progman` 下截走桌面点击焦点 → 用 `IsClipboardFormatAvailable`（不打开剪贴板免唤醒延迟渲染）判无上述三格式才截 `Ctrl+V`；普通目录直用 `CREATE_NEW` 自编 ` (2)`（仅无权/虚拟目录用 `IFileOperation` + `FOF_SILENT`），写完立刻 `SHChangeNotify(SHCNE_CREATE, SHCNF_PATH | SHCNF_FLUSHNOWAIT)`（勿用 `SHCNF_FLUSH`），先选后每 25 ms 查 `IFolderView2::GetFocusedItem`（勿用 `GetItemPosition`）命中后再 `SVSI_EDIT`；目标须有 `SFGAO_FOLDER`、无 `SFGAO_STREAM`、有 `FILESYSTEM`/`STORAGE` 且复核 `FILE_ATTRIBUTE_DIRECTORY`；`.bat` 用 `WideCharToMultiByte(CP_OEMCP, WC_NO_BEST_FIT_CHARS)` 检查 `lpUsedDefaultChar`，有损则改 UTF-8；不支持 `Ctrl+Z`（测试严禁按）；桌面测试须 `Win+D` 进 `SysListView32`。

## 任务栏搜索框与 `Win+S`

- **Win11 UCPD 禁止改 `SearchboxTaskbarMode` 与不劫持原生按钮**：Win11 25H2 用户选择保护驱动（`UCPD`）拒绝所有外部（含管理员）写 `HKCU\...\Search\SearchboxTaskbarMode`（错误 5）；鼠标钩子拦原生搜索按钮点击会丢失按下/展开/彩色放大镜动效 → 只读注册表（`HKLM` 组策略 `SearchOnTaskbarMode` 优先），提供按钮进 `ms-settings:taskbar` 由用户隐藏，任务栏独立放 Win顺 自有入口。
- **点任务栏子窗口仍使启动器失活与快关竞态**：点击异线程任务栏子窗口时系统先撤掉原前台（`MA_NOACTIVATE` 不阻挡），`GetForegroundWindow()` 瞬时为空，且失活与点击回传先后不定 → 失活时鼠标在框上、或打开 500 ms 内前台为空给 400 ms 宽限（`m_boxPressGrace`/`m_launcherShown`）待点击拉回前台；前台若已换成其他真实窗口（含任务栏非框处）立即收起。
- **`ms-screenclip:` 降权激活与关 `Win+S` 后勿抢 `Win+Shift+S`**：`ShellExecute("ms-screenclip:...")` 遇 UserChoice 校验异常弹“打开方式”，命令行别名只开主窗，`IApplicationActivationManager` 报 `0x80270254`；管理员直启截图工具会使其高完整性运行导致普通工具受 UIPI 失灵；关 `Win+S` 重启 explorer 时若在 `TaskbarCreated` 抢占 `Win+Shift+S`，explorer 注册失败不再重试随后 Win顺 放手致截图键彻底失灵 → 读 `AppModel\Repository\Packages\Microsoft.ScreenSketch_*\App\Capabilities\URLAssociations` 的 `ms-screenclip` 类名，经资源管理器运行普通权限 `WinShunSearch.exe --screenclip` 调 `ShellExecuteEx(SEE_MASK_CLASSNAME)`；仅在确实持有 `Win+S` 时才注册 `Win+Shift+S`，explorer 重启窗口期不占其热键。
- **`TaskbarManager` 固定到任务栏的 AUMID 与通知等待**：未打包程序未设一致 AppUserModelID 时 `IsPinningAllowed` 恒假；同程序上一固定通知未回答时新请求被拒；拉起前台的透明窗未及时关会吃掉用户输入 → 进程调 `SetCurrentProcessExplicitAppUserModelID` 与开始菜单快捷方式 `PKEY_AppUserModel_ID` 对齐（`propkey.h` 须在 `shobjidl.h` 之后包含）并 `SHChangeNotify(SHCNE_UPDATEITEM)`，请求前轮询最多等 6 s（实测 ~3 s 生效）；请求发出立刻关透明窗，被拒退回打开文件夹手动固定。
- **任务栏搜索框固定两端、弃用 XAML 注入与空 `TaskbarFrame` 误跳（#35）**：Win11 图标交错滑动（每项晚 16.6 ms，动画 333 ms）、UIA 提前报终点且全树慢（48–164 ms）；`InitializeXamlDiagnosticsEx` 的 `DiagnosticsInterop` 仅通知最后连入者，与 TranslucentTB 冲突且注入 DLL 在 explorer 重启前卸不掉；任务栏重建时 `TaskbarFrame` 短暂为空若算有效读数会把整框误跳至托盘旁 → 弃用 DLL 注入（旧 tap 卸载用 `MOVEFILE_DELAY_UNTIL_REBOOT`），不跟图标滑动，固定在任务栏两端（居中放最左/小组件右，靠左放托盘左）按三档定宽（240/图标+字/44）降级或隐藏；125 ms 轮询仅用于被压住时应急收窄，末事件 1 s 后相隔 250 ms 两次读数相同（上限 4 s）才安定放置；Win11 下 `TaskbarFrame` 读到 0 个图标判 `measured = false`，丢缓存原地不动等待重试。
- **透明任务栏（TranslucentTB）残影与不在任务栏后滑动**：启动器滑入任务栏后面在 TranslucentTB 模糊/透明任务栏下会透出并定格残影至下次前台切换，且 Win11 前台普通窗口 Z 序有时排在 `Shell_TrayWnd` 上方致插到任务栏后整窗看不见 → 弹出/收起淡入淡出全部在任务栏上方间隙内（≤12 逻辑像素 `kTaskbarGap`）完成，不再进任务栏后面。
- **任务栏框 150% 描边发虚与子窗口 Tooltip 压栏**：1 逻辑像素描边在 150% 下为 1.5 物理像素未取整且底色只铺到描边中线致四边宽亮不一；原生 tooltip 默认弹鼠标处压住任务栏且不跟任务栏深浅色 → 线宽按 `std::round(s)`（≥1 px）取整，底色铺满后整条描边画在上面并落整设备像素；Tooltip 建为无主 `WS_EX_TOPMOST` + `TTS_ALWAYSTIP` 窗（不可属异进程任务栏），在 `TTN_SHOW` 自用 `SetWindowPos` 摆到框上方 12 逻辑像素并返回 TRUE，深色任务栏设 `SetWindowTheme(tip, L"DarkMode_Explorer", nullptr)`。
- **启动器弹出像素抖动与 D3D11 筛选条缩放停顿**：`Placement::contentShift` 小数位移与 `verticalCenter` 居中控件在 150% 下落半像素致停稳后末帧跳 1 px；范围切换展开/收起筛选条时 D3D11 默认交换间隔会导致首次 resize 停顿 ~120 ms → `stepSlide` 位移按设备像素取整、搜索栏控件 `y` 用 `onPixel` 对齐整设备像素；搜索窗在 `create()` 前单独设 `QSurfaceFormat::setSwapInterval(0)`，外框高度直接绑定 `TypeStrip.height` 与列表/底栏共用 200 ms `OutCubic` 进度。
- **StartAllBack / ExplorerPatcher 经典任务栏适配**：经典 Win32 任务栏无 XAML `TaskbarFrame`，但 Win11 原生也含隐藏的 `MSTaskListWClass`；经典任务栏增删按钮不发 `EVENT_OBJECT_LOCATIONCHANGE`；托管 .NET `System.Windows.Automation` 读不到其 MSAA 子按钮 → 以 `MSTaskListWClass` 可见且无可见 `DesktopWindowContentBridge` 判经典任务栏，用原生 COM `CUIAutomation8` 读按钮；另挂 `MSTaskListWClass`（`OBJID_CLIENT`、子 ID ≠ 0）的 `EVENT_OBJECT_CREATE`/`DESTROY` 钩子触发测量（勿听 `STATECHANGE`，悬停即空转）；StartAllBack 注册表仅重启 explorer 生效。
