# 截图、标注、OCR 与录屏踩坑

面向截图插件（`WinShunCapture`）、标注与编辑窗口、长截图、区域录屏及 OCR / 二维码识别链路的可复用技术约束与已知边界。

## 截屏捕获、遮罩、HDR、多屏与显卡驱动

- **非整数 DPI 全屏遮罩差 1 像素与 `QImage` DPR 误用**：非整数缩放（如 150% 下 2560×1600 对应逻辑 1707×1067）时 Qt 缓冲区按 `round(logical × dpr)` 取整，真实缩放为 `round(logical×dpr)/logical` 而非 DPR；给 `QImage` 设 `setDevicePixelRatio` 后其 `implicitWidth` 仍是物理像素数，直接布局会被再放大 → 原生 `SetWindowPos` 将遮罩放到显示器精确物理矩形，图与坐标统一按真实 `bufferScale`（`CaptureScreen::scaleX/scaleY`）显式给逻辑尺寸，`smooth: false`，`CaptureImage` 不设 DPR。
- **SDR 抓屏选型与 WGC 适用范围**：WGC `CreateForMonitor` 单次耗时 22–24 ms，若对每块屏常驻 D3D 设备和 capture item 会白占提交内存；BitBlt 与 WGC 在任务栏亚克力边缘存在百余像素固有差异，并非缩放错位 → 普通 SDR 单次截图用 `BitBlt` 直接画进 `CreateDIBSection`（省去 `GetDIBits` 二次拷贝，保留 `CAPTUREBLT` 以拍到贴图等分层窗口），WGC 仅用于 HDR 预热或长截图 / 录屏连续流，校验比对时忽略该任务栏固有差异。
- **多屏遮罩必须全屏预热，避免切屏或空闲后现建设备卡死**：Qt 线程渲染循环首次显示无显卡资源的窗口时，GUI 线程会阻塞等待 `QSGRenderThread` 建 QRhi / D3D11 设备，在 `IdleTrim` 整理后实测可卡 156 ms 至 11.4 s → 每块显示器的遮罩均在后台预热（带图按最终物理尺寸画一帧再画空帧收起），用完隐藏复用不销毁重建；把读注册表、列历史等非首帧工作移至 `Capture::afterUp`。量内存与延迟须等 `IdleTrim` 触发后（≥40 s）且同时看 `PrivateWorkingSetSize` 和 commit。
- **遮罩禁翻转呈现（`QT_D3D_NO_FLIP=1`）**：铺满屏、置顶且不透明的 D3D11 `FLIP_DISCARD` 交换链会被 Windows 移出合成走独立翻转 / MPO，在部分显卡驱动上易引发黑屏闪烁或光标平面异常 → 建遮罩创建 QRhi 前临时设 `QT_D3D_NO_FLIP=1`（强制 `Composed: Copy with GPU GDI`），预热完取消以免影响其他窗口（可用 `WINSHUN_CAPTURE_FLIP=1` 做对照）。
- **AMD 驱动遮罩呈现固定卡顿约 2 秒（`NtGdiDdDDIPresent`）**：RX 6800 XT 等环境在首次或距上次超 1 分钟后截图，即使改拷贝呈现，GUI 线程仍在 `Qt6Quick` 等 `QSGRenderThread` 固定卡 2.06–2.17 s，渲染线程阻塞在 `dxgi.dll` → `d3d11.dll` → `amdxx64.dll` → `NtGdiDdDDIPresent`（疑似 2 s TDR 或 FreeSync / MPO 切模式，与 `IdleTrim` 无关）→ 排查须联动 `ui-stall-threads`、`GraphicsLoss`（`graphics_lost`）与 `DisplayPulse` 双节拍（`D3DKMTWaitForVerticalBlankEvent` 的 `vblank_gap_ms` 与 `DwmFlush` 的 `dwm_gap_ms`）区分硬件重置、DWM 停滞与交换链自等，并由 `DisplaySetup` 后台采集 EDID / HDR、MPO / TDR、AMD 驱动键与 Display 4101 事件；**切勿用 `DwmGetCompositionTimingInfo` 的 `cRefresh` / `cFrame` / `rateRefresh` 当节拍时钟**（Win11 静止时几乎不涨且刷新率失真）。
- **隐身（`DWMWA_CLOAK`）显示遮罩后鼠标指针丢失或滞留旧样式**：窗口隐身显示时对鼠标不算窗口，解除隐身后 Windows 不补发鼠标移动，Qt `QWindowsWindow::applyCursor` 不触发；若下层程序打字藏了指针，截图里指针直接消失（且 `GetCursorInfo` 仍报 `CURSOR_SHOWING`）→ 遮罩解除隐身后只要指针在遮罩上，立即 `SetCursorPos` 到原位（`Capture::frameDrawn`）触发刷新；验证指针须核对 `cursor_shown` 的实际尺寸与热点。
- **自定义截图指针兼容、跟随系统尺寸与 `MouseArea` 继承**：系统默认单色反色十字 / I 形指针在部分驱动上易出现红条、黑块或不可见，而固定 21 px 十字会无视辅助功能里调大的指针尺寸 → 十字和文字 I 形改用显式 RGBA 自绘并按 DPR 缓存，建窗时读 `HKCU\Control Panel\Cursors\CursorBaseSize`（缺省 32）按比例放大、线宽按平方根加粗、热点用 `qRound(logical × dpr)` 对齐 Qt；`MouseArea` 构造默认设箭头会遮盖父项，继承自定义指针须显式写 `cursorShape: undefined`。
- **放大镜布局、显隐联动、纹理复用与按住鼠标微调**：放大镜盒子宽度若被提示文案撑开，右侧会留空白条；移动时每帧重建纹理节点开销高；工具栏 `hoverEnabled` 接走悬停会让放大镜僵在原位 → 盒子宽锁死 `loupe.width + 2` 且文案 `elide`；改用持久 Qt / RHI 画布纹理并按采样点缓存；选区确定后仅在选区及蓝框内显示（不含框外手柄，拖边时显示），整屏 `MouseArea` 借 `onExited` / `onEntered` 处理悬停工具栏显隐；`C` 与单按 `Shift` 换色格式跟随 `magnifierShown` 并滤掉 `isAutoRepeat` 与组合操作；按住鼠标键时方向键亦应同 WASD 挪指针（`CaptureSession::keyPressed`）。
- **后台选区 OCR 派发勿把裁剪和灰度化留在主线程**：仅把模型推理放工作线程、而在主线程先 `copy` 选区并在回调中对整图转灰度，4K 选区主线程仍需约 29 ms → 直接将共享只读冻结图和选区矩形交给工作线程完成裁剪、灰度化与识别，回调按轮次号丢弃过期选区。
- **HDR 判定、归一化与无 HDR 屏测试法**：`DisplayConfig` 类型 9 的 `advancedColorEnabled` 在 WCG 广色域下也为真，不能用于判真 HDR；普通 SDR 桌面在 HDR 下最亮仍只到 SDR 白，测不出超白亮部保留 → 用类型 15（`ADVANCED_COLOR_INFO_2`）的 `activeColorMode` 确认真 HDR，经 WGC 半精度抓图导出 `.jxr`（`Hdr.cpp` 按 80 尼特白电平映射）；SDR 屏可设 `WINSHUN_TEST_HDR_CAPTURE` 验证 `.jxr` 链路，验证超白亮部须用 `R16G16B16A16_FLOAT` 翻转交换链加 `SetColorSpace1(RGB_FULL_G10_NONE_P709)` 的置顶小窗 `ClearView` 输出 >1.0 灰度。
- **Win11 25H2 开始菜单在前台时抢锁与悬停框错落背后窗口**：开始菜单（`SearchHost.exe` / `StartMenuExperienceHost`）处于更高 Z 序带且不在 `EnumWindows` / `GetWindow` 链中，`SetForegroundWindow` 关不掉它，关闭动画未完前立刻重截又只比出一小块 → 检测到 `win::isShellFlyout` 时先冻结屏幕，发带 `kOwnInput` 的 `Esc` 等其退出再显遮罩；每 15 ms 重截与冻结图比对 `changedRegion`（去阴影行），连续两次矩形稳定（上限 500 ms）后作为最顶窗口并补入任务栏矩形（`Capture::findFlyout`）。
- **商店应用全屏时遮罩被盖、安全边界与非激活遮罩输入转发**：媒体播放器等商店应用全屏后，框架窗口（`ApplicationFrameWindow`）进入 Z 序带 8，普通桌面窗（带 1，含置顶）盖不上且 `SetForegroundWindow` 被拒，Win10 下普通进程 `EnumWindows` 也不列它；旧方案发 `Win+Shift+Enter` 退全屏会唤出控制条、缩小窗口并露出任务栏；而 `winshun.capture` 装在用户可写目录，绝不能直接给插件 UIAccess → 改由受保护 `WinShunService.exe --capture-surface`（高完整性 + UIAccess，Z 序带 2，无 Qt/Shell/SendInput）跨 IL `DwmRegisterThumbnail` 1:1 镜像普通权限的带 1 `CaptureOverlay`，不改动播放器全屏状态即可直接覆盖并拿前台与全部键鼠（双端互核 PID、仅针对非提权 Band>1 商店窗、外部失活立即自毁）。关键细节：① 带 2 窗非文字输入态必须 `ImmAssociateContextEx(hwnd, nullptr, 0)` 关 IME，否则中文拼音把快捷键变成 `VK_PROCESSKEY`（`0xE5`），仅 `Qt::ImEnabled` 为真时开启并转发 `WM_IME_COMPOSITION`；② Qt Quick 非激活窗（`isActive() == false`）的 `Keys.onPressed` 依赖 `activeFocusItem`，桥接层须向遮罩派发纯 Qt `QFocusEvent(FocusIn)`（不调 Win32 激活）并把 `QKeyEvent` 交给 `QQuickWindow`；③ 结束时须先关带 2 镜像再清遮罩图片防闪空帧，仅贴图 / OCR / 另存为 / 录屏 / 长截图等带 1 后续窗才退全屏；④ 服务不可用时自动回退 `Win+Shift+Enter`（切回全屏须等其重获前台并晚 150 ms）。
- **悬停窗口过滤：按句柄 / 类名排除，切勿按 PID 排除**：按 `GetWindowThreadProcessId == GetCurrentProcessId()` 跳过同进程窗口会把 Win顺 自己的设置窗、编辑窗一并过滤掉；系统“文本光标指示器”（`CursorVisualClass`）是置顶可见分层窗，不排除会被误框选 → `WindowSnapshot::take(overlays)` 仅按句柄排除遮罩，按类名排除 `WinShun.Pin` / `WinShun.Countdown`（`isCaptureSurfaceClass`）、`CursorVisualClass`、`WS_EX_TRANSPARENT` 及透明度为 0 的分层窗。
- **UIA 控件识别：严禁查询 Chromium 与注册全局焦点监听，按最小面积选链**：遮罩盖屏时 `ElementFromPoint` 只会命中遮罩自身；对 Chromium / WebView2 / CEF / Qt WebEngine 发起任何 UIA 请求（含注册全局 `IUIAutomationFocusChangedEventHandler`）都会永久激活 `kAXModeComplete`，令 VS Code 切入屏幕阅读器模式（另：`HKCU\Software\Microsoft\Narrator\NoRoam\RunningState` 残留为 1 也会触发）；仅按深度挑链会让多层空窗格胜过浅层小按钮 → 从目标窗口 `ElementFromHandle` 逐层 `FindAllBuildCache(TreeScope_Children)` 缓存 `BoundingRectangle` / `IsOffscreen` 下探，先由 `isChromiumClass` / `hostsChromium` / `wantsUia` 拒绝所有 Chromium 及其宿主（退回纯 user32 Win32 子窗口矩形）；遍历所有含点分支（限深 32、限 400 元素、总预算 150 ms），优先取链内最小有效矩形面积、再比深度，并去重同尺寸矩形。
- **PrtScn 热键接管与配置副本覆盖**：`PrintScreenKeyForSnippingEnabled` 未设或改 0 后未广播通知时，`RegisterHotKey(VK_SNAPSHOT)` 照样返回成功但系统仍拦截 PrtScn（弹 OpenWith 或整屏进剪贴板）；App 内部直接改写 `PrintScreenBefore` 等设置未同步给设置窗副本会被下次保存冲掉 → 写值后必须广播 `WM_SETTINGCHANGE`（`lParam` 为 `"Control Panel\Keyboard"`，`printscreen::write`）再注册，测试须真按键验 `WM_HOTKEY` 到达；App 自改 `m_settings` 后立即同步 `SettingsEditor`。
- **无修饰单键全局热键在管理员窗口前失效（#243）**：高完整性窗口在前台时，普通权限进程 `RegisterHotKey` 仅带 Ctrl / Alt / Shift / Win 的组合键触发，单独的 F1–F24、`VK_SNAPSHOT`、Enter、Esc 均收不到 → 经 `platform/PlainHotkeys` 将 F1–F24 与 `VK_SNAPSHOT`（最多 32 个，不转发普通字母和 Enter / Esc 防变键盘记录）交索引服务的高完整性 + UIAccess 按键助手（`--listen-keys`，`kCapabilityHotkeyRelay` 仅授权自身界面），仅在高权限前台时挂 `WH_KEYBOARD_LL` 吞键并 `AllowSetForegroundWindow` 转发 `WM_HOTKEY`。已知限制：csrss System 级置顶错误框仍会压在非 UIAccess 遮罩上方。
- **插件化热键交接与跨进程前台锁（#138）**：宿主接管 `Win+S` 时会先占着 `Win+Shift+S`，截图插件只上报注册成功的键会让宿主永远不放；从宿主托盘 / 卡片 / 剪贴板拉起插件设置窗或编辑窗会受前景锁拦截，窗口落在背后闪任务栏 → 插件经 `winshun/hotkeys` 上报所有解析出的目标热键（含注册失败项），失败时 300 ms 后重试一次再标被占用（仅列表变化时上报，录制快捷键期间不上报）；宿主在用户点击触发的 `Host::request` / `Host::notify`（`foreground`）前调 `AllowSetForegroundWindow(pid)`。
- **插件化菜单统一与诊断日志白名单（#138）**：拆为独立进程后，贴图右键菜单若仍走系统 `shell::popupMenu` 会与宿主字体、行距、图标、勾选位置分裂；插件独立目录日志不会自动进主程序诊断包 → 自有菜单统一复用 `traymenu::popup` 并通过回调衔接业务状态；`diagnostics::exportArchive` 白名单须纳入 `plugins/winshun.capture.data/diagnostics/events*.jsonl`（不含插件设置和历史图），`capture` 事件另记 `graphics`、`refresh_hz`、`presented`（`copy` / `flip` / `software`）、`begun_ms`、`shown_ms`、`page_faults`。
- **截图插件的 Qt 日志须自己写到 stderr**：插件与录屏工作进程都没有控制台，Qt 默认把 `qWarning` / `qInfo` 交给 `OutputDebugString`，而宿主只按行收插件 stderr 记入 `plugins.log`，录屏结束摘要（编码器、抓屏方式、帧数）和各类告警曾全部丢失 → 两个入口（`winshunCaptureMain`、`winshunCaptureWorker`）启动即装 UTF-8 stderr 消息处理器（跳过 debug，同 OCR 插件）；工作进程的 stderr 由插件转记为 `Recording worker: …`，最终进 `plugins.log` 与诊断包。新加依赖系统能力的分支（如老系统退化）须 `qWarning` 记一行。
- **遮罩 QML 隐性错误与像素 / 帧率校验陷阱**：`QImage` 在 QML 中是不透明 variant，读 `.width` 得 `undefined` 且无警告；子 `Item` 声明 `left` / `top` / `right` / `bottom` 会覆盖 FINAL 锚线致窗口创建失败；.NET / GDI+ `Graphics.CopyFromScreen`（`GetHdc` / `ReleaseHdc`）存在哨兵色缺陷（KB 311221，实测 `#0D0B0C` 即 `(13,11,12)` 被当未绘制跳过成黑 / 旧色）→ QML 判图改由 C++ 暴露 `bool hasImage`；避开锚线属性名；像素真值校验用 DXGI 桌面复制、原生 GDI `BitBlt` 到 DIB 或导出文件，含指针比对以日志记录的实际 `GetCursorInfo` 句柄坐标为准；测流畅度须以高于刷新率的连续输入测“输入到出帧”延迟并对照空窗基线，勿把 `grabWindow()` 或脚本 `Sleep` 空档当掉帧。

## 标注、智能打码、贴图与编辑器

- **FreeType >64 px 大字受小字亚像素残影偏移 & ClearType 彩边**：Qt FreeType 让同字体多字号共用 `FT_Face`，小字缓存留下的亚像素偏移会让 >64 px 走轮廓的大字偏 1/64 px（瓦片与整图灰阶不一）；GDI / DirectWrite 往 `ARGB32` / `RGB32` `QImage` 画字在开启 ClearType 时无视 `QFont::NoSubpixelAntialias` 必出彩边 → >64 px 每段改用独立字体副本（`QRawFont::setPixelSize(px + 1/4096)`，26.6 尺寸不变、偏移归零）；文字和序号先画入 `RGBA8888` 对象层（灰度抗锯齿）再转预乘 `ARGB32` 整像素贴回瓦片。
- **截图工具条快速拖动丢位移**：`DragHandler.activeTranslation` 在激活瞬间从零起算，若系统将快拖合并为单次 `MouseMove` 则无后续增量、工具条不动 → `AnnotateToolbar` 改用稳定场景坐标 `centroid.scenePosition - centroid.scenePressPosition`，激活与后续移动均向遮罩上报完整位移。
- **双击对象误触发复制与拼音组字期 `Esc`**：`MouseArea` 双击时第二下先发 `pressed` 进入 `Annotating` 手势再发 `doubleClicked`，会话若忽略双击会跌落到“选区双击=复制” → `CaptureSession::doubleClick` 先取消进行中手势再询模型，开着工具或点中任何对象绝不复制；遮罩根按键项不接 IME，仅文字 `TextEdit` 接 IME，拼音中按第一次 `Esc` 由输入法取消组字，第二次才提交。
- **序号工具状态机、撤销顺序、分组切换与面板宽度**：放下序号立刻进入旁注文字输入时，`AddItems` 暂存在 `Private::placing`，若期间调样式（`Restyle`）直接进栈会颠倒撤销顺序；`newSeries()` 不清选中会把新写法改到上一组；点击序号直接开输入框会吞掉 Delete / 方向键；序号样式面板展开宽约 917 逻辑 px 超出默认窗宽 → `AnnotationModel::push()` 开头先把 `placing` 压栈；`newSeries()` 先 `m_picked.clear()`；点击序号先仅选中，再点同一选中项或点其字才打开编辑（`Private::reopenWords`）；`EditWindow.qml` 的 `minimumWidth` 随面板与状态行动态增长；`Shift+B` 归智能打码后打码工具键仅 `B` / `9`。
- **编辑窗口非整数 DPI 精度、底图去透明与裁剪手柄防抢按**：编辑窗每轴缓冲比例随尺寸 / 屏幕 / DPR 实时变化，`Flickable` 会引入小数偏移；非截图底图直接 `QImage::convertToFormat(RGB32)` 会把透明像素变黑；贴边对象易被裁剪手柄抢按 → 每轴独立算 `bufferScale(windowLogicalSize, dpr)`，内容原点与视口取整到设备像素，鼠标用 `toPhysical(logical, dpr)`；命中容差与手柄按屏幕逻辑像素经 `AnnotationModel::setView` 换算图像像素，手柄按 `unitX` 画；非截图底图先铺白 `flatten` 再转 `RGB32`；`cropHandleAt` 在框内有工具或点中对象时不抓手柄，有工具时仅从框外抓。
- **长图编辑的瓦片预算、纹理上传节流与共享 `QImage` 防深拷贝**：1080×30000 全览可达近 600 块瓦片，一次重画与建纹理会卡顿且爆内存；重画仍被纹理引用的共享 `QImage` 会触发无意义深拷贝 → `fitZoom` 小于 25% 改按短边适配；`limited` 画布每次 polish 最多画 ~8 ms（中心优先，上限 480 块），D3D11 每帧最多新建 8 个纹理（`kUploadsPerFrame`）；重画瓦片前若 `!isDetached()` 先丢弃旧图再分配；软件渲染下移动过的父节点内新建瓦片脏区算在旧坐标，单测须单独开窗验像素。
- **编辑窗口关闭路径禁用 `close.accepted = false`**：标题栏关闭按钮或 Alt+F4 若绕过控制器直接隐藏，模型、瓦片和纹理均不释放；若在 `onClosing` 中设 `close.accepted = false`，Qt 退出时会给隐藏窗也发关闭事件，拒绝将直接取消 `QGuiApplication::quit()` 导致 `--quit` 退不掉 → `TitleBar` 设 `closeIntercepted` 经 `closeRequested()` 与 Alt+F4 统一调 `editor.close()`（cloak、画两空帧释纹理、隐藏），并接 `visibleChanged(false)` 兜底；析构删窗前须断开该连接。
- **编辑窗口焦点路由、贴靠几何还原与 Alt+滚轮**：从剪贴板或启动器开编辑窗时若前窗未先收起，`KeyRouter` 会把按键继续送往旧窗；贴靠（Snap）过的编辑窗再 `show()` 会被 Windows 还原为贴靠前几何；Qt 会将 Alt+滚轮转成横向分量 → 打开编辑窗前先同步 `dismissRequested` 收起剪贴板 / 启动器；`CaptureEditor` 记录目标位置尺寸，用 `showNormal()` 显示并在 `present()` / `settle()` 重设；`CaptureEditor::wheeled` 同时收纵横分量，Alt 时竖直为 0 取横向。
- **智能打码字框吸附、长笔迹抹平限距、INI 列表与测试密钥脱敏**：OCR 行高 48 px 下 CTC 每 8 px 一时间步且有 unclip 外扩，直接用字框边缘易偏 3–10 px（误盖邻字或漏首字）；涂抹抹平四向搜最近可读像素沿长笔迹会拖慢至十几秒；QSettings 读手写无引号的逗号列表（`ToolbarHidden`、`SmartWords`）会得到 `QStringList` 导致转 `QString` 为空；单测中完整写入合成 API Key 会触发 GitHub Secret Scanning 报警 → `SmartRedact::atTheInk` 按墨迹吸附（空白向内缩，落字内按距首尾 / 邻字中点决定整字包入或退回，不切字）；抹平扫描上限 64 px 且仅算笔迹内一次覆盖；`Settings::load` 对逗号配置遇到 `QStringList` 用逗号拼接还原；单测密钥在前缀处拆分拼接（如 `u"AIza"_s + u"Sy..."_s`）。
- **贴图窗口（`WinShun.Pin`）：Alpha 归零、IME 候选窗与混合 DPI**：`BitBlt` 所得 32 位像素 alpha 常为 0，`UpdateLayeredWindow` 会把整张贴图合成透明；原生贴图窗默认带线程输入上下文，中文输入法下按键会在左上角冒出候选窗 → 拷入 DIB 时一律将 alpha 置 0xFF（`copyOpaque`），透明度只走 `SourceConstantAlpha`；建窗后立即 `ImmAssociateContextEx(hwnd, nullptr, 0)` 禁用 IME（测 IME 须先用 `WM_IME_CONTROL` 确认并切到 `IME_CMODE_NATIVE` 中文态）；混合 DPI 下贴图维持 1:1 物理尺寸，`WM_DPICHANGED` 只重算边框阴影并返回 0、不用系统缩放建议矩形。
- **穿透贴图实现与 UIPI 限制**：装全局键盘钩子监测 Ctrl 会与 `KeyListener` 双击 Ctrl 冲突；拖动或右键菜单展开时收回可操作态会中断交互；前台为高完整性管理员窗口时 UIPI 致普通权限读不到 Ctrl → 仅在存在穿透贴图时启 40 ms `QTimer` 轮询 `GetAsyncKeyState(VK_CONTROL)`，切换 `WS_EX_TRANSPARENT` 须带 `SWP_FRAMECHANGED`（`applyClickThrough`），拖动中与菜单开着时不收回可操作态；按住 Ctrl 时滚轮为调透明度而非缩放，管理员前台下无法穿透属已知限制。

## 长截图

- **预览框被截进长图：`visibleChanged(true)` 早于平台 `ShowWindow`（#378）**：Qt 6.12 `QWindowPrivate::setVisible` 先发 `visibleChanged(true)` 再调平台 `ShowWindow`，若 `excludeFromCapture` 要求 `::IsWindowVisible()` 为真才设 `WDA_EXCLUDEFROMCAPTURE`，窗口未显示会被误清为 `WDA_NONE`（在无后续几何变更的机器上预览窗会被层层截进长图）→ `excludeFromCapture` 只判断“正在取帧且窗口矩形（按 `GetDpiForWindow` 外扩阴影）与选区相交”，不再判断 `IsWindowVisible()`；预览窗整块支持 `DragHandler` → `startSystemMove()` 拖离选区后自动取消排除（自动化 `SendInput` 拖动须先缓步越过阈值再大步拖）。
- **结束后对已隐藏的被拥有窗口改回 `WDA_NONE` 留空框残影**：控制面板是预览窗的 owner（QML 嵌套 `Window`），两者设 `WDA_EXCLUDEFROMCAPTURE` 后若先双双隐藏、再在 `ended()` 里将已隐藏的二者改回 `WDA_NONE`，DWM 会在原位永久留下预览窗的圆角边框与阴影（纯 Win32 `WS_CAPTION` + `DwmExtendFrameIntoClientArea` 同样复现）→ `LongCapture::updateExclusion` 仅在长截图进行中更新面板与预览窗亲和性，结束后保持原设置隐藏，下次开始 / 移动 / 显示时再重设；若须清除 `SetWindowDisplayAffinity`，务必在窗口可见时清除。四条无 owner、无阴影的细边框照旧在结束时恢复。
- **动态排除边界、DWM 阴影外扩与贴边选区可见性**：对面板与边框一律永久排除会导致普通截图拍不到控件；只按 `GetWindowRect` 判交会漏掉窗外的 DWM 阴影（离选区 15 px 时阴影会截入长图边缘发暗）；选区贴屏幕边时外侧边框会落出屏幕 → 保留强调色轮廓与附近控制条（置顶不激活），`longCaptureBorder` 将贴边轮廓收进屏内；仅在取帧期（长图至 `ended()`，录屏至 `m_control && !m_exporting`）由 `capture/CaptureExclusion.h` 动态排除与选区相交的窗口：面板与预览按自身 DPI 外扩 64 逻辑 px 判交，收进选区的贴边边框按不扩阴影判交（MCP `take_screenshot` 确认卡亦不再排除，改关淡出后 `DwmFlush` 两次再拍）。
- **投递滚轮超前于修饰键抬起、冷启动误判与指针停靠让权**：`PostMessage(WM_MOUSEWHEEL)` 进入投递队列可能排在目标尚未处理的 `Ctrl+L` 的 `Ctrl` 抬起前面，Word 读到 Ctrl 仍按着会误缩放；若 `m_keysUpAt` 构造时置 0 则无按键时也会白等 150 ms；点击“自动滚动”开关后左键刚抬起若先判指针在选区外再判 `keysHeld(true)` 会把刚点完开关误报为 `MouseOutside` → `ScrollInput` 构造时以当前无修饰键时刻初始化 `m_keysUpAt`，`SendWheel` 与 `parkCursor` 均先检 `keysHeld(true)` 再检选区位置；`parkCursor` 避开自身面板/预览窗口矩形，用户挪动指针超阈值立即让权不再回拉，结束时仅在用户未动过指针时归位。
- **连续流式滚动、局部动图抗误丢、亚像素防抖与全画布重定位**：大步跳停配 `samePixels` 全图比对会让覆盖式滚动条淡出引发走走停停；聊天/信息流里的动图、视频或淡入淡出若按全段占比判变且把周围静止列误标为侧边栏，会导致静止画面误报 `Lost`；亚像素兜底若跳过 `dy=0` 则会把静止动图误判成 `dy=±1` 并引发 `需要接回 ↔ 拼接中 ↔ 已截取的内容` 反复闪切，还会把动图下方的静止文字误锁成吸底栏；快速回甩超出单帧重叠后仅靠 `m_prev` 很难接回 → `ScrollGrabber::changed` 按排除滚动条后的区域判变；`ScrollAutoEngine` 以连续节律细粒度滚轮脉冲（不支持小步进的老旧 Win32 控件自动回落整格）及在途背压驱动；`ScrollStitcher` 仅认贴边连续侧边栏并按行共识识别局部动图原地变化与带动画滚动，亚像素兜底纳入 `dy=0` 并将吸顶/吸底栏增长门槛约束为真实滚动位移（≥48 px），`m_prev` 失配时依次重匹配 `m_far`/`m_near` 并用行签名全画布重定位；`LongCapture` 对 `Lost`/`Behind` 展示加防抖滞回。
- **各应用滚动路由与开关状态记忆**：Chromium/Electron 下 `deepestChild` 常命中忽略滚轮的 `Intermediate D3D Window`；WinUI/UWP 的 `InputSite` / `CoreWindow` / `DesktopChildSiteBridge` 恒忽略投递滚轮；UIA `ScrollPattern` 不可用于 Chromium；管理员程序 `PostMessage` 报拒绝访问（5）→ `wheelTarget` 绕过 `Intermediate D3D Window` 投递给 `Chrome_RenderWidgetHostHWND` 或父窗；WinUI/InputSite 目标优先走 `SendWheel`；管理员目标直接提示手动滚动；自动滚动开关重启默认关，跟丢或用户接管转手动仅生效本次（`m_autoScrollChosen`）不改用户偏好。
- **长截图结束后 WGC / D3D11 内存不回落**：释放 WGC 整屏双缓冲帧池与 staging 纹理后，D3D11 延迟销毁、驱动缓存及隐藏面板场景图仍可多占约 67 MB commit → 流结束按序释放 staging、帧池、session，再执行 `ClearState()` + `Flush()` + `IDXGIDevice3::Trim()`，面板隐藏后调用 `releaseResources()`。

## 区域录屏、音频、点击与按键提示

- **Win10 1809 上 WGC 报 `0x80004002`（`E_NOINTERFACE`）与 GDI 回退**：`IGraphicsCaptureItemInterop::CreateForMonitor` 与 `Direct3D11CaptureFramePool::CreateFreeThreaded` 自 Win10 1903（18362）起才有，`IsCursorCaptureEnabled` 自 2004 起；1809（17763，UniversalApiContract 7）只能走 `GraphicsCapturePicker`，C++/WinRT 取工厂接口直接抛 `hresult_no_interface` → `openScreen` 优先 WGC（`CaptureSource`），起不来统一回退 GDI（`ScreenDcSource`）：每帧 `BitBlt` 选区且**不带 `CAPTUREBLT`**（30 fps 下会令指针闪烁，DWM 合成后分层窗口已在屏幕像素内），按 `GetCursorInfo` + `DrawIconEx` 绘指针（按形状缓存热点），alpha 补 255（GDI 留 0）后 `UpdateSubresource` 进 BGRA 纹理复用后续编码；共用 `displayOf`，在 `Progress::screen` 与日志写明源与报错阶段。调用高于 1809 的 WinRT API 必须留退路并在真实旧系统验证（虚拟机须关自动熄屏防 DWM 停合成）。
- **同进程二次录屏崩溃在 `AddRef`（WinRT 工厂缓存悬空）**：`winrt::get_activation_factory` 将 `IGraphicsCaptureItemInterop` 等工厂缓存在静态变量中，`winrt::uninit_apartment()` 卸载对应 DLL 后缓存指针悬空，同进程再录（如单测）即访问违例 → `winrt::uninit_apartment()` 之前必须先调用 `winrt::clear_factory_cache()`。
- **无 D3D11 视频能力的驱动 / 虚拟机 / RDP 录屏报 `0x887a0004`（#214）**：建 D3D11 设备若强制带 `D3D11_CREATE_DEVICE_VIDEO_SUPPORT`（供 GPU 视频处理器转 BGRA → NV12），虚拟机、基本显示适配器、RDP 与老驱动直接返回 `DXGI_ERROR_UNSUPPORTED`，连软件编码都进不去 → 先带该标志创建，失败后不带标志重建（`Graphics::video = false`），不建 `Converter` 和 `MFDXGIDeviceManager`、不试硬件编码，画面拷入 BGRA staging 纹理读回并在 CPU 用 `bgraToNv12` 按 BT.709 有限范围转 NV12 交软件编码器（`Writer::video`），日志加 `(no D3D11 video: NV12 on the CPU)`；单测以 `Options::noVideoDevice` 覆盖。
- **Media Foundation 复用同一可变 `IMFMediaType` 致 `Finalize` 失败**：将 AAC 输出类型传给 `AddStream` 后又把同一对象改成 PCM 输入类型，Sink Writer 内部仍持引用致输出类型被篡改，写帧成功但封装 `Finalize` 报 `MF_E_SINK_HEADERS_NOT_FOUND` → 输入、输出各自新建独立 `IMFMediaType`，提交后不再修改；涉及音轨的回归必须完成封装，并用独立 Source Reader 同时解码视频和音频校验真实音量。
- **奇数选区补偶、解码行距（stride）与画质对比真值校验**：录屏奇数宽高选区须在 GPU 复制末行 / 末列补齐偶数（避免缩放糊字）；Source Reader 解码缓冲常带更宽行距与对齐填充，直接按 `width × height × 4` 拷贝会误判画面错行；桌面录屏也会录进上方遮挡窗口误导压缩体积对比 → 验证器优先读 `IMF2DBuffer::Lock2D` 行距，普通缓冲在读帧后重查当前媒体类型的 `MF_MT_DEFAULT_STRIDE` 逐行拷贝可见像素；编码档位对比须固定同源置顶生成窗并解码抽帧核对内容。
- **“不清晰”是 4:2:0 色度抽样，不是编码质量；量清晰度要把亮度和颜色分开**：H.264（NV12）每 2×2 像素只存一个颜色，彩色小字与 ClearType 字边发灰；把编码质量从 70 提到 100，亮度还原度 46 → 55 dB，含颜色的还原度却一直停在约 30 dB，肉眼几乎看不出档位差别。Media Foundation 的软件和硬件 H.264 编码器都不出 4:4:4 → “超清”把画面最近邻放大 2 倍再编码（`Doubler`，每个色度样本正好对应一个屏幕像素），还原度约 47 dB、体积约 2 倍。D3D11 视频处理器的缩放滤波由驱动决定（一般是双线性，会糊），放大必须自己用最近邻做；被 Direct2D 当源图的纹理要带 `D3D11_BIND_SHADER_RESOURCE`。验证：`tst_recording` 的 `clarityByQuality` 直接取解码出的 NV12 亮度平面比亮度（经 RGB 再算亮度会被解码端的颜色转换封顶在约 43 dB，看不出档位差别），颜色用 2×2 取平均后的 RGB 比；`recording-probe sample … --quality N --fps N --scale 2 --backdrop ref.png` 可配合 ffmpeg 的 `psnr` 复核（参考图转 YUV 要指定 BT.709 有限范围）。
- **质量模式下各家编码器认的参数不一样：质量值和量化值要一起给**：`eAVEncCommonRateControlMode_Quality` 实际是固定量化值（QP）。系统软件编码器只按 `CODECAPI_AVEncCommonQuality`，给了 `CODECAPI_AVEncVideoEncodeQP` 也不理；NVIDIA 的 MFT 反过来，给了 QP 就按 QP（质量 100 配 QP 30，出来就是 QP 30），没给才从质量值换算（实测 QP = 46 − 0.3 × 质量，即 70/80/90/100 → 25/22/19/16）。只给质量值时，不会自己换算的显卡编码器会让四档都落在驱动默认 QP 上，表现为“最高档也不清晰” → 两个都给且保持一致（`recording::quantizer`），被拒再只给质量值、再退码率。给了不等于用了：协商后用 `ICodecAPI::GetValue` 读回模式、质量值、QP 写进日志（`encoder holds: mode 3, quality 100, QP 16`）；读回的码率不可信（NVIDIA 答的是它自己的默认值，实际按给的编），所以不记。核对真实 QP：`ffmpeg -i f.mp4 -c copy -bsf:v trace_headers -f null -`，看 `pic_init_qp_minus26` + `slice_qp_delta`。比较两段视频的还原度时两路要先 `settb=1/帧率,setpts=N` 对齐帧号，否则 mkv / mp4 时间基不同会错帧，量出来只有 20 dB 上下。
- **AMD 的编码器不要用质量模式，也不要只给输出类型的码率**：Chromium 专门对 AMD 关掉了“质量模式 + QP”这条路；别人在 RX 6800 XT / 6900 XT 上实测，只设 `MF_MT_AVG_BITRATE` 时实际码率是目标的 2 倍，显式设了码率控制模式才守得住，纯 CBR 还会塞填充数据，“峰值受限可变码率（平均 + 1.5 倍峰值）”正常；Cap 在 AMD 上同样只用按码率的可变码率 → AMD（`Graphics::vendor == 0x1002`）直接走显式的峰值受限可变码率，码率按 Cap 的每像素比特数给足（静止画面用不满，不会白占体积）。本机没有 AMD 显卡，这条靠资料和日志：拿到 AMD 用户的日志先看 `rate` 里的 `bitrate … kbps, peak …` 和 `encoder holds: mode 1`。认证要求显卡编码器的 QP 只保证 20–40，更低的（“超清”的 16）在别家可能被夹住或拒收，拒收时逐级退回。
- **60 帧/秒靠 `Sleep` 定不准；帧时间不能用整数间隔累加**：`Sleep` / `sleep_for` 醒在系统时钟节拍上（默认 15.6 ms），而 60 fps 每帧 16.7 ms，实测 3 秒时好时坏，差的一次只录到 133/180 帧、最长空档 83 ms；`1 s / 60` 也不是整数个 100 ns，按固定间隔累加会让时间戳漂成 60.0002 fps → 用 `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` 可等待定时器（Win10 1803 起，不改全局时钟精度）等到下一帧，帧时间由帧序号算（`n × 1 s / fps`）。编码或 HDR 回读跟不上时循环会跳帧（前一帧多停留一会儿），日志的 `frames` / `elapsed ms` / `fps` 能看出实际帧率，面板也会提示。
- **录屏占用：量了再改，别凭感觉加优先级**：高刷新率屏上 WGC 每显示一帧就送一帧（240 Hz 屏录 60 帧时 4 帧里丢 3 帧），`MinUpdateInterval`（Win11 24H2，`IGraphicsCaptureSession5`）让系统按录制帧率送，录制进程 CPU 11% → 5.5%（单核）、GPU 少 5 个点；用 `try_as` 取接口，取不到就照旧。给录制线程挂 MMCSS（`AvSetMmThreadCharacteristics("Capture")`）实测没有收益：32 个逻辑核全部占满时，挂不挂都是 360/360 帧、无空档，所以没有加。软件编码的开销在 CPU 上（720p 区域 30 帧约 1/3 个核，60 帧 2 倍约 2 个核），显卡编码时 CPU 只有 3%–6% 单核；测占用要用每帧都变的画面（静止画面几乎不送帧），并同时看 `dwm.exe`。
- **“没跟上帧率”先看日志里的每帧耗时，别猜**：录屏结束的日志带 `read … ms, encode … ms a frame, waits by …`（读屏、编码的平均耗时和等待方式）以及 `refused`（被拒的编码方式、阶段和错误码）。1809 虚拟机选 60 帧只录到 31 帧，看起来像定时精度（31 ms 正好两个系统节拍），日志却是 `read 31.5 ms, encode 0.7 ms, waits by timer`：慢在 GDI `BitBlt` 读屏，定时器和编码都没问题；22H2 虚拟机（WGC）是 `read 0.1 ms`，60 帧录满。降级不能静默：没按 2 倍保存、没跟上帧率都在保存后的面板上说明（`Recorder::advice`）。
- **新编码不是白捡的**：同一段滚动文字（2 倍尺寸，本机 NVENC 经 Media Foundation），HEVC 比 H.264 只小约 5%（1,809 对 1,909 kbps，还原度高 0.4 dB），AV1 在相近还原度下小约 25%–30%；但 Windows 自带播放器放 HEVC 要另装扩展，AV1 只有较新的显卡能硬件编码、系统没有软件编码器。所以录屏仍用 H.264。
- **点击高亮：复用唯一鼠标 Raw Input 订阅与全链路验证**：同进程另起鼠标 Raw Input 接收器会覆盖已有注册；向 QML 面板发 `QMouseEvent` 不产生 Raw Input，且 ClearType / 色度压缩会在文字边缘产生假橙色像素 → 复用 `KeyListener` 唯一鼠标注册，关闭时只撤销点击订阅；验证须分别覆盖真实系统输入、事件队列时间轴及最终解码画面图像核对，不可单凭颜色像素计数断言。
- **鼠标拖尾的自绘指针须与 DWM 逐像素一致**：`GetIconInfo` 只给系统 DPI 默认尺寸（指针调大后得 48 px，屏上实为 `CursorBaseSize` × 缩放 = 120 px）；`LoadImageW(LR_LOADFROMFILE)` 按尺寸加载时即使文件含恰好该尺寸的帧，也会改从更大帧重采样，白色轮廓偏约 1 px、黑色内芯多约 11%；D2D 不收 A8 位图（`0x88982F80`），`MASK_INVERT` 的掩码须为白色预乘 BGRA → 自行解析 .cur/.ani，取恰好尺寸的帧经 `CreateIconFromResourceEx` 按原尺寸解码。验证时在同一位置背靠背录关 / 开拖尾两段比对指针区域（只应剩编码噪声）；不同时段的画面不可比，背景与指针形状（箭头变手形）可能已变。
- **录屏键帽低级钩子随前台装卸致切回首击丢失（#98）**：本进程已登记键盘 Raw Input，自身窗口在前台时装低级钩子会干扰按键接收，故仅在外部程序前台时挂 `WH_KEYBOARD_LL` / `WH_MOUSE_LL`；但从控制条点回目标窗的首下点击先过完钩子链才切前台，`EVENT_SYSTEM_FOREGROUND` 到达装钩子时按下已过 → 前台事件装钩子时用 `GetAsyncKeyState` 读当前按着的鼠标键（按 `SM_SWAPBUTTON` 换算逻辑左右键），指针在目标窗上即补作一次按下（`KeyHook::pressHeld`，定时器与恢复重装不补）。注意：剪贴板面板不抢焦点，前台仍是外部程序，其搜索框打字会显示为键帽。
- **低级钩子防缺页超时与失联自恢复**：`WH_KEYBOARD_LL` / `WH_MOUSE_LL` 回调若因 `IdleTrim` 30 s 清工作集引起硬缺页而超过 `LowLevelHooksTimeout`（Win10 1709+ 硬封 1 s），系统会提前放行输入造成漏记或异常 → `IdleTrim` 的 `busy` 回调在 `Capture::busy()`（录屏 / 延时 / 长截图）时禁止清工作集；两钩子入口盖 `GetTickCount`，250 ms 定时器见 `GetLastInputInfo` 晚于它 500 ms 以上（`inputWentPast` 含回绕处理）且前台非高完整性 / 安全桌面时自动重装新钩子再卸旧钩子（`KeyHook::checkDropped` / `refresh`）。
- **录屏自动化测试环境约束**：Qt Quick 普通 `Text` 未设 `Accessible.role` 不进 UIA 树，窗口设 `applicationDisplayName` 后原生标题会追加程序名；手动直接运行 `tst_recording` 不设平台变量会导致 `gpu-click-highlight` 淡出尾帧失败 → 脚本用按钮 `TogglePattern` 代替读说明文字、用 `EnumWindows` 标题前缀找窗；手动跑 `tst_recording` 须照 CTest `ENVIRONMENT` 设 `QT_QPA_PLATFORM=offscreen`。

## OCR 与二维码识别

- **极端长宽比图像引发检测 OOM（`std::bad_alloc`）**：仅限宽度 ≤ 2000 若同时要求“短边 ≥ 30”，32739×35 等极细长条会让宽度上限失效（缩为 28062×30），再按“补黑到宽的 1/4”膨胀成 28062×7014（1.97 亿像素），ORT `NchwcMaxPool` 直接 `std::bad_alloc` 且无 AVX 的 CPU 走 SSE 极慢 → 短边规则使检测宽 > 2000 时横向分块（块宽 ≤ 2000、重叠 160），每块单独补黑、再纵向分条（条高 512、重叠 160）保证单次检测输入 ≤ 2016×512，再合并跨块同行重叠框（`joinedAcrossTiles`）；单行按 48 高缩放超 12000 列时在空白最多列切分（`partsOf`）分段识别并换算字位（拉丁词间补空格），每批合计 ≤ 36000 列。尺寸规则须用极端长宽比实测并查 trace 中的模型输入尺寸。
- **整张图一次过检测模型，瞬时内存按像素算（#467）**：找文字行（DBNet）每个输入像素约占 80 字节，持续整个检测过程；1920×1080 的截图一次检测就多出约 184 MB，复制一张截图时截图插件（智能打码预识别）和主程序（剪贴板图片识别）各来一次 → 条高由 2000 降到 512（`kStrip`），峰值降到约 1/3，检测多约 0.1 秒；高过重叠区（160）的大字在哪一条里都不完整，凡是归属本条的框贴到了条的切边（`kCutEdge`），该块改用 2000 高的条重新检测（`kTallStrip`，trace 里有 `looked at again`）。模型带全局池化，分条后个别行的结果会和整图略有出入（本机 80 张历史图：字数差约 0.9%，有多有少）。量峰值看 `PeakPagefileUsage`，按 0.4 秒采样会漏掉这种不到半秒的尖峰。
- **ZXing 扫码超单边 65535 像素抛 `std::invalid_argument`**：未检出二维码时 2× / 3× 放大重扫若只限总像素（如 1200 万），32739×35 放大 3 倍成 98217×105（仅 1030 万像素）仍破 ZXing `ImageView` 单边 65535 上限而抛异常 → 原图或放大后任一边超 65535 即跳过放大 / 跳过扫码，并捕获 ZXing 全部异常按无二维码处理，不影响已读出文字。
- **识别线程未捕获异常触发 `abort()` 绕过日志与坏图重启死循环**：`std::thread` / `std::jthread` 内 ORT、ZXing、Qt 容器抛出未接异常会走 `std::terminate` → `abort()`（WER 报 `c0000409` 参数 7、`ucrtbase.dll`），日志一片空白；剪贴板启动后 20 s 后台补读（`m_backlogTimer`）会反复命中同一坏图形成闪退死循环 → `TextRecognizer::work` 用 `try/catch(...)` 包住整张图识别，异常记为不可读且不再重试；配合 `reading-picture` 守卫文件（读前写入、读完删除，启动残留则首次延后、二次放弃并记 `clipboard-picture-not-read`）断死循环。
- **zxing-cpp 集成构建、UTF-8 编码与快捷识别动作隔离**：全局 `qt_standard_project_setup` 会给第三方目标开 `AUTOMOC` 与预编译头引发编译问题；ZXing 写二维码默认 Latin-1 遇汉字直接抛异常；快捷识别动作不应污染 OCR 结果窗口 → 对 `ZXing` 目标设 `AUTOMOC OFF` 与 `DISABLE_PRECOMPILE_HEADERS ON`；测试写中文二维码须 `setEncoding(CharacterSet::UTF8)` 并传 `std::string`；识别并复制 / 搜索 / 网页搜索使用独立 `CaptureOcr` 实例，`defaultWebSearchUrl` 取网页搜索列表首个带 `%s` 的条目（无则退回必应，测试设 `WINSHUN_WEB_DRYRUN` 只记日志不打开浏览器）。
