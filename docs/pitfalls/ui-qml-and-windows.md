# 界面、QML、DPI 与窗口踩坑

## 屏幕缩放、物理像素与清晰度

- **逻辑与物理像素边界及小数缩放误差**：Win32 消息（`WM_MOVING`、`WM_NCHITTEST`、`GetWindowRect`）使用物理像素，Qt/QML 使用逻辑像素；125%/150%/175% 下换算存在 ±1 px 取整误差 → 仅在 Win32/Qt 交界处换算一次，交互阈值与间距按逻辑像素定义，跨单位比较须先统一或容差 1 px。
- **像素验收工具与抓图陷阱**：不带 `--renderer d3d11` 的软件渲染边缘与桌面不同，不能用于数像素；`QT_SCALE_FACTOR` 在本程序无效；GDI+ `CopyFromScreen` 会丢失 `RGB(13,11,12)` 像素 → 改动边框或尺寸后在 125%/150%/175% 下用 `--preview-settings <dir> --scale 1.5 --renderer d3d11 --tree`（或 `QT_SCREEN_SCALE_FACTORS=1.5`）查 `.edges.txt`（`.02` 偏移属正常，`.5` 才是问题），真窗口像素抓图用 GDI `BitBlt` 到 DIB 或 DXGI。
- **1 px 细线、边框内缩与圆角框发虚**：150% 下 1 逻辑像素 = 1.5 物理像素，`Rectangle { height: 1 }` 会按小数位随机落成 1 或 2 行，而 `border.width: 1` 由 Qt 取整为 2 行；子项按 `x: 1` / `margins: 1`（1.5 px）内缩会压掉边框半行；圆角框落在 `.5` 设备像素上会抗锯齿糊成三行 → 细线厚度、边框内缩与含边框父项尺寸增量（`2 * edge`）一律用 `Theme.edge(dpr)`；锐利圆角框坐标与尺寸用 `Theme.snap` / `Theme.snapUp`，居中用 `y: Theme.snap((parent.height - height) / 2, dpr)` 替代 `anchors.verticalCenter`；自动排版容器的项高用 `snap` 取整（勿全用 `snapUp` 避免累计偏移）。
- **奇数 px 字号发虚与 `font.pixelSize` 截断**：150% 下 11/13 px 为 16.5/19.5 物理像素，FreeType 竖直微调对不齐笔画；且 QML `font.pixelSize` 是 `int`，非整数逻辑字号会被截断 → 优先用 `Theme` 预设字号档位（确保 150% 下为整数物理像素）；需要非整数逻辑字号时改用实数 `font.pointSize`（`像素 × 72 / 96`，高 DPI 下逻辑 DPI 恒为 96）。
- **普惠体紧凑行间距失衡**：Qt 在 Windows 默认按 `usWinAscent + usWinDescent` 排版，默认字体阿里巴巴普惠体 3.0 该值偏大，使紧凑行中名字离自身路径比离下一行更远 → 结果行标题与路径设 `font.preferTypoLineMetrics: true` 改用排版行高（紧凑行 `spacing` 收至 2）；涉及行高的改动须切换多款字体与字号档位复测墨迹间距。
- **圆内数字居中偏下**：`anchors.centerIn` 含下伸留白，`TextMetrics.tightBoundingRect` 底边也低于基线约 0.45 逻辑像素，且程序用 FreeType 而独立 `qml` 工具默认用 DirectWrite，竖直位置不同 → `CenteredNumber.qml` 按基线与字形顶端居中并改用 `Text.CurveRendering` 绘轮廓，居中效果须在程序自身截图中量像素。
- **FreeType 漏登 Windows 字体与误落细体**：FreeType 下 Qt 拿 Windows 家族名匹配注册表 `Fonts` 键，名称表 ID 1/4 不一致（如霞鹜文楷常规体）或 Windows 拆出的字重家族（如 `Noto Sans SC Medium`、`Cascadia Code SemiBold`）会漏登，退回 Tahoma 或按 ID 16 误画成 Light 细体 → 先用 `QFontInfo::exactMatch()` / `QRawFont` 校验（勿用 `QFontDatabase::hasFamily()` 一刀切），未识别时走 DirectWrite GDI 互操作（`CreateFontFromLOGFONT` → `IDWriteLocalFontFileLoader::GetFilePathFromKey`，临时字体回退 `GetFontData`）加载并设上 GDI `tmWeight`（勿用 DirectWrite `GetWeight()`，可变字体上会误报 700）；验收字重须比对渲染墨量。
- **中文路径字体加载失败与 `addApplicationFontFromData` 堆驻留**：FreeType 下 `QFontDatabase::addApplicationFont(path)` 经 ANSI C 运行库打开文件，非 ASCII 路径静默返回 `-1` 并回退微软雅黑；改用 `addApplicationFontFromData(file.readAll())` 又会让整份字体常驻堆并翻倍膨胀（8.5 MB 占 16 MB）→ 统一用 `ws::addFontFromFile`（`FontFile.h`）以 `QFile::map()` 内存映射加载并传 `QByteArray::fromRawData`。
- **透明窗口子像素抗锯齿反向彩边**：运行过 ClearType 调谐器的机器（存在 `Avalon.Graphics\DISPLAY1\PixelStructure`）在 FreeType 下输出子像素字形，叠加到 alpha=0 的 Mica 窗口会出现左蓝右橙反向彩边 → `SystemTheme::backdropAvailable` 时建窗前即给应用字体加 `QFont::NoSubpixelAntialias` 统一灰度抗锯齿（文字项创建时复制字体，不可等开关透明时再改）；开发机可用 `QT_SUBPIXEL_AA_TYPE=RGB` 复现。
- **图标按容器排版，不看笔画**：`Glyph.size` 曾是比 Phosphor em 小的框（em = size × 1.125，且按磅设字号随字体 DPI 变，离屏预览漏设 `QT_FONT_DPI=96` 时图标大 1.5 倍），笔画伸出框外，按框留的间距看着贴字或左右不均，于是出现量笔画定位的补丁 → `Glyph.size` 就是图标容器（偶数方格：12/14/16/18/20/24），Phosphor 的 em 恰为该方格、与字体 DPI 无关，笔画带着图标库自己的留白待在里面；周围元素只与容器保持间距，不测笔画、不给 `Glyph` 另设比 `size` 大的 `width`/`height`；带前置图标的选项（类型条、剪贴板分组、筛选项）容器到左、上、下三边等距。
- **`PhosphorGlyph` 像素对称对齐与按钮按下缩放**：FreeType 原生文字横居中、竖绑 15/16 em 基线且 `QFont` 逻辑取整，使小数 DPR 下叉号/加号/箭头一边实一边虚；同时 `PhosphorGlyph` 用 `QSGTexture::Nearest` 贴图，对其或其父 `Row` 设 `scale` 会丢行丢列变糊（原生文字 `scale` 亦糊）→ Phosphor 图标统一走 `PhosphorGlyph`（1024 px 未微调 `QRawFont` 轮廓、按居中笔画宽奇偶对齐像素中心/边缘、`QPainter` 按设备像素光栅化并加 `+1/64` 逻辑 px 避开半像素平局；插件测试须同步 `qmlRegisterType<PhosphorGlyph>`）；按下缩小改用 `Glyph.inkScale` 按缩小后整数设备像素重绘轮廓并保持中心相位不变。
- **`QGlyphRun::stringIndexes` 跨后备字体错乱**：Qt 6.12 `QTextLine::glyphRuns` 拆段时向后备字体段传入整段 `logClusters`，导致 `stringIndexes` 全为段首，且 `QTextLayout::glyphRuns` 按字体哈希合并打乱顺序 → 显示自检不依赖 `stringIndexes`，改对单行一字一形样例用 `RetrieveGlyphPositions` 按横坐标顺序对应字符。
- **QML `sourceSize` 单位差异、衰减动画余抖与 `QQuickPaintedItem` 细缝**：`image://`、SVG、PDF 的 `sourceSize` 为**逻辑像素**（Qt 自动乘 DPR），PNG/JPG 为**物理像素**（须手动乘 DPR），弄反会触发二次缩放（150% 产生 3 px 周期锯齿或发虚）；衰减动画（如 `sin(…)·exp(-k·t)`）永不归零会使图片持续微旋并保持 `smooth: true`；`QQuickPaintedItem` 默认线性插值在半物理像素位置会让棋盘格产生过渡色细缝 → 像素精确图设备像素取整、`width = 像素数 / dpr`、静止时 `smooth: false`；衰减动画设阈值（如 `< 0.15°`）强制归零并关 `smooth`；不缩放的自绘项构造时 `setSmooth(false)`，圆角先画满再用 `CompositionMode_DestinationOut` 擦除外圈（禁用不抗锯齿的 `setClipPath`）。
- **异步图片提供器的单线程阻塞、取消泄漏、析构竞态与低分缓存**：Qt 6.12 每个 QML 引擎仅 1 条 `QQuickPixmapReader` 线程（`ForceAsynchronousImageLoading` 不增线程），慢缩略图走同步提供器会堵死全列表图标；`cache: false` 致复用重解码闪烁；Qt 内置未用缓存仅 2 MB；`SIIGBF_INCACHEONLY` 可能命中先前小列表留下的低分缩略图；`cancel()` 不发 `finished()` 会内存泄漏；引擎销毁时 Qt 直接删除未完成响应对象，后台线程裸指针写回必崩 → 缩略图与剪贴板图改走自带线程池和 `QCache`（URL 带时间戳防脏图）的 `QQuickAsyncImageProvider`；无图时 `textureFactory()` 返回 `nullptr` 且 `errorString()` 留空（QML 查 `status === Image.Ready && implicitWidth > 0`）；取消必发 `finished()`；后台任务统一经 `PooledImageResponse` 的加锁 `Handle` 访问响应；大图模式发现缓存长边不足时在后台用 `SIIGBF_BIGGERSIZEOK` 重取（上限 1024 物理像素）。

## 窗口边框、DWM 圆角/阴影、Mica 与窗口状态

- **原生事件过滤器漏收输入消息与 `*result` 空指针崩溃**：Qt 窗口过程直接拦截鼠标、非客户区鼠标、键盘、`WM_MOVING`/`WM_SIZING`/`WM_SYSCOMMAND`/`WM_COMMAND`/`WM_NCMOUSELEAVE`/`WM_PAINT`/`WM_INPUT` 与 IME 消息（QTBUG-67095），不交 `QAbstractNativeEventFilter`；投递消息（如 `startSystemMove()` 投递的 `SC_DRAGMOVE`）经 `"windows_generic_MSG"` 过滤器时 `result` 为 `nullptr` → 窗口消息统一用 `SetWindowSubclass` + `DefSubclassProc` 拦截，过滤器写 `*result` 前必先判空。
- **还没建原生窗口就交给 `WindowFrame`/`SavedWindowSize`，被当成换了句柄**：`setWindow` 若先装事件过滤器、再在挂钩时第一次调 `winId()` 建窗，建窗发出的 `PlatformSurface`（`SurfaceCreated`）会被过滤器当作“句柄换新”，误报 `Window frame: the window has a new native handle … hooked again` 并重复挂钩（预览窗由工厂现建时就会这样）→ `setWindow` 先挂钩（需要时此时建窗）再装过滤器；真正销毁重建仍靠 `SurfaceCreated` 重新挂钩并记日志（`Placement::setWindow` 本来就先取句柄）。`tst_appearance` 的 `windowFrameTakesAWindowNotYetMade` 两种情况都查。
- **自定义拖动区、`HTCAPTION` 悬停/右键与可点击把手**：`MouseArea` 调 `startSystemMove()` 时系统移动循环吞掉松开，导致只能拖第一次；`HTCAPTION` 属非客户区，QML 收不到悬停且 `WM_NCRBUTTONUP` 交 Qt 会转成客户区 `WM_CONTEXTMENU`；把手上先 `DragDetect` 再进系统移动循环会丢掉触发拖动阈值的位移 → 用 `WM_NCHITTEST` 对拖动区返回 `HTCAPTION`（`frame.addDragArea`/`addControl`）；悬停由子类用 `WM_NCMOUSEMOVE` + `TrackMouseEvent(TME_LEAVE | TME_NONCLIENT)` 写 `frame.pointer` 并在 `visibleChanged` 清空；在 `HTCAPTION` 吞掉 `WM_NCRBUTTONUP`（设置窗自弹 `TrackPopupMenu(TPM_RETURNCMD)`）；可点把手通过 `WindowFrame::addHandle` 在 `WM_NCLBUTTONDOWN` 调 `DragDetect`，假则发单击并吞掉，真则先 `SetWindowPos` 补齐“当前 − 按下点”位移再交移动循环，并吞掉 `WM_NCLBUTTONDBLCLK`。
- **窗口浮层被拖动区点穿与缩放边抢占滚动条**：挂在 `contentItem` 上的弹层压在底栏或标题栏时，未登记到 `WindowFrame` 会命中 `HTCAPTION`/`HTMAXBUTTON`；可缩放无边框窗内嵌缩放边宽为 `SM_CXSIZEFRAME + SM_CXPADDEDBORDER`（150% 下 10 px），贴右边的 `ListScrollBar` 会命中 `HTRIGHT` → 可点击浮层显示时调 `frame.addPopup(item)`（`hitTest` 最先返 `HTCLIENT`，各窗口根沿用 `required property WindowFrame frame`）并垫全按键 `MouseArea`；可缩放窗贴右控件须留 `anchors.rightMargin: window.frame.resizeMargin(window.dpr)`（离屏探针不经过 `WM_NCHITTEST`，须显式断言）。
- **`WM_MOVING` 累加死锁、拖动吸附与物理工作区贴边**：`WM_MOVING` 提议矩形基于上次被改过的矩形累加，拖动中拉回吸附线会死锁窗口，中途吸附手感也像卡顿；`QHighDpi::toNativeWindowGeometry` 与 `QScreen::availableGeometry()` 各自舍入，150% 下逻辑贴底会多 1 物理像素压任务栏 → 首次 `WM_MOVING` 记抓取点，后续按“光标 − 抓取点”重算；拖动时仅按当前实际高度限在工作区，松手后再滑向中线/默认高度或上移保底 3 行空间；落位后用 `GetMonitorInfo` 物理工作区按 Qt 舍入公式复核，超界回退 1 逻辑像素；文件夹搜索框定位还须从 `SHELLDLL_DefView` 扣除 `DirectUIHWND > CtrlNotifySink` 下可见的 `ScrollBar` 子窗口。
- **无边框最大化裁边与 Win11 贴靠布局**：`WS_OVERLAPPEDWINDOW` 配合 `WM_NCCALCSIZE` 返回 0 时，最大化后四边各超出显示器一个边框宽度（150% 下 11 px，QTBUG-113736），改 `WM_GETMINMAXINFO` 无效 → 最大化时在 `WM_NCCALCSIZE` 将客户区与显示器工作区取交集；最大化按钮在 `WM_NCHITTEST` 返回 `HTMAXBUTTON` 启用贴靠布局，吞掉 `WM_NCLBUTTONDOWN`/`DBLCLK`，在 `WM_NCLBUTTONUP` 切换最大化。
- **禁自绘窗口外框、Win10 直角定论与 Win11 阴影样式约束**：自绘圆角/外边/阴影与 DWM 冲突频发漏色断缝；DWM 无阴影强弱 API，Win11 按样式给阴影（`WS_CAPTION` + `WM_NCCALCSIZE(0)` 为完整阴影 + `DWMWA_COLOR_DEFAULT` 原生边，纯 `WS_POPUP` + `DWMWCP_ROUND` 为半浅阴影 + 原生边，`WS_POPUP` + `DWMWCP_DONOTROUND` 无阴影无边，Win10 `WS_POPUP` 均无阴影，无法原生实现“无阴影圆角”）→ 所有主题严禁自绘窗口圆角/外边/阴影（内圆角按 `max(8 − 间距, 4)` 同心计算）；Win10 窗口一律走无 alpha、无 Region 的原生直角 DWM 阴影路径并用 `WindowEdge.qml` 画 1 px 直角边；搜索框阴影经 `win::setWindowShadow` 在 `WM_STYLECHANGING` 控制 `WS_CAPTION`（无阴影强制直角并回退 `WindowEdge.qml`，展开面板含 `WS_THICKFRAME` 恒为标准阴影）；外框/阴影验证须抓桌面像素（禁用 `grabWindow()`），`DWMWA_BORDER_COLOR` 只写不可读。
- **原生子窗圆角同步与 Windows `small` 宏冲突**：独立 STA 预览弹窗与任务栏 D2D 子窗不在 `QGuiApplication::allWindows()` 中，且先刷 Look 后调 `applyAppearance()` 会拿到旧偏好；Windows RPC 头文件将 `small` 宏展开为 `char` 导致编译报 C2632 → 原生窗口共用 HWND 圆角登记，在 `applyAppearance()` 写入偏好后立即刷新所有登记窗口与任务栏 Look（直角时光环外扩半径也须归 0）；参数禁用 `small` 命名（用 `smallCorners`）。
- **Mica 启用条件、平灰回退、Swapchain 告警与清屏预乘**：软件渲染下带 alpha 窗口为分层窗口不绘 Mica（探针软件渲染下 Mica 透明区还会被 `WindowFromPoint` 点穿，真鼠测须带 `--renderer d3d11` + `SetThreadDpiAwarenessContext(-4)`）；`DwmExtendFrameIntoClientArea` 传 `-1` 会画出系统标题栏按钮；半透明窗口底色 Qt 未预乘会被 DWM 溢成纯白；Qt 不将无边框窗口的 `WM_NCACTIVATE` 交 `DefWindowProc` 会让 DWM 画未激活平灰；`QQuickWindow::setColor()` 切回不透明时会把 `alphaBufferSize` 改回 `-1`，引发 D3D11 每次 resize 刷告警；D3D11 透明窗配合淡入动画带 `WS_EX_LAYERED` + `LWA_ALPHA` 后 `DWMWA_NCRENDERING_ENABLED` 为假，带 `WS_CAPTION` 时（如浅/无阴影展开搜索面板）`uxtheme` 的 `ThemeDefWindowProc` 会拦截 `DefWindowProcW(WM_NCACTIVATE, ..., -1)` 并无视 `lParam=-1` 直接往 GDI 重定向位图绘制旧版 Win7 Aero Basic 蓝边与标题栏，永久透出 Mica/Acrylic → 仅 Win11 22H2+ 且 D3D11 启用 `DWMSBT_MAINWINDOW`，边框扩展维持 `{0,0,1,0}`，底色仅全透明或不透明（半透明叠层用 `Rectangle`）；`applyFramelessToHwnd` 调 `SetWindowTheme(hwnd, L"", L"")` 关掉该窗口的 `uxtheme` 非客户区钩子，`nativeFrameProc` 与 `WindowFrame` 拦截 `WM_NCPAINT`/`WM_NCUAHDRAWCAPTION`/`WM_NCUAHDRAWFRAME` 返回 `0`、剥离 `WM_PRINT` 的 `PRF_NONCLIENT`，并将 `WM_NCACTIVATE` 统一以 `lParam=-1` 经 Qt 交给 `user32` 的 `DefWindowProcW` 更新 DWM 激活态（勿连发成对刷新），失焦/关透明/高对比度铺回不透明底；`prepareBackdrop` 设 `alphaBufferSize(8)` 后监听 `colorChanged` 随时补回。
- **主题/调色板切换重置深色 Mica**：主题切换或仅换系统强调色触发 `ApplicationPaletteChange` 时，Qt 会把所有顶层无边框窗口（含隐藏和不抢焦点的剪贴板面板）的 `DWMWA_USE_IMMERSIVE_DARK_MODE` 重设为浅色，且与我们的修改挤在同一帧内 DWM 可能忽略 → 显示前在 `visibleChanged` 调 `win::keepDarkFrameOnShow` 按需修正；主题与 `ApplicationPaletteChange` 触发 `App::guardDarkFrames`，延迟 50 ms 设回并在 1 s 内每 10 ms 守护全部已有原生窗口。
- **Mica 打开激活渐变与 `DWMWA_TRANSITIONS_FORCEDISABLED` 致最大化变黑**：首帧未激活会触发 Windows ~250 ms 的 Mica 激活渐变；但对带系统材质的窗口设 `DWMWA_TRANSITIONS_FORCEDISABLED` 后，Win11 26200/26300 上一最大化背景材质即永久变纯黑（事后设回 `FALSE` 仍无效）→ **严禁**对可最大化或可贴边窗口设 `DWMWA_TRANSITIONS_FORCEDISABLED`（仅固定小窗可用）；显示前用 `win::expectActivation` + QML `arriving` 透明首帧消除渐变，并以 `win::setCloaked` 隐身到首帧画好即现身、隐藏前先隐身消除淡入淡出。
- **代码改大小的窗口长出的部分先黑一下（或残留旧画面）**：QML `Window` 的 `x`/`y`/`width`/`height` 绑定逐个下发 `SetWindowPos`，且每次改大小到画出新尺寸的一帧之间，DWM 会显示截断的旧帧、在长出的部分补黑（#414 剪贴板大图换图闪黑约两帧）→ 由代码定位定尺寸的窗口用 `WindowPlacer`（`place(rect)` 一次 `setGeometry`；可见窗口改大小时先 `win::setCloaked`，经 `FrameReveal` 等到新尺寸画好的帧再现身，150 ms 兜底；只挪位置或隐藏时直接放）；换内容也别留空档：下一张在另一个槽位读好再切过去（`ClipPictureViewer` 双槽），不要先清空再加载。
- **隐藏复用窗口的状态错乱（`SIZE_RESTORED`、跨 DPI 错宽与面板高度竞争）**：隐藏时 `setWindowStates(Qt::WindowMaximized)` 后，显示前任意 `SetWindowPos` 会发 `WM_SIZE (SIZE_RESTORED)` 把状态改回 `NoState`；隐藏窗口经 Qt `setPosition` 跨不同 DPI 屏幕时，因 `m_inSetgeometry` 为真导致 `handleDpiChanged` 不按新缩放调大小（`setScreen` 无效）；小框 `height` 绑定与 `minimumHeight: panel ? 360 : 0` 同时依赖 `panel` 时求值顺序不定，收回面板易被 360 截断留底白 → 最大化延后到 `QEvent::Show` 才设且隐藏期间状态不持久化；跨屏复用先用 Win32 `SetWindowPos`（只移不改大小，`win::moveToMonitorOf`）触发正常 `WM_DPICHANGED` 再 `resize`/`setPosition`；面板切换用 `Binding { when: !window.panel; restoreMode: Binding.RestoreNone }` 让开尺寸，`height` 条件写成 `!window.panel && window.minimumHeight === 0`。
- **后台抢前台、Shell 浮层锁焦点与托盘菜单冷启卡顿**：`WM_INPUT` 不授予前台权，禁用 `AttachThreadInput`（会拖死前台响应）；开始菜单/搜索/控制中心/通知中心（`SearchHost`/`StartMenuExperienceHost`/`ShellExperienceHost`/`ShellHost`）会锁死前台；首个 `SHGetFileInfoW` 会拉入第三方菜单钩子（如 Nilesoft Shell `shell.dll`）拖慢首次 `TrackPopupMenuEx`（~310 ms），加上首焦点 IME 加载和同步查计划任务 → 先用 `AllowSetForegroundWindow(GetCurrentProcessId())` 探权（勿先试可能被拒的 `SetForegroundWindow`），无权时发零位移空鼠标 `SendInput(INPUT_MOUSE, kOwnInput)` 再激活；前台属 Shell 浮层时先发 Esc 等其退出（最多 500 ms）；测试夹具短连输入队列拿前台后须立即断开，涉及前台/输入的测试须串行；首次取图标后在后台线程对无主菜单调一次失败的 `TrackPopupMenuEx` 预热钩子（`shell::prepareMenuHooks`），预激活 `ITfThreadMgr`（不释放），缓存自启状态。
- **浮层菜单与按键提示的字号**：原生菜单（托盘、贴图右键）、截图角落的按键提示（`CaptureKeyHints.qml`）、贴图的按键卡（`PinKeyCard`，原生分层窗）和启动器/剪贴板的快捷键浮窗（`ShortcutTip.qml`）同一套：正文（每行做什么）取 `Theme.menuTextSize`，键帽字、分组标题和页脚取 `Theme.menuCaptionSize`，键帽高 `Theme.keycapHeight`，都随界面大小（紧凑/密集 14/12 px，即 Windows 11 自己的菜单字号）；取 `fontCaption` 当正文会小一号（12 px），高分屏小屏幕上看着吃力，与旁边的菜单也对不上。C++ 自绘的从 `Theme` 单例读这三个值（`traymenu`、`PinKeyLook.h`），不写死。菜单行高随字号留 14 px 余量（不低于 28），项宽向上取整——四舍五入少掉的零点几像素会让最宽那一行被省略成“剪贴板…”；按键提示行高取 `max(键帽高, 正文 + 6)`。`tst_traymenu` 的 `textSize`、`tst_pinwindow` 的 `keyCardType` 逐档查字号与行高，`--preview-capture-tools --key-hints`/`--pin-keys` 和 `--shortcut-panel` 查各自的字号。截图工具条的“按键”总表是长篇参考（三十来行），保持说明字号，否则 800 逻辑像素高的屏幕放不下。
- **自绘菜单外圈的方形影子**：自绘（`MFT_OWNERDRAW`）的 Win32 菜单在 Windows 11 由 DWM 画圆角和软阴影，菜单窗口类 `#32768` 的 `CS_DROPSHADOW` 还会另建一个方形 `SysShadow` 窗口，偏右下露出一圈方边。影子在菜单显示时创建，须在 `TrackPopupMenuEx` 之前用一个不显示的 `#32768` 窗口改本进程的类样式（`traymenu` 的 `matchMenuDropShadow`）；直角或 Windows 10 时 DWM 不给菜单影子，保留旧影子。`tst_traymenu`（`WINSHUN_TRAYMENU_LIVE=1`）逐行查类样式和可见的 `SysShadow` 数。
- **全局修饰键双击（Raw Input / UIPI / 游戏防误触）与进程环境污染**：仅听键盘 Raw Input 漏判同位 Ctrl+点击与触摸板捏合（转 Ctrl+滚轮），按指针位移取消又误杀移动中双击；在 `WM_INPUT` 里现查 `GetAsyncKeyState` 会漏掉已抬起的组合键；管理员/UIAccess 窗口前台时 UIPI 拦截普通进程 Raw Input；无边框全屏游戏报 `QUNS_BUSY` 而非 `QUNS_RUNNING_D3D_FULL_SCREEN`，`GameConfigStore` 不可靠；`applicationFilePath()` 含 `/` 传 Shell 会退回默认图标；从 VS Code 启动会继承 `ELECTRON_RUN_AS_NODE=1` 导致 `ShellExecuteEx` 打不开 Electron 应用；中文环境变量用 `qputenv` 按 ANSI 乱码、`SetEnvironmentVariableW` 不同步 CRT → 同时听鼠标 `RIDEV_INPUTSINK`（按键/滚轮/按住鼠标键均作废，不按位移取消），按事件流追踪修饰键（仅静默 >1.5 s 重查补安全桌面丢失抬起），过滤 Alt `< 20 ms` 合成连按（勿全丢 `hDevice == NULL` 以兼容改键工具）；高权限前台由服务按用户令牌派生 `UIAccess=1` + `IL=0x3000` 子进程监听并授权前台（会话 0 服务不能跨会话查用户 HWND，以 `kReportsAlt`/`kReportsShift` 兼容旧服务）；游戏防护结合独占全屏与“光标隐藏（非打字隐藏/非 `CURSOR_SUPPRESSED`）+ 锁区/捕获/铺满显示器”；Shell 路径必 `QDir::toNativeSeparators()`，`main()` 清 `ELECTRON_RUN_AS_NODE`，中文环境变量用 `_wputenv_s`。

## QML / JavaScript、无障碍树（UIA）与列表性能

- **Qt 6.8 起的增量垃圾回收会在空闲时崩（#490）**：JavaScript 引擎默认在事件之间分步回收（`QV4::MemoryManager::onEventLoop` → `GCStateMachine::transition`），0.50.0 有一例托盘里空闲、电脑睡眠唤醒后 `c0000005` 崩在这里，KDE Plasma 等基于 Qt 6.8+ 的程序也有同类报告 → 每个带 QML 引擎的进程在建引擎前调 `ws::qmlruntime::prepare()`（`QmlRuntime.h`，设 `QV4_GC_TIMELIMIT=0`，一次回收完，和 6.8 之前一样）；新增带 QML 的进程（插件的 `*Main.cpp`）照做。没有 Qt 的 PDB 时，崩溃栈的偏移可用 `dumpbin /exports Qt6Qml.dll` 找最近的导出函数定位到模块内的大致位置。

- **无障碍树（UIA）扁平化导致前台 O(N²) 卡顿**：Qt 6.12 `QAccessibleQuickItem::unignoredChildren` 会穿透所有未设 `Accessible.role` 的容器（含不可见项），`QAccessibleQuickWindow::child(i)` 每次重算 `rootItems()`，`QWindowsUiaMainProvider::Navigate` 逐个跳过不可见项；前台被输入法、AI 助手等 UIA 客户端轮询时 GUI 线程卡顿 130–305 ms → 新增页面、分区、卡片、列表项和对话框必须给外层容器设 `Accessible.role`（卡片/分区/行用 `Grouping`，页/导航/页头/Flickable 用 `Pane`，对话框用 `Dialog`），让 Qt 截断遍历并整棵跳过隐藏容器；普通 `Rectangle` 按钮（如 `FlatButton`）不设 `Accessible.role`/`name` 则 UIA 不可调用。验证须激活窗口到前台，**禁用 `QAccessible::installUpdateHandler` 计数**（会覆盖默认处理屏蔽平台通知），勿在 `afterAnimating` 遍历整树。
- **跨屏与复用池释放的 `QQuickScreenAttached` O(N²) 卡顿**：每个直接读 `Screen.*` 的项各建一个 `QQuickScreenAttached` 并往共用 `QScreen` 挂 ~9 条连接；拖过跨屏边界或 `ListView` 改尺寸清空复用池（`drainReusableItemsPool`）时，`QObject::disconnect` 线性扫描全屏连接呈 O(N²) 阻塞（数百行可卡 30 s）→ 仅在窗口根部读一次 `readonly property real dpr: Screen.devicePixelRatio`，以普通属性下传给分区、行组件和 `HoverTip`；列表行严禁直接访问 `Screen.*`。
- **行内风格部件禁随悬停造毁，操作按钮改由列表池借用 3 套**：悬停底放进 `Loader { active: containsMouse }` 会随滚动每行造毁一次（`Hook` 的 `createObject` + `Qt.binding` 慢 5–10 倍），首悬停现建 7 个行内按钮也会顿 2.2–3.5 ms → 偶发浮层（气泡/历史下拉/菜单条目）用建后保留的 `Loader { active: made || shown }`；行内风格小部件用常驻 `Hook { lazy: true }`（首显建后仅切 `visible`，并把当前状态与 `extra` 作为 `createObject` 初始属性传入防 `Behavior` 从默认值渐变）；结果/剪贴板行内操作按钮由隐藏 `Item` 池（`RowActionsPool`，禁用 `QtObject` 否则报未入场景）首次借用时一次建 **3 套**（覆盖 Qt 6 先发新行进入再发旧行离开时的当前行 + 旧悬停 + 新悬停）复用：`reuseItems` 时 `onPooled` 归还、`onReused` 重借，`showActions` 不可绑定借来对象属性（防绑定循环，按钮写宿主普通属性前须先缓存 `host`）。
- **设置页切分类懒建与异步孵化限频**：首次点进未建页在同帧现建会拖住侧栏高亮；QML 异步孵化（`incubateObject(..., Qt.Asynchronous)`）每帧只分 1/3 帧预算（240 Hz 仅 1 ms），QML `Timer` 也受动画帧限频且保活驱动；探针进程默认 `incubationController()` 为空会使 `asynchronous: true` 退化为同步 → 分类按下即切高亮，未建页置 `navPending` 经 `FrameAnimation` 第二帧再建；悬停 60 ms 预建并由 `SettingsEditor::hurryIncubation` 用零间隔 `QTimer` 空闲时每次 `incubateFor(8)` 推进；插件库条目用 `Loader { asynchronous: !visible }` 分帧建（提前切入自动转同步补完）；探针测异步预建须先 `setIncubationController(window->incubationController())`，对比帧率前先确认电源模式 `interval_p50` 一致。
- **设置页建了不放，窗口只隐藏，内存越攒越多（#459）**：每看过一页（或用过设置内搜索把各页全建出来）约占 20–40 MB，全建约 250 MB（150%），窗口关闭只是隐藏，这些页面陪进程到退出；设置开着时它们全在“窗口和数据”里 → 关闭 30 秒后由 `App` 的 `m_settingsUnload` 调 `SettingsWindow.unloadPages()`，每轮事件循环经 `PageSlot.unload()` 销毁一页，只留窗口壳和首页（重开仍约 10 ms），`按键一览` 的分段模型一并清空；30 秒内重开保持原样。计时器放在 C++ 而不是窗口里（隐藏窗口内不许有东西在跑，`--settings-reopen-check` 的 `nothing_runs_while_hidden`）；`destroy()` 是 `deleteLater`，探针里要用真实事件循环等待才会真的删。销毁后堆块多半留在堆内待复用，私有提交只降约 40 MB，物理内存靠空闲归还。窗口开着时同理（#467：开着设置看“运行状况”，逛过的页面一直占着 250–430 MB）：停在一页满 30 秒（`leftPagesMs`，换页重新计时），`SettingsWindow.putPagesAway(true)` 销毁当前页以外的各页，回到某页时按 `navHistory` 重建并恢复滚动位置；设置内搜索进行中（要查所有页）、对话框打开、录制快捷键、指针停在某个分类上（即将去的那页）时不动。窗口在前台时空闲归还不会触发，销毁后须经 `SettingsEditor.pagesPutAway()` → `IdleTrim::freed()` 主动归还一次，否则腾出的堆页仍算在工作集里、数字不降（Win10 22H2 实测：逛完 11 页 305 MB，改后 30 秒降到 38 MB）。
- **列表滚动像素抖动与向上滚轮回跳**：Flickable 滚动会停在小数位置（`pixelAligned` 只对齐逻辑像素，Windows 上 `wheel.pixelDelta` 恒 0），`textmask.vert` 单精度对 `.5` 设备像素随机取整致行内图文互抖；`ListView` 向上滚动时视野外行未创建，旧对齐会选到身后行边回跳一帧；嵌套 `ListView` 到边界会把滚轮漏给外层页 → 不改 `contentY`（保护原生惯性），每行加 `Translate` 补齐设备像素（列表 y 用可通知属性累加，勿用不会随布局重算的 `mapToItem()`）且行内文字放整数设备像素；控件多的整页/长文本/横标签用整体 `Translate` 补齐再加 `+0.02` 偏置固定取整方向；`settleOnEdge` 绝不逆滚动方向对齐；嵌套列表超出高度（`interactive: contentHeight > height`）时挂 `ListWheelScroll` 吞尽滚轮。
- **长富文本 `TextEdit` 拖滚动条后整页空白**：Qt 6 的 `TextEdit` 在 `text` 超过 1 万字符（插件说明转成 HTML 后很容易超过）时自动打开 `ItemObservesViewport`，只画视口内的段落；滚动条拖动造成的大跳转会让它记录的“已渲染区域”把中间没画的段落也算进去，之后不再补画，整页空白 → 读物类长文本挂 `ReadingStyle`，它在每次换文本后（`setText` 结束后的排队调用里）清掉该标志并改一遍格式，让整篇重画；同时负责阅读排版（标题字号阶梯、段落/列表间距、按字体实测行距）。滚动时文字照“列表滚动像素抖动”一条，用 `ScrollPixelAlignment`（`pixelBias: 0.02`）加 `ListWheelScroll`。
- **类型按钮条滚动抖动**：贴图渐隐（`ShaderEffectSource`）让原生文字对齐整逻辑像素；奇数逻辑宽在 150% 下把后续按钮推到 `.5` 设备像素；均分空余逐项取整致间距交替差 1 px；滚动与间距各自开动画相位错开；滚轮连转每次 `stop()` 重启 `OutCubic` → 取消贴图渐隐，按钮宽按 `stepUp` 补到 `n × dpr` 为整数的倍数，间距向下取整到设备像素再乘序号（余量留尾），间距与滚动共用同一 `slideProgress` 并 `onPixel`，目标未变且滑行中直接返回。
- **绑定循环、`Behavior` 误播、布局滞后与模型插入时序**：`TileFlow` 卡片文字宽度依赖可变 `tileFace` 改折行与高度并反推网格改宽会报 `Binding loop`；父项绑子项 `visible` 隐藏一次即死锁；新造部件立刻被置选中会误播 `Behavior`；懒建菜单条目立刻定位时 `Column`/`Row` 尚未 polish，`implicitHeight` 为 0；`ListView` 在 `currentIndex` 上方插行会拖走当前行号；QML `Connections` 比 `ListView` 先收到 `rowsInserted`，当场 `positionViewAtEnd()` 差一行；绑定里用 `Repeater.itemAt()` 读子项不登记依赖，模型换新（重排、换数组）后仍停在旧项的位置（类型条拖到尽头松手后左侧空出一格）→ 卡片横向排布只看固定属性 `tile`，网格拆分 `widths`/`heights`；父子显隐各自绑原始条件；加 `settled` 经 `Component.onCompleted` + `Qt.callLater` 启用 `Behavior`；定位前调 `column.forceLayout()`；需锁第 0 行时批量插完显式设回 `currentIndex = 0`；追底在 `rowsAboutToBeInserted` 记是否在底，于 `rowsInserted`/`onHeightChanged` 用 `Qt.callLater(positionViewAtEnd)`；按位置读 `Repeater` 子项经一个同时读计数的函数（`TypeStrip.chipAt`，计数在 `onItemAdded`/`onItemRemoved` 加一），换新后当场要用位置先 `row.forceLayout()`。
- **范围切换防抖动、焦点截留、遮挡与弹出层层级**：换范围/排序/类型时套用 300 ms 输入防抖会发迟钝，空状态直绑 `!launcher.searching` 会在切范围时让窗口先缩扁再撑开；面板内筛选框留住焦点不认 Esc/Ctrl+A；同窗两份 `SearchBar` 共用 `objectName` 会让 `findChild` 按声明顺序找错；铺满行且后声明的 `MouseArea`（`hoverEnabled: true`）会截走下层 `HoverHandler`；`MouseArea` 快速连点第二下只发 `doubleClicked` 不发 `clicked`；就地弹框仅靠 `z` 盖不过父项之后的兄弟卡片 → 查询词未变切换条件时免防抖且无结果时 5 ms 轮询首命中，空状态用快照在 `Qt.callLater` 中随 `shownRows` 同步切换；筛选框 Enter/Esc 交还 `SearchBar.focusAtEnd()`（不全选）；同窗多份控件各起唯一 `objectName`；行内下层悬停改用 `area.containsMouse && item.contains(item.mapFromItem(area, area.mouseX, area.mouseY))`；每击必响用 `onPressed`；页内弹层统一走 `DropMenu` 挂 `anchor.Window.contentItem`（`z: 1000`），按在打开按钮上时交按钮自身切换。
- **QML / JS 语法与 `qmlcachegen` 编译陷阱**：`on` + 大写开头的属性名被当信号处理器，依赖变化不重算；`qmlcachegen` 会把 `{ page.rev; return ... }` 中未用结果的读取当死代码删掉；行首为 `(`/`[`/模板字面量时 JS 不补分号会拼成调用报错；`QQmlListProperty`（如 `children`）不是 JS 数组，`Array.prototype.indexOf.call` 静默返回 `-1`；内联 `component X:` 看不到外层 id；`TextInput` 只设 `anchors.right` 加 `x` 会忽略 `x` 且隐式宽为 0 → 禁用 `onXxx` 属性名（如 `accentText`）；强依赖必须参与求值（`page.rev >= 0 && ...`）；行首不写 `(`/`[` 先存变量；遍历 `children` 用下标循环；需访问外层 id 用 `Loader { sourceComponent: Item { … } }`；输入框左右同时锚定。
- **Qt/C++ 绑定、快捷键、模块部署与语言陷阱**：Windows 上 `StandardKey.PreviousChild` 绑成 `Ctrl+Shift+Backtab` 接不到 `Ctrl+Shift+Tab`；QML 文件与同模块 C++ `QML_ELEMENT` 同名会加载到不可创建的 C++ 类；`Qt::UniqueConnection` 连 lambda 静默失败；`QLocale::uiLanguages()` 是首选语言顺序不等于 Windows 显示语言；引入 `QtQuick.Shapes`/`Effects` 编译和 qmllint 均过但 dist 缺对应 DLL 上线闪退（且 `--app-dir` 含中文也会报 `QtQuick.Shapes` 未装）；含 `#include "*.moc"` 文件写原始字符串 `R"(...)"` 会搅乱 `moc` 报 `metaObject` 未解析 → 显式写 `sequences: ["Ctrl+Shift+Tab"]`；QML 窗口与 C++ 类错名（如 `DialogBarWindow.qml`）；防重连保存 `QMetaObject::Connection`；系统语言调 `GetUserDefaultUILanguage()`；界面优先只用原生 `QtQuick`（增模块必同步部署 DLL 并从 dist 实测，预览 `--app-dir` 用全 ASCII 目录）；moc 文件禁用原始字符串字面量。
- **同一 QML 类型里 `Q_ENUM` 键名重复会换掉按钮的动作**：QML 默认不带枚举名取值（`CaptureSession.Pin`），类型里两个 `Q_ENUM` 都有同名键时编译出的是后一个的值，qmllint 和编译都不报。截图插件 1.1.33 给 `CaptureSession` 加了 `QuickMode { None, Ocr, Pin }`，工具条的“贴图”变成 2（`Action::Cancel`，直接退出），“识别文字”变成 1（`Action::Save`，弹出保存）→ 只在 C++ 用的枚举不加 `Q_ENUM`；必须给 QML 用的，键名在整个类型里唯一，或在 QML 写成 `Type.Enum.Key`。`tst_capture` 的 `qmlEnumKeysAreUnique` 检查 `CaptureSession`；也可以扫构建出的 `.qmltypes`，看同一 `Component` 里各 `Enum` 的 `values` 有没有重名。
- **探针事件循环、对象查找与前台内存/诊断陷阱**：探针手动调 `processEvents()` 永远不执行 `deleteLater`（制造列表假泄漏）；`named(window, id)` 只查根文件 id，`Repeater`/按需页的项无 QObject 父对象，`findChildren` 找不到；`thread_local` 定长数组随 TLS 模板在每线程启动即写入内存（64 KB × 169 线程 ≈ 10.7 MB）；全量搜索若每条调 `index.entry(id)` 会把冷字段页拉进工作集；直接链接 `mfplat.lib` 在 Windows N 版缺 DLL 启动失败；`DiagnosticLog` 单条超 8 KiB 会整条变成 `{"truncated": true}` → 探针等待用 `QEventLoop::exec()`，跨组件查找给 `objectName` 走 `visualNamed(window->contentItem(), ...)`（点按钮前先把复制/打开桩成空操作）；线程局部缓冲改堆或 `thread_local std::vector`；全量扫描只读热分片（`scanChunk`/`scan`/`parent`）；可选系统 DLL 用 `/DELAYLOAD` + `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_SYSTEM32)` 检查；诊断事件只记精简摘要，完整数据留内存导出 `summary.json`。
- **改 `Image.mipmap`、`sourceSize` 会重新读图**：这类属性一变 `Image` 就重新加载，期间 `status` 回到 Loading、什么都不画；把 `mipmap` 绑在缩放比例上（`scale < 1`），每次缩放复位都会闪空，并在 `onStatusChanged` 里改状态时报 `status` 绑定循环 → 这类属性定死（大图查看固定 `mipmap: true`：原尺寸时 GPU 仍取第 0 级，像素不变），只让 `smooth` 这种不重读的属性随缩放变。

## 预览、图标、拖拽与设置窗口

- **结果缩略图只认写死的类型，装了处理程序的格式（`.cdr` 等）不显示**：`ThumbnailProvider::hasThumbnailType` 的类型表之外一律不问，CorelDRAW、切片软件、CAD 这类靠各自软件注册缩略图处理程序的格式永远只有图标 → 表外类型按本机注册表判断：`AssocQueryStringW(ASSOCSTR_SHELLEXTENSION, ".ext", IID)` 查 `IThumbnailProvider`（`{e357fccd-…}`）或旧式 `IExtractImage`（`{BB2E617C-…}`），且 `AssocGetPerceivedType` 不是文档/文本/音频/压缩包/程序（Office 文档也注册了处理程序，小行里一页白纸不如图标），`.lnk`/`.url`/`.theme`/库文件除外；每个扩展名只查一次（新装软件重启后生效）。本机的 `.pdf` 查不到处理程序却出得了缩略图，所以内置表不能删。测试在 `HKCU\Software\Classes` 下临时注册假扩展名指向 Windows 照片缩略图处理程序 `{C7657C4A-9F68-40fa-A4DF-96BC08EB3551}`，对改了扩展名的 PNG 实取缩略图（`tst_commandicons::thumbnailsOfTypesWithAHandler`）。

- **图片预览解码、长路径斜杠与 en-US 下的 GBK**：发布包不含 Qt `imageformats` 插件，`QImage` 读不了 JPEG/HEIC/WebP；加 `\\?\` 前缀后 Windows 不再转换 `/`；非 CJK 系统代码页（如 CP 1252）预览 GBK `.txt` 会乱码 → 预览图统一走 WIC 解码（`FilePreview.cpp` 的 `decodePicture`，一并按 EXIF 转正并缩解），不加回 `imageformats`；交 `win32::longPath` 前必先 `QDir::toNativeSeparators`；非 CJK 代码页文本解码追加严格 `MB_ERR_INVALID_CHARS` 且非 ASCII 全中文的 GBK 试探。
- **`PreviewHost` 线程隔离、Z 序同步与 Word 重排**：把 `IPreviewHandler` 设为 Qt 窗口子窗或被所有窗会隐式绑定输入队列，预览器一卡就锁死启动器键盘；弹窗移动用 `SWP_NOZORDER` 会被置顶预览窗压住（误用 `HWND_TOPMOST` 又会压过启动器）；同一 Word 文档从预览窗切到搜索面板预览标签时，Word 代理进程沿用旧尺寸切掉顶部 → 预览宿主跑在独立 STA 线程的无父无主弹窗上，GUI 线程仅用 `ShowWindowAsync`/`PostMessage` 异步驱动；每次挪动按 `GetWindow(previewHwnd, GW_HWNDPREV)` 重排 Z 序；`DoPreview()` 成功后用 1 px 高矩形再回原矩形调两次 `SetRect` 强迫 Word 重排。
- **第三方预览器初始化、卡死隔离、抢前台与悬停防雪崩**：Office/Edge PDF 只认 File/Item 不认 Stream，Edge `DoPreview` 2 ms 即返但子窗未出；未装 Outlook 时 `.msg` 的 MAPI 处理器在 `CreateInstance`/`Release` 永不返回；Excel `-Embedding` 冷启会抢前台令启动器失焦关闭；单线程串行读文件遇坏盘/断网会堵死后续预览；鼠标划过大文件触发不可取消的 Office/PDF `DoPreview` 会连续拉起 Office；中键预览另一行若先改 `currentIndex` 会被 `Binding` 先切走再被 `togglePreview` 误关 → 依次试 Stream/File/Item 并等预览子窗出现（上限 3 s）再显示弹窗，Word 类工厂 `LockServer` 保活 1 分钟；超时 10 s 直接丢弃线程不 `Release`（勿杀共享的 `prevhost.exe`）且本次运行屏蔽该 CLSID；按 CLSID `LocalServer32`/`DllSurrogate` 记服务进程名，8 s 内切前台视为预览自身并抢回；文件读取超 2 s 自动换通道（最多 4 路），超 5 s 提示无响应；悬停 `follow` 预览器等待停满 300 ms 且指针换行立刻 `postponeHandler` 重置；中键先 `togglePreview(index)` 再改选中行。
- **外部预览兼容（Seer 2.8/4.7 与 QuickLook）**：老版 Seer 2.8 有 `SeerWindowClass` 却不认 5000 显示，冷启 Seer 4.7 在 1.5 s 内可能未显且对同文件重发 5000 会关掉它；记忆 `PreviewOpen` 在打开启动器时自动带回预览，会直接弹出 QuickLook/Seer 的独立大窗 → 交文件**前**先问 5007 版本（有回复即信任），无回复才在 1.5 s 后查 5004/可见窗，失败必先发 5005 隐藏再记录该进程回退内置预览；`Launcher::followPreview` 仅在 `!FilePreview::showsElsewhere()` 时自动恢复。
- **老 Win10 图标字体缺字借汉字、全字体加载与 Phosphor 规范**：老 Win10 缺新版 Segoe MDL2 字形，Qt 字体合并会借用系统 EUDC 造字字体显示出汉字；QML 图标 `Text` 直接设 `font.family` 在绑定更新中间态（`text` 先换新码、`font.family` 仍旧）会遍历加载全部系统字体（~17 MB 且不释放）；Phosphor 与 Segoe 同在 PUA（E000–F8FF）且码位重叠 → 自有功能图标统一走随包 Phosphor 字体（源码 Segoe 码仅作兼容别名经 `Phosphor.cpp` 映射，**绝不**把 Phosphor 码当 Segoe 码用，Fill 版替代 `overlay`，共用 `phosphor::kScale = 1.125`；测试直接读资源字节防本机装字体掩盖缺失）；仍需系统图标字体处须由 `QRawFont` 校验 `hasGlyph`，并一律由 C++ 传带 `QFont::NoFontMerging` 的完整 `font`（`SystemTheme.glyphFont` / `look.glyphFont`，QML `font.*` 无此开关）。
- **自绘图标用 `Shape` 曲线渲染器在设置窗口里不显示、改按钮顺序后图标不画**：`Shape { preferredRendererType: Shape.CurveRenderer }` 在搜索框窗口里正常，在设置窗口里一笔都不画（普通渲染器能画，但斜线没有抗锯齿），“复制完整路径”因此在“结果行按钮”里是空的；把按钮 `parent = null` 再挂回 `Row` 末尾来换顺序，元素树里位置和可见性都对，画面上却只剩没动过的那个 → 自绘图标一律交给 `PhosphorGlyph`（`kDrawnFamily`，按 Phosphor 的 256 网格和 16 线宽在 `drawnOutline()` 里给出轮廓，与字体图标同一套栅格化），不再用 `Shape`；要换一排控件的顺序就按次序计算各自的 `x`（`ResultActions.sequence` / `leftOf()`），不重挂父子关系。只查位置和 `visible` 的检查发现不了这类问题，新控件要看实际出图（`--preview-settings` 的 `search-结果行按钮.png`、`--shortcut-panel` 的 `row-buttons-chosen.png`）。
- **SVG 外链安全、网站图标与搜索建议接口**：QtSvg 支持 `<image>`/`<use>` 读取本地或网络路径；`apple-touch-icon` 往往与浏览器标签图标不同；透明黑图标在深色行不可见；`cn.bing.com` 可能 TLS 握手失败；百度建议是 GBK 非严格 JSONP，无 ICU 的 Qt `QStringDecoder("GBK")` 无效；`WinHttpSetTimeouts` 是分步超时而非总超时；原位改写建议列表途中存在临时重路径，按路径删会误删刚改写的行 → SVG 渲染前整段拒绝非 `#片段` 和非 `data:image/png|jpeg|gif` 的外部引用，不设 `QtSvg::AssumeTrustedSource`；网站图标优先 `rel="icon"` / `/favicon.ico` 最大帧，≤16 px 才退触摸图标，90%+ 不透明像素与底色 RGB 距离 `< 64` 时垫反色圆角底板（按 RGB 距离不按亮度）；必应改用 `www.bing.com`；GBK/GB18030 用 `MultiByteToWideChar(54936)` 并放宽 JSONP 解析，由 `WebSuggester` 自控 1.5 s 总超时；删建议行按位置从后往前调 `ResultModel::removeRange`。
- **拖出文件、自定义拖拽图像与 `DoDragDrop` 吞抬起**：`SHCreateDataObject` 父级传 `nullptr` 会静默丢弃 `apidl` 使资源管理器不认；`SHDoDragDrop` 无图时补暗色占位方块，`IDragSourceHelper2::InitializeFromBitmap` 强制半透明不可调；`DoDragDrop` 模态循环吞 `WM_LBUTTONUP` 令 `MouseArea` 残留在 pressed 并误触发后续单击 → 父级传桌面 PIDL（`SHGetKnownFolderIDList(FOLDERID_Desktop)`）并自补双 `\0` 结尾的 `CF_HDROP`；带图拖出改用 `DoDragDrop` + 自定义 `IDropSource` 在 `GiveFeedback` 移动 `WS_EX_LAYERED | WS_EX_TRANSPARENT` 分层窗（照片效果须在部署目录验，build 目录缺 `qjpeg.dll`），结束补发 `WM_LBUTTONUP` 并在行内标记已拖出跳过 `onClicked`。
- **跨权限拖入（UIPI）、跨进程写配置与 UNC 存在性误判**：管理员→普通进程拖出不受 UIPI 挡，但资源管理器→提权设置窗的 OLE `DropArea` 会被拦截；两进程高频共读/写配置时 `QSaveFile::commit` 会因对方读文件未带 `FILE_SHARE_DELETE` 报拒绝访问；网络不通的 UNC 收藏被 `QFileInfo::exists()` 误标“已不存在” → 仅需收最终文件的提权窗在显示后立刻 `RevokeDragDrop` 撤掉 Qt OLE 目标，再 `DragAcceptFiles` + `ChangeWindowMessageFilterEx` 放行 `WM_DROPFILES`/`WM_COPYDATA`/`0x0049`（`WM_COPYGLOBALDATA`）；需过程落点反馈的收藏圆盘改由普通权限 `DropPieHelper` 接 OLE 拖放；跨进程小文件仅内容变了才写且 `commit` 失败间隔 20 ms 重试；UNC 路径存在性用 `GetFileAttributesExW`，仅 `ERROR_FILE_NOT_FOUND`/`ERROR_PATH_NOT_FOUND` 判不存在。
- **长文件名提示的截断判定、滚轮收起与折行**：C++ `elidedHtml` 预截断的富文本令 `Text.truncated` 为假；列表滚不动时 `contentY` 不变致滚轮收不掉提示；按键/滚动收起提示后 Qt 因行内控件变化补发原地悬停移动导致提示重现；无空格长英文名被 `Text.Wrap` 拆出孤立扩展名（中文 `\` 后插零宽空格也不改变 Qt 逐字折行）→ 截断判定同时看 `truncated` 或去标签后 `…` 多于原文；行 `MouseArea` 加 `onWheel` 收提示并置 `wheel.accepted = false`；`NameTip` 在 `dismiss()` 记全局坐标 `quietAt`，同坐标 `offer` 忽略直至指针真动；提示最大宽至少取文件名单行 `TextMetrics` 宽。
- **设置搜索防过度命中与设置窗离屏预览/导航**：分类关键词与节提示语若算给整页每一行会导致整页误命中；`--settings --settings-at` 在设置窗尚未创建时不跳页（仅已存在时调 `showPlace`），设置表单输入框也不在 Tab 链内；离屏预览不能触发 `refreshNumberKeys()`（会试探全局热键撞运行中实例）→ `pageKeywords` 仅放分类别名、≥3 字母才走拼音匹配、节提示语不参搜；`--preview-settings` 用 `__COMPAT_LAYER=RunAsInvoker` + Qt bin 前置 `PATH` 即可免 UAC 离屏渲染全页（`setMaximumHeight(32000)`，渲染器传 `Settings::resolveRenderer` 免误出重启提示；单测增项勿漏 `tests/CMakeLists.txt` 的 PATH 列表防 `0xc0000135`，杀测试副本须等单实例互斥量退出，`--profile <dir>` 配置在 `<dir>\WinShun\WinShun.ini`）。
