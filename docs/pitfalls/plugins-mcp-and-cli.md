# 插件系统、MCP 与命令行（ws）踩坑

## 插件沙箱、进程隔离与权限

- **提权宿主拉起普通插件的令牌与 `CreateProcessWithTokenW` 边界**：`CreateProcessWithTokenW` 经 `seclogon` 转发，不接受 `EXTENDED_STARTUPINFO_PRESENT`（传 `STARTUPINFOEX` 报 `87`），传不进 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` 和 `PROC_THREAD_ATTRIBUTE_MITIGATION_POLICY`（但 seclogon 只复制三个标准句柄不泄漏其他可继承句柄，`CREATE_SUSPENDED`、挂作业、`CREATE_NO_WINDOW`、`CREATE_UNICODE_ENVIRONMENT` 均有效）；无 `SeAssignPrimaryTokenPrivilege` 时拿不同登录会话的资源管理器令牌调 `CreateProcessAsUserW` 报 `1314`（`ERROR_PRIVILEGE_NOT_HELD`）；`TokenLinkedToken` 无 `SeTcbPrivilege` 时只是鉴别级模拟令牌，无法 `DuplicateTokenEx` 成主令牌（报 `1346`），且在非提权进程里反而指向提权那半 → 提权 Win顺 用 `CreateProcessWithTokenW`（非提权用 `CreateProcessW`）仅起**一次** runner（令牌只取资源管理器令牌或自身 `CreateRestrictedToken` 降权），runner 启动后自调 `SetProcessMitigationPolicy` 补扩展点禁用与镜像加载限制（ASLR 编译期开启），再由 runner 用普通 `CreateProcessW` 带完整属性表启动各插件。
- **判断令牌是否提权不能看 `TokenElevationType`**：提权令牌经 `CreateRestrictedToken` 降权并设为中完整性后，`TokenElevationType` 仍是 `TokenElevationTypeFull`（2），仅 `TokenElevation.TokenIsElevated` 变为 `0` → 硬检查必须同时确认 `TokenIsElevated == 0` 且完整性 RID < `12288`（High）；若资源管理器本身以管理员运行，回退为自身降权令牌。
- **管理员插件防 TOCTOU、DLL 劫持与环境注入**：用户插件目录普通权限可写，先验哈希再按原路径启动存在替换空窗，且持句柄不释放也挡不住运行中往同目录放 `version.dll` 等按需加载 DLL；`CreateEnvironmentBlock` 会读用户可改的 `HKCU\Environment`，且系统 `PATH` 常含用户目录、`COR_PROFILER_PATH` / `DOTNET_STARTUP_HOOKS` / `NODE_OPTIONS` 均能向管理员进程注入代码 → 管理员插件永远从 `%ProgramFiles%\WinShun Elevated Plugins\<SID>\…` 受控副本运行（禁放普通用户可抢建并留 `WRITE_DAC` 句柄的 `ProgramData`），每级目录仅不存在时由提权 Win顺 创建（属主 Administrators、普通用户不可读），已存在则按句柄验 `FILE_FLAG_OPEN_REPARSE_POINT`/最终路径/属主/DACL 且全程保持句柄不共享删除；副本仅在提权 Win顺 经用户确认或已验签列表（`PluginUpdates::signedItem`，插件库页无签名缓存不算）创建；环境改用 `sandbox::elevatedEnvironment` 去掉代码加载变量与普通权限可写的系统 `PATH` 项、`TEMP` 放副本旁。
- **双 runner 信号隔离、实例号精度与管道权限**：普通 runner 与管理员 runner 共用回调时不验来源，普通 runner 可冒充 `>= 2^48` 的管理员实例 → `connectRunner` 按 `runnerFor(instance)` 只认各自实例；管理员实例号从 `2^48` 起，runner JSON 原样输出 `< 1e15` 的整数；管理员 runner 管道仅允许 `SYSTEM`/`Administrators` 且完整性标签为“高”（单测同大小重写文件可能 mtime 不变触发哈希缓存漏判，测试须调后 mtime）。
- **嵌套作业对象限制**：父进程（终端、seclogon 等）常已在作业中，子进程出生即 `IsProcessInJob == TRUE`；Win8+ 嵌套作业下子进程 `QueryInformationJobObject(NULL)` 看到最内层限制 → Runner 自身作业只设 `KILL_ON_JOB_CLOSE`（不可设 `ActiveProcessLimit` 否则起不了插件），每个插件由 runner 建独立嵌套作业；测试必须核对 `LimitFlags`、`ActiveProcessLimit` 和 `UIRestrictionsClass`，不能只看 `IsProcessInJob`。
- **作业 `UILIMIT_HANDLES` 挡剪贴板，任意 UI 限制均阻断 UI Automation**：`JOB_OBJECT_UILIMIT_READCLIPBOARD` 下 `OpenClipboard`/`EnumClipboardFormats` 仍成功，直到 `GetClipboardData` 才报错 `5`；即便给了 `clipboard:read`，只要作业带 `JOB_OBJECT_UILIMIT_HANDLES`，`GetClipboardData` 仍报错 `6`（`ERROR_INVALID_HANDLE`）；更严重的是，作业只要含**任意** UI 限制（哪怕仅 `READCLIPBOARD`），跨作业窗口消息即被拦，`GetFocusedElement` 约 16 ms 返 `0x80131505`（`UIA_E_TIMEOUT`）、`SendMessage(EM_GETSEL)` 返 `0..0`（`SendInput`/`PostMessage`/`OpenProcess` 不受影响）→ `sandbox::makeJob` 仅在既无 `ui` 也无剪贴板权限时加 `UILIMIT_HANDLES`；读他进程选区一律走宿主 `selected_text` 工具（权限 `selection:read`，且宿主跳过 Chromium/Firefox 窗口防触发屏幕阅读器模式），绝不为 UIA 去掉剪贴板限制。Windows 10（19045 实测）更严：作业含**任意** `JOB_OBJECT_UILIMIT_*` 就读不到他进程放进剪贴板的数据（文件、文字都在格式列表里，但 `GetClipboardData` 返回 `NULL`/`ERROR_INVALID_HANDLE`），Windows 11 26200 上则只有 `UILIMIT_HANDLES` 会这样（#435，局域网传输与剪贴板同步在 Windows 10 上因此读不到复制的文件）→ `sandbox::uiRestrictions(limits, build)` 对带 `clipboard:read` 的插件在 Windows 11 24H2（build 26100）之前不加任何 UI 限制，其余限制（单进程、内存、随 Win顺 结束、缓解策略、令牌）照旧；19046–26099 未实测，按“能读”一侧处理。改剪贴板读取相关的沙箱限制要在 Windows 10 虚拟机上复测（`tst_plugin` 的 `uiRestrictionsLeaveTheClipboardReadable`、`clipboardReaderReadsAnotherProgramsFiles`）。
- **图形插件隔离需兼顾内部工作进程与传统输入法（#164）**：未声明 `processes` 的插件受 `ActiveProcessLimit=1` 限制，内部拉起录屏/编码子进程报 `1816`（`ERROR_NOT_ENOUGH_QUOTA`）；对 UI 插件开启 `EXTENSION_POINT_DISABLE_ALWAYS_ON` 会按微软文档阻断微信输入法等传统输入法扩展，致无法中文组字（直跑 QML 预览测不出此边界）→ 需要子进程的插件必须声明 `processes`（走权限确认）而非绕过作业隔离；仅对明确有 `ui` 权限的插件放开传统输入法扩展，runner 与无 `ui` 插件继续禁用扩展点，远程/低完整性映像、内存与进程树限制照旧保留。
- **声明式 `open` / `open_item` 在宿主执行，必须受 `processes` 权限约束**：item 的 `open`、`open` 效果与 `open_item` 由宿主以用户权限直接执行，绕过了插件作业沙箱 → 三个执行点统一走纯函数 `ws::plugin::ruleOpen`（`src/plugin/OpenPolicy.*`）：无 `processes` 时 URL 仅放 `http`/`https`/`mailto`，本地路径仅放文件夹与非可执行/脚本文件（展开环境变量、处理 `file:`、去尾点尾空格后以 `PATHEXT` + 危险扩展名表 + `AssocIsDangerous` 判定；相对路径、裸名、无扩展名、ADS 数据流一律拒），且禁 `args`/`cwd`；零代码起程序插件（如 `winshun.go`）必须声明 `processes`。
- **`sandbox: strict` 低完整性进程无法写用户 `%TEMP%`**：低完整性进程继承的用户 `%TEMP%`（`AppData\Local\Temp`）无低标签，SQLite 大事务语句日志（>64 KiB）或大表 `ORDER BY`/`GROUP BY` 落盘报 `SQLITE_CANTOPEN`，导致旧索引升级回滚卡死 → 宿主（0.21+，`Host::specFor`）与插件自身都将 `TEMP`/`TMP` 重定向到继承低标签的 `<id>.data\tmp`（用 `SetEnvironmentVariableW` 防中文路径走 `qputenv` 乱码），工作进程自动继承；SQLite 插件测试须在低完整性受限令牌下用足够大的旧索引实测。
- **`ActiveProcessLimit=1` 下各类 Python 启动器均触发 `1816`**：`py.exe`、`WindowsApps` 别名、uv trampoline 及 `python -m venv` 的 launcher 都会再 spawn 真 `python.exe`，在单进程作业下报 `1816`（或退出码 `101`）；仅查注册表 `PythonCore` 还会漏掉 PEP 514 下其他厂商（如 `Astral`）→ `programs::resolvePython` 保持单进程限制不动，启动前最多递归解析 4 层至真实 `python.exe`：uv trampoline 用 `LoadLibraryExW(LOAD_LIBRARY_AS_DATAFILE | LOAD_LIBRARY_AS_IMAGE_RESOURCE)` 读 `RT_RCDATA` 的 `UV_TRAMPOLINE_KIND`/`UV_PYTHON_PATH`（兼容旧版文件尾 `UVPY`/`UVSC`）；venv 读 `pyvenv.cfg` 的 `home` 并设 `__PYVENV_LAUNCHER__` 保 `sys.prefix`/`site-packages`；注册表扫全部厂商（跳过 `PyLauncher`，`PythonCore` 优先）且**禁 `QSettings`**（会为不存在的键 `RegCreateKeyEx` 留空键），用 `RegOpenKeyExW`/`RegEnumKeyExW`/`RegGetValueW`；启动固定加 `-u -X utf8` 防管道块缓冲。
- **常驻插件冷启动隐藏建窗抢前台致搜索框收起（#242）**：首次键入关键字启动常驻插件（如 Python+Tk/PyInstaller）时，即便 `withdraw()` 隐藏，Tk 仍对首个顶层窗调 `SetActiveWindow`；刚由前台进程拉起的新进程有权拿前台，使不可见 `TkTopLevel` 抢走焦点、搜索框失焦收起 → 插件侧隐藏建窗段包在 `LockSetForegroundWindow(LSFW_LOCK)`…`LSFW_UNLOCK`（拿到锁才在 `try/finally` 解），等 `action` 到达再显示（Win顺 0.23.0+ 发 `action` 前调 `AllowSetForegroundWindow`）；宿主侧 `App::launcherLostFront` 见前台是他进程不可见窗（`win::hiddenWindowInFront`）时不收起，排队 `win::bringToFront` 抢回（单次打开最多 3 次，不用全局 `LockSetForegroundWindow` 防漏解），用 `m_takingFrontBack` 合并 Qt `activeChanged` 与前台钩子重复触发，且回调执行时前台已回到搜索框须直接忽略。
- **随包小插件进程内合并（`inProcess`）的线程、退出与句柄约束**：随包（`Entry::Source::Bundled`）、常驻、非管理员的 `winshun.tools`（静态库 `wstools`）与 `winshun.switches`（加载 `WinShunSwitchesApp.dll`）可在 runner 线程运行（`WINSHUN_PLUGINS_APART=1` 恢复独立进程；无作业和低完整性沙箱，第三方永远独立进程）→ 必须遵守：① 首个用 Qt 的线程即 Qt 主线程，换线程重建 `QCoreApplication` 行为未定义，switches 固定跑在同一条常驻 `QtLane` 线程且 DLL 不卸载；② 线程不能强杀，停用靠关输入管道送 EOF，5 秒未返或输出关后仍在跑则 runner 以退出码 `4` 自退（`giveUp`）由宿主整组重拉，退出时不等到的线程不 `join`、不释放其对象；③ 进程内禁用 `GetStdHandle`，一律用传入管道端（含 Qt 日志写传入 stderr）。
- **宿主侧资源上限、统一退出清理与目录命名防撞**：子进程内存上限保不了宿主无限累积 stdout、不限分批结果/等待请求/缓存或动作无超时（永久判忙）；仅在单插件退出清理会在 runner 崩溃时漏清热键与工具 → 宿主对输出总量、分批结果、等待请求和缓存分别设限并给动作加超时，停止/移除/权限变化/runner 断连复用同一清理路径且失效结果只完成一次；插件 ID 允许含 `.`，固定 `<id>.old`/`<id>.data` 可能撞上另一插件，更新备份须建本次独立目录、安装不覆非插件目录、删数据前查冲突。
- **插件不继承宿主环境变量 & 中完整性无法结束提权进程**：Runner 用 `CreateEnvironmentBlock(受限令牌)` 为插件建用户默认环境，宿主临时设的 `WINSHUN_*` 传不进去 → 测试开关写到测试清单副本的 `runtime.env`。另外中完整性插件对提权进程缺 `PROCESS_VM_READ`/`PROCESS_TERMINATE`（错 `5` / `PermissionDenied`），`winshun.kill` 等应在查询时对读不到 `Path` 的行标明无权结束，动作端捕获错 `5`/denied 转本地化提示而非截断英文异常。

## 插件协议、共享 Qt 与生命周期

- **共享宿主 DLL 加载必须带 `LOAD_LIBRARY_SEARCH_USER_DIRS`**：插件装在用户目录，由启动器通过 `AddDllDirectory` 加入 Win顺 主目录来共享宿主 Qt / `pdfium.dll`；若用仅 `LOAD_LIBRARY_SEARCH_APPLICATION_DIR` 会只搜插件自身目录（build 目录混放测不出来），安装后全部失败 → 改为 `LOAD_LIBRARY_SEARCH_APPLICATION_DIR | LOAD_LIBRARY_SEARCH_USER_DIRS`（仍不搜 `PATH`/CWD），集成验证必须用“插件独立目录 + 宿主 DLL 仅在 app 目录”的真实安装布局。
- **常驻后台提供者契约与结果列表结构刷新**：提供者若仅经已就绪 `Host::request` 通信，合法 `lazy` 清单不会被拉起，带闲置退出的 `eager` 插件退出后也会失效并丢掉保持唤醒等状态 → `systemSwitches` 契约要求 `resident` + `eager` + `idleExitSec=0` 与显式权限；异步状态变化若增删行（首答、到期、停用、崩溃），`dataChanged` 无法增删行，对可见空查询须按结构差异刷新，缓存关闭时断开旧信号并更新角色与快捷键。
- **JSON 坏 UTF-8 致整行作废 & `shutdown` 清理窗口**：不可信外部文本含非法 UTF-8 时原样写进 JSON 行会使宿主解析失败丢弃整条回答；宿主等约 2 s 拿到 `shutdown` 回复便立即结束进程，析构与后台线程来不及收拾 → SDK `Json::quote` 按 Unicode 表 3-7 逐字节校验并将坏字节替换为 `U+FFFD`；收尾清理放进回复 `shutdown` 之前调用的 SDK `shuttingDown()` 钩子，并在启动时清理上次残留兜底强杀。截图与录屏插件收到 `shutdown` 后在 `shutdown()` 里还回热键、`PrtScn` 并收起演示，回复后再 `QCoreApplication::quit()`；但 `quit()` 会先请各窗口关闭，窗口关不掉就可能被忽略（Qt 文档），而编辑窗口、识别文字窗口和设置窗口为保留原生窗口框架在 `QEvent::Close` 里 `ignore()`（`CaptureEditor::eventFilter`、`CaptureApp::eventFilter`）→ 这些窗口开着时插件进程不会自己退出，要靠宿主的 `stopInstance` 结束进程。
- **`rerun` 自动刷新：防 Enter 误触与超时断链**：`rerun` 刷新在顶部插入新行而行号不变，用户按 Enter 会误操作刚顶上来的行；定时器仅在收到回复时续期，单次超时就会永久停刷 → `Launcher::followCurrentRow`（`LauncherNavigation.h`）保持光标跟随原行，原行消失则留原位并启用 800 ms 误触保护（拒 Enter/数字键/点击并提示；从该插件通知点开 3 s 内 `openedFromToast` 例外留首行，同带 800 ms 保护）；`Host::onQueryTimeout` 对 `rerun` 查询超时后按原间隔重排。
- **插件通知防冒充、63 字截断与气泡队列不卡死**：插件名含零宽/韩文填充符（`U+3164`）或叫 `"Win顺"` 会冒充官方通知，`NOTIFYICONDATAW.szInfoTitle` 含 `\0` 仅容 63 `WCHAR`；新气泡顶掉旧气泡时系统不一定补发旧结束消息，靠结束消息放行会永久卡住插件通知，且 `NOTIFYICONDATA` 无键鼠输入不计超时 → `ToastPolicy` 先按码点剔除控制/格式/填充/变体符（留 emoji ZWJ），无可见字形退回 plugin id，用户插件强制套 `插件「名字」`，标题截 63 字不劈代理对，空正文用标题兜底（防 `NIF_INFO` 空正文变收起）；`NotificationTurns` 仅记最新与刚被顶掉条目，官方气泡最多占位 8 s 配定时器兜底，1.5 s 内旧结束消息与点击不误路由；自动化点通知前须移开光标并清旧横幅。
- **启动器关键字模式：保留尾空格、防 trim 误判刷新、提示行与 `displayTextChanged`**：传入插件前 `trimmed()` 会抹掉 `"kill "` 尾空格；进出模式时 `=` 与 `= ` trim 后相同会被误判为刷新导致列表与光标串台；第 0 行插提示行会使 `ListView` 把 `currentIndex` 顺推成 1；`TextInput::textChanged` 发在 `updateLayout()` 之前，此时 `positionToRectangle(length)` 返 x=0 致占位提示盖住前缀 → 原文传 `m_query` 给 `Catalog::match`（去前导留尾空格），在 `startPluginQuery` 之前用无副作用 `matchKeyword()` 比对 `m_shownKeyword`（零代码命令在 `Host::query` 同步回调）；`placeHint` 在 `currentRow == 0` 时置 `m_betterFirstRow` 拉回 0；占位位置改监听 `displayTextChanged`。
- **插件行底栏提示、权限文案与 `winshun:settings` 首帧滚动**：零代码插件无进程，权限对话框须区分无 `runtime`、`sandbox: strict` 与普通沙箱（禁写“内存上限 0 MB”）；底栏 `Launcher::keyHints` 随当前行动作刷新；`open.url` 认 `winshun:settings` 打开**自身**设置卡片，首次新建窗口首帧卡片 `y=0`，须记 `revealAfterFrame` 在下次 `frameSwapped` 补调一次 `revealRow`。
- **进程启动底价、`wsbench --plugin` 与 `--profile` 目录坑**：Windows（含 Defender）下起无 Qt 静态进程到首行输出固定 12–15 ms（经 runner ~15 ms），常驻 L2 仅 0.02–0.05 ms，L1 一次性插件预算扣除底价并保留 120 ms 防抖（PowerShell 进程查询切忌在过滤阶段读每个进程惰性 `MainWindowTitle`，耗时 2.5 s，仅对展示行读取可降至 14–20 ms）；`wsbench --plugin` 关键字查询须带空格与后续字（如 `--query "tabs x"`）且 `--action noop` 仍送进 `action()`，插件须检 `a.action == "default"`；`--profile` 下用户插件放 `<profile>\plugins\<id>`、数据放 `<profile>\plugins\<id>.data`，仅 `WinShun.ini` 多一层 `<profile>\WinShun\`（且测试副本会改写 `HKCU\Software\Classes` 三处 `WinShun.SearchHere`，测后须还原）。
- **头文件遮蔽与插件/宿主 Qt/QML 构建契约**：PUBLIC include 目录严禁放与 C/C++ 标准头（不分大小写，如 `Limits.h` 遮蔽 `<limits.h>`）或其他模块同名的通用头（如 `Protocol.h`），改用专名（`RateLimits.h`、`SwitchProtocol.h`）并全量编译；后台原生启动器用 GUI 子系统免多出 `conhost`。跨线程 `connect` 必带接收线程上下文 `QObject`；`QObject` 信号名独占（查询方法改 `isReady()`）；含 `Q_OBJECT` 源文件的原始字符串禁含 `//`/`/*`（`moc` 当注释吃掉类声明）；`Q_PROPERTY` 指针写全命名空间（如 `ws::PluginSettings*`），纯 C++ model 加 `QML_ANONYMOUS`，角色名禁用 `QQuickItem` 已有属性（如 `enabled` 改 `pluginEnabled`）；离屏预览窗不收 resize/expose 需两遍 `contentItem()->setSize()` + 丢弃首帧 `grabWindow()` 并关 `animated`；提权跑 build 产物须先 `windeployqt` 到临时目录，否则缺 Qt DLL 弹不可见窗永久挂起。
- **PowerShell 5.1 BOM/编码与凭据库契约**：Windows PowerShell 5.1 无 BOM `.ps1`/`.psm1` 按 ANSI 读致中文乱码，OEM 437 输出中文变 `?` → 所有 `.ps1` 模板、插件与测试脚本必带 UTF-8 BOM（`EF BB BF`，`[IO.File]` 用绝对路径）且首行设 `[Console]::OutputEncoding = UTF8`（`encoding: oem` 仅兜底）；脚本 `$script:` 变量勿与参数同名（不分大小写）。插件凭据用 Credential Manager `CRED_TYPE_GENERIC`，目标名 `WinShun/plugin/<id>/<key>`（UTF-16 blob），`CredDeleteW` 遇 `ERROR_NOT_FOUND` 算成功，按前缀用 `CredEnumerateW`，提权与非提权共享同用户凭据库。

## AI 助手（MCP）与命令行 `ws`

- **命名管道重叠 I/O、安全描述符、防抢注与禁 `FlushFileBuffers`**：同步句柄上 `ReadFile` 阻塞会堵死同句柄 `WriteFile` 形成死锁；提权 Win顺 默认 DACL 与高完整性标签会拒掉普通权限客户端；同用户恶意进程也能抢先建 `\\.\pipe\WinShun.Mcp.<SID>` 诱导 `ws open` 打开任意路径；命名管道 `FlushFileBuffers` 会一直等客户端读完，放进 stop/join 会卡死（同步 WinHTTP 句柄亦不可在别线程等待时关闭，严格超时改异步并在 `HANDLE_CLOSING` 后释放）→ `pipe::Client`/`pipe::Server` 一律 `FILE_FLAG_OVERLAPPED` 读写独立 `OVERLAPPED`+事件、关闭时 `CancelIoEx`；建管显式指定 `D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;FRFW;;;<用户 SID>)S:(ML;;NW;;;ME)`（降标签为“中”拦低完整性沙箱）且首实例带 `FILE_FLAG_FIRST_PIPE_INSTANCE`；`ws open` 发任何数据前先用 `GetNamedPipeServerProcessId` 确认对端是安装目录里的 `WinShun.exe`（配合 `SECURITY_IMPERSONATION`，发包前对端连模拟机会都没有）。
- **管道客户端模拟时机与 `AccessCheck`**：客户端安全上下文随**首次写入**到达，`ConnectNamedPipe` 返回后立刻 `ImpersonateNamedPipeClient` 报 `ERROR_CANNOT_IMPERSONATE` → 读到首包后再模拟、`OpenThreadToken` 复制令牌（先试 `SecurityImpersonation`，失败降 `SecurityIdentification`）并 `RevertToSelf`；访问检查一律走 `AccessCheck`（`Visibility`）而非“模拟后 `CreateFile`”（`SecurityIdentification` 与无 `SeTcbPrivilege` 时的 `TokenLinkedToken` 均不可打开文件）。提权运行 `tst_mcp` 时直接起的中继会继承管理员令牌，受限目录断言 `relayRestricted()` 提权下 `QSKIP`。
- **单行 16 MB 断连与按字节预算渐进截断**：`pipe::Client::readLine`（`ws` 与 `WinShunMcp.exe` 共用）读满 `kMaxLineBytes`（16 MB）未见换行直接断开无报错；序列化完超限改回 `too_large` 错误又会让长路径或满是控制符（转义成 6 字节/字）的回答全军覆没 → 组装阶段按 `kAnswerBudget`（15 MB；AI 客户端取 1/3 因含文本副本并二次转义）用 `jsonBytes`（控制符 6、引号/反斜杠 2、汉字 3）逐条装配、满即停并置 `truncated: true`，读文本用 `fitText`（不劈开 UTF-16 代理对）并返回 `next_offset`；序列化后超限返回 `isError` + `structuredContent.error: "too_large"` 仅作不可切分内容（如插件工具返回）的最后防线。
- **多引擎车道、`kind: "files"` 截断、`truncated` 精度与排队超时**：各 `SearchEngine` 请求 ID 独立从 1 起且 `runContentSearch` 启动先发空 `resultsReady(id, {}, 0, 0)`；`search_files` 设 `kind: "files"` 时引擎先按用户“文件夹在前”合并截断会截光文件 → `ToolHost` 按引擎分 `Lane` 隔离信号；要文件时请求强制 `KindOrder::FilesFirst`（要文件夹用 `Scope::Folders`）；仅确认上限外仍有可见项、或触发字节预算/同类型引擎截断时置 `truncated: true`（`total` 不计排除项）；内容搜索 `timeout_ms` 从请求到达起计时，排队中到期直接移出队列返 `complete: false`，开跑只给剩余时间。
- **大批量（5 万条）性能与索引锁死防护**：逐条 `QDateTime::toString(Qt::ISODate)` 5 万条耗时 ~1 s 超搜索本身；`searchNames` 227 块并行每块 `TopHits::reserve(55000)` 一次吃 ~380 MB；`GetNamedSecurityInfoW` 多线程锁竞争严重；并发扫描持 `FileIndex::readLock` 等独占 `WorkerPool::parallelFor` 遇写者等待会靠 SRW 锁死全部名字搜索 → 单次回答用 `LocalTimes`（`src/mcp/IsoTime.h`）按 UTC 日缓存偏移手拼 `isoText`（DST 切换日与非整分钟历史地方时回退 `QDateTime`）；堆初留 1 024 按需增长、上限 ≥ 块项数时不建堆，合并 `nth_element`（`keepBest`），行构造每份 4 096 并行；访问检查改 `GetFileSecurityW`（栈 1 KB 缓冲，16 线程 ~3 µs/次，读联接点自身描述符；改句柄方式必加 `FILE_FLAG_OPEN_REPARSE_POINT`），仅本机 SSD（`QuietIo::solid`）且批内未查目录 ≥ 32 才并行；先拿 `ToolHost::m_scanMutex` 再加锁，长扫描用过 `m_writerGate` 的 `FileIndex::longReadLock()`。另：仅可移动 `win32::UniqueHandle` 进 `std::function` 包成 `std::shared_ptr<void>(copy, ::CloseHandle)`；线程后台模式（`THREAD_MODE_BACKGROUND_BEGIN`）禁嵌套（报 `ERROR_THREAD_MODE_ALREADY_BACKGROUND`）且线程池线程须配对 `END`。
- **目录排除防绕过、无权路径防探测与掉线共享短路**：字面排除比对会被联接点、8.3 短名、`\\?\` 设备路径和 `\\localhost\C$` 绕过；先查类型再查权限会向无权调用者泄露不可列目录内的文件存在；对掉线 UNC 调安全检查/读大小会阻塞 SMB 超时数秒 → 直接拒设备路径（`\\?\`、`\\.\`、`\??\` 含 `/` 变体），其余以 `FILE_READ_ATTRIBUTES` + `FILE_FLAG_BACKUP_SEMANTICS` + `FILE_FLAG_OPEN_NO_RECALL` 打开取 `GetFinalPathNameByHandleW(FILE_NAME_NORMALIZED)` 做排除与访问检查，读取对同一句柄 `ReOpenFile` 防 TOCTOU，有排除时同时拒本机 UNC 或同卷序列号网络路径（残余边界：硬链接、`.lnk`）；`checkFolders` 按“掉线共享 → 索引无 → 文件先验可见性（不可见回 `not_found`）→ 可见才报文件 → 不可列目录回 `not_found`”判定；掉线共享先经 `ShareIndexer::offline`/`SearchResult::offline` 跳过，网络/映射盘参数先经带缓存 1.5 s 超时的 `share::reachable`。
- **修改用户/系统 `PATH` 的四重坑**：`QSettings` 读 `REG_EXPAND_SZ` 会展开 `%VAR%` 并写回 `REG_SZ`；读注册表失败（如 `REG_BINARY`/无权限/`ERROR_MORE_DATA`）当空写回会抹空整个 `PATH`；含 `;` 路径不加引号按 `;` 切会认不出并反复追加；对每项调 `GetLongPathNameW` 会被掉线共享卡数秒 → 用 `RegGetValueW(..., RRF_NOEXPAND)` 保原文与类型（Inno 用 `RegQueryStringValue`+`RegWriteExpandStringValue`，禁 `{olddata}`/`uninsdeletevalue`）；仅 `ERROR_FILE_NOT_FOUND` 算无值、`ERROR_MORE_DATA` 重读、写前再读比对防并发覆盖；含 `;` 加引号且按引号切分（`splitPath`），只精确移除写入时记在 `HKCU\Software\WinShun\CliPathEntry` 的原样项；仅含 `~` 的项才调 `GetLongPathNameW`（`ws` 的 `absolutePath` 同理）。
- **环境变量编码、更新与 GUI 降权捕获控制台输出**：`qputenv` 走本地 ANSI 致中文乱码、`SetEnvironmentVariableW` 不更新 CRT 拷贝使 `qEnvironmentVariable` 读不到；`CreateProcessW(nullptr)` 继承宿主启动时旧环境、提权 `CreateProcessWithTokenW` 拿管理员环境，看不见用户新 `setx` 的 `CLAUDE_CONFIG_DIR`；`startUnelevated` 不返回输出且无 `CREATE_NO_WINDOW` 会闪黑窗 → 本进程双写用 `_wputenv_s`；子进程环境用 `CreateEnvironmentBlock` + `CREATE_UNICODE_ENVIRONMENT`（非提权 `bInherit=TRUE`，提权用桌面 shell 令牌 `bInherit=FALSE`，链 `userenv`）；捕获输出走 `shell::runUnelevatedCaptured`（匿名管道同接 stdout/stderr、stdin 接 `NUL`、非提权带 `HANDLE_LIST`、提权 `CreateProcessWithTokenW`+`STARTF_USESTDHANDLES`），以 10 ms 轮询 `PeekNamedPipe` + 等进程句柄代替阻塞 `ReadFile` 确保超时可终止。
- **`ws` 命令行参数、默认过滤与二次启动转交**：`recent_files` 默认过滤向下继承的 `EntryFlag::Hidden` 与 `LowPriority`（`AppData`/`%TEMP%` 同时命中）；测试若把 `--pipe` 放用例参数后面，遇 `--` 会变查询词连上用户真实管道；二次启动 `--settings --settings-at` 若只转交 `settings` 会丢位置 → `ws recent --in` 首次无结果时自动补 `include_hidden`+`include_system` 重试并提示 stderr；测试附加的 `--pipe`/`--instance` 一律放最前并配 `WS_TEST_START`/`WS_TEST_OPEN`/临时 `CLAUDE_CONFIG_DIR` 隔离；二次启动将位置编码为 `settings:<页>,<标签>` 经 `SettingsCommand.h` 解析调 `showPlace`。
- **MCP 界面、设置搜索与 `tst_mcp` / 构建细节**：`HoverHandler` 不可直挂非 `Item` 的 `Window` 下（需内嵌 `Item`，`WS_EX_NOACTIVATE` 窗照收悬停点击）；供 QML 直调的 `Q_INVOKABLE` 必放 `public:`（`private:` 被 QML 跳过静默报 TypeError）；Windows 上 `tst_mcp` 驱动 `WinShunMcp.exe` 弃用不稳定 `QProcess`，改 Win32 `CreatePipe`+`CreateProcessW` 独立读线程 + `QTest::qWait`；`editor.mcp` 关闭时 `pageTabs` 为空，“命令行”节放权限标签，动态状态放固定尾行（`SettingsEditor::cliTally`），开关动画用 `SettingsWindow.holdInView` 补滚动，长路径单独成行防 760 px 窄窗词中折断；设置搜索 1–2 字符 ASCII 及拼音（如 `ws` 避 `Windows` 与“帮我设置”）限词首或分隔符后起配（`Term::atWordStart`），全 ASCII 不走拼音；C++ `//` 注释禁以 `\` 结尾（如 `\\.\pipe\` 吞下一行），`#include <shlobj.h>` 带入 `rpcndr.h` 的 `#define small char` 避用该变量名，`Copy-Item` 还原源文件需刷 `LastWriteTime` 免 ninja 跳过重编。

## 官方插件专项踩坑

### 系统开关（`winshun.switches`）

- **深浅色必须广播 `"ImmersiveColorSet"`，且广播不可阻塞界面线程或退出 `join`**：只写 `Personalize` 的 `AppsUseLightTheme`/`SystemUsesLightTheme` 不会通知 Qt 窗口和任务栏；`SendMessageTimeout(HWND_BROADCAST, WM_SETTINGCHANGE, ..., SMTO_ABORTIFHUNG, 1000)` 逐窗同步发送耗时 2.5–3.8 s 且自家窗排最后，在界面/STA 线程等或退出 `join` 会因自家窗不泵消息而死等超时 → 先在本线程同步发给自家顶层窗（3–4 ms 立刻换肤），全系统广播交独立 **detached** `std::thread`（按值捕获不碰析构对象、单并发+脏标记补发，测试退出前轮询 `settingbroadcast::busy()`）。
- **隐藏文件/扩展名走 `SHGetSetSettings` 与 `SHELLSTATE` 符号位域**：只写 `Explorer\Advanced` 或 `SHChangeNotify(SHCNE_ASSOCCHANGED)` 不刷新已开资源管理器窗口 → 用 `SHGetSetSettings(&ss, SSF_SHOWALLOBJECTS | SSF_SHOWEXTENSIONS, TRUE)`（~1.7 ms 写注册表并带 `"ShellState"` 广播，失败才退回写注册表+异线程广播）；`SHELLSTATE` 1 位有符号位域置位读回为 **`-1`**，判断一律用 `!= 0` 禁用 `== 1`。
- **音频/无线电同值静默成功无回调 & 回调线程不固定**：`IAudioEndpointVolume::SetMute` 同值返 `S_FALSE`、`SetMasterVolumeLevelScalar` 返 `S_OK`、`Radio::SetStateAsync` 返 `Allowed` 且均无回调；`Radio.StateChanged` 与 `IAudioEndpointVolumeCallback::OnNotify` 落在任意线程 → 写前先比当前值相同直接提示，成功用 `SUCCEEDED()`；回调一律带上下文 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 回主线程，`IMMNotificationClient` 回调内禁直接调 MMDevice，投给开关线程重绑。
- **Shell 与测试陷阱**：`CoCreateInstance(ShellBrowserWindow)` 报 `E_FAIL` 仍会在 `explorer.exe` 残留不可见“库”窗口 → 开测试窗用 `ShellExecuteEx` `opennewwindow` 并核对非用户原 HWND；`rundll32 shell32.dll,Options_RunDLL 7` 窗口属 `explorer.exe` 不可按 rundll32 PID 找；找托盘按钮用 `Shell_NotifyIconGetRect`；勿 `ShellExecute` 改名备份（如 `.bak-*`，会弹“打开方式”）。

### 局域网传输（`winshun.localsend`）

- **不可信对端文本清洗**：对端设备名和文件名含非法 UTF-8、换行或 BiDi 方向控制符会破坏 JSON 行或伪造界面文字 → `Protocol.cpp` 的 `peerText`/`shown` 先把坏字节换为 `U+FFFD`、按字符截断并剔除换行与方向控制符。
- **接收中临时文件 `.wspart` 与 `shuttingDown()` 清理**：宿主收到 `shutdown` 回复即杀进程（~2 s 内）来不及跑析构 → 接收先写隐藏文件 `*.wspart`，收完才改名；在 SDK `shuttingDown()` 中止接收并删 `.wspart`，启动时再扫当前保存目录清遗留兜底强杀。

### 休息提醒（`winshun.break`）

- **Direct2D 硬件渲染目标拖入显卡驱动致空闲占 ~50 MB**：`ID2D1DCRenderTarget` 默认硬件目标会把显卡驱动加载进进程吃掉 ~47 MB → `makeTarget()` 显式用 `D2D1_RENDER_TARGET_TYPE_SOFTWARE`，空闲降至 ~3.2 MB。
- **休息画面低级键盘钩子防漏 Esc 重复键与防卡键**：严格模式长按 Esc 退出若立刻卸钩，后续自动重复会漏进前台窗；若吞掉休息前已按住键的抬起，系统会永久卡键 → `KeyGate`（`Keys.h`）只吞自己截过按下的键及对应抬起，开始前已按住的键与音量/媒体键（`0xAD–0xB3`）始终放行，结束先进 `startDrain` 等已拦截键松开再卸钩。
- **管理员窗口前台时普通权限 `WH_KEYBOARD_LL` 收不到 Esc**：UIPI 限制普通权限钩子收不到管理员窗按键 → 普通模式可鼠标点自身窗口按钮绕过，严格模式等倒计时走完（已知边界）。
- **屏幕常亮不可等同于 `idleMs() == 0` & 半透明遮罩透字**：放视频触发屏幕常亮若让 `idleMs()` 恒返 0 会推迟提醒；alpha=240 遮罩仍透下层文字 → 屏幕常亮拆为独立标志 `Sense::keptOn`（仅阻止把离座算作休息）；文字背后叠加径向渐变（`Graphics::glow`）。

### 资源管理器标签页（`winshun.explorer-tabs`）

- **无公开新标签 API：未公开 `WM_COMMAND` 与 PIDL `Navigate2`**：`Navigate2(navOpenInNewTab/BackgroundTab)` 仍在原页打开 → 向 `ShellTabWindowClass`（`FindWindowEx` Z 序最前为当前标签）发 `WM_COMMAND 0xA21B` 新建标签，登记后拿 `IWebBrowser2` 传 PIDL（`VT_ARRAY|VT_UI1` SAFEARRAY）调 `Navigate2` 防 `#`/`::{GUID}` 失败；切标签向顶层窗发 `0xA221`（lParam 从 1 起），关标签发 `0xA021`（lParam 1）。
- **跨进程藏窗闪烁边界、串行锁与崩溃还原任务栏按钮**：`DwmSetWindowAttribute(DWMWA_CLOAK)` 跨进程报 `0x80070005`；SHOW 时改样式等忙碌 explorer 80–360 ms，登记时藏仅 1–7 ms → 藏/还原用 `Hider::m_serial` 串行，采用 `WS_EX_LAYERED` alpha=0 + `ITaskbarList::DeleteTab` 并**先持久化** `hidden.txt`；所有还原路径（含 `stop()`、启动、崩溃、`std::terminate`）必**先**恢复不透明并在当前线程 `CoInitializeEx` 调 `ITaskbarList::AddTab` 后再改记录；**MSVC `std::set_terminate` 按线程生效**，每个自建线程开头均须设置。
- **COM 回调禁干活、启动禁等 explorer 与 STA 重入防护**：`WindowRegistered::Invoke` 内做跨进程 COM 查询会让 `ShellExecute` 偶发死锁 40 s；STA 跨进程 COM 期间嵌套泵消息会致 `handle()` 重入 → `Invoke` 仅 `PostMessage` 异步处理，第一步不跨进程 COM 先按类名藏未知 `CabinetWClass`；`connect()` 完前忽略 WinEvent；`handle()` 记重入深度，>0 时入队事件待外层结束再处理，全程只持 HWND/下标并在 COM 后重查。
- **预开备用标签关闭排队 & 区分用户主动新窗口（Ctrl+N）**：`0xA021` 与 `Quit` 只关顶层窗当前标签（脚本对 `Shell.Application.Windows()` 调 `Quit()` 会关整窗，关整窗应发 `WM_CLOSE`）→ 仅备用标签为当前标签时以 `SendMessageCallback` 单并发关闭（`SpareCloser` 排队）；用 `EVENT_SYSTEM_FOREGROUND` 回溯最近非自藏窗，若已知旧 explorer 窗且非插件刚置前则保留新窗不并。
- **标签顺序不能信 `IShellWindows`（#273）、关机禁写会话与全局原子判首次登录**：`IShellWindows` 复用关闭槽位、`ShellTabWindowClass` 是 Z 序 → 多标签窗稳定后用 UIA `FindAll(ControlType == TabItem)` 按顺序匹配 `InternalGetWindowText`；`SM_SHUTTINGDOWN != 0` 或 `GetShellWindow() == nullptr` 禁写会话；用窗口站全局原子 `WinShun.ExplorerTabs.Logon` 加外壳运行 ≤10 min 区分首次登录与插件重启。

### 图片文字搜索（`winshun.ocr-search`）

- **`PROCESS_MODE_BACKGROUND_BEGIN` 暗设 32 MB 工作集硬上限**：进程后台模式强加 32 MB 工作集上限致 ONNX 狂缺页慢 2.5 倍、HEIF/AV1 WIC `CopyPixels` 报 `E_OUTOFMEMORY` → 进入前保存上下限与标志，进入后立刻 `SetProcessWorkingSetSizeEx` 还原（`OcrWorker::enterBackground()`）。
- **`QFile::read(上限)` 预分配 128 MB 与长图/ONNX 768 MB 沙箱控内存**：`QIODevice::read(maxSize)` 按上限向上取整预分配不缩容；长宽比 >3 的长图按长边 4096 缩会字糊 → 先查 `file.size()` 超限即拒再 `read(size)`；长图留原宽控总像素 ≤4000 万，算完指纹即转 24 位推理并关 ONNX `DisableMemPattern`。
- **单页超 60 s 误判卡死、转曲 PDF 漏检与检索归一化**：仅整页完结报进度会被超时跳过；只渲染含图 PDF 漏转曲/盖章页 → `PaddleOcr::find()` 在每条带检测与每批行识别后回调真实进度；无图 PDF 页若可读字符 <16 或过半无 Unicode 且含矢量路径/批注也渲染；存查双侧去中日文旁空格、经 OpenCC 繁折简、1–2 字符字母数字建整词词元。
- **长路径单行 `ElideMiddle` 与 `tst_ocr` 勿用 offscreen**：`ElideMiddle` 配 `Text.Wrap` 会硬截文件名；`tst_ocr` 设 `QT_QPA_PLATFORM=offscreen` 会缺字体画空图 → 长路径独占单行不换行 `Text` 配 `ElideMiddle`；`tst_ocr` 按 ctest 注册直接跑。

### 鼠标手势（`winshun.gestures`）

- **作业内跨进程 `IsWindow` 误报 FALSE**：在 Win顺 作业对象内对其他进程有效窗口调 `IsWindow` 返 `FALSE` → 跨进程判窗口有效改用 `GetAncestor(hwnd, GA_ROOT) != nullptr`。
- **作业 UI 限制阻断 UIA 读选区**：只要作业存在任意 UI 限制，`GetFocusedElement` 约 16 ms 返 `UIA_E_TIMEOUT` → 读选区走宿主 `selected_text` 工具（权限 `selection:read`），不撤剪贴板限制。
- **右键钩子共存、管理员窗口 UIPI 与虚拟机测试**：钩子吞按下后移动超 6 逻辑像素判手势，未动松开补发按下+抬起弹菜单，按住 350 ms 补发按下还右键拖动；补发带 `dwExtraInfo` 标记、见 `LLMHF_INJECTED` 放行；按住修饰键、触摸/笔（`0xFF5157`）或目标窗口完整性高于自身时直接放行；全局钩子测试在 Win10 虚拟机用 Hyper-V `Msvm_SyntheticMouse` 模拟真实硬件输入。
