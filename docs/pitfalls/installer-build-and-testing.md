# 安装升级、构建、编码、内存与测试踩坑

## 乱码与编码

- **UTF-8 路径被当成 GBK 解码（#346）**：外壳扩展或外部调用方可能将 UTF-8 字节按系统代码页（中文 Windows 为 CP936/GBK）解码（如 `预设` → `棰勮…`） → 用 `core/Mojibake.h`（`utf8ReadAsAnsi()`、`ungarbledPath()`）仅在还原路径磁盘存在时替换；文件对话框（`ShellDialogs.cpp` 的 `onDisk()`）先还原再试外壳解析名，读设置时同步还原备份与索引目录。
- **文件编码与 BOM 规范（`tst_encoding`）**：Windows PowerShell 5.1 与 Inno Setup 将无 BOM 脚本按 ANSI 解析，中文字符串会吞掉引号或造成向导乱码 → 文本一律 UTF-8；含中文的 `.ps1/.psm1/.psd1` 及 `installer/` 下 `.iss`/`.isl` 必须带 UTF-8 BOM；`.bat/.cmd` 只用 ASCII；含非 ASCII 的 `.rc` 须写 `#pragma code_page(65001)`；改动后运行 `ctest -R ^tst_encoding$`。
- **Win32 字符集与代码页调用白名单**：`A` 后缀 Win32 调用或随意转本地代码页在非中文区域下会静默损坏路径 → 代码内文字一律走 `QString` 与 `W` 后缀 Win32 API，禁止任何 `A` 后缀调用；仅当外部数据确属系统代码页（旧剪贴板格式、旧 zip、给 `cmd` 的 `.bat`、Everything ANSI 协议等）才允许 `fromLocal8Bit`/`CP_ACP`/`CP_OEMCP`，并须在 `tests/tst_encoding.cpp` 的 `kCodePageUsers` 登记理由，停用时及时移出。
- **子进程与命令行输出编码**：设 `QT_FORCE_STDERR_LOGGING=1` 时 Qt 默认消息处理器按 ANSI 写 stderr；`cmd /c mklink` 按控制台代码页输出，且 `VsDevCmd` 找不到 `vswhere` 时在 GBK 控制台输出乱码 → 插件进程须装 UTF-8 消息处理器，运行器对非 UTF-8 stderr 回退 ANSI 转换且控制行绝不放非法 UTF-8；测试建联接用 `tests/TestJunction.h` 的 `makeJunction()`；进 MSVC 环境统一用 `scripts/devshell.ps1`。
- **向 Qt 子进程/探针写入 Unicode 环境变量**：`qputenv` 经字节接口受 ANSI 代码页影响（CP1252 下中文路径变乱码），而 `SetEnvironmentVariableW` 不更新 Qt 读取的 CRT 环境表 → 统一用 `_wputenv_s` 设置与清理环境变量，并在探针中断言 Qt 能读回相同路径。
- **会上屏的测试与预览文字不能像乱码**：`tst_foldermenu`、`tst_pinwindow` 等测试和 `--preview-*` 会在用户屏幕上真实弹窗，`QString(90, u'长')` 这类单字重复或无意义填充（「长长长长…」「很长很长很长…」）编码没错，但看上去就是乱码 → 凡是会显示出来的测试数据都用读得通的真实名称（长名用 `tests/tst_foldermenu.cpp` 的 `longFolderName(n)` 这类按长度截取的自然文本）；改完看一眼实际弹出的画面，不只看断言通过。

## 安装程序（Inno Setup）、升级、卸载与 Scoop

### Inno Setup 流程、占用文件与提权

- **装完点“完成”才启动会导致无响应假象**：新 exe 首次启动受杀毒扫描阻塞，`main()` 前无窗无托盘，用户点向别处后搜索框随即失焦收起；二实例在 `MessageWindow` 未建好或忙时转交也会丢命令 → `[Run]` 中不带 `postinstall` 先以 `--background` 启动完成冷启动（禁加 `runhidden`，否则隐藏后续首个正常窗），“完成”仅唤醒或退出；二实例等待 `MessageWindow` 最多 30 秒且命令只发一次（超时重发 `--toggle` 会抵消）。首次安装时这份提前启动的会直接弹出欢迎引导（压在“完成”页上），点“完成”后再弹一次搜索框 → 非静默安装另带 `--setup-page`：引导建好但不显示，引导期间由临时 `MessageWindow`（`App::m_guideMessages`）收“显示”/“退出”，“完成”才弹出；安装程序进程结束 10 秒仍没收到就照常显示并记警告。
- **自定义安装模式对话框与非管理员提权（`installer/InstallMode.iss`）**：内置 `PrivilegesRequiredOverridesAllowed=dialog` 不看账户是否管理员且早于 `[Code]` 弹出；`[Code]` 的 `Exec` 在安装前禁止自启（`IsProtectedSrcExe` 错 5），`InitializeSetup` 返回 False 恒定退出码 1（跳过 `GetCustomSetupExitCode`） → 改 `PrivilegesRequired=lowest` + `PrivilegesRequiredOverridesAllowed=commandline`，在 `InitializeSetup` 按 `TokenElevationType` 排序双按钮对话框；需提权时用 `Exec('>', ...)` 以普通权限重跑自身并带 `/ALLUSERS`、`/LANG` 与标记文件让 Inno 自行提权（禁 `runas`，否则破坏 `runasoriginaluser`，#21；`/LOG` 另写 `.allusers.log`），结束后 `ExitProcess` 透传退出码；标记缺失且非 0 退出（UAC 取消为 2）时询问改为“只为我安装”。
- **占用文件侧移（`.wsold`）与 MCP 中转后置安装（#97 / #300）**：AI 工具的 `WinShunMcp.exe` 被杀后约 0.2 秒即重启并经 `--start-winshun` 拉起 Win顺，外加插件进程、杀软或挂起 WebDAV（约 61 秒）占住 DLL，旧式仅靠 Restart Manager 等待重试会在复制时报代码 5 → `PrepareToInstall` 先经 WMI 识别 AI 工具并询问（静默除外），将 `WinShunMcp.exe` 改名 `.old` 再按 `{app}` 路径结束（`EndProgramsOfApp`），新中转用 `Excludes: "\WinShunMcp.exe"` 放到 `[Files]` 最末安装；占用检测改用 `FileHeld`（`CreateFileW` 独占读写打开）而非易对杀软误报的 RM，短暂等待（常规 4 秒，`HoldersOwn` 检出自有进程时 90 秒）后将仍被占用的文件改名侧移为 `*.wsold`/`*.wsold2`（`MoveHeldAside`），仅无法改名的独占锁才阻断并回滚（`PutAsideBack`/`PutRelayBack`/`StartIndexService` + 重启旧版）；`.wsold` 在本轮结尾、下次安装、卸载及全员安装时的 `MOVEFILE_DELAY_UNTIL_REBOOT` 清理。
- **WMI 性能、`RmGetList`、`{app}` 展开与静默安装**：WMI 循环调 `ItemIndex(i)` 扫全机进程呈 O(N²)（547 进程耗 27 秒）；`RmGetList` 缓冲过小返回 `ERROR_MORE_DATA(234)` 会漏报；`DeinitializeSetup` 在选目录前或 `InitializeSetup` 失败时展开 `{app}` 报内部错误；`/VERYSILENT` 下 `PrepareToInstall` 失败仍弹窗 → WMI 须用 `WHERE ExecutablePath LIKE ...`（`WqlLike` 转义）限定 `{app}`（含 `.exe.old`），严禁全局 `taskkill /IM`；RM 仅用于列示占用者名称（256 项缓冲、单次批量 `RmRegisterResources`、忽略瞬时 `svchost.exe`）；仅在 `RelayMoved <> ''` 后展开 `{app}`；静默调用必带 `/SUPPRESSMSGBOXES`；改安装器前必跑 `tools/verify-installer.ps1`（`/DTestInstall` 隔离验证）。
- **深色模式向导图、卸载时机与旧版 `WM_CLOSE`**：`WizardStyle=... dynamic` 深色模式读 `WizardImageFileDynamicDark`/`WizardSmallImageFileDynamicDark`，缺省退回内置光盘图；`InitializeUninstall` 早于确认框运行；0.2.0 及更早版本收 `WM_CLOSE` 只毁消息窗不退进程 → 浅/深两组向导图齐设；卸载关程序放 `CurUninstallStepChanged(usUninstall)`；安装器按进程等退出 15 秒未退再 `taskkill /F`。
- **Inno 6.7 `TaskDialogMsgBox` 与 `[Code]` 语法陷阱**：6.7 的 `TaskDialogMsgBox` 是 VCL `TTaskDialogForm`（非 `#32770`/`TDM_CLICK_BUTTON`），按钮为 `TNewButton`（UIA 中向导按钮类型为 `Pane`，命令链接标题尾带 `\r`，英文重试为 `&Try again`），中文自动折行会劈开“Win顺”；`[Code]` 中行首 `[` 被 ISCC 当新段名报 `Invalid section tag` → 测试脚本按标题给父窗发 `WM_COMMAND(BN_CLICKED)`，中文手加 `%n` 并在 150% 复核；`[` 留在上一行末尾。
- **右键动词、`schtasks /Change` 与覆盖安装保留提权任务（#20 / #400）**：右键直接指向提权 exe 每次弹 UAC，普通转发的 `WM_COPYDATA` 被 UIPI 拦截；`schtasks /Change` 改交互式登录任务会在隐藏控制台卡在输密码；覆盖安装若无条件删旧任务再由普通权限 `--take-autostart` 重建，会把管理员直读的 `HIGHEST` 降为 `LUA` → 右键走普通权限 `WinShunSearch.exe --search-here "%V"`（直接读原始命令行，避开盘根 `"D:\"` 被 `CommandLineToArgvW` 转义引号），转发给仅认合法目录路径的 `WinShun.SearchHere` 窗；`runAutostartTask` 先核对任务目标确为同目录 `WinShun.exe` 再用；重注册开机任务走 COM（`--take-autostart`），覆盖安装时原用户 `schtasks /Query` 可读的自建任务原样保留（仅删他人答 UAC 所建任务，#21），且 `--take-autostart` 遇需提权模式且任务已为 `HIGHEST` 时不改写。
- **卸载与 Scoop 清理恢复 `Win+V` / `Win+S`（#270）**：资源管理器仅在启动时读 `DisabledHotkeys`，删掉注册表项后不重启 Explorer 会导致系统 `Win+V`/`Win+S` 失效至注销 → 卸载删文件前运行 `WinShun.exe --restart-explorer`（提权卸载也能以用户权限拉回 Explorer；开着文件夹或复制窗时先询问，静默卸载不重启）；Scoop 清理仅在无此类窗口时重启。

### 应用内升级、便携版与 `RUNASADMIN`

- **应用内更新后回到管理员身份（#400）**：`App::elevateOnceUpdated` 原先只要窗口开着就无限静默等待且不记日志 → 逻辑收口至 `update::ElevationWait`：等升级助手最多 10 分钟，结束后无窗即重启，窗口刚关等 2 秒，窗口持续开满 1 分钟则发通知“Win顺 已更新”供点击提权重启（设置开着带 `--settings`）；记录 `elevation-after-update-waiting` 与 `elevation-after-update`，发布前用 `tools/verify-installed-upgrade.ps1 -Mode InApp` 实测完整链路。
- **便携版管理员直读升级回滚（#274）**：旧版升级助手 `WinShunUpdate.exe` 只等它启动的初始进程建好 `MessageWindow`，新版若启动即自行提权并退出初始进程，旧助手会误判失败并换回旧版 → 新版见到互斥量 `Local\WinShun.Updating` 存在时留在初始进程/原权限完成启动，等助手退出后再由 `App::elevateOnceUpdated` 提权；任何启动自交接逻辑都须顾及外部等待者，且修在助手里的逻辑要到下个版本才生效。
- **`RUNASADMIN` 兼容标记导致错误 740（#68 / #274 / #111）**：`HKCU`/`HKLM\...\AppCompatFlags\Layers` 含 `RUNASADMIN` 时，普通权限 `CreateProcess`/`CreateProcessWithTokenW` 一律报 740 → 安装器 `PrepareToInstall` 先 `RemoveRunAsAdmin`（仅删该词）；升级助手 `start()` 遇 740 回退 `ShellExecuteEx`（用户取消 UAC 返回 `ERROR_CANCELLED` 时保留新版）；必须普通权限运行的自身助手（如拖放圆盘）由 `shell::startUnelevated` 遇 740 且目标在本目录时注入 `__COMPAT_LAYER=RunAsInvoker` + `WINSHUN_AS_INVOKER`，`main()` 首行 `shell::dropInvokerLayer()` 用 `_wputenv_s` 清除两者防传给孙进程（绝不对外部程序套用）。

### Scoop 打包与更新

- **Scoop 快捷方式、更新检测与卸载钩子**：`WScript.Shell` 按 ACP 建快捷方式（CP1252 下 `Win顺.lnk` 失败）；`scoop update winshun` 不同步本地 bucket 且遇文件占用报 `skip updating` 退出码仍为 0；更新时也会执行旧清单 `pre_uninstall` → 清单快捷方式名用 ASCII `WinShun`；应用内先跑 `scoop update` 再跑 `scoop update winshun`，以 `current\scoop-manifest.json` 版本变化判成败；清理钩子必须判断 `$cmd -eq 'uninstall'`。
- **Scoop 系统登记路径必须走 `current`**：版本目录在 `scoop cleanup` 后被删除，从版本目录启动时 `GetModuleFileNameW` 返回的是版本路径 → 所有写入注册表/计划任务的路径经 `scoop::stablePath()` 转为 `current` 联接，路径比对用 `scoop::sameCopy()`。

## 权限分离与索引服务（`WinShunService`）

- **普通权限面对管理员窗口的 UIPI 边界**：管理员窗口在前台时，普通进程收不到 Raw Input、低级钩子和无修饰键 `RegisterHotKey`（带 Ctrl/Alt/Shift/Win 的组合键仍触发，单键 F1–F24/PrintScreen 须由服务按键助手转发），`AttachThreadInput` 错 1314、`WM_COPYDATA` 错 5、`SendInput` 静默丢弃；但可 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `OpenProcessToken(TOKEN_QUERY)` 查完整性级别、`SetForegroundWindow` 与进程外 `EVENT_SYSTEM_FOREGROUND` → 通过 `integrity::higherThanOurs(hwnd)`（自身提权恒 false，读不出视作更高）避开剪贴板键盘接管与对话框栏附着，粘贴改仅复制提示或交由服务助手。
- **普通权限下的进程启动与卷访问**：非提权进程借资源管理器令牌调 `CreateProcessWithTokenW` 报 1314（缺 `SeImpersonatePrivilege`）；访问权限 0 可查卷区段/寻道惩罚，但 `FSCTL_GET_NTFS_VOLUME_DATA`/`FSCTL_QUERY_USN_JOURNAL` 错 1、`GENERIC_READ`/`$MFT` 错 5 → `!integrity::processElevated()` 时直接 `ShellExecuteExW`/`CreateProcessW`（`Ctrl+Shift+Enter` 仍走 `runas`）；无服务且读不了日志时由 `IndexService` 退回目录遍历 + `ReadDirectoryChangesW`。
- **普通权限无法修改或关闭 `HIGHEST` 开机任务（#67）**：普通权限写/删提权注册的 `HIGHEST` 任务必报 `E_ACCESSDENIED`，`schtasks /Create /SC ONLOGON` 不带 `/RU` 亦被拒；复现时 `Register-ScheduledTask -Force` 会保留旧安全描述符导致测不出 → 运行级别仅由提权实例 `App::reconcileAutostart` 修改，普通权限用 COM `ILogonTrigger::put_UserId` 注册限本人的 `LUA` 任务；UI 统一经 `autostartRequested` → `App::setAutostart`，关闭未果且未提权则由 `autostart::removeAsAdministrator` 提权执行 `schtasks /Delete /TN WinShun /F`，并在写入与打开设置时后台重读经 `showAutostart()` 刷新；本副本任务已存在时不回退写 `Run` 键（防双启）。
- **索引服务命名管道通信陷阱**：`DisconnectNamedPipe` 会丢弃客户端未读走的末帧（如 `VolumeLost`）；多盘线程并发连单一监听实例在 `WaitNamedPipe` 后竞态报 `ERROR_PIPE_BUSY(231)` 悄悄退回遍历；复用 `Writer` 未重置会拼进旧帧字段；`ws::ntfs` 内 `using namespace volproto` 时 `Read` 误解析为 `ntfs::Read` → 断连前先 `FlushFileBuffers`；`connectSession` 与测试 `RawClient` 在 2 秒期限内循环 `WaitNamedPipe` + `CreateFile`；复发前 `Writer::reset()` 或新建实例；显式写 `volproto::Read`；排错无控制台进程 Qt 日志须设 `QT_FORCE_STDERR_LOGGING=1`。
- **服务最小特权与测试卷干扰**：打开卷读 MFT 靠卷 DACL（Administrators/SYSTEM）而非特权；在持续写入的 `C:` 上 `FSCTL_READ_USN_JOURNAL(BytesToWaitFor=1)` 立刻返回且 MFT 漂移，`%TEMP%` 处于排除列表会让 `wsbench --mft` 自测失败 → `SERVICE_CONFIG_REQUIRED_PRIVILEGES_INFO` 仅留 `SeChangeNotifyPrivilege`；`tst_service` 用 `readUntil` 循读目标名、允许万分之一 MFT 差异或设 `WINSHUN_TEST_VOLUME=D:`；`wsbench --mft` 移出 `%TEMP%` 运行。
- **启动等待服务期间 `Pass::Volumes` 误清快照**：等待索引服务最多 30 秒期间若来一次 `Pass::Volumes`（插盘/改设置/服务连上）且 `m_volumes` 仍空，`dropStaleRoots` 会删光快照全盘条目 → 快照加载完毕立即落存 `m_volumes`/`m_journals`，并用 pass 起始时的 `previous` 计算 `volumesChanged`。
- **服务路径本地提权防护（`svcloc::pathProtected`）**：LocalSystem 服务若直接注册于便携目录或用户可写目录，普通用户可替换 exe 或放同名 DLL（如非 KnownDLL 的 `wtsapi32.dll`）实现 SYSTEM 代码执行 → `svcloc::pathProtected` 排除 SYSTEM/Administrators/TrustedInstaller 后分三级 `svcloc::Role` 检查：`Object`（exe 全写权）、`Parent`（exe 所在目录加禁新建文件/子目录，防 DLL 劫持并拦截 `C:\ProgramData\*` 继承）、`Ancestor`（上级仅禁删改子项/重设 DACL/改属主，**不含**新建子目录以免误伤默认给 Authenticated Users `0x4` 的 `C:\`）。不安全时经 `SHGetKnownFolderPath(FOLDERID_ProgramFiles)`（禁环境变量）复制到显式设权且不继承的 `%ProgramFiles%\WinShun Service`（预存在目录须过 `folderProtected`），走“读源入内存 → `CREATE_NEW` 临时名 → `MoveFileEx(REPLACE_EXISTING)` 对错误 5/32/33 重试并关闭不带 `FILE_SHARE_DELETE` 的 `QFile` → 复验 DACL 与字节一致”。
- **服务日志目录抢建联接点提权**：普通用户可在 `%ProgramData%` 下预先建 `WinShun\` 并在 `service.log` 挂联接点，诱导 SYSTEM 写删任意文件 → 建目录走 `svcloc::createProtectedDir`、安装与服务启动时用 `svcloc::secureLogFolder` 收紧已存在弱目录，打开日志一律带 `FILE_FLAG_OPEN_REPARSE_POINT`。
- **自选目录安装版的身份识别与存量兼容（#104）**：正式版装到用户可写目录（如 `D:\Apps\WinShun`）时服务同样迁往 `%ProgramFiles%\WinShun Service`，仅靠 `svcloc::isWinShunBeside` 判身份或安装器无条件删专用目录会破坏对话框跳转与服务启动 → `--install` 迁移时把主程序路径写入 `ImagePath` 的 `--installed-from`，通用界面能力按 `svcloc::servesDialogNav` 识别（仅 `uiAccess` 保持同目录要求）；安装器 `RemoveServiceFolder` 删除前必核对服务当前 `ImagePath`；存量不安全便携服务启动自检只记日志不拒跑，界面读 SCM `QueryServiceConfigW`（`registeredInUnsafeLocation`）提示一键修复。

## 构建、Qt 升级与依赖打包

- **禁止经 Git Bash 触发 CMake/Ninja 编译**：CP1252 下经 Bash 调编译会使 MSVC `/showIncludes` 将中文路径输出为 `??????`，毒化 `.ninja_deps`（二次编译 `FindFirstFileExA` 报错）及 `CMakeFiles\rules.ninja` 的 `msvc_deps_prefix`（依赖记为 0，改类头文件不重编导致内存错乱） → 配置与编译一律直接在 PowerShell 跑 `./scripts/build.ps1`；已毒化时删 `.ninja_deps` 并删 `CMakeCache.txt`/`CMakeFiles` 在 PowerShell 重配；脚本抓错用 `*>&1 | Out-String -Stream`。
- **并行构建目录、260 字符路径限制与补丁合并**：双会话共用 `build/` 会 `ninja: failed recompaction: Permission denied`；深路径超 260 字符令 `qmlcache` `.obj` 报 `C1083`，中文路径作 MSVC 暂存目录报 `D8050`；主目录有未暂存改动时 `git apply -3` 报 `does not match index` → 每任务用独立短路径（`build/<任务名>`、8.3 短路径或 `subst T:`），源码隔离用 `.worktrees/<任务名>/`；主目录未暂存时先 `git stash create` 建快照再到独立工作树 `git apply -3` 验证后同步。
- **pwsh 7 `Select-Object -First` 会半途杀掉编译**：Qt 头文件 C4702 警告极易填满前 N 行，pwsh 7 拿满后直接终止整条管道上游的 `cmake` 进程，产出旧/半成品 exe → 先整段收集输出（`$out = cmake --build ... 2>&1`）再查 `$LASTEXITCODE` 并筛选，确认 `ninja: no work to do` 与 exe 时间戳。
- **严禁往构建目录拷 Qt DLL，部署带齐运行库**：`build\` 里残留旧 Qt DLL 会在升 Qt 后盖过 `PATH` 报 `0xc0000139`；普通终端改 `PATH` 直接跑 `build\WinShun.exe` 在自提权后不继承修改的 `PATH`，弹 `0xC0000135` → 构建目录只留构建产物，测试/运行统一经 `./scripts/build.ps1 -Deploy`（`windeployqt` + `fonts` + `onnxruntime.dll` 所需的 `msvcp140_1.dll`）部署到 `dist\`，或在已提权终端运行。
- **Qt 6.12 升级与进程内旧 `QTDIR`**：6.12 的 Qt Qml 依赖新拆出的 `Qt6TaskTree`（`aqtinstall` 默认不装）；VS Code 及子终端持启动时的旧 `QTDIR`；CMake 缓存记着旧 Qt 路径 → 安装加 `-m qttasktree`；按“装新版 → 改 `QTDIR` 并重启终端（或显式传 `-QtDir`）→ 对全部 `build/*`（含 `asan`）用 `--fresh` 重配编译实测 → 再删旧 Qt”推进。
- **Qt 工具中文路径与无控制台弹窗坑**：`qmlimportscanner`、`lrelease`、`qmllint` 按 ACP（1252）读命令行或超 240 字符生成的 `.rsp` 文件，中文源路径全坏；无控制台时 `qmllint --version` 等 Qt CLI 工具弹消息框卡死脚本 → `qt_add_qml_module` 内直接写 `NO_IMPORT_SCAN`（事后设目标属性太晚），长路径编 `capture-probe-qt` 用短目录或 `subst`；`lrelease` 弃用 `qt_add_translations`，改 `qt_add_lupdate` + 源码目录相对路径 `add_custom_command` + `qt_add_resources`；跑 `qmllint` 切进 `src\app\qml` 用相对文件名或拷到纯英文目录；脚本禁调 `--version`/`--help`，改查 `C:\Qt` 目录名或 `qtpaths`。
- **`lupdate` 译文“未完成”与跨会话误删**：`lupdate` 对他处已有同源文的条目自动填译文但标 `type="unfinished"`（`lrelease` 默认不收，界面仍显中文），且全扫工作区会删掉其他会话未提交的界面条目 → 跑完检索全部 `type="unfinished"` 而非仅空译文；运行前先 `git status`，有他人未提交 UI 改动时手工编辑 `.ts` 或 `git diff` 仅留己方变更。
- **MSVC / Win32 头文件与宏雷区**：项目定义 `WIN32_LEAN_AND_MEAN` 时 `<uiautomation.h>` 缺 COM 定义报 C2146；`windows.h` 的 `minwindef.h` 定义了空宏 `near`/`far`（`NOMINMAX` 不处理） → 包含 `<uiautomation.h>` 前先 `#include <ole2.h>`；函数与变量禁叫 `near`/`far`。
- **`moc` 原始字符串与 MSVC lambda 宽串拼接**：`moc` 词法器不认 `Q_OBJECT` 类里的 `R"(...)"` 原始字符串；MSVC（VS 2022）在 lambda 内把跨段 `u"a" "b"_s` 拼成窄串报 C3688 → `Q_OBJECT` 类中改用普通转义字符串；lambda 内多段拼接每段加 `u` 前缀（`u"a" u"b"_s`）。

## 内存、归还（`IdleTrim`）、卡死与闪退诊断

### 内存口径、前台内存、空闲归还与后台唤醒

- **任务管理器“内存”口径与基准对比**：任务管理器显示**私有工作集**（不含共享 DLL、映射文件页及未触碰提交页），`Get-Process` 的 `WorkingSet64`（含共享）与 `PrivateMemorySize64`（提交量）与之可差上百 MB → 统一用 `\Process(WinShun)\Working Set - Private` 或 `PROCESS_MEMORY_COUNTERS_EX2.PrivateWorkingSetSize`，私有工作集与私有提交分开报；新旧版本交替运行对比，避开后台编译干扰。
- **图标字体缺字形回退与字体堆驻留**：QML 图标 `Text` 用 `font.family:` 在绑定切换瞬态缺字形时触发 Qt 字体合并，挨个加载全机字体（约 69 个 / 17 MB，永不释放）；`addApplicationFontFromData(file.readAll())` 几何扩容并常驻私有堆（8.5 MB 占 16 MB） → 图标统一由 C++ 给带 `QFont::NoFontMerging` 的 `SystemTheme.glyphFont` / `look.glyphFont`；加载字体文件改用内存映射的 `ws::addFontFromFile`（`FontFile.h`）。
- **`thread_local` 数组膨胀与索引冷热字段混排**：TLS 模板随每个新线程复制并写脏（64 KB × 169 线程 ≈ 10.7 MB）；全量扫描按 4 KB 页进内存，冷热字段同构会把不读的字段一并拖入 → 禁在 `thread_local` 放数组（改按需堆分配或 24 字节 `thread_local std::vector`，`--foreground-memory` 断言 TLS < 4 KB）；保持 `EntryScan`（9B）/ `EntryLinks`（8B）分离，全量遍历只调 `index.scanChunk(c)`/`scan(id)`/`parent(id)`，严禁循环内调 `chunk(c)`/`entry(id)`。
- **Win11 分段堆排查与分配器钩子禁区**：Win11 分段堆下 `umdh`/`gflags +ust` 无调用栈，须靠 `platform/AllocationTrace` 挂钩各模块 IAT 的 `HeapAlloc`/`HeapFree` → 钩子内禁用 `thread_local` 和函数内 `static`（加载器线程早于 TLS 初始化即分配，必崩），持锁期间禁分配内存，直接读 TEB TLS 槽以免 `TlsGetValue` 清掉调用方 `GetLastError`。
- **热页保留归还（`IdleTrim` / `HotPages`，#280）**：全量 `SetProcessWorkingSetSizeEx(-1, -1)` 清掉窗口热页，内存紧张时下次呼出缺页数千次拖慢至百毫秒乃至秒级 → `IdleTrim` 后台用 `VirtualUnlock` 仅逐出非热页（先经 `QueryWorkingSetEx` 跳过真锁定页）；显示后在后台快照增量页，按“首次基线 + 连续两次归还后打开才入集 + 达首次 2 倍（至少 +32 MB）回退基线”学习，启动器与剪贴板分开记并排除文件索引块；`FileIndex::warm()` 移至窗口显示之后；阈值设为 `上次归还后私有工作集 + 32 MB`；改 `IdleTrim.cpp` 构造或依赖时同步改截图和图片文字搜索插件的 `CMakeLists.txt`。
- **关设置窗后不归还与后台全扫回涨**：Windows 下关闭有焦点的 Qt 窗口只清 `focusWindow`、不离 `ApplicationActive`，导致 `IdleTrim::inUse()` 一直判在用；全量内容扫描会把约 90 MB 索引带回工作集 → `inUse()` 同时判 `focusWindow()` 与前台窗口属本进程，关闭设置调 `poke()` 并延迟到 `check()` 再判 `inUse()`；`IndexService::stateChanged` 后 5 秒收一次，闲置每 30 秒复查超阈值即归还；测空闲归还须带 `--background`（无参启动会开搜索框算在用）。
- **后台线程空醒与主线程卡顿探针盲区**：隐藏 D3D11 窗口的 `QDxgiVSyncThread` 按屏幕刷新率（240 Hz）空醒；常驻鼠标 Raw Input 被高回报率鼠标每秒唤醒上千次；`SendMessageTimeout(WM_NULL)` 探针会在主线程等 COM 或跨线程时被“插队”回答而漏测 → 建 `QGuiApplication` 前设 `QT_D3D_NO_VBLANK_THREAD=1`；鼠标监听仅在按下 Ctrl 时开启并自按下起计时兜底撤除（`KeyListener::listenToMouse`，防锁屏丢抬起）；重操作（如大 HTML/RTF 写库 `ClipStore::add`）离主线程；测命令端到端耗时比对二实例寿命差（`--settings` 减 `--background`）。

### 闪退（`abort()` / WER）、卡死（`UiStallWatch`）与符号还原

- **WER `c0000409`、工作线程异常与 `CrashRecord`**：`c0000409` 参数 7（`FAST_FAIL_FATAL_APP_EXIT`）若模块是 `ucrtbase.dll` 即 `abort()`（常见为 `std::thread`/`std::jthread` 未接异常引发 `std::terminate`，或 `std::bad_alloc`），绕过全部日志；`Qt6Core.dll` 则是先落日志再 `__fastfail` 的 `qFatal` → 线程内所有可能抛异常的库调用（ONNX Runtime、ZXing、Qt 容器，如 `TextRecognizer::work`）必包 `try/catch`；加 `reading-picture` 守卫两次失败后放弃（记 `clipboard-picture-not-read`）断死循环；`CrashRecord` 捕获 `SIGABRT`/未处理异常写 `crash.txt`（下次上报 `app-crash`），处理函数内禁堆分配、禁调 Qt，只用栈缓冲 + `CreateFileW`/`WriteFile` 与 `codeaddress::describe`；崩溃测试子进程须设 `_set_abort_behavior(0, _WRITE_ABORT_MSG | _CALL_REPORTFAULT)` 与 `SetErrorMode(SEM_NOGPFAULTERRORBOX)`。
- **极端长宽比图像击穿 OCR/ZXing 上限与 dump 回溯**：仅限总像素或并行“宽 ≤ X”与“短边 ≥ Y”会让超长条图（如 32739×35）被短边规则撑破宽度上限引发数 GB `bad_alloc`，2×/3× 放大还会超 ZXing 单边 65535 抛 `std::invalid_argument` → 超宽图横向分块检测，超长行空白切段，调用第三方库及放大前均校验单边上限；用户现场定位用 `tools/ocrtest` 在限额内抓 dump，`cdb` 查 dump 须加 `-i` 指向同版本 `onnxruntime.dll`。
- **`UiStallWatch` 挂起抓栈防死锁与 Release 偏移符号化（#111）**：`SuspendThread` 停住界面线程时它可能握着堆锁、加载器锁或函数表锁，抓栈线程此时分配内存、调 `RtlLookupFunctionEntry` 或写日志会永久死锁 → 停住期间仅做 `GetThreadContext` 和 `memcpy` 到预分配缓冲，立刻放行后再在栈副本上 `RtlVirtualUnwind`（原栈区间指针重映射到副本并包 `__try`）；无 PDB 发布版的 `WinShun+<偏移>`，按同 tag 以 `/Z7 /bigobj` + 链接 `/DEBUG /OPT:REF /OPT:ICF` 仅重编 `WinShun`，用 `cdb -z WinShun.exe -y <pdb目录> -c "ln WinShun+<偏移>; q"` 或 `llvm-symbolizer --obj=WinShun.exe 0x<偏移+基址>` 还原。

## 自动化测试、离屏探针与截图工具

### 单元测试与离屏探针

- **`--profile` 路径层级、注册表副作用与单实例互斥**：`--profile <目录>` 同时重定向 `APPDATA`/`LOCALAPPDATA`，配置文件在 `<目录>\WinShun\WinShun.ini`（非根目录），且默认 `ExplorerMenu`/`UriProtocol` 开启会改写系统右键与 `winshun://`；单实例互斥量 `Local\WinShun.Instance` 跨权限互斥但普通进程发给管理员副本的 `WM_COPYDATA` 被 UIPI 丢弃 → 测试配置先在 `[Launcher]` 设 `ExplorerMenu=false`、`UriProtocol=false`，测完确保正式/dist 副本恢复注册。
- **探针图标倍率异常与 `deleteLater` 不执行**：`--probe-runtime`/`--preview-*` 关闭高 DPI 缩放改用 `--scale` 时逻辑 DPI 取显示器 DPI（150% 为 144），令按磅设字号的 `Glyph` 放大 1.5–2 倍；仅用 `processEvents()` 不进事件循环时 Qt 不执行 `deleteLater`，导致伪内存泄漏或退出时旧 QML 委托报 `DirectWrite: CreateFontFaceFromHDC() ... Family="MS Sans Serif"` → 跑探针前必设 `QT_FONT_DPI=96`；探针泵事件用 `QEventLoop::exec()`（`ForegroundUseProbe::pump`），或在触发列表重建后显式调 `QCoreApplication::sendPostedEvents(nullptr, QEvent::DeferredDelete)`。
- **探针跳过 `aboutToQuit` 崩溃与退出期警告查栈**：探针直接析构 `App` 时，插件宿主若延迟到自身析构才 `shutdown()`，插件退出回调会落到声明在后已析构的 `App` 成员上（`0xC0000374`/`0xC0000005`） → `App::~App()` 首行即幂等调用宿主 `shutdown()`；抓退出崩栈在启动后 `cdb -p <pid>` 附加；查退出期 Qt 警告可在消息处理器临时用 `CaptureStackBackTrace` + `SymFromAddrW`（`RelWithDebInfo` + `/bigobj`）定位对象。
- **`QTRY_VERIFY` / `QTRY_COMPARE` 表达式严禁副作用**：`QTRY_*` 循环成功后会再次求值做超时诊断和最终 `QVERIFY`，如 `::DeleteFileW(path)` 二次调用返回 FALSE 会多等两倍超时并误判失败 → 所有 `QTRY_*` 表达式须幂等（如 `QFile::remove(p) || !QFileInfo::exists(p)`）。
- **`IdleOpenProbe` 与插件探针运行约束**：带尾反斜杠加引号的参数（`"C:\;F:\"`）会转义引号吞掉后续参数；后台编译会令呼出耗时翻倍并出现 600–700 ms 输入法毛刺；插件库探针若不检查索引加载成功，失败空模型送入卡片会制造次生警告 → 命令行路径一律正斜杠，剔除整机 CPU > 30% 样本并新旧交替跑；插件探针须断言数据角色且日志零 QML 警告。

### 真实输入界面实测与 PowerShell 陷阱

- **`-WindowStyle Hidden` 会吞掉进程首个窗口显示**：Windows 将隐藏启动参数套用到进程首次 `ShowWindow`（`GetForegroundWindow`/`Visible` 仍为真而 `IsWindowVisible` 为假），致使测试窗点击穿透到 VS Code、服务回 `ERROR_INVALID_WINDOW_HANDLE`，也会让 `--background` 启动的 Win顺 首个设置窗永久隐形 → 启动 Win顺 必用 `-WindowStyle Normal`；隐藏测试脚本首窗须再显示一次并断言 `IsWindowVisible()`；点击/滚轮前先以 `WindowFromPoint` 核验最顶层窗口归属。
- **权限分工与 DPI 感知**：向提权 Win顺 发输入/热键须提权脚本，而重启资源管理器、开常规文件夹窗及弹 `Win+V` 面板须由普通权限进程执行；Windows PS 5.1 不感知 DPI 致 `GetWindowRect` 与 `CopyFromScreen` 错位 → 拆分为普通权限与提权两段脚本，且开头统一调用 `SetThreadDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)`（`-4`），坐标全按物理像素。
- **`SendInput`、输入法与本机热键冲突**：64 位 C# `INPUT` 严格 40 字节；方向键/Home/End/PgUp/PgDn 缺 `KEYEVENTF_EXTENDEDKEY` 在 NumLock 下会被插假 Shift 抬起破坏多选；单次 `SendInput` 打包按下+抬起使 `WM_ACTIVATE` 时 `VK_LBUTTON` 已松开；`SendKeys` 会进中文输入法；`Ctrl+1/2/3` 易与本机 PixPin 冲突 → 绝对坐标带 `MOUSEEVENTF_VIRTUALDESK` 并检查 `SendInput` 返回值；导航键加 `KEYEVENTF_EXTENDEDKEY`；切英文或用剪贴板粘贴输入；查拖动区直接发 `WM_NCHITTEST`。
- **串行执行、前台守卫、窗口识别与破坏性操作核验**：并行跑前台/输入/截图测试会互相抢焦；窗口可见≠在前台；Qt 标题自动拼 ` - Win顺`；`GHOST_WindowClass` 是 Blender 而非卡死幽灵窗 `Ghost`；`Win+V` 不抢前台也不增 `EnumWindows` 项 → 前台测试一律串行，发键前必查 `GetForegroundWindow()` 属 Win顺；启动器认 `Qt6120QWindowToolSaveBits` + `--dump` 几何，设置窗匹配 `"设置 - Win顺"`，`Win+V` 用截图差分判定；删改测试放专用索引目录（非 `%TEMP%`），每步前 `Ctrl+Shift+C` 核对路径；测完还原设置/日志且勿重拉 `Program Files` 旧版。
- **第三方应用隔离、剪贴板卫生与虚拟磁盘测试**：Edge/Firefox/WT/`conhost` 须独立用户目录或实例；Blender `--factory-startup` 仍读用户目录并写恢复文件；Excel 退出时会把缓存信任设置写回注册表覆盖中途删除的 `AccessVBOM` → Blender 预建私有 `BLENDER_USER_*`；Excel 宏测试等 `EXCEL.EXE` 彻底退出后再删 `AccessVBOM`；非剪贴板测试临时将 `pwsh.exe`/`WinShun.exe` 加入 `[Clipboard] ExcludedApps`（只读 `sqlite3 mode=ro` 核对条数）；测卷锁定/弹出用 VHD（弹出后用 `Dismount-DiskImage` 卸载而非报错 `0x80070057` 的 `diskpart detach`）。
- **PowerShell 测试脚本高频坑**：内置别名优先于函数（避 `r`/`sp`）；变量/参数不区分大小写（`$t` 冲 `$T`，`[string]` 把数组拼成单串，`[switch]` 禁赋 0）；`@($a + 1, $b)` 逗号结合更紧须加括号；`"$h:"` 被解析为作用域须写 `"${h}:"`；中文弯引号 `’`/`“”` 会截断字符串改用 `[char]0x2019`；`$null` 传给 .NET/Win32 `string` 变 `""` 须传 `[NullString]::Value`；PS 5.1 `Start-Process -ArgumentList` 不自动给含空格参数加引号须手拼，pwsh 7 `Start-Process -Wait` 等子孙进程改用 `-PassThru` + `.WaitForExit()`；`System.Drawing` 用 PS 5.1；`System.Windows.Automation` 偶发读空任务栏改用 COM `IUIAutomation` 核验。

### 截图工具（`tools/screenshots/`）

- **Mica 取色、亚克力验证与提权背板置顶**：Mica 仅取桌面壁纸色（纯色背景也验不出亚克力模糊）；提权进程非前台时对新建窗口调 `SetWindowPos(HWND_TOPMOST)` 返回成功却不置顶 → 拍 Mica 前用 `scene --wallpaper` 临时换壁纸（`SPI_SETDESKWALLPAPER` 仅带 `SPIF_SENDCHANGE`）拍完 `restore`，验亚克力后垫彩色竖条纹窗；抠图黑白背板创建即带 `WS_EX_TOPMOST`，把目标窗重排其上并校验无遮挡窗，三拍（黑/白/黑）双黑有差即重拍。
- **剪贴板捕获、演示配置防污染与去阴影合成**：剪贴板窗不抢焦点默认拍前台会拍到记事本；演示期复制内容和当前 Explorer 目录会污染演示态；抠图带出的 DWM 阴影会被 64 px 边缘切断，且去阴影时窗口本体与后方探出 logo 的遮挡关系相反 → 拍剪贴板用 `shoot --winshun`；启动前按 `made-for-screenshots.txt` 守卫清空演示剪贴板，中文经剪贴板进记事本再复制，拍对话框前先用 Explorer 打开演示目录；合成前 `lifted` 去原阴影再在大画布生成三层柔和阴影，窗口按阴影在下（`C = l·L/a`）、logo 区域按阴影在上（`C = (1−s)·l·L/a`）分开解算，且排除边距取 2 px（非 3 px）以免对话框与 6 px 缝隙搜索条间留暗线。
