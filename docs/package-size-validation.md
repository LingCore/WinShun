以同一份已验证的新版部署目录为基础，补回原来的完整粗体文件、ONNX Runtime 和两个 OCR 模型，再分别使用相同的 Inno Setup 压缩设置及 ZIP 打包方式。这样比较的是资源取舍，不把其他协作修改带来的代码体积变化算作收益。对照安装包仅用于测量，没有执行安装。

## 字体

保留原始完整的 `AlibabaPuHuiTi-3-55-Regular.ttf`，文件哈希与源码资源一致，没有裁剪或修改字库。移除单独分发的 `AlibabaPuHuiTi-3-85-Bold.ttf`，减少约 8 MiB 原文件；原文件继续保留在源码仓库。字体许可见 `resources/fonts/LICENSE.txt` 及其中记录的[官方法律声明](https://www.yuque.com/yiguang-wkqc2/hgpff0/nus9wiinq4aeiegy)。修改字库需要另行授权，本次没有做字体子集化。

FreeType 在仅有 Regular 时不会为 `DemiBold` 合成粗体，因此 QML 统一使用 `Theme.fontStrong = Font.Bold`，相关自绘文本也使用 `QFont::Bold`。加载保留对非 ASCII 程序路径的字节读取方式，避免中文路径下 FreeType 打不开字体。安装程序仅清除旧版自带的同名粗体文件，不清理用户数据或旧 OCR 文件。

`tst_uifont_freetype`、`tst_uifont_gdi` 检查 100%、125%、150%、200% 下粗体的实际绘制墨量，以及中英、日文、韩文、希腊文、俄文、emoji 和扩展汉字的字体回退。实际设置窗口及截图 OCR 窗口也完成了中英文、深浅色和缩放检查。

## 增强 OCR

- 标准安装版和便携版不再附带 ONNX Runtime、OCR 模型。完整离线安装包仍带同一份模型和运行库。
- 主程序提供“设置 › 剪贴板 › 记录 › 增强文字识别”，支持下载、进度、取消、失败重试及本地 ZIP 安装。剪贴板未安装增强组件时沿用 Windows 可用的识别语言。
- `OcrFiles` 优先找当前用户或便携配置的 `components/ppocr-v6-ort1.30.0-x64`，再兼容程序旁的旧版 / 离线版文件。旧文件不搬动、不删除。截图插件通过 `WS_COMPONENTS_DIR` 使用同一份组件。
- 主程序持有安装任务，使用受生命周期约束的 `std::jthread`。组件清单固定每个文件的大小及 SHA256；临时目录全部校验通过后才原子发布。取消、损坏包、缺失或多余文件不会发布半份组件，失败保留已有文件。
- 截图 OCR 保留待识别原图。安装入口只调用已有 `ui` 权限的 `show_ocr_setup`，打开主程序设置；安装期间隐藏置顶 OCR 窗口，避免挡住设置，完成后继续原图。截图插件不新增联网权限。
- 已存在的贴图在安装组件后重新检查可用性；未安装时菜单仍可进入安装流程。关闭待识别窗口会丢弃待续识别图片。
- 剪贴板等当前批次结束后切换识别引擎并补读历史，无需重启。

`tools/package_ocr.py` 校验并生成组件 ZIP，也用于离线安装目录。`scripts/release.ps1` 已接入标准安装包、便携包、离线安装包、组件 ZIP 及四个产物的 SHA256。CMake 默认安装同样不带增强组件，显式选择 `--component EnhancedOcr` 才安装运行库与模型。

## 尚未覆盖与发布要求

没有在 Windows 10 或干净虚拟机中执行安装 / 升级，没有运行当前用户的真实安装程序，也未验证公网 GitHub 上的组件下载。现有数据兼容有目录解析和部署测试，不应描述为已在所有旧版本用户环境完成升级验证。

组件尚未上传。下次正式发布必须更换应用版本，并把 `WinShun-ocr-ppocr-v6-ort1.30.0-x64.zip` 与同版本 Release 一起发布；否则应用内默认下载地址尚不可用。当前可通过已验证的本地 ZIP 或完整离线安装目录使用。这次没有创建、覆盖或发布任何 Release。
